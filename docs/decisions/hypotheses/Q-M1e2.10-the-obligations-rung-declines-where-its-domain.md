# Q-M1e2.10 — The obligations rung declines where its domain can grow

The obligations rung reads each obligation's candidates off its guard at root. It declines, and the blind enumerator
builds H, wherever that reading could miss a payment: where a guard scans a relation the rung itself proposes, and
where an obligation's trigger, or a guard beside its witness step, reads a relation a commitment can change. That
set is computed once from the rules, seeded with what the rung would propose and closed under the saturation plans,
at relation grain, so a program that already names the value at root declines too. R is then over the blind
enumerator's universe, which on an untyped relation holds facts no rule refutes or requires. The `rung` line says why
it declined: *an obligation scans `food`, a relation a commitment can change*.

**Why.** A domain value only a commitment derives is in no candidate scanned at root, so the rung's H would lack the
model that value licenses; a choice among an obligation's payments is exhaustive only while the set of them cannot
grow beneath it.

**Held by.** `ein_infer::oblgen`'s decline, over `ein_infer::monotone`'s set of relations a commitment can change;
`ein-infer/tests/obligation_rung.rs`: `the_ladder_dispatches_by_what_the_program_declares`
(`tests/stdlib/bijection/06_blind_enumeration.ein` declines); the `:expect` of
`examples/ein-bugs/wrong-answers/oblig-fresh-name-two.ein` and `oblig-stdlib-total-owed.ein`, each the blind
enumerator's region.
