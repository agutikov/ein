# Q-M1c.7 — A claim may name a relation only a rule derives

A claim may list a fact of any relation of the program, and so may a query's goal: one the program declares,
states a fact of, or writes in a rule or an obligation, at any depth, a rule's `:assert` and a hypothesis `(open
F)` among them, and one an activator gives a rule's parameter that heads a form. A relation only saturation creates, such as an
activator a library's fan-out rule concludes, is a relation of the program once the module that writes it is
imported, and a claim names it by the short name the file lists. A name the program writes nowhere is refused at
load: `(solve … :expect …) names <r>, and the program names no relation <r> — …`.

**Why.** The refusal exists to catch a misspelt relation, which would close the held extent of a relation no state
holds a fact of, and pass for ever. A misspelling is written in no rule as well as in no declaration, so counting
what rules write keeps the refusal and admits every derived relation, which is often the one a test is about.

**Held by.** `program_relations` (`ein-ir/src/from_ir.rs`), the one list a goal and a claim are held to;
`ein-cli/tests/goal_premises.rs`: `a_goal_is_answered_as_a_rules_match_would_be` (its region claim over a rule's
conclusion) and `a_goal_over_a_relation_of_the_program_loads` (a goal over a relation only an imported rule
concludes). The page: [`07-diagnostics.md` § 2.21](../../ein/user/04-reference/07-diagnostics.md#221-a-goal-is-held-to-what-a-rules-match-is-held-to).
