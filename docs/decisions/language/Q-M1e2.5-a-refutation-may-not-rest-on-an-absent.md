# Q-M1e2.5 — A refutation may not rest on an `absent` a commitment can still fill

A rule that concludes `(false)` or a stored negation may not rest on an `(absent P)` over a relation whose held
extent a commitment can still extend: directly, through a fact a rule derives resting on such an `absent`, or
through its activator. A program that writes one is refused, one line per refusing rule, by every command that takes
the universe, and the line names the forms that say what was meant: close the relation's held extent if no
commitment is meant to extend it, state the requirement as an obligation, or conclude from a stored negative.
*Extendable* is the static check's set of relations whose held extent a commitment can change, followed through
every rule with parameters whose activator it holds. Over a held extent no commitment can extend, the same shape is
closed-world reasoning and loads.

**Why.** Over a held extent a commitment can extend the shape judges a state that has not yet decided `P` as if `P`
were false: it says *contradiction* where the truth is *not yet*, an obligation written as a refutation, and *dead*
stops being closed upward, so a commitment that adds `P` would bring a dead state back to life.

**Held by.** `ein_infer::forbid`, run after root's fixpoint. `ein-infer/tests/refutation_under_absent.rs`:
`the_probe_is_refused_and_the_message_names_the_replacements`, `the_written_activator_programs_are_refused`,
`beside_an_hrule_the_remedy_names_the_hrule_and_not_the_list`,
`beside_an_obligation_the_remedy_names_the_obligation`.
