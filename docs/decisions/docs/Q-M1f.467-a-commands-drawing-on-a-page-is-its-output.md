# Q-M1f.467 — A command's drawing on a page is its output, canonical unless the page is about the fold

A drawing a page presents as what an `ein` command draws is that command's output for the program the page gives, as
the page writes the command: canonical by default. It is folded where the page's point is the compact view, and the
page then writes `--fold` in the command, or, under `docs/ein/reasoning/`, which names no command, says that the
drawing folds.

**Why.** A reader who runs the command the page shows gets the drawing the page shows, so a page cannot draw what
the engine does not; and the canonical form is the graph, which a page shows unless its subject is the fold.

**Held by.** The pages and their `diagrams/` folders
([Q-M1f.368](Q-M1f.368-a-diagram-is-a-file-and-a-page-shows-its-picture.md)): a drawing of the engine's is kept as
the file the command wrote, with what [Q-M1f.468](Q-M1f.468-a-pages-drawing-of-a-knowledge-base-may-be-a-cut.md)
allows left out.
