# Q-M1f.474 — A hand schematic may draw an arrow the graph lacks, a view never

A drawing made by hand for an explanation may carry an arrow that is no arrow of the knowledge base's graph, where
its page says what the arrow means. A command's drawing never does: every arrow `ein` draws is an arrow of the
graph, a step's reading of a fact, or a mark the view's legend states, and arrows go only between shapes
([Q-M1f.429](../cli/Q-M1f.429-no-arrow-goes-to-or-from-an-arrow.md)).

**Why.** An explanation may need to point from a fact to what it switches on, which is no object; a view is what the
engine computed, and an arrow in it that the graph lacks would draw something the knowledge base does not hold.

**Held by.** The hand drawings that carry such an arrow, each with its page's sentence;
[rendering](../../ein/user/04-reference/12-rendering.md), the legend of every arrow a view draws.
