# Q-M1f.559 — The elimination of a double negation is a module a program imports

That `g` holds where `(not (not g))` does is a step of one logic, and it is `std.negation`'s: `eliminate-0` to
`eliminate-6`, one rule a count of arguments with the relation a parameter, each applied under an activator a program
states, `(eliminate-2 likes)`. A program that imports nothing of the kind holds the denial of a denial as a fact and
concludes nothing from it ([Q-M1f.391](../language/Q-M1f.391-the-negation-of-a-negation-is-a-fact.md)). The module
every program gets, `std.core`, holds no such rule
([Q-M1f.551](Q-M1f.551-std-core-is-loaded-into-every-program.md)), and neither does the contradiction's
([Q-M1f.557](Q-M1f.557-the-contradiction-is-a-theory-a-program-imports.md)).

The elimination's rule concludes a fact whose relation is its parameter. An activator that puts a fact in that
parameter's place activates nothing, and nothing says so
([Q-M1f.1](../language/Q-M1f.1-a-rule-that-could-derive-an-activator-binding.md)).

**Why.** The meaning of a denial is a theory's, and the classical step from a double negation to the fact is one a
program may want or not, as it may want the contradiction or not. Given to every program it would be every program's
logic; imported, a program says which relations it is for.

**Held by.** `stdlib/negation.ein`; `tests/stdlib/negation/01_eliminate.ein`; `examples/beliefs/06_double_negation.ein`,
which imports `eliminate-2`, against `03_liar_denial.ein`, which does not; `stdlib/core.ein`, one rule.
