## V-1 — *forbid* reads rules, and the kernel's contradiction is none

**What.** Q-M1e2.5 (cancelled 2026-11-19, [Q-M1f.564](../../../docs/decisions/answer/Q-M1f.564-a-non-monotone-program-loads-with-a-warning.md)) refuses
a rule that concludes `(false)` or a stored negation where it rests on an `(absent …)` over a relation a
commitment can still extend, *directly, through a fact a rule derives resting on such an `absent`, or through its
activator*. The kernel's contradiction, a fact beside its stored negation, is the same refutation and is no rule,
so *forbid* does not read it: a program in which a fact derived under such an absence can stand beside its
negation loads.

**Shown by.** The contradiction written as a rule, one rule a count of arguments with its activators derived
from the declarations ([`design.md` Appendix A.1](design.md#a1-the-contradiction-rule-set-contrainc)), appended to
every corpus program `ein solve` answers ([`sweep_clash.py`](design.md#b1-sweep_clashpy)): 560 answer as they
did, and seven are refused, each by *forbid*, each naming the written rule. For
`examples/lattice/08_absent_witness_hole.ein` with the set appended, `ein solve` prints, exit 1:

```text
rule 'clash-0' [activator meal]: concludes (false) from meal, which rule 'soup-unless-allergic' derives resting on (absent …) over allergic, a relation a commitment can still extend — so it calls a state that has not yet decided allergic a contradiction, and a commitment would lift it (dead is not upward-closed under absent; Q-M1e2.5). …
```

The seven: `examples/features/07_unstratifiable.ein`, `examples/lattice/08_absent_witness_hole.ein`,
`examples/lattice/10_fifo_gap.ein`, and `f07-fpoff.ein`, `f07-rules-swapped.ein`, `kw-neq-in-absent.ein`,
`kw-neq-in-absent-twin.ein` under `examples/ein-bugs/wrong-answers/`.

**What it is not.** No wrong answer. Each of the seven is a program the static check flags as it stands
(`monotonicity.monotone` is `false` in its `--json-summary`), since the fact derived under the absence is a
positive conclusion from an absence a commitment can fill, and of a flagged program the engine claims nothing.
So the two readings agree that the program is outside what is claimed; they differ in that one refuses it and
the other answers it. The refusal is also at relation grain: it is issued for `clash-0` under an activator
whether or not any rule can conclude the negation of that relation's fact.

**Whose.** The reading of *forbid* is [F21](../../m1n_non_monotone_programs/f21_non_monotone_programs_decided.md)'s ground. It
bears on S1f.21.2 only as one line of the contradiction rule's account: what the kernel does differs from firing
the rule in that *forbid* does not read it.

## V-2 — the surfaces say *derives (false)* of a state that holds none

**What.** A state dead by a fact beside its negation holds no `(false)`: the contradiction is read, and nothing

contradiction and the elimination, in that module. The contradiction's rules load wherever a program does
(`clash-N` concludes `(false)`). The elimination's do not: as the rule is written and as the loader's check reads
it, putting it in a module every program gets would refuse those four programs, which import nothing.

**The smallest program that shows it**, run four ways on the build of S1f.21.8's branch:

```lisp
(import std.negation)                       ; (1) no import · (2), (3) this line · (4) (import std.contradiction)
(relation is-a   X T :why "{?3} is a {?4}")
(relation chosen D   :why "{?3} is chosen")
(relation served D   :why "{?3} is served")
(is-a Tea Drink) (is-a Milk Drink)
(hrule guess (?R ?T)
  :match  (is-a ?x ?T)
  :assert (?R ?x)
  :why    "guess: is {?x} {?R}?")
(solve :hrules (guess (chosen Drink) guess (served Drink)))    ; (2): (solve :hrules (guess (chosen Drink)))
```

| | the program | `ein solve` |
|---|---|---|
| 1 | no import, `guess` named twice | `states (k_s) 16` |
| 2 | `std.negation` imported, `guess` named once | `states (k_s) 4` |
| 3 | `std.negation` imported, `guess` named twice | **refused** |
| 4 | `std.contradiction` imported, `guess` named twice | `states (k_s) 16` |

The refusal: *kb load error: rule 'std.negation.eliminate-2': its :assert writes (?R ?a ?b), whose ?a is rule
'guess''s parameter ?R, which names a relation, and (not (not (?R ?a ?b))) can bind ?a to a fact, as an argument of
(?R ?a ?b) — a relation is named by a symbol, not a fact*.

**Why the loader says so.** `eliminate-2` concludes `(?R ?a ?b)`, a fact of two arguments of whatever relation its
activator names. `guess` is a rule of two parameters, so a fact `(guess a b)` would be an activator of `guess`,
binding its first parameter, which names a relation, to `a`; and `a` comes out of a double negation, where it may
be a fact. The check does not ask whether anything activates `eliminate-2` with `guess`: nothing does here, and
nothing can. It reads the conclusion as able to write into every rule of that count whose name the program writes
as an argument (Q-M1f.42), and the second `guess` of the `:hrules` list counts as one
([V-13](#v-13--the-check-on-a-parameters-conclusion-counts-an-hrule-from-its-second-naming)), which is why row 2
loads and row 3 does not. So the refusal is of something no run could reach: the check is sound and coarse.

**The ways out**, S1f.21.11's to show, each on the corpus (its task 1.6): the elimination stays a module a program
imports, and `not`'s meaning in the module every program gets is the contradiction alone, the default, which
changes no program; the check reads what an activator can name, and no longer refuses these; the `:hrules` list is
read as a list (V-13), which frees these four and not a program that names a rule as an argument elsewhere.
