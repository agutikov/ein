# P1f.23 — findings (R-n)

What a stage of [P1f.23](README.md) finds outside its scope, each with what shows it and whose call it is.

| id | finding | shown by | call |
|---|---|---|---|
| R-1 | **`--models grid` reads `is-a`.** `ein-render/src/grid.rs`, the functional licence's rows: beside the pairs of the licensed columns, every `(is-a x Anchor)` adds `x` as a row, so an object of the anchor's that no column names still has a row. Treating `is-a` as an ordinary relation (Q-M1f.421) there drops those rows: a grid lists only what the columns' facts name, and an anchor's object that holds no fact of a column is no row. Its doc names `crate::kb_dot` as reading `is-a` the same way, which the KB view no longer does. S1f.23.2 removes `grid.rs` and `models.rs` in its worktree | `grep -n '"is-a"' ein.rs/crates/ein-render/src/grid.rs` | **the user's**, with the general ruling on theory names; S1f.23.2's removal may answer it |
| R-2 | **The loader takes `is-a` for a relation of every program.** `ein-ir/src/from_ir.rs`' `program_relations` adds `is-a`, `eq` and `neq` to the relations a goal and a claim are held to (Q-M1f.114), so a program that never writes `is-a` may name it in a `:goal` or a `(solve …)` list and be answered, where any other unwritten name is refused. Treated as ordinary, a goal over `is-a` in a program that does not write it is refused as a misspelt relation is; `eq` and `neq` are the kernel's and stay. Two refusals' texts suggest `(is-a ?y T)` to bind a variable (`from_ir.rs`, the unbound conclusion's note), a theory's name in the engine's words | `grep -n 'is-a' ein.rs/crates/ein-ir/src/from_ir.rs` | **the user's** |
| R-3 | **`--models grid`'s help speaks of a type.** `ein-cli/src/cmdline.rs`: *each as a table, the anchor type's objects down the side*, the reading R-1 computes. Ordinary, the help says *the objects the licensed columns name* | `grep -n "anchor type" ein.rs/crates/ein-cli/src/cmdline.rs` | **the user's**, with R-1 |
