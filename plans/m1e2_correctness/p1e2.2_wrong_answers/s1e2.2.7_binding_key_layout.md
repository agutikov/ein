## The case

[`defined_behaviour.md` §3.2](../../../docs/kernel/defined_behaviour.md)'s
thirteen-line program, banked as [`corpus/fuzz_findings/binding-key-layout.ein`](../../../corpus/fuzz_findings/binding-key-layout.ein):

```
(rule note (?R ?f) :match (and (?R ?a ?b) (holds ?f)) :assert (noted ?a ?f))
(edge 1 2) (edge 2 3)   (holds 1) (holds 3)
(note edge 1)
(note edge (src Y))
```

```
$ ein saturate --dump corpus/fuzz_findings/binding-key-layout.ein        # release
  (noted 1 1) (noted 2 1) (noted 2 3)                     ← (noted 1 3) missing
$ ein saturate --dump corpus/fuzz_findings/binding-key-layout-swapped.ein     # the two activator lines swapped
  (noted 1 1) (noted 1 3) (noted 2 1) (noted 2 3)
```

The derived set depends on the **order of two facts**. A debug build panics
instead (`engine.rs:250`, `check_layout`, a `debug_assert`). The binding key
`(rule, activator, values)` compares two register layouts position by
position, so an `int` beside a nested `Fact` in one position collides with a
different binding. Pinned today, as a defect, by
`rule_semantics.rs::an_int_beside_a_nested_fact_in_one_position_loses_a_derivation`,
which expects the missing fact in release and the panic in debug.

**Reach:** zero corpus activators carry an int or a nested fact (S1e.1.4).
It is a wrong answer on a well-formed program that no shipped puzzle writes.

## The three fixes (Q-M1e.16, priced 2026-08-29)

1. **Give `ActivatorId` every argument**, not the symbol-filtered list. The
   compile-cache key already computes that string. Smallest, and
   **provably golden-neutral** on the corpus (every activator argument is a
   symbol there). It changes what `fire` / `enqueue` / `compile` print in their
   `activator` field, and what `naf_deps.rs` and `obligations.rs` key on, for a
   program with a non-symbol argument.
2. **Put the layout in the key.** It changes no event, leaves the harmless
   `Fact`/`Fact` collapse collapsed, and costs a word per key on the hottest
   path.
3. **Refuse the program.** `check_layout` becomes a compile error in every
   profile. Cheapest, and it refuses a well-formed program, which is a
   language decision, not a repair.

**Recommendation: (1).** It makes two keys that already disagree agree, which
is AR-M1's *one artefact, one owner*, and the corpus proves it free. (2)
keeps two keys and makes them compatible. (3) is out for a milestone that
answers rather than refuses.

## What moves

`rule_semantics.rs`' pin flips to *four facts in either order, in both
profiles*; `check_layout`'s assertion stays as the guard that the fix holds;
`defined_behaviour.md` §3.2 moves from a preserved defect to a fixed one; the
`activator` field on non-symbol programs (none in the corpus).
