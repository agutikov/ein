## The case

```
(relation seed T) (relation p T) (relation p2 T) (relation q T) (relation r2 T)
(seed a)
(hrule g  () :match (seed ?x) :assert (p ?x))
(hrule g2 () :match (seed ?x) :assert (p2 ?x))
(rule mk () :match (and (p ?x) (absent (p2 ?x))) :assert (q ?x))
(rule q  (?n) :match (seed ?n) :assert (r2 ?n))
(rule r2 (?k) :match (seed ?k) :assert (false))
```

`{(p a)}` derives `(q a)` resting on `(absent (p2 a))`. `(q a)` activates
rule `q`, which asserts `(r2 a)`, which activates rule `r2`, which concludes
`(false)`. So `{(p a)}` dies, and its superset `{(p a), (p2 a)}` lives: a
dead hole, the shape *forbid* exists to refuse. It loads:
`ein solve build/s1e2.2.16/extra/node-chain-sym.ein` at `a766c025` reports R
three states, *"not monotone: 2 sites — 1 hole"*, minimal hole `{(p a)}`,
exit 0, and the oracle agrees.

**Why *forbid* misses it** (S1e2.2.16's reading): D's closure follows reads
and not activators. `r2`'s activator relation is in N (through `q`'s pattern)
and not in D, so *forbid* does not read `r2` from its pattern, and root
compiled no plan of it. The chain's last activator first appears at a node.

**A label beside it:** the read-out's status line says *"non-monotone here
(exercised, by )"*, an empty list where the site that exercised the hole
should be named.

**Reach:** no corpus program today (the S1e2.2.5 census of the refused set,
re-taken by S1e2.2.16's sweep, moved nothing on this shape).

## The method

1. **Re-take, and measure the wider D first.** At the stage's HEAD, re-take the
   witness. The fix will make D's closure, or *forbid*'s reading of rules
   root has no plan of, follow activators as well as reads. **D is shared**
   (`monotone::dynamic`, since S1e2.2.15): the static check, the read-out's
   sites, *forbid*, and the obligations rung's decline all read it. Prototype
   the change, then run the full corpus sweep against HEAD. List every program
   whose flag, sites, refusal, rung decline, H, R or exit code moves, before
   any edit. **If any program other than the witness and its variants moves
   an answer, a refusal or a rung decline, stop and report**: that is a
   question for the user, not a default. A flag or site that moves with no
   answer moving is listed, not a stop.
2. **Bank the witness** under `examples/ein-bugs/wrong-answers/`, with
   variants that pin the chain's length (one activator hop, two), and a
   control where the chain does not rest on an `absent`, which loads. File
   **W17** `open`, one row per witness, `right` = the refusal. This is the
   first commit, with the list, and nothing built.
3. **The fix:** the narrowest change that makes *forbid* follow an activator
   chain, keeping D computed in one place. The refusal line names the chain,
   as F2's refusals do. The status line names the site that exercised a hole,
   or says why none can be named.
4. **The pages:** `defined_behaviour.md` § 4.7, `absent_semantics.md`,
   `monotonicity.md` § 7.7 where they state what *forbid* reads; the
   S1e2.2.5 stage record (a dated note); Q-M1e2.5's entry.

**Why each loads.** *forbid* reads a rule with parameters root has no plan of
(an *open* rule) from its pattern, and three things about that reading are
one gap, D's closure following the plans root compiled and not activators:

1. **Which open rules it reads**: those whose activator relation is in D.
   An activator relation only an open rule writes is not in D, so `r2` (and
   `r3`) are never read: `-1`, `-2`. This is the case as filed.
2. **What an open rule taints**: N is seeded from root's plans' odd reads
   only, so an open rule's own `absent`, over a relation (`-node-absent`) or
   over its parameter's relation (`-param-absent`), taints nothing it
   derives. `-param-absent`'s `watch` is open and would be refused as the
   refutation (`Cause::Parameter`); what it derives is not followed.
3. **What is extendable**: D, so a relation only an open rule writes reads as
   static to *forbid*, and to the static check (`-node-writes`).
