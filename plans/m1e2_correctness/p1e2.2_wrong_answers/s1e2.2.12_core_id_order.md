# S1e2.2.12 — W11: which core is reported depends on interner id order

**Phase:** [P1e2.2](README.md) (The wrong answers)
**Estimate:** 1.5 days
**Depends on:** [S1e2.2.11](s1e2.2.11_alt_cap_core.md), since both change how a
core is chosen and the tie-break should be written once.
**Carries:** [`corpus/fuzz_findings/unsat-core-id-space.md`](../../../corpus/fuzz_findings/unsat-core-id-space.md)
(*"a decision nobody has taken"*) and `d3-unsat-core`. The class is
[design/02](../../../docs/history/m1a_rust/design/02_determinism_and_order.md)'s
determinism contract.

## The case

The id-order sweep (`ein-render/tests/id_order_invariance.rs`, which re-runs a
file under a permuted interner) on the two fuzz findings, 2026-10-14:

```
unsat-core-id-space.ein [solve[default]] seed 1
    plain:    CORE 1 [(r1 o4 o5)]
    permuted: CORE 2 [(r1 o1 o5) (r1 o4 o1)]
d3-unsat-core.ein [trace[answer]] seed 15839   (EIN_ID_SEEDS=3)
    plain:    … (unsat core: 4 facts).
    permuted: … (unsat core: 6 facts).
```

The same program reports a different core, of a different **size**, when only
the ids its names were interned under change. Ids are not part of the
program. [`corpus/fuzz_findings/README.md`](../../../corpus/fuzz_findings/README.md)
says `d3-unsat-core` *"is green under a permuted id space"*, which is true at
seed 1 only.

This is a different defect from [W10](s1e2.2.11_alt_cap_core.md). There the
store's **retention** order decides; here the search's **tie-break** among
candidates, or its traversal order over ids, does. The size difference (1 vs
2, 4 vs 6) says it is not only a tie-break among equal-size cores: the minimum
is not always found.

## The fix

1. Find which: is `explain.rs`'s search exact, so that the size difference
   comes from what was *recorded* (firing order follows id order)? Or is it a
   bounded search whose cut-off depends on id order? The answer decides
   between fixing the recorder (with S1e2.2.11) and fixing the search.
2. Then a canonical choice among equal-size cores: smallest size, then
   lexicographic on the rendered facts, never on ids. The same rule as
   `defined_behaviour.md` § 6's for goal rows (inventory **S7**, the sibling
   in the read-out).

## What moves

`fuzz_findings/README.md`'s sentence, and the two findings become `regression`
corpus entries with the sweep running them at `EIN_ID_SEEDS=8`. Corpus cores
that were already minimal stay as they are, and any that move are listed.
