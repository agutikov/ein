## The case

The loader holds a string written as a fact's argument as **the symbol it
names**: `(holds "b")` is the fact `(holds b)`, and `"1"` is the symbol `1`,
not the int `1` ([`01_grammar.md`](../../../docs/kernel/ir/03-ein-lang/01_grammar.md)'s
`STRING` row, since S1e2.2.16). The rule compiler does not lower a string:

| witness (`build/s1e2.2.16/textkey/`, at `a766c025`) | today | right |
|---|---|---|
| `str-in-match.ein`: facts `(holds 1) (holds "1") (holds a) (holds "b")`; rules `s` `:match (holds "1")`, `t` `:match (holds b)`, `u` `:match (holds 1)` | `t` and `u` fire, **`s` never does**: in a `:match` a string is an opaque slot that matches nothing (`compile.rs`' `slot`) | `s` fires on `(holds "1")` |
| `str-in-assert.ein`: `:assert (tag ?x "lbl")` | `ein saturate` stops: *`TypeError: an unrecognised `:assert` slot has no value to store`*, exit 1 | `(tag 1 lbl)`, `(tag a lbl)` |

No rule under `examples/`, `tests/` or `stdlib/` writes a string in either
clause (S1e2.2.16's scan of the rule forms, 300 files, 2026-11-04).

**The fix, by default: lower a string in a rule as the loader lowers it in a
fact**, the symbol it names, so a rule and a fact that write the same string
mean the same value. The alternative, refusing a string in a rule's `:match`
or `:assert` at load, also ends the wrong answer, and makes the language
smaller than its loader. The stage takes the default, and the user may
override it before the stage runs.

#### The default fix, prototyped

- **A string in a rule is the symbol it names**, as the loader holds it in a
  fact: `slot` lowers `Node::Str` as `Node::Atom`, at any depth, in a
  `:match`, an `absent` and an `:assert` alike, and `guard_arg` does the same
  for a guard. A string under a keyword pair is not reached, since the
  compiler lowers nothing there, so a keyword's value keeps its meaning.
- **A string in a rule is a name of the program**: `invariant::walk_constants`
  reads it as it reads an atom, outside keyword pairs, so `lbl` in
  `str-in-assert`'s `:assert` is a candidate object (Q-M1e2.9 (a)), as it is
  in the atom twin, and the alive-set invariant holds of `(tag 1 lbl)`
  (default 3).
- **`FireError::NotAFact` stays reachable**, by five shapes no string is
  among: a keyword pair, a range or a wildcard in a template, a relation
  written as a variable the activator does not bind, and a top-level
  conclusion that is not a fact (`probes/na-*.ein`). Its line takes Ein's
  spelling: the rule and the slot as the program writes them, with no class
  name, the one line `ein saturate` and `ein solve` both print (default 4):

  | `:assert` | the line, `ein saturate` and `ein solve` alike, exit 1 |
  |---|---|
  | `(tag ?x b :source "x")` | `rule 's': its :assert writes :source "x" as an argument of tag, and no fact can hold it — an argument is a name, a string, an int, a variable its :match binds, or a fact (relation argument …)` |
