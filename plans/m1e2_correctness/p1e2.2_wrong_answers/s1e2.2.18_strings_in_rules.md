## The case

The loader holds a string written as a fact's argument as **the symbol it
names**: `(holds "b")` is the fact `(holds b)`, and `"1"` is the symbol `1`,
not the int `1` ([`01_grammar.md`](../../../docs/kernel/ir/03-ein-lang/01_grammar.md)'s
`STRING` row, since S1e2.2.16). The rule compiler does not lower a string:

| witness (`build/s1e2.2.16/textkey/`, at `a766c025`) | today | right |
|---|---|---|
| `str-in-match.ein`: facts `(holds 1) (holds "1") (holds a) (holds "b")`; rules `s` `:match (holds "1")`, `t` `:match (holds b)`, `u` `:match (holds 1)` | `t` and `u` fire, **`s` never does**: in a `:match` a string is an opaque slot that matches nothing (`compile.rs`' `slot`) | `s` fires on `(holds "1")` |
| `str-in-assert.ein`: `:assert (tag ?x "lbl")` | `ein saturate` stops: *`TypeError: an unrecognised `:assert` slot has no value to store`*, exit 1 | `(tag 1 lbl)`, `(tag a lbl)` |

No rule under `examples/`, `tests/` or `stdlib/` writes a string in either
clause (S1e2.2.16's scan of the rule forms, 300 files, 2026-11-04).

**The fix, by default: lower a string in a rule as the loader lowers it in a
fact**, the symbol it names, so a rule and a fact that write the same string
mean the same value. The alternative, refusing a string in a rule's `:match`
or `:assert` at load, also ends the wrong answer, and makes the language
smaller than its loader. The stage takes the default, and the user may
override it before the stage runs.

## The method

1. **Re-take and list first.** At the stage's HEAD, re-take both witnesses on
   a fresh release build and in debug, run the full corpus sweep, and list
   every move before any edit. The probe predicts none outside the witnesses.
2. **Bank the witnesses** under `examples/ein-bugs/wrong-answers/`, with
   corpus entries, and file **W18** `open`, one row per witness. Compare
   facts by value (events, summary counts), not by the printed dump, which
   drops a string's quotes (P1e2.3's N5). First commit, nothing built.
3. **The fix:** a string in a rule's `:match` or `:assert`, at any depth, is
   lowered as the symbol it names; a string in a `:why` template, `:goal-text`
   or provenance keeps its meaning. Held by a `compile_semantics.rs` test
   with both clauses, and a `rule_semantics.rs` test that `s` fires.
4. **The `TypeError:` spelling.** If `FireError::NotAFact` stays reachable
   after the fix, its line is given Ein's spelling and a test; if not, the
   stage says so and leaves it to its parked note.
5. **The pages:** `01_grammar.md`'s `STRING` row (a string in a rule means
   what it means in a fact), `defined_behaviour.md` where it lists what a
   rule may write, `compile.rs`' `slot` docs.
