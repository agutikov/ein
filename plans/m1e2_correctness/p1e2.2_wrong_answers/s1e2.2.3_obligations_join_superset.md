## The case

[`examples/ein-bugs/wrong-answers/owed-seats.ein`](../../../examples/ein-bugs/wrong-answers/owed-seats.ein), nine lines over the
stdlib's own obligation rules:

```
(import std.algebra :symbols (total-owed surjective-owed))
(relation is-a   T T)
(relation seats  Guest Chair)
(is-a Ann Guest) (is-a Bob Guest)
(is-a C1 Chair)  (is-a C2 Chair)
(total-owed      seats is-a)
(surjective-owed seats is-a)
(query :goal (seats ?g ?c))
```

```
$ ein solve -e -s -P examples/ein-bugs/wrong-answers/owed-seats.ein                      # default flags
  solutions (k)   3       Ambiguous …                   exhausted true
  ── 1/3 ── (seats Ann C1) (seats Bob C2)
  ── 2/3 ── (seats Ann C2) (seats Bob C1)
  ── 3/3 ── (seats Ann C1) (seats Ann C2) (seats Bob C1)        ← a superset of model 2
$ ein solve -e -s -P examples/ein-bugs/wrong-answers/owed-seats-renamed.ein              # Ann → Zed, nothing else
  ── 3/3 ── (seats Bob C1) (seats Bob C2) (seats Zed C1)        ← a different triple
$ EIN_TRAVERSAL=tree ein solve -e -s -P examples/ein-bugs/wrong-answers/owed-seats.ein
  solutions (k)   6   (a lower bound — the search did not exhaust)   ← both matchings, all four triples
```

**A model set that changes when a constant is renamed is wrong under any
reading.** Which right answer it should be is the reading:

| reading | k | warrant |
|---|---:|---|
| **minimal**: a discharged state that extends a discharged state is not a new model | **2** | the lattice's own design: `lattice_semantics::a_layer_that_yields_complete_models_stops_descending`, where a complete node *leaves the frontier* |
| **literal**: Q-M1e.6's obligations arm, *a state that owes nothing* | **7** | both matchings, four triples and the full four-seat state. The tree's 6 misses the last, so the tree is wrong under this reading too |

**Mechanism** (`apriori.rs:138-139` at `71dd237`). The comment reads *"the
'every (k−1)-subset ∈ a_prev' condition holds by [`apriori_prefix_join`]'s
construction and is deliberately not re-verified."* That is false. The prefix
join guarantees only the **two parents**. A subset that was recorded
`complete` has left the frontier, is not dead, and is not checked, so its
superset is joined whenever its two parents survive, and *which* supersets
those are depends on the name-sorted prefix order. Under the blind and hrule
rungs such a superset dies (completeness there means every remaining
candidate is refuted), so nothing shows. Under the obligations rung,
completeness means *discharged*, and the superset is alive and discharged.

**Reach:** no corpus entry has a recorded model that strictly contains
another ([inventory § 4](../inventory.md#4-reach--corpus-sweeps-run-for-this-inventory)).
`zebra2-minus-15-obligations` (tree 32 = lattice 32) is protected by its
functional constraints. Any obligation program without them is exposed.

## The fix, per reading

- **Minimal (k = 2):** re-verify every (k−1)-subset against `a_prev` in the
  join (k lookups per candidate). The comment becomes true, and a complete
  node's supersets are never generated. Then the **tree** must agree. It
  answers 6 by branching past a discharge, so its stop condition needs the same
  rule: a discharged node is a leaf.
- **Literal (k = 7):** the lattice must enumerate *every* discharged superset,
  which makes the join's frontier include complete nodes. This is a much
  larger change, and it makes every obligation program's model set
  upward-closed, which is unlikely to be what `(total-owed …)` means.

Recommendation: **minimal**. A requirement is discharged by a witness, and a
second witness is a different question (`functional`'s, not `total`'s).
The ruling is the user's.
