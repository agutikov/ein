## The case

```
(relation seed T) (relation p T) (relation p2 T) (relation q T) (relation r2 T)
(seed a)
(hrule g  () :match (seed ?x) :assert (p ?x))
(hrule g2 () :match (seed ?x) :assert (p2 ?x))
(rule mk () :match (p ?x) :assert (q ?x))
(rule q  (?n) :match (seed ?n) :assert (r2 ?n))
(rule r2 (?k) :match (seed ?k) :assert (false))
```

`examples/ein-bugs/wrong-answers/forbid-chain-no-absent.ein`, which loads (no
`absent`, so *forbid* has nothing to refuse). `{(p a)}` is dead: `(p a)`
derives `(q a)`, which activates rule `q`, which asserts `(r2 a)`, which
activates rule `r2`, which concludes `(false)`. Its core, at `ff023413` and
re-taken at `876767e6` (2026-11-04):

```
$ ein solve examples/ein-bugs/wrong-answers/forbid-chain-no-absent.ein --dump-answer DIR
  DIR/nogoods.json: set [(p a)]  core [(seed a)]  refuted_by [r2]
```

`(seed a)` is root's, and root is alive, so `(seed a)` alone refutes nothing.
The refutation rests on the commitment `(p a)`, through the activators
`(q a)` and `(r2 a)`. The derivation of `(false)` records `r2`'s matched
premise and not the activator its plan was compiled from, so neither
`smallest_contradiction_frontier` nor `absent_premises` reaches `(p a)`
(S1e2.2.17's reading). The same holds on W17's five witnesses studied past
their refusal (*minimal hole {(p a)} — dead: (seed a)*).

## The method

1. **Re-take and measure first.** At the stage's HEAD, re-take the witness
   and W17's five through `forbid::studying`. Prototype the fix: a derivation
   by a plan compiled from an activator rests on that activator too, so the
   frontier follows it. Then run the full corpus sweep and diff **every core**
   the corpus reports (`nogoods.json`, `--json-summary`'s `region.core`, the
   read-out's core and `dead:` lines, `trace[answer]`), against HEAD.
   - **A given activator.** Many stdlib rules are activated by a declaration
     the program states, `(bijective color-loc)` among them. Following every
     activator would put such declarations into cores, on many programs. The
     narrower reading follows an activator into the frontier only where it is
     itself derived, so a declaration stays out as root's. **If the sweep
     moves cores on corpus programs beyond the witnesses under the narrower
     reading, or if the two readings differ on any corpus core, stop and
     report**, with the moved cores listed and a recommended default: which
     facts a core names is the user's question then.
   - A core that moves under the narrower reading is a core that was wrong:
     each such program becomes a W19 row, filed open in this commit.
2. **Bank the witness** under `examples/ein-bugs/wrong-answers/` (it is
   banked; add a chain-length variant if T1 finds one useful), and file
   **W19** `open`, one row per witness, `right` = the core that names the
   commitment. First commit, with the list and the measurement, nothing
   built.
3. **The fix**, in provenance or in the frontier search, whichever T1 finds
   narrower, with the register's `core` check (schema /6) holding each row.
4. **The pages:** `explain.rs`'s statement of what the frontier follows,
   `glossary.md`'s core entry, `02_store.md` if it states what a justification
   records.

## Acceptance

- Every W19 row `fixed`: each dead set's core is a set of facts from which,
  with the program's rules, saturation derives `(false)`, and it names the
  commitment.
- No core moves that step 1 did not list.
