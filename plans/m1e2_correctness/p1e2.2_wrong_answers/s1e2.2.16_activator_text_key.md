## The case

`compile::plan_key` keys a plan by `(rule, the activator's arguments)`. A
symbol argument is its own symbol. Any other argument is **rendered as text
and the text interned**, so the integer `1` and the string `"1"` give one key
and one plan. `compile.rs` documents this as *the one collision* and calls it
deliberate. It is a lost derivation:

```
(relation edge  Node Node) (relation holds Node) (relation noted Node Node)
(rule note (?R ?f) :match (and (?R ?a ?b) (holds ?f)) :assert (noted ?a ?f))
(edge 1 2) (edge 2 3)
(holds 1)  (holds "1")
(note edge 1)
(note edge "1")
```

The KB holds two `holds` facts, so the loader treats `1` and `"1"` as two
values. Each activator alone derives its own two `noted` facts
(`string-only.ein`). Together they derive **two, not four**
(`int-and-string.ein`, `string-then-int.ein`): `ein saturate --dump` at
`5fd72d03`, and the same at `16a05caf`, so it predates S1e2.2.7. The events
show one `compile` and enqueues for one activator only.

A string is a value a fact can carry: `examples/syntax/arg-kinds.ein` exists
to show *every argument kind a fact can carry*, `(r 7 "a string")` among them,
though `01_grammar.md`'s token table gives `STRING`'s role as *provenance and
`:why` templates only*. The stage corrects that row to say what the loader
accepts.

**The second shape, not probed** (S1e2.2.7's second note): `forbid` and
`monotone` test *the plan has an activator* as
`!p.activator_args.is_empty()` (`forbid.rs:267`, `:315`), and
`Plan::activator_args` keeps symbols only. So an activator whose every
argument is an int or a nested fact reads as no activator there. Whether
that misses a refusal or a non-monotonicity site is not measured.

**Reach:** no corpus program has a non-symbol activator argument outside W7's
family (S1e2.2.7's instrumented sweep, 2026-11-04: 92 of 10 744 plans, all on
W7's six files).

## The method

1. **Re-take and probe first.** At the stage's HEAD, re-take the three
   textkey probes. Write a probe for the second shape: a rule with a
   parameter, an activator whose arguments are all ints, and an `absent`
   (or obligation trigger) over a relation in D, so that *forbid* or the
   static check would act if it saw the activator. If it reproduces, it is
   a W16 row and this stage's too. If it does not, say why in the stage file.
   Run the full corpus sweep and list every move before any edit.
2. **Bank the witnesses** under `examples/ein-bugs/`, with corpus entries:
   `int-and-string`, its order-swapped twin, and the single-activator
   controls. File **W16** `open`, one row per witness, with `right` = the four
   `noted` facts, the union of the controls'. This is the first commit, with
   the list, and nothing built.
3. **The fix, by default: key a plan by the activator's values**, not their
   text, so an int, a string and a symbol with the same text are three keys.
   The binding key reads the same list, as S1e2.2.7 made it. If the second
   shape reproduces, the *has an activator* test reads the full argument
   list. Both changes are golden-neutral on the corpus by the measurement
   above, and any move outside W16's files is a finding, a stop, not a
   re-bless.
4. **The pages:** `compile.rs`'s key docs (the collision is gone, with the
   date), `defined_behaviour.md` where it states the key,
   `01_grammar.md`'s `STRING` row, and Q-M1a.8 or Q-M1e.16's entry if either
   repeats the collision as accepted.
