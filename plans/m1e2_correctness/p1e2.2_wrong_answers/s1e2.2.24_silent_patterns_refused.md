## The case

All three were re-taken on the inventory's snapshot build at `cdcc3994` (2026-11-05):

| shape | what the engine does | witness |
|---|---|---|
| `_` in a guard | It compares as a raw IR node: `(eq ?x _)` never holds, `(neq ?x _)` always holds, and `(eq _ _)` holds | [`wild_in_guard.ein`](../inventory_2026-11-05/probes/wild_in_guard.ein): `ein saturate --dump` derives `(hit-neq a)` and `(hit-both a)`, and no `hit-eq` |
| a premise that is not a form | It is dropped (`compile.rs:544`, `_ => return Ok(())`), so the rule fires as if the premise were not there: `:match _`, `(and (hit ?y) _)`, `:match foo`, `:match ?x` | [`bare_premise.ein`](../inventory_2026-11-05/probes/bare_premise.ein): `(r1 z)`, `(r2 w)` and `(r3 z)` are all derived |
| a nested pattern whose relation is a variable no parameter binds, or that holds a keyword pair | Left as `Slot::Opaque` (`plan.rs:98–104`), it never matches, in silence. At top level, `(?r a)` stops with a `CompileError` | [`nested_unbound_head.ein`](../inventory_2026-11-05/probes/nested_unbound_head.ein): exit 0 and `r` never fires, where `unbound-relation-head.ein`'s top-level shape exits 1 |

No corpus rule writes any of the three (the inventory, 2026-11-05).

## The ruling

The user, 2026-11-05 ([Q-M1e2.16](../open_questions.md#q-m1e216--what-does-the-close-do-with-the-inventorys-items) (1)): **refuse each at load**, as a range and a head `_` are refused ([Q-M1e2.13](../open_questions.md#q-m1e213--what-does-a-wildcard-or-a-range-in-a-rules-pattern-mean) (a), [Q-M1e2.14](../open_questions.md#q-m1e214--how-does-a-head-wildcard-match-every-relation) (c)). Each refusal is one line in Ein's spelling, naming the rule and the clause.

## The method

1. **Re-take and list first.**
   - Bank the three witnesses under `examples/ein-bugs/wrong-answers/`.
   - File **W24** `open`, one row per shape. Each row's `right` is the refusal.
   - Find every shape of the three, in a rule, an hrule and an obligation:
     - every argument kind in a guard;
     - every premise that is not a form (an atom, a variable, `_`, a number, a string, a range, a keyword);
     - every nested position an unbound relation variable or a keyword pair can take.
   - Prototype the refusal in S1e2.2.20's load pass (`from_ir`'s `refuse_ranges`). Run the full sweep and `cargo test` under it, and write every move into this file before any edit. A move outside W24's programs is a finding: stop and report.
2. **What the ruling leaves to settle.** Each is a default recorded here, unless it moves an answer beyond the witnesses; then stop and ask.
   - A top-level `(?r a)` that no parameter binds joins the same load pass. It moves from the `CompileError` (a Python spelling, D-1 of the inventory, which [F23](../../followups/f23_diagnostics_in_eins_words.md) owns) to the load line. Exits stay as they are: 1 from `solve` and `saturate`, and `ein test` as a load error's.
   - A keyword pair at top level of a pattern stays dropped, as Q32 rules (the inventory's G-15). Only the nested pair, which today never matches, is refused.
   - `_` in an `:assert` keeps S1e2.2.18's line.
3. **Tests that fail at the stage's HEAD in both profiles:** each witness refused with its line, from every command.
4. **The pages:**
   - `defined_behaviour.md` § 4.8, which carries the range and head lines, gets the three new lines;
   - `02_patterns.md`: what a guard argument and a premise may be;
   - `01_grammar.md` if its premise row allows a bare atom.

## Acceptance

- No rule shape reads nothing in silence among those step 1 lists.
- No answer moves outside W24's programs.
