## The case

H is built by `region::prepare_with` → `hypgen::generate_config_free` with
`Rungs::Ladder`: a program's hrules if it declares any, else the obligations
rung (`oblgen::generate`), else the blind enumerator. The obligations rung
builds its candidates by running each obligation guard's domain scan
(`scan_without`) over **root's** KB. A domain value that only a commitment
derives is not in root's KB, so the rung never proposes it, and the blind
enumerator, which would, is not consulted.

The rung's C4 check (`oblgen::scanned_relation_in`) declines only when a guard
scans a relation the rung itself proposes. It does not decline when a guard
scans a relation that grows by derivation from a commitment, a relation in D.
[`domain_contract.md`](../../../docs/history/m1d_satisfiability/domain_contract.md)'s
C4 (*not hypothesis-eligible*) misses the same case.

| witness (`build/s1e2.2.4-probe/r1/`) | H | R today | right (the control) |
|---|---|---|---|
| `oblig-fresh-name.ein`: Ann owes a `likes` whose object is a `food`; the only food at root is Soup, which is ruled out; liking anything derives `(food ?x)`, and the rule names `Z` | 1, `(likes Ann Soup)`, dead | `k_s 0`, `owing ∅ — owes 1` | `-declared` (+ `(food Z)` at root): `k_s 1`, `(model (likes Ann Z))`; `-blind` (the rung declined): the same |
| `oblig-fresh-name-two.ein`: + Bob, who may like Soup | 2 | `k_s 0`, owing `{(likes Bob Soup)}` | `-declared`: `k_s 3`; at node `{(likes Bob Soup)}` the rung itself proposes `(likes Ann Z)`, not in H |
| `oblig-derived-domain.ein`: Pie named by a fact, **no rule constant at all** | 1 | `k_s 0` | `-declared`: `k_s 1`, `(model (likes Ann Pie))` |
| `oblig-stdlib-total-owed.ein`: the shipped `total-owed` | — | `k_s 0` | `-declared`: `k_s 1`. Flagged non-monotone (an `obligation-trigger` site on `is-a`), with no hole in its cube |

`-committed` (`(likes Ann Z)` as a fact) shows the witness's own rules make
`{(likes Ann Z)}` alive and discharged: `∅ in R`, `(food Z)` derived. W4's
control, `(seen Z)`, does **not** catch it (`-named`, the same wrong R).

**It is not W6**: `likes` is covered (`uncovered 0`), so the scoped
certification does not apply. **It is not F21's**: the first three
witnesses are monotone (`--monotone` passes them).

**Corpus reach: none today.** Of the 55 programs that declare an obligation
and load, the rung builds H at root on 34. None has a guard that reads a
relation in D that H does not propose, and over 6 333 nodes built the rung
never proposed a candidate outside H.

## The method

1. **Re-take first.** At the stage's HEAD (after S1e2.2.14), re-take the four
   witnesses and their controls, run the full corpus sweep, and list every
   move the fix will make. The probe predicts none outside the witnesses; a
   move not on the list is a finding.
2. **Bank the witnesses** under `examples/ein-bugs/wrong-answers/`:
   `oblig-fresh-name`, `oblig-fresh-name-two` and `oblig-derived-domain`, each
   with its `-declared` control. `oblig-stdlib-total-owed` is banked too if it
   loads after S1e2.2.5's *forbid* (it is flagged, but its site is an
   obligation trigger, not a refutation); if it is refused, the stage records
   that and banks it as the refusal's witness instead.
3. **File W14**, `open`, one row per banked witness, `right` = the control's R
   held by the oracle. First commit, with the list, nothing built.
4. **The fix, by default: decline the rung** when an obligation guard's domain
   scan reads a relation in D (the set the static check and *forbid* already
   compute), so the ladder falls to the blind enumerator, whose objects carry
   every name of the program since S1e2.2.14. The decline narrates its reason
   in the rung event, as the existing declines do. Widening the rung's scan to
   D's reach instead is not this stage: it changes what the rung proposes on
   every obligation program, and the probe found no program that needs it.
5. **The pages.** `domain_contract.md`'s C4 gains the D case (a dated note:
   it is a milestone record, so a note, not a rewrite); `oblgen.rs`'s docs;
   `hypotheses_from_obligations.md` only if it states the rung covers this;
   `solution_semantics.md` where it says how H is built.

## Acceptance

- Every W14 row `fixed`: each witness's R equal to its control's and to the
  oracle's.
- A rung that declines on a guard over D says so in its event, held by a test.
- No corpus program outside the witnesses moves, as the probe predicted, or
  every one that does is on step 1's list.
