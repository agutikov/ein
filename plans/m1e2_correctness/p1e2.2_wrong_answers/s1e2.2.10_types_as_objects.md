## The case

```
$ ein solve -e examples/branching/06_lookahead_on.ein
  solutions (k)   22   (a lower bound — the search did not exhaust)
```

Counted from `--json-summary` on 2026-10-14: **all 22** recorded models
contain a `co-located` fact over a type (`Color` or `House`), **10 of 22**
have a goal row binding `?h` to a type, and 6 print it as the displayed
binding. (D8 said *20 of 22 bind `?h`*. The inventory's count is finer:
*contain* and *bind* are different numbers.) `candidate_objects` collects
every object the KB mentions. `(is-a Color T)` makes `Color` an object, and
the blind rung is untyped, so `(co-located Blue Color)` is a candidate, and
`(relation co-located T T)` permits it.

**Why it is contested.** Under every reading Q-M1e.12 lists, the engine does
what the program says. A model that puts a colour in the type `Color` is a
model of `(relation co-located T T)`. What nobody chose is which reading the
repo holds, and a corpus fixture quietly demonstrates the consequence. It also
makes `branching/06` the standing proof of S1f.10.6's loss mechanism.

## The three readings (Q-M1e.12)

| | reading | what it means here |
|---|---|---|
| **a** | the program is under-specified | fix the fixture: type `co-located`. [`branching/12_typed_blind_solve.ein`](../../../examples/branching/12_typed_blind_solve.ein) already shows the typed alternative. `not-wrong` for the engine |
| **b** | the enumerator is right, and the read-out is wrong | a goal row binding a type is suppressed or marked. A presentation change beside SE-M1 / AR-M2, which decides nothing |
| **c** | `candidate_objects` excludes types | an engine change with corpus-wide reach, and *a type system arriving by the back door*: the kernel commits to no type system (S1.7.23) |

Recommendation: **(a), with a diagnostic**. Type `branching/06`'s relation,
and have the blind rung narrate a `warn` when it proposes a fact whose
argument is an object that appears on the right of an `is-a`. That is a
fact about the KB, not a type system, and it tells an author their relation
admits it. It is the `invariant.rs` precedent, which warns without refusing.

#### The warning's surface, decided

**Not an event.** The stage file proposed a `warn` category, through
`events_reference.rs` and `EVENT_COVER`. That kind has no emitter since
S1e2.2.5 retired `:warn-derived-naf`, and it left the schema (19 kinds). A
category brought back for this would put the warning where `--events` is on,
which no reader of R sees by default, where the user's rule (one tool,
consistent answers) asks that every command that reports R say it alike.
And the warning is a fact about H, computed once at root, which is what
S1e2.2.8's `outside` is: the engine's way to say one, since that stage, is a
row under `universe` and a key in `root.hypgen` on every run, and the
`rung` and `hyp` events already narrate how H was built, candidate by
candidate.

**The `types` row, under `universe`**, after `outside`, at the same sub-row
indent, on every question that prints `universe` (describe, `--count`,
`--maximal`, `--minimal`, `--single`, `-n`, `--monotone`, `ein oracle`, and
so `--trace`'s headline and `--dump-answer`'s `answer.txt`), printed only
when the warning names something:

```
  universe          15 candidates
    types           Pet — on the right of an is-a, and 9 candidates of co-located, is-a name it as an object: the blind enumerator is untyped, and no signature names it
```

It says which names, the fact about the KB that makes them types, how many
candidates of which relations name them, and why: the enumerator is untyped,
and a name a signature declares would not be a candidate at all, which is the
program's way out and the retype's. Two or more names read `name one as an
object … no signature names them`. The same words, as `a type as an object:
…`, beside each claim `ein test` prints (under `-v`, or a claim not held), as
the `outside` line is; and as `**Types as objects**: …` under `ein oracle
--dump`'s `region.md` candidate count.

**The field: `root.hypgen.types_as_objects`**, on every run, `--monotone`
included: `{"objects": [...], "relations": [...], "candidates": n}`, sorted,
empty lists and 0 when nothing (SE-M2). The schema stays `ein-summary/2`, as
S1e2.2.8's `outside` and S1e2.1b.5's keys kept it. `region.json` gains
`types_as_objects` beside `outside`, the same object, and stays
`ein-region/1`. `ein test --json-report` is unchanged: its rows carry no
universe.

Considered, and why not:

- **The `warn` event, one category**: above.
- **A `warning:` line on stderr**: the read-out's warnings are rows (the
  detector's under `lattice`, `outside` under `universe`), and stderr carries
  a partial run's `note:` and a refusal; a row reads the same in `answer.txt`
  and in `--trace`, which stderr does not reach.
- **Counting `is-a`'s own candidates out**: `taxonomy.ein`'s `(is-a Animal
  Mammal)` binds `Animal` as an object of the type `Mammal`, which is the
