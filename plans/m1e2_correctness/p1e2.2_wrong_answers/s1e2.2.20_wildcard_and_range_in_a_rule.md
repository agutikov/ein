## The case

`01_grammar.md`'s token table calls `_` a *head / arg wildcard in patterns*,
and the rule compiler lowers it, like a range, as an opaque slot that matches
nothing (`compile.rs`' `slot`). Re-taken at `876767e6` (2026-11-04,
`build/w20-probe/`):

| program | what the engine does | right, as ruled |
|---|---|---|
| `(holds a)` `(rule w () :match (holds _) :assert (hit w))` | `w` never fires: no `(hit w)` | `w` fires, as with `(holds ?any)`: `(hit w)` |
| `(holds a)` `(rule w () :match (_ a) :assert (hit w))` | `ein saturate` exits 1 with `ein.inference.compile.CompileError: unbound relation head ?Wildcard() …`, a Python spelling | `w` fires on any fact whose one argument is `a`: `(hit w)` |
| `(n 2)` `(rule r () :match (n 1..3) :assert (hit r))` | `r` never fires, in silence | refused at load, a line in Ein's spelling naming the rule and the slot |

No rule under `examples/`, `tests/` or `stdlib/` writes either in a `:match`
or an `:assert` (S1e2.2.18's scan, 711 rule forms, 2026-11-04).

## The ruling

The user, 2026-11-04 ([Q-M1e2.13](../open_questions.md#q-m1e213--what-does-a-wildcard-or-a-range-in-a-rules-pattern-mean)):
**`_` in a rule's pattern matches any value, as the grammar says, in the head
and in an argument. A range in a rule is refused at load**, since a range is
cardinality metadata and no fact can hold one.

## The method

1. **Re-take and list first.** Bank the three witnesses under
   `examples/ein-bugs/wrong-answers/`, each with its twin (`_` written as a
   fresh variable the rule reads nowhere else; the range program's twin is
   the refusal). File **W20** `open`, one row per witness. Prototype the fix,
   run the full corpus sweep and `cargo test` under it, and write every move
   into this file before any edit. A move outside W20's programs is a finding:
   stop and report.
2. **What the ruling leaves to settle**, each a default recorded here unless
   it moves an answer beyond the witnesses (then stop and ask):
   - two `_` in one pattern are independent; neither binds a name, so a rule
     cannot read one in its `:assert` or a guard;
   - `_` under an `absent` means *no fact of that shape at all*, as a fresh
     variable there does;
   - `_` in an hrule's `:match`, and in an obligation's, is the same pattern;
   - a head `_` matches every relation of that arity. M1 binds a relation
     head by the activator (Q29): measure what it costs to scan every
     relation, and if the compiler cannot do it without a second matching
     path, stop and report with what each path costs;
   - `_` in a guard, and `_` or a range in an `:assert` (which S1e2.2.18 left
     stopping the run at the firing with Ein's line): the ruling refuses a
     range in a rule at load, so a range there moves from the firing to the
     load. A wildcard in an `:assert` is not a pattern; the default is
     S1e2.2.18's line, unmoved;
   - `_` is not a name of the program (`invariant::program_names`).
3. **The fix**, in `compile.rs`'s `slot` and the head lowering, with tests
   that fail at the stage's HEAD in both profiles: the wildcard program by
   value against its twin, every command (`saturate`, `solve`, `oracle`,
   `test`); the range refused with its line, exit 1 from `solve` and
   `saturate`, 2 from `test`.
4. **The pages:** `01_grammar.md`'s token table and § patterns (dated, what
   `_` and a range did until this stage), `defined_behaviour.md` § 4 (the
   load error's row), the `CompileError` line the head wildcard printed if it
   no longer reaches anything.

#### The head wildcard: Q-M1e2.14

A head `_` is no slot. M1 compiles a plan per `(rule, activator)` pair and
binds a relation head by the activator (Q29), so a `RelStep` names one
relation, and what a head `_` must match, *every relation*, includes the
kernel's (a declaration's `(relation a)`, an activator such as `(total a)`,
`not`, `is-a*`). Either way to match it is a second path: **(a)** a plan per
relation, the compiler expanding the head over every relation a fact can
ever have, which a node can add to, so every name of the program (82 plans
for one head `_` on `zebra2.ein`, the product for several, one guard per
relation under `absent`), with the readers of a rule's pattern (*forbid*'s
D⁺, the invariant) taught a case; or **(b)** a step over every relation, a
second matching path in the matcher (a scan of the KB's every fact of the
arity: 388 on `zebra2.ein`'s root, where one extent is at most 103), the
saturator's index, and every reader of a step's relation, 52 sites in 13
files of `ein-infer` (`grep -rn '\br\.rel\b\|step\.rel\b\|\.rel ==\|\.rel
!=\|rel: r\.rel\|Slot::Nested { rel' crates/ein-infer/src/*.rs`, 2026-11-05),
the static check's D, *forbid*'s D⁺ and the obligations rung's decline among
them. **(c)**, refusing a head `_` at load as a range is, is the agent's
recommendation: no corpus program writes one, what it matches includes the
kernel's own facts, and both (a) and (b) add a path every static reader
must know, the class of reader W14 and W17 were defects of. **So the stage
stops here** (the stage file's step 2) and the question is
[Q-M1e2.14](../open_questions.md#q-m1e214--how-does-a-head-wildcard-match-every-relation),
put to the user with the measurements. Its row, `W20/wild-in-head`, keeps
the twin's answer as `right` until the ruling; under (c) it becomes a
refusal, as `W20/range-in-match`'s is.
