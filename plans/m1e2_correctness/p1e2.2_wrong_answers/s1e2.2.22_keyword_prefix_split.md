## The case

The inventory re-took this on its snapshot build at `cdcc3994` (2026-11-05). The witnesses are [`F1_keyword_prefix_split.ein`](../inventory_2026-11-05/findings/F1_keyword_prefix_split.ein) and [`F1b_or_prefix.ein`](../inventory_2026-11-05/findings/F1b_or_prefix.ein).

| program | what the engine does | right |
|---|---|---|
| `(relation neqw Node) (p a)`, `(rule r () :match (p ?x) :assert (neqw ?x))`, `(query :goal (neqw ?y))` | Root derives `(neq w a)`, a fact of the reserved `neq`. `w` joins the program's names, and R has 8 states over H = 3 candidates. The query prints as `(neq w ?y)` | Root derives `(neqw a)` and R = {∅}. The query's one class is `?y = a` |
| the same with `orz` | `(orz ?x)` in an `:assert` stores `(or z a)` | `(orz a)` |
| the same with `andz` | `(andz ?x)` in an `:assert` stops the rule with *"concludes z, which is not a fact"*. In a `:match` it reads as a conjunction | `(andz a)`, a fact like any other |

[`00_ebnf.md`](../../../docs/kernel/ir/03-ein-lang/00_ebnf.md) § 1, fact 1, says the opposite of what the engine does: *"`neq` is not a SYMBOL; `neq_test` is"*. A keyword is a whole word. The split happens inside the parser's keyword alternatives: `parse.rs`'s `alt_and_or` and the `neq` alternative's `eat_lit` (`parse.rs:499–527` at `cdcc3994`). No corpus program writes such a name, according to the inventory's grep for `(neq`, `(or` or `(and` followed by a word character.

Re-taken at `3db6187f`, after S1e2.2.21 (2026-11-05): `ein solve plans/m1e2_correctness/inventory_2026-11-05/findings/F1_keyword_prefix_split.ein` still reports `states (k_s) 8`.

## The method

1. **Re-take and list first.**
   - Bank the witnesses under `examples/ein-bugs/wrong-answers/`. Each gets a twin: the same program with the relation renamed so it starts with no keyword.
   - File **W22** `open`, one row per shape.
   - Test every reserved word in `lex.rs`'s keyword lists (`not`, `and`, `or`, `neq`, `rule`, `hrule`, `query`, `solve`, `config`, `trace`, `macro`, …), each followed by a name character. Do it in every place the parser reads a keyword: a fact, a rule's `:match`, its `:assert`, a guard, an `absent`, a query goal, an hrule, an obligation, an `:expect`, a `(solve …)`. A shape found to split is a row.
   - Prototype the fix. Run the full corpus sweep and `cargo test` under it, and write every move into this file before any edit. A move outside W22's programs is a finding: stop and report.
2. **The fix.** A keyword matches only as a whole word, as the EBNF says, everywhere the parser reads one. The default is no new error: the whole name parses as the symbol it is.
3. **Tests that fail at the stage's HEAD in both profiles:**
   - each witness by value against its twin, on every command;
   - a parse test over every reserved word × a name suffix × every position step 1 covered.
4. **The pages.** `00_ebnf.md` § 1 gets a dated note on what the parser did until this stage. `01_grammar.md` gets one too if its keyword table says how a keyword ends.

## Acceptance

- Every W22 row is `fixed`. Each witness answers its twin's R on every surface, in release and in debug.
- No reserved word followed by a name character is split anywhere the parser reads one.
- No answer moves outside W22's programs.
