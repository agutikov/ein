A shape found to split is a row.

3. **Tests that fail at the stage's HEAD in both profiles:**
   - each witness by value against its twin, on every command;
   - a parse test over every reserved word × a name suffix × every position step 1 covered.
4. **The pages.** `00_ebnf.md` § 1 gets a dated note on what the parser did until this stage. `01_grammar.md` gets one too if its keyword table says how a keyword ends.

**Why each is wrong.** `00_ebnf.md` § 1, fact 1, excludes a reserved word
from `SYMBOL` only where a word boundary follows it, so `neqw` is a `SYMBOL`.
The parser does not ask: `lex.rs`' `match_literal` compares the word with no
boundary after it (*"a literal carries no word boundary, which is precisely
why `rulex` can be read as `rule` + `x`"*), and `parse.rs` tries the keyword
alternatives before the `SYMBOL` reading and keeps the first that consumes
the whole form. A keyword followed by a name character is read as the keyword
and the rest of the name wherever the rest fits the keyword's form:
`(neqw ?x)` is `neq` with the values `w` and `?x`. The split was documented
as intended (`grammar_decisions.rs`: *"A reserved word is a legal SYMBOL
prefix and the split reading wins wherever it parses"*; `ir_semantics.rs`
pins 15 of its readings; `00_ebnf.md` § 3 tries *the literal reading before
the `SYMBOL` reading*), and the stage file's ruling is that it is a wrong
answer.

#### Q-M1e2.17: where a keyword ends

The prototype reads a keyword as a whole word at the boundary `00_ebnf.md`
§ 1 states, `WordChar`. The grammar has a second set of name characters,
`SYMBOL`'s body, `[A-Za-z0-9_*.-]`, in which `-`, `.` and `*` continue a
name. Where a value follows the keyword (`not`, `and`, `or`, `neq`), `-` is
the one character that both continues a name and starts a value, an `INT`'s
sign. So `(neq-1 ?x)` is read as `neq` and `-1` at `35186bc0` and under the
prototype, while `neq-1` is no name anywhere: `(p neq-1)` is a parse error,
since fact 1's exclusion fires at the `-`. That is a shape that splits where
the whole-word reading has two meanings, so **the stage stops here** and the
question is
[Q-M1e2.17](../open_questions.md#q-m1e217--where-does-a-keyword-end) (i).
The agent recommends (a), the word boundary fact 1 states, which moves
nothing beyond the prototype. The alternatives: (b), where a name could not
continue, under which the 435 `-`-and-a-digit cases become parse errors; and
(c), (b) with `neq-1` a name, a language change.

Its part (ii) is the trace events. A trace word read whole has no other
reading inside a `(trace …)`, so `(trace (stepx :a b))`, the step `x` at
`35186bc0`, is a parse error under the prototype. The stage file's default
is *no new error*, and its acceptance is *no reserved word followed by a
name character is split anywhere the parser reads one*; the two disagree
here. The agent recommends (a), the acceptance, as prototyped. No corpus
program writes the shape under either part, and no answer moves outside
W22's programs under any option.
