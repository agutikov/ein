# S1e2.2.9 — W9: with the kill cache off, a state is recorded as consistent because an entailment went unnoticed

**Phase:** [P1e2.2](README.md) (The wrong answers)
**Estimate:** 1 day
**Depends on:** [S1e2.2.1](s1e2.2.1_maximal_not_recorded.md), whose fix
caveat is this case's mechanism.
**Carries:** [Q-M1e.7](../../m1e_review_processing/open_questions.md#q-m1e7--the-read-out-prints-the-solution-kb-and-calls-it-a-model)
ruling A's consequence. The ruling says in words that `-K` is *"the cache
being less complete"*. Nothing says it changes answers.

## The case

```
$ ein solve -e -s -P -K examples/ein-bugs/complete-records-stale.ein
  solutions (k)   2       Ambiguous       exhausted true      (q A)  |  (p A) (p B)
$ ein solve -e -s -K examples/ein-bugs/alive-empty-phase1.ein
  solutions (k)   1       Solution        exhausted true
```

The right answers are the default runs': `Solution k = 1 {(p A),(p B)}` and
`Contradiction k = 0`. Under ruling A the negatives a dead singleton entails
(`¬h` when `root ∪ {h}` is dead) are part of the state. The kill cache is
what writes them. With it off (`-K`, *"disable the lookahead-kill cache"*),
they are never materialised, so `record_node`'s re-saturation (CO-M1's fix)
has nothing to re-derive from, and a state ruling A calls inconsistent is
recorded as a model.

`-K` is a lever, so no default run is wrong. But it is a **certified** wrong
answer under a documented flag, and the corpus sweep finds two certified
changes (these two) and three lower-bound ones (`branching/02` 4 → 2, `06`
22 → 20, `08` 8 → 6) ([inventory § 4](../inventory.md#4-reach--corpus-sweeps-run-for-this-inventory)).

## The fix

The entailment is not the cache's to own. S1e2.2.1 materialises a dead
child's negative before recording its parent, because maximality needs it.
Do the same for every recorded state regardless of `-K`: a candidate
proven dead at the state's own layer contributes its `¬h` before the record.
After that, `-K` changes how often an entailment is *discovered early*, not
whether it is discovered before a state is called a model, which is what a
cost lever is allowed to change.

If that is too expensive to do without the cache, the other answer is the
`-L` precedent from [`corpus/README.md` § Levers](../../../corpus/README.md):
`-K` is a debugging mode, and a run under it **does not certify**
(`exhausted` forced `false`, with the qualifier saying why). Measure first.

## What moves

The `-K` lever cells of every corpus entry whose answer changes (the five
above), plus `configuration.md`'s *does it change the answer* column for `-K`,
which today says it does not.
