## Why

[N6](README.md#candidates-found-on-the-way). On a run stopped past
`--region-limit`, `--dump-answer`'s `nogoods.json` lists the members of N the
run met with an **empty core and no refuting rule**:
`lattice/06_friends_tables.ein`, 68 of 68 (`ein solve FILE --dump-answer DIR`
at `a41eb76e`). An empty core reads as *refuted by nothing*; the run did not
take one. No answer moves.

## The method

1. **Re-take first**, at the stage's HEAD: which members get an empty core,
   whether every surface that prints a core (the read-out's `dead:` lines,
   `--json-summary`'s `region.core`, `trace[answer]`) does the same, and
   whether any member of N on a run that did **not** stop has an empty core.
   The last is a wrong answer, not this stage's: report it.
2. **The default fix: say so.** A member whose core the run did not take
   carries no core, and the read-out and the dump say why (*not taken: the
   run stopped at `--region-limit`*). Taking the cores instead is more work
   than the question asked (*minimum work per question*); if step 1 finds
   them free, report the cost and keep the default.
3. **A test** on `lattice/06` that fails on the empty list.
4. **The pages:** `inference/answer_dump.md`'s `nogoods.json` row, and
   `region_dump.md` if it states the field.

## Acceptance

- No surface prints an empty core for a core the run did not take.
- No answer, exit code or register row moves.

#### Defaults

None changes an answer; each is recorded here, as the brief asks.

1. **The word is `not-kept`, not `not-taken`.** The run takes the core: by
   S1e2.2.21's ruling `--dump-answer` and `--trace` take every dead node's
   core they visit, and the 0.58 s above is that search. What it does not do
   past the limit is keep it. *Not taken* would be false of the run that
   printed it; the sentence says what is true, *not kept: the run stopped
   at `--region-limit`*.
2. **`null`, not `[]`, for the core and the rules both.** An empty rules
   list reads as *refuted by no rule* as an empty core reads as *refuted by
   nothing*; the stage's Why names both. `nogoods.json` changes type at
   those two keys for such a member alone.
3. **The sentence names `--region-limit` alone**: the description that
   keeps no core is reached only past the limit (`flagged`, `!within`),
   where the cube is bounded by the limit and not by facts, and `-T` exits
   2 with no answer.
4. **The trace's old line stays** for an empty core with any other status;
   no run reaches it (the sweep under the fix prints it nowhere, and the
   test holds it absent on the three runs).
5. **The review bundle's N page says it too**, the core cell, since it read
   an empty core as `—`.
6. **The corpus claim rides on dumps already written** (`answer_round_trip.rs`),
   so the gate runs no extra solve; the library's side is
   `corpus_cores.rs`'.
7. **No probe banked**: the witness and its control are corpus entries.
