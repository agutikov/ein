## Why

[N6](README.md#candidates-found-on-the-way). On a run stopped past
`--region-limit`, `--dump-answer`'s `nogoods.json` lists the members of N the
run met with an **empty core and no refuting rule**:
`lattice/06_friends_tables.ein`, 68 of 68 (`ein solve FILE --dump-answer DIR`
at `a41eb76e`). An empty core reads as *refuted by nothing*; the run did not
take one. No answer moves.

## The method

1. **Re-take first**, at the stage's HEAD: which members get an empty core,
   whether every surface that prints a core (the read-out's `dead:` lines,
   `--json-summary`'s `region.core`, `trace[answer]`) does the same, and
   whether any member of N on a run that did **not** stop has an empty core.
   The last is a wrong answer, not this stage's: report it.
2. **The default fix: say so.** A member whose core the run did not take
   carries no core, and the read-out and the dump say why (*not taken: the
   run stopped at `--region-limit`*). Taking the cores instead is more work
   than the question asked (*minimum work per question*); if step 1 finds
   them free, report the cost and keep the default.
3. **A test** on `lattice/06` that fails on the empty list.
4. **The pages:** `inference/answer_dump.md`'s `nogoods.json` row, and
   `region_dump.md` if it states the field.

## Acceptance

- No surface prints an empty core for a core the run did not take.
- No answer, exit code or register row moves.
