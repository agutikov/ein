## Why

The user, 2026-11-03: *"yes, fix the tmp leak in those tests - add a new stage
for that"*. Two things came before that request:

- **`corpus_cli` has already been fixed.** It wrote one directory per run under
  `temp_dir()` and never removed it, 88–257 MB per gate run. Once, 49 of those
  directories (4.7 GB) filled this machine's 16 GB tmpfs. 8a420a28 removes
  each cell's directory once it is read, and the root at the end.
- **S1e2.1c.5's agent was not allowed to sweep the leftovers.** It reported
  about 72 directories from its own runs, and the permission classifier denied
  its `rm`. The leak is in the tests, so this stage fixes the tests rather
  than sweeping `/tmp` by hand.

## The method

1. **The sweep is the instrument.** Run the whole gate, and the slow tier,
   with `TMPDIR` pointed at a fresh, empty directory under `build/`.
   `std::env::temp_dir()` and Python's `tempfile` both honour it. Every entry
   left in that directory after a green run is a leak, and each one is named
   with the file that wrote it. Then repeat the sweep with one test made to
   fail, to find leaks that happen only on the failure path. Fixing those is
   optional, but each one is recorded.
2. **One way to make scratch.** Where `ein-corpus` (the dev-only crate every
   test binary already depends on) has no helper, add one. It is a scratch
   directory under `temp_dir()` named `<prefix>-<pid>-<n>`, removed on `Drop`,
   with a `keep()` for a test that wants to leave its output for a human after
   a failure. The leaking tests move onto it. Tests that already clean up are
   left alone, unless moving them makes them simpler.
   `utils/corpus_cost.py` uses `tempfile.TemporaryDirectory`, or removes its
   directory in a `finally`.
3. **The check that keeps it fixed.** `./run_tests.sh` runs `cargo test` with
   `TMPDIR` set to a fresh directory under `build/`, and fails if anything is
   left in it after a green run. It names what is left, then removes the
   directory. CI runs the same script, so the per-commit workflow gets the
   same check. `ein-cli/tests/gate_steps.rs` diffs the script against
   `.github/workflows/per-commit.yml`; keep the two lists the same.
4. **The leftovers on this machine** are not this stage's to sweep. Once the
   fix lands, the stage's report says how many there are and the command that
   removes them, and the user runs it.

## Acceptance

- A green `./run_tests.sh`, and `./run_tests.sh --slow`, leaves nothing in
  `TMPDIR`. The check in step 3 fails when it does, which is shown once by
  re-introducing one leak in a scratch commit that is never committed.
- Every leaking writer in the sweep is fixed, or recorded with why it is left
  alone. The failure-path leaks are listed.
- No golden, answer, register row or exit code moves.
- `AGENTS.md`'s *Running the gate* section says the gate checks its own
  scratch, in one sentence.

- **[`utils/check_test_scratch.py`](../../../utils/check_test_scratch.py)
  DIR** names every entry in DIR, with the source files under `ein.rs/crates/`
  and `utils/` that spell its prefix, removes DIR, and exits 1 if there was
  anything; 0 on an empty DIR, 2 on one that is not a directory. A prefix is
  what comes before the pid, shortened a component at a time until some source
  spells it as `"prefix-{`, `"prefix-"` or `"prefix"`, so a test's tag is no

## Notes

- **Found on the way, not in the sweep, and left alone.**
  `utils/fork_split.py` makes an `ein-fork-split-*` directory of verbose event
  logs and never removes it. It is one of the walk's instruments, re-taken
  against a binary at or before `7ec8a480` and run by nothing in the gate.
  `nightly.yml` runs its `cargo test` steps without this check; whether
  `./run_tests.sh --nightly` carries it is
  [S1e2.3.6](s1e2.3.6_the_nightly_workflow.md)'s, since that stage holds the
  script to the workflow.
- **Why `TMPDIR` and not a per-test assertion.** A test cannot see what
  another binary leaves, and a forgotten directory is by definition one that
  no test knew it was writing. One empty directory per gate run sees all of
  them at once.
- **`build/` and not `/tmp`** for the gate's `TMPDIR`. `/tmp` here is a 16 GB
  tmpfs, the size that already filled once. `build/` is gitignored and on
  disk.
