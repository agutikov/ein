## The question

> **Do the forms share stdout's 100 lines with the read-out, and does
> `--dump-answer` write what they leave out?**

| | (a) share the 100 lines; the dump holds each form uncut | (b) each form gets its own 100 lines; the dump holds the rest | (c) exempt: a form asked for by name prints whole | (d) a form goes to a file only |
|---|---|---|---|---|
| stdout on `pets --models grid` | the read-out's 124, or a few lines more: the forms print what fits after the read-out's listings, at least one item, then where the rest is | 124 + about 100 | 34 143, as today | 124 + one line naming the file |
| what the forms draw from | the states the screen listed, so the screen and the forms agree | all listed states, cut at 100 | all listed states | all listed states |
| the dump | `DIR/forms/<form>.txt`, or `answer.txt` growing one section per form; a sub-question | the same | unchanged | the form's file, so `--dump-answer` or a new path flag is needed to ask for a form at all |
| the rule | one: stdout's listings share 100 lines, and a form is a listing | two: 100 for the read-out, and 100 more per form | an exception, written in `read_out.md` § 4.1 and in each form's help | a form is not stdout at all |
| the bundle | passes `--dump-answer` to each form run and reads the uncut file | the same | unchanged | the same as (a) |
| tests that move | those whose region passes the cut: `model_set_report.rs`' `colors` cases; the rest of the regions are small | the same, fewer | none | every form test |

**Recommendation, mine: (a).** The ruling of 2026-10-16 gave its reason as a
shared screen, and a form is a listing of the same states. Under (a) the forms
describe what the screen listed, which ends the mismatch above. (c) costs
nothing, but it writes a second rule beside the user's. (d) turns a form into
a file option, which is a new interface. `-H` lists candidates, not states:
under (a) it shares the 100 lines as a listing too, and the read-out's
`universe` row already gives its count.

**Sub-questions under (a) or (b):**

1. **Where the dump puts a form.** One file per form, `DIR/forms/grid.txt` and
   so on, named in `index.json`? Or one section per form at the end of
   `answer.txt`, which then stops being *the read-out uncut*? The
   recommendation is one file per form: `answer.txt` keeps its definition, and
   `answer_dump.md` gains a row.
2. **What the forms draw from when stdout cut the listing**: the states stdout
   showed, or every listed state cut separately? The recommendation is the
   states stdout showed, so a form is never about a state the screen left out.

## How it is measured

Lines and bytes are `wc -lc` of stdout, with stderr kept apart. The re-take
above is this, on 2026-11-02 at `7b33c3ab`:

```sh
f=examples/saturation/type-exclusivity/pets.ein
for a in "" "--models grid" "--models key" "-p" "-P" "-f"; do
  echo "$a: $(ein.rs/target/release/ein solve $a $f 2>/dev/null | wc -lc)"
done
```

T1e2.3.3.1's corpus sweep is the same command over every corpus program and
each of the three asks. `--diff-models` is fed two want files built as
S1e2.4.2 built them (its T1e2.4.2.1): *the states themselves*, and *every
state one fact off*.
