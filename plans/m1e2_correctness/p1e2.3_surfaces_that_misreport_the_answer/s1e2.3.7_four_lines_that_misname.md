## The method

1. **Re-take each witness first**, at the stage's HEAD, and write down every
   golden each fix will move before editing anything (the help golden, the
   read-out pages, the `-f`/`-p` cells). A golden that moves and is not on
   the list is a finding; it is reported, not re-blessed.
2. **One fix per line, each held by a test** that fails on today's text: N1
   and N2 in a `factdump` test, N3 in `saturate.rs`'s or `cli_semantics`'
   tests, and N4 in a `read_out` test on `ein oracle` that also checks the
   line it names exits 0.
3. **N3's exit code does not move.** A step limit leaves a partial KB, and
   the ruling that every answer exits 0 (`read_out.md` § 9) covers it. § 4
   is corrected to the code the binary takes, and the row moves to the
   section where the stage finds it belongs. If the binary turns out to exit
   non-zero after all, the stage stops and reports.
4. **The pages.** `read_out.md` § 8.6 gets a dated note for N1, N2 and N4.
   `defined_behaviour.md` § 4 is corrected (N3), and so is `configuration.md`'s
   `--max-steps` row if it repeats the help. The phase README's N1–N4 notes
   point here and say *fixed*.

## Acceptance

- The four lines say what they print, each held by a test.
- No answer, exit code, `corpus/wrong_answers.toml` row or `corpus_exits.txt`
  row moves. Every golden that moves is on step 1's list.
- `ein oracle` names no option it refuses: every `--dump-answer` mention in
  its stdout names a command that exits 0.
