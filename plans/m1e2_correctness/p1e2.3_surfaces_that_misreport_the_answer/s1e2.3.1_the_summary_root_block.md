### The mechanism, read in the code

[`summary::root_block`](../../../ein.rs/crates/ein-cli/src/summary.rs) forks
root and, on the fork:

1. runs `closed::emit_closed`, which writes `(__closed__ R)` for every
   relation no rule concludes. No route runs this pass.
   [`closed.rs`](../../../ein.rs/crates/ein-infer/src/closed.rs)'s module note
   says its call sites were `-H` and the summary. Since `-H` lists H, the
   summary is the only one;
2. saturates;
3. runs the walk's `hypgen::generate`, which reads the program's lookahead and
   kill-cache flags through the KB, and `EIN_OBLIGATION_CHOICE`. With the
   lookahead on, a candidate killed in one firing gets its `(not h)` written
   into the fork;
4. counts the fork's facts after all three.

H is built elsewhere.
[`region::prepare_with`](../../../ein.rs/crates/ein-infer/src/region.rs)
saturates root without `emit_closed`, then runs `hypgen::generate_config_free`,
which pins the lookahead and the kill cache off and the obligations rung to
`rule-order`. It sorts the candidates and drops duplicates. Every route starts
from that root and that H.

`-L` and `-K` change only the resolved config's copy, which `-c`, the `run`
event and the `config` echo read. They never reach the KB
([S1e2.1a.6](../p1e2.1a_the_solution_region/s1e2.1a.6_engine_against_oracle.md)),
so they cannot move the block. A program's `(config …)` does reach it.

## The question

> **What should `--json-summary`'s `root` block describe: H, root's fixpoint,
> or neither?**

The milestone README left it to this phase. Every option drops the
`emit_closed` pass and the walk's generator from the summary. None of them
moves an answer.

| | (a) H and root's fixpoint, config-free | (b) root's fixpoint only | (c) neither: the block goes |
|---|---|---|---|
| `root.facts`, `facts_by_relation` | root's fixpoint as `region::prepare_with` builds it: 22 on `branching/02` | the same | gone. Root is state ∅ in `--dump-answer` when ∅ ∈ R, and `ein render kb FILE` draws it, but neither speaks when root is dead or owes |
| `root.plans`, `root.saturator` | kept | kept | gone, and these numbers are on no other surface |
| `root.hypgen` | `generate_config_free`'s stats over that root. `emitted` counts before deduplication, so the block grows a `distinct` that equals `region.universe.candidates` | gone. H is `region.universe` (`candidates`, `dead_alone`) and `-H`'s listing | gone |
| H stated in one summary | twice, held equal by a test | once | once |
| work a summary adds | one saturation and one generator pass beyond the run's | one saturation, or none if the block reads the run's prepared root | none |
| key set | unchanged; `distinct` added | `hypgen` removed | `root` removed |
| tests that move | `summary_properties` gains the identities | `cli_semantics`' hypgen key-set assertion goes; `summary_properties` loses two counters and the `raw` identity | both, and `cli_semantics`' list of blocks |
| the bundle | unchanged (it reads `facts`, `facts_by_relation`, and tables the rest) | its *rest of the block* table shrinks | both root tables need another source |
| schema id | stays `ein-summary/2` (an added key) | a removed key: `/2` or `/3`, a sub-question below | a removed block: the same sub-question |

**Recommendation, mine: (b).** One number, one place, which is the ruling of
2026-10-16 that no two paths may disagree. The block keeps the numbers only it
states, `plans` and the `naf_*` counters, and the facts by relation the bundle
tables. No summary runs a generator a question did not ask for, which is the
same day's least-work ruling. (a) is the cheapest change to the shape, but it
writes H twice and needs a test to keep the two equal. (c) loses what nothing
else reports.

**The sub-question under (b) and (c): does a removed key bump the schema?**
`ein-summary/2` is named in 18 files
(`grep -rl "ein-summary/2" --include='*.rs' --include='*.py' --include='*.md'

## How it is measured

`s4_census.py` sweeps the block against H and under every lever.
`s4_facts.py` sweeps it against root's fixpoint. Both were run on 2026-11-02
at `7b33c3ab` as `python3 -I SCRIPT "$PWD" "$PWD/ein.rs/target/release/ein"
SCRATCH < FILES`, with FILES the output of `find examples tests
corpus/fuzz_findings stdlib plans/m1e2_correctness/probes -name '*.ein'`.
They are kept here, not banked, because T1e2.3.1.3's tests replace them.

```python
# s4_census.py — the root block against H, and under every lever.
import json, os, subprocess, sys
repo, ein, sc = sys.argv[1:4]; os.chdir(repo)
FLAGS = ["enable-pre-branch-lookahead", "enable-lookahead-kill-cache"]
def summ(path, *args, env=None):
    out = os.path.join(sc, "s.json")
    if os.path.exists(out): os.remove(out)
    try: subprocess.run([ein, "solve", "-n", "1", *args, path, "--json-summary", out],
                        capture_output=True, timeout=30, env=env)
    except subprocess.TimeoutExpired: return None
    try: return json.load(open(out))
    except Exception: return None
n = h_ne = 0; cfg, env, cli = set(), set(), set(); rows = []
for f in [l.strip() for l in sys.stdin if l.strip()]:
    d = summ(f)
    if not d or "root" not in d: continue
    n += 1; root = d["root"]; H = d["region"]["universe"]["candidates"]
    if root["hypgen"]["emitted"] != H: h_ne += 1; rows.append((f, H, root["hypgen"]["emitted"], root["facts"]))
    for flag in FLAGS:   # flipped from the program's own resolved value; the last block is kept whole
        c = dict(d["config"]); c[flag] = not c[flag]
        block = "(config " + " ".join(f":{k} {str(v).lower()}" for k, v in c.items()) + ")"
        cp = os.path.join(sc, "flip_" + os.path.basename(f)); open(cp, "w").write(open(f).read() + "\n" + block + "\n")
        d2 = summ(cp)
        if d2 and d2["root"] != root: cfg.add(f)
    for lev in ["-L", "-K", "-y"]:
        d3 = summ(f, lev)
        if d3 and d3["root"] != root: cli.add(f)
    for v in ["off", "fail-first"]:
        d4 = summ(f, env=dict(os.environ, EIN_OBLIGATION_CHOICE=v))
        if d4 and d4["root"] != root: env.add(f)
print(f"files with a summary: {n}")
print(f"root.hypgen.emitted != region.universe.candidates: {h_ne}")
print(f"root block moves when the program flips the lookahead or the kill cache: {len(cfg)}")
print(f"root block moves under -L, -K or -y: {len(cli)}")
print(f"root block moves under EIN_OBLIGATION_CHOICE=off|fail-first: {len(env)}")
for r in rows: print("  ", *r)
```

```python
# s4_facts.py — root.facts against root's fixpoint as `ein saturate` counts it.
import json, os, subprocess, sys
repo, ein, sc = sys.argv[1:4]; os.chdir(repo)
n = ne = 0; rows = []
for f in [l.strip() for l in sys.stdin if l.strip()]:
    out = os.path.join(sc, "f.json")
    if os.path.exists(out): os.remove(out)
    subprocess.run([ein, "solve", "-n", "1", f, "--json-summary", out], capture_output=True, timeout=30)
    try: d = json.load(open(out))
    except Exception: continue
    s = subprocess.run([ein, "saturate", f], capture_output=True, text=True, timeout=30).stdout
    m = [l for l in s.splitlines() if l.strip().startswith("facts (total)") and len(l.split()) >= 4]
    if not m: continue
    fix = int(m[-1].split()[3]); n += 1
    if d["root"]["facts"] != fix:
        ne += 1; rows.append((f, d["root"]["facts"], fix, d["root"]["facts_by_relation"].get("__closed__", 0)))
print(f"files: {n}; root.facts != root's fixpoint: {ne}")
for r in rows: print("  ", *r)
```
