## Context

written with hypothesis provenance, the saturation resumed and run to
quiescence"*. [`solution_semantics.md` § 1.5](../../../docs/kernel/inference/solution_semantics.md#15-commitment-node-state):
*"For a monotone program, building the state from scratch gives the same fact

## The general form: a path, not only root

Added 2026-11-02, from the user's observation that day: *"I guess this is a
special case of more common sat(P+C1+C2) != sat(sat(P+C1)+C2) ? so in general
non-monotonic is not only about root scratch and fixpoint"*. **It is right**,
and it is evidence the census already held:

- **Fork from root is the case C1 = ∅**: sat(sat(P) ∪ C) against sat(P ∪ C).
  Every shipped route (the oracle, route 1, route 2) builds a node from root
  with all of C at once, which is why it was the only case this stage set out
  to compare.
- **A parent path is C1 = C \ {h}.** [`node_census.md` § 6.1](node_census.md#61-the--y-abort-on-d3-unsat-core)
  ran `-y`'s old check, `sanity::check_commutativity`: a parent path reaches a
  different state from the direct fork on `lattice/08` (2 of 4 nodes), the
  probe `via_hole` (1 of 4) and `d3-unsat-core` (8 of 26), and on every one of
  them the direct fork is scratch's node.
- **`lattice/08` shows it with nothing at root.** `soup-unless-allergic` fires
  at the parent `{(seats Ann C1)}` and keeps `(meal Ann Soup)` after
  `(allergic Ann)` is added. It is stratified, so (D) does not remove it.

So under (A) a node's state on a flagged program is **not, in general, a
function of C**: on these three programs it depends on the path. Any route that builds a node from a parent's fixpoint (P1e2.1c's, if one
is built over a flagged program) would then disagree with the oracle, against
the user's ruling of 2026-10-16 that *"results must be consistent: region is
a region of oracle"*. The question under Q-M1e2.2 is *is a node's state a
function of C alone?* Given cumulative saturation that is the same as *is the
state monotone?*, and the boundary's FIFO admission is where cumulativity
fails ([`monotonicity.md` § 7](../../../docs/kernel/inference/monotonicity.md#7-two-properties-of-the-node-functions-and-path-dependence),
written 2026-11-02, with each claim's standing). Every split C1 ⊆ C, longer
chains and the cumulativity census are
[S1e2.1b.7](s1e2.1b.7_the_consequences_written_down.md)'s; F21's D3 is the
decision.

## The question

**Deferred to [F21](../../followups/f21_non_monotone_programs_decided.md),
2026-11-02**, as its D2, with D1 and D3 beside it. The question and the
options stay here as the evidence was gathered against them.

> **On a program the static check flags, what is a node's state? Root's
> fixpoint with the commitment written in and the saturation resumed (fork);
> the program's facts with the commitment as given facts, saturated from
> nothing (scratch); either one checked so that no state counts whose facts
> rest on an `absent` the state falsifies (guards are premises); or is a
> program on which they can differ refused at load?**

| | what a node is | what it is known to change | composes with |
|---|---|---|---|
| **(A) fork, append-only** | `sat(sat(program) ∪ C)`, today's | nothing. W8's rows close `not-wrong` with the reason written, which is S1e2.2.6's third reading. L0 stays a property of the node | — |
| **(B) scratch** | `sat(program ∪ C)` | `stale-naf-fork`'s `{(q one)}` joins R. L0 holds only where scratch agrees with fork. Root is re-derived inside every node, at a cost the stage measures. On an unstratified program the fixpoint can depend on rule order, which (C) or (D) has to settle | (C), (D) |
| **(C) guards are premises** | (A) or (B), and a state holding a fact whose derivation's `absent` premise the state falsifies is not a solution | a node gets a third outcome beside dead and owing, so a sub-question follows: is it its own status, or counted as dead? | (A), (B) |
| **(D) refuse what cannot be stratified** | a load error for a program whose rule dependency graph has a cycle through an odd `absent` over D | `features/07` would be refused. `stale-naf-fork` is stratified and still needs (A), (B) or (C). M1f's [S1f.5.15](../../m1f_hypothesis_and_documentation/p1f.5_the_no_owner_items/s1f.5.15_rule_priority.md) plans the diagnostic, so the dependency moves here or waits | (B), (C) |

**(E), added 2026-11-02**, is F21's D1: extend *forbid* to every `absent`
site over a relation a commitment can extend, whatever it concludes. Then no
program that loads has a site that breaks the state, fork = every path =
scratch on all of them, and (A)–(D) are moot. Its cost is 13 programs with an
`absent` site that concludes a positive fact: the 12 of
[site census § 2](site_census.md#2-the-sites) and `lattice/08`, banked after
it. How many are refused beyond *forbid* depends on S1e2.2.5's F1 and F2.

## How it is measured

1. **Both routes, node for node.** Over every flagged cube S1e2.1b.1 lists,
   the register's W8 witnesses and S1e2.4.1's probes: each node's two status
   bits and its state under fork (`ein oracle --dump`) and under scratch
   (`utils/region.py --json`, the second route since S1e2.1a.1). Every
   disagreement is listed with the facts that differ and the site whose rule
   produced them. If `region.py`'s process per node is too slow, a library
   prototype replaces it. No flag reaches the prototype, since a node chosen
   by an option would be a lever that changes R.
2. **The staleness census.** On every node of those cubes, under each route:
   the facts whose primary derivation has an `absent` premise that the node's
   own state falsifies. `region::Node::absent_premises` reads the premises of
   a contradiction today, and the check over every fact is new.
3. **The stratification check.** The rule dependency graph over D, and every
   cycle through an odd `absent`, over every program in S1e2.1b.1's
   selection. It reports which programs (D) would refuse, by name.
4. **Invariance.** Scratch's R at `-j 1` against `-j 16`, under permuted
   interners (as `id_order_invariance` permutes them with `EIN_ID_SEEDS`), and
   under a reordering of equal-priority rules, on every flagged cube. A route
   whose R moves under any of these breaks the config principle there, and the
   option that needs it needs (C) or (D) as well.
5. **Cost.** Per-node wall and facts beyond root, fork against scratch, on
   every flagged cube and on the largest monotone cubes as the control.
6. **The three known cases read under each option**: the `-y` abort on
   `d3-unsat-core`, L0 on `features/12`, and the synthesizer's dead ∅.
7. **W8's two rows**: `right` computed under each option by the route that
   option defines. No hand derivation is left.

Every number goes on a dated page, `node_census.md`, in this phase's
directory, with the commands that re-take it.
