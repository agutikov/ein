## Context

The user, 2026-10-16, verbatim:

> change solve behaviour; the default simple `solve` without flags we get
> exhausive certifying full region description; while with some flags can
> simplify the task - e.g. look for any solution, or expect there is a single
> solution - so k>=2 is a contradiction; or look for only maximal solutions,
> or only for minimal solutions

and, in the reply to Q-M1e2.8, *"Q-M1e2.8 - yes"*: the oracle becomes `solve`'s
answer wherever it reaches, now, and the region search is a phase of its own,
next.

Today `ein solve` stops at the first model (`-n 1`) and walks for the maximal
line, which the user called *"relevant only in special case with no
obligations"*. Even `-e` certifies the walk and not R (Q-M1e.8). The walk
cannot count R: it records complete nodes and does not expand them. So `k_s`
and `k_c` have no honest source in today's engine, and S1e2.1a.5 cannot print
them until this stage gives it one.

## What the default computes

**R, in full, with its certificate.** That means k_s, k_c, both lines, the
components, the maximal sub-cubes and their dimensions, the trivial lines
named as trivial, monotonicity, and holes through the stub. How each of these
is printed is S1e2.1a.5's. This stage computes them and says which route was
used.

**The routes, cheapest licensed first:**

1. **Monotone (the static check says so): enumerate the alive down-set.**
   - Start at ∅ and grow layer by layer. Each node is a fork of root plus C,
     saturated by saturation alone.
   - Never generate a superset of a dead node. By the theorem, dead is
     upward-closed, so every such superset is dead without being visited.
   - The cost is |alive| · n saturations, not 2ⁿ. R is the alive nodes that
     owe nothing, and every unvisited node is dead *by the theorem*. The
     certificate is the static verdict, plus N read off the border, plus E.
   - On [`06_friends_tables`](../../../examples/lattice/06_friends_tables.ein)
     that is **277** alive nodes of 524 288. The corpus-wide ratio is
     T1e2.1a.9.1's measurement, and its first take is below.
2. **Non-monotone, or a static verdict the cube contradicts: the oracle**, all
   2ⁿ nodes, at n ≤ `--region-limit`. Its region carries the stub's *assumes a
   monotone lattice*. The meaning is P1e2.1b's.
3. **Beyond both: a partial description.** That covers an alive set too
   large for the route-1 budget, and a non-monotone n over the limit. The run
   prints what it has certified and bounds for the rest, with `exhausted =
   false`, and the read-out says which route declined and why. It runs no
   walk: the user withdrew it on 2026-10-16
   ([`solve_interface.md`](solve_interface.md) § 1, C3). Taking these cases further is
   [P1e2.1c](../p1e2.1c_the_region_search/README.md)'s.

**No lever chooses a route.** The route is decided by the program and the
limit. A lever may still change the speed inside a route, which is the config
principle.

## The flags that make the task simpler

They are the user's four, read as two independent axes, which is the plan's
reading:

| axis | flag (names in T1e2.1a.9.2's page diff) | what is computed | what it answers |
|---|---|---|---|
| **which nodes** | default: **all of R** | the full description | — |
| | **minimal only** | the minimal line | its members and its count |
| | **maximal only** | the maximal line | the same |
| **what is asked** | default: **describe** | as above | — |
| | **any solution** | the first node of the chosen set found, checked by one saturation | one node, `exhausted = false` by definition |
| | **expect a single solution** | enough to decide whether the chosen set has one state | **0** contradicts the expectation (`Contradiction`); **≥ 2** contradicts it (`Ambiguity`); **1** meets it (`Solution`) |

They compose. *Maximal* together with *single* asks whether \|max R\| = 1,
which is the uniqueness question for a program that states no obligation,
since there ∅ ∈ R and the plain *single* would always fail (Q-M1e2.7 (a)).
Under *single*, today's three verdict words are what the read-out says, and
they judge the stated expectation, as (i) rules. In the default, describing
mode the read-out names no verdict word and describes R. That is S1e2.1a.5's
to print.

A program states the same expectation in the language through
[S1e2.1a.4](s1e2.1a.4_the_language.md)'s `(solution …)`. The flag and the form
must mean the same thing, and the grammar page says which wins when both are
given.

## Acceptance

- **The default is exhaustive and certifying.** `ein solve FILE` with no flag
  computes R by route 1 or 2. It reports which route was taken, k_s, k_c and
  `exhausted = true`. Route 3 says *partial*, names the route that declined,
  and gives the reason.
- **Root is never written.** No route writes into root: not a forced
  positive, and not a negative. Root's fact set after any `solve` equals
  `sat(program)`, held by a test (Q-M1e2.7's third answer). The old walk keeps
  its root writes until S1e2.1a.5's switch retires it.
- **Route 1 equals the oracle.** On every monotone corpus entry and register
  witness with n ≤ 16, route 1's R is held to the oracle's node for node, with
  every unvisited node dead in the cube. That is the empirical half of the
  theorem, made a test. A monotone verdict with a disagreement fails the test.
- **The four flags**, each with a test on `06_friends_tables`,
  `07_two_pairs_two_tables` and one program with obligations only (a trivial
  maximal line). *Any* returns a node of R. *Single* exits as `:expect` does
  when the expectation fails. *Minimal* and *maximal* each equal the oracle's
  line.
- **Today's flags.** Under the new default, `-e` changes nothing, and `-n N`
  becomes *any*, N times. T1e2.1a.9.2's page diff proposes whether each is
  kept, renamed or retired, and the user rules before the parser changes. The
  option census (`configuration.md`, `help_surface.rs`, `help_shape.txt`)
  moves deliberately.
- **The corpus.** Every entry's declared `solve` and `solve -e` runs change
  meaning. Before anything is re-banked, the stage names every golden that
  moves and why: the exit cells, the shape digests, the summaries and the
  `:expect` outcomes. A corpus `:expect` that held only because the search
  stopped early is listed and not re-blessed silently.
- **The cost is measured.** Wall time of the corpus sweep with the new
  default, per route. If route 1's budget or the oracle's limit would push a
  default-tier entry past `slow`'s 1 s, the entry is named and the user rules.
  A run is not dropped for cost.
- **No lever changes R.** Held over every route-1 and route-2 entry, every
  declared lever cell. This test is
  [S1e2.1a.6](s1e2.1a.6_engine_against_oracle.md)'s, extended to the new
  default.

## Tasks

### Task T1e2.1a.9.1 — How far route 1 reaches

Measure |alive|, its border and 2ⁿ on every corpus cube, together with the
zebra family's alive set at a budget. The measurement decides route 1's
default budget.

**Done 2026-10-16**: [`route1_reach.md`](route1_reach.md), taken with
`cargo run --release -p ein-infer --example route1_reach`. Over 195 programs:

- **Route 1 describes R on 162**: every monotone program at `n ≤ 16` (147),
  and 15 past the oracle's limit, up to `n = 204`. At `n ≤ 16` it costs
  49 303 saturations against 268 138, and 1.75 s against the oracle's 21.18 s.
- **It never saw the cube contradict a static verdict.**
- **The zebra family's alive set is finite and counted.** `zebra.ein` has
  270 454 alive commitments, and R is **one state** of 261 982 commitments
  with 63 minimal generators: 25 s on 12 jobs, past the default budget.
  `zebra2-minus-15` is not countable this way: 704 443 commitments of R at
  sizes ≤ 5 alone.
- **The budget's unit should be facts derived, not nodes visited**, because
  per node the cost spreads 400× and per fact 28×. The proposed default is
  2¹⁹ facts: the knee of the curve, with a worst decline of 5.7 s at one job.
  That default is the user's to rule.

### Task T1e2.1a.9.3 — Route 1

**Done 2026-10-16**:
[`ein_infer::downset`](../../../ein.rs/crates/ein-infer/src/downset.rs). It
works layer by layer from ∅ by the prefix join over candidate indices, and
visits a commitment only when every one-smaller subset is alive. It shares the
oracle's root fixpoint, universe, static check, node and fan-out, which moved
out of `region::compute` into `region::prepare` and `region::fan_out`. The
census re-taken on the 220 programs of its default selection is identical row
for row.

It declines in three cases:

- on a flagged program;
- at its budget, between layers;
- when it sees an alive discharged node with an alive owing node one fact up,
  which would contradict the static verdict. The corpus never does.

Its description holds k_c, k_s, both lines, `N`, the components, the
sub-cubes, and the merged classes (the third answer's `(merged (to from))`).
Three tests in `ein-infer/tests/region.rs` cover it:

- **`route_1_is_the_oracle_on_every_monotone_program_it_reaches`** is the
  acceptance's *route 1 equals the oracle*, over every corpus file and
  register witness. Its checks:
  - the visited set is exactly alive ∪ N;
  - both bits agree on every node;
  - the lines, k_c, k_s, components, sub-cubes, states, closures and merges
    agree;
  - every flagged program is declined;
  - root afterwards is `sat(program)`.

  It takes 8 s in the dev profile, with the oracle on up to 8 threads. The
  two W7 witnesses are left out in a debug build, which aborts on them, as
  the register says.
- **`route_1_jobs_change_nothing`**.
- **`route_1_declines_at_its_budget_with_whole_layers`**.

No CLI path reaches the route yet. The measurement's example is the only
caller outside the tests.

## Notes

- **What route 1 is not.** It is not the search under review. It has no
  lookahead, no forced positive, no kill cache and no learned clause, and it
  prunes only what the static theorem licenses. It is the oracle restricted to
  what monotonicity proves it can skip.
- **The old walk** is retired by the user's ruling of 2026-10-16: no `ein
  walk`, and no CLI path to it after S1e2.1a.5's switch. The register's rows

  commit, against `right` blocks restated under R at S1e2.1a.7

`examples/`, `tests/` and `corpus/` through `ein solve FILE --dump-region DIR`,
counting the alive nodes and their dead border on each computed cube.

- **154** cubes were computed, and the static check calls **141** of them
  monotone. Over those 141, route 1 saturates the alive nodes plus their dead
  border: **64 197** of **202 612** nodes, **32 %**.
- **The ratio is bimodal.** It is driven by the programs where nearly
  everything is alive:
  - `features/02_star_in_identifiers.ein`: all 32 768 nodes alive, and all in
    R;
  - `syntax/constraint-scopes.ein`: all 4 096;
  - `type-exclusivity/pets.ein`: 11 339 of 32 768.

  Where restrictions bite, route 1 is nearly free:
  - `branching/01_saturate_only.ein` and `bijection/06_blind_enumeration.ein`,
    each n = 16: 1 alive node and 16 border nodes, against 65 536;
  - `branching/05_mini_zebra.ein`: 56 of 512;
  - `06_friends_tables`: 277 alive of 524 288.
- **Where everything is alive, R is one sub-cube**, [∅ … ⊤], and a description
  by sub-cubes is one line. Getting there without visiting the cube is
  P1e2.1c's duality stage, S1e2.1c.2. Route 1 does not try.
