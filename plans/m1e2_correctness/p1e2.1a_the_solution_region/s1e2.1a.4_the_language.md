## Context

A program can state its own answer since M1c:
`:expect (model …)`, `(or (model …) …)` or `(false)`, where *naming a
relation closes it*
([`01_grammar.md` § Query](../../../docs/kernel/ir/03-ein-lang/01_grammar.md#query)).
Each form states **one model set**. Under
[Q-M1e2.7](../open_questions.md#q-m1e27--the-answer-is-a-region-of-the-lattice)
a model set is one line of R, and nothing says which. A query cannot ask for
the minimal line, the maximal line or both, and an expectation cannot state R
or say that it has holes.

The user asked for the language to *"fully cover R in all cases with holes
and without"*. The phase's line is **forms for R only**.

## Acceptance

- **What the rulings call for, and no more.** The candidates, each built only
  if its ruling asks for it:
  - a query keyword choosing the line, for (b);
  - an `:expect` form over a region, with a minimal line, a maximal line,
    their sizes, and *no holes* or the holes, for (c);
  - a program-level refusal of what cannot be stratified, for (d) if it rules
    so.

  A form the rulings do not need is not built.
- **Today's forms keep their meaning**, or the change is ruled and every
  corpus `:expect` it affects is named before it moves. The register's rule
  holds: an `:expect` that states today's wrong answer stays until its fixing
  stage moves it.
- **`ein test` checks the new forms**, and `--json-report` gains the fields
  that describe them: the claim's shape, which line, and the outcome. A form
  the runner cannot check reports `NOT CHECKED` with a stderr line, as
  M1d S1d.4.3 requires.
- **The grammar page, `defined_behaviour.md`** (for any new load error), and
  `configuration.md` (for any new keyword) say so. Every new form gets a
  corpus fixture under `tests/` that exercises it.
