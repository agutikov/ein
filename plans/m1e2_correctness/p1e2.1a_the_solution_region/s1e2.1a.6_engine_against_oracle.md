## Context

Every right answer in the register was derived by hand. M1e's record says
it *did not check the engine's answers*, and M1e2 exists because of that.
For programs whose candidate list is small, the oracle turns *the right
answer* from a reading into a computation. This stage points it at the whole
reachable corpus, under every lever, which the user's config principle
makes a correctness claim rather than a cost measurement.

## Acceptance

- **A census first**: every corpus entry and register witness the oracle
  reaches at the default limit, every declared run and every lever cell. For
  each, the engine's reported line (as S1e2.1a.5 reports it) is compared with
  the oracle's. Disagreements are listed by mechanism.
- **Every disagreement is a register row** or an explained non-defect: a
  budget that cut the walk and says so, or an answer outside the oracle's
  universe (W4, W6). New rows get ids after W12, with the oracle's answer as
  `right` and `derived = "the oracle, …"`. A new W-case gets a P1e2.2 stage
  or a written reason it does not.
- **The test**: `ein-cli/tests/oracle_agreement.rs`. It is in the gate if it
  is cheap enough, and in the nightly otherwise, with the cost measured and
  written down. For every reachable entry and cell, the engine agrees with
  the oracle **or** the cell is a register row. An agreement that turns into a
  disagreement fails, and so does a register row that starts agreeing without
  flipping to `fixed`.
- **Lever invariance**: for every reachable entry, every lever cell is held to
  the **same** R as the default run. That is the config principle as a test.

## Notes

- **What this cannot find**: wrong answers on programs the oracle does not
  reach (the zebra family), and wrong answers the saturator causes, because
  the oracle saturates with the same code. The census page says both.
- **The R half of lever invariance is already measured** (S1e2.1a.3,
  [region_census.md § 9](region_census.md#9-the-config-principle)):
  `utils/region_census.py --levers` recomputes R under each of 24 levers on
  every program the oracle reaches. R moves under one flag,
  **`enable-symmetric-mirror`** on `features/06_symmetric_native.ein`, which
  this stage files as a register row with the fix left to the user's ruling
  (retire the flag, or make it switch the mirror's implementation and not its
  meaning). What remains here is the report half: the engine's reported
  answer under each lever, against R.
