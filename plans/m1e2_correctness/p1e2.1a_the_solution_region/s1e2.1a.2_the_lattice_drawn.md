## Context

The user drew W1 in words: *"a whole solutions topology {empty, A, B, C,
(B, C)} and an upper bound of this sub-lattice {A, (B, C)}"*. Nothing in
the repo draws that.
[`ein render lattice`](../../../docs/kernel/ir/03-ein-lang/04_dot_rendering.md)
runs a solve and shows survivors and their pruned siblings. Its `--view full`
falls back to the same, because the solve keeps no per-commitment DAG. The
bundle's `pages/lattice/` is one page per entering, with no picture of how
they relate. The user has said what this view is for: *"its visualization
become so important for solution correctness analysis"*.

## Acceptance

- **`ein render region DIR`** reads a `--dump-region` directory and prints
  DOT, so the picture comes from the run whose answer it shows (S1e2.1.3's
  reason for `render kb FILE`).
- **The Hasse diagram**, as the user draws it: L0 at the top, one rank per
  layer, and an edge from each node to its supersets one layer down.
  - **Each node** is labelled with its commitment and coloured by status:
    dead, owing, or in R. A hole has a mark of its own.
  - **Each node's tooltip** gives the reason: for a dead node its core and
    the rule chain that reached `(false)`; for an owing node its owed
    instances.
  - **R's minimal and maximal lines** are outlined, each in its own style.
- **The walk, overlaid.** Each node also says what this run did with it:
  - entered (`alive`, `dead_pre`, `dead_post`);
  - killed by the lookahead before entering;
  - pruned by a learned clause;
  - never generated;
  - **recorded** as a model or an open state.

  A node on R's reported line that was not recorded is drawn as
  **missing**. A recorded node that is not on that line is drawn as
  **spurious**. The legend says which line was compared, which is
  S1e2.1a.3's ruling (a). Until that ruling exists, the drawing marks both
  lines.
- **Views that stay readable.** The full diagram has 2ⁿ nodes, so:
  - n ≤ 6 (64 nodes): the whole diagram.
  - Up to the oracle's limit: **R and its border**, meaning R, its holes, and
    every dead or owing node adjacent to R. The other nodes are counted per
    layer in the rank label.
  - At any n: a **per-layer table** page (markdown) listing every node with
    its status, its reason and what the walk did with it.

  The thresholds are measured: the stage draws `owed-seats` (n = 4),
  `lattice/02` (n = 3) and the largest corpus program under the limit,
  and fixes the cutoffs on what still reads.
- Every view goes through `dot -Tsvg` in a test, which is `dot_wellformed.rs`'s
  standard. The legend is in `04_dot_rendering.md`.

## Tasks

### Task T1e2.1a.2.1 — The diagram and its legend

`ein-render::region_dot`, one function per view.

### Task T1e2.1a.2.2 — The walk overlay

The walk is read from the same run's records: the timeline, the per-entering
outcomes, the kill-cache and lookahead writes, and the recorded nodes. Those
already exist in `LatticeProof`, `--dump-lattice` and `--dump-states`'
`00_timeline.jsonl`. The overlay is a join on the commitment, done in Rust,
because computing *missing* and *spurious* is a comparison and the bundle
script does not compute.

### Task T1e2.1a.2.3 — The thresholds

Draw, read, fix the cutoffs, and write down what each cutoff was chosen on.

## Notes

- **Which way up.** The user's drawing puts L0 at the top and large sets at
  the bottom, so *bottom* in the drawing is the maximal line. The legend
  names lines **minimal** and **maximal** and never *top* or *bottom*, so a
  reader who flips the picture is not misled.
