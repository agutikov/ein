## Context

[Q-M1e2.7](../open_questions.md#q-m1e27--the-answer-is-a-region-of-the-lattice)
defines the answer as `R = { C : C alive and discharged }`. The only thing
that computes anything like it today is the search under review. An oracle
has to compute R **independently of the walk**: every commitment, not the
ones the join proposes, and classified by what the program's rules say,
not by what the search wrote at root.

The scratch prototype behind Q-M1e2.7's table did this with one `ein
saturate` process per subset. It also found the trap. Read through `solve
-m 0`, the commitment `{(seats Ann C1)}` came back owing nothing, because the
search had promoted `(seats Bob C2)` as `<forced-positive>` and written two
`<lookahead-dies-immediately>` negatives. That is the config-dependent
inference the user ruled may not touch the answer.

## Acceptance

- **`ein_infer::region`**, a library module.
  - **Input**: a loaded program, and a candidate list (default: the root
    candidate list, below).
  - **Output**: one record per commitment `C`, holding
    - `C` itself and a digest of its saturated state;
    - its **status**: `dead` with its core and the rule chain that derived
      `(false)`, `owing n` with the owed instances, or `in R`;
    - whether `C` is on R's **minimal** or **maximal** line;
    - whether `C` is a **hole**: outside R, yet between two members of R.

  R's lines are computed by subset comparison over R, never by assuming that
  R has no holes.
- **Classification by saturation alone.** Fork root, assert `C`'s facts,
  saturate, and read `(false)` and the obligations pass. There is **no**
  lookahead, forced positive, kill cache, writeback or learned clause: none
  of the search's machinery. A test pins Q-M1e2.7's witness: `{(seats Ann
  C1)}` on `owed-seats` + `functional` + `injective` owes **2**.
- **The candidate list.** The generator's hypothesis list at root's
  fixpoint, before any search-time write. Today's
  [`alive₀`](../../../docs/kernel/inference/solution_semantics.md) is taken
  *after* the forced-positive cascade, which is a config switch, so the two
  differ. The oracle uses the config-free list. Where they differ, the run's
  page says so. That is evidence for Q-M1e2.7's (h), not a decision of it.
- **The limit**, as the user ruled it on 2026-10-15
  ([Q-M1e2.7 § The oracle's limit](../open_questions.md#the-oracles-limit-ruled-2026-10-15)):
  - n ≤ 16 runs silently.
  - 17 ≤ n ≤ 19 is refused with a message naming the option that raises the
    limit. When it is raised, the run prints one warning line on stderr.
  - n ≥ 20 is refused the same way. When it is raised, the run first prints a
    prominent warning on stderr: 2ⁿ, the per-node cost measured on this
    program's first 64 nodes, and the projected wall time.

  Each arm has a test.
- **The door: `ein solve --dump-region DIR`.** It writes `region.json` (every
  node) and `region.md` (a summary). The oracle runs inside **the same solve**
  whose walk it is compared with. That is S1e2.1.3's reason for making a model a
  file rather than a second solve: the picture and the answer come from one
  run. Above the limit, the directory holds the walk alone and a line saying
  why there is no region. `help_shape.txt`, the option census in
  `configuration.md` and `config_reference.rs` move deliberately, and
  `help_surface::every_artefact_flag_of_solve_is_driven_by_the_review_bundle`
  will require the bundle to pass the flag.
- **Two routes agree.** On the seven programs of Q-M1e2.7's table, the
  library oracle's statuses, lines and holes equal the per-subset route,
  node for node. That route is
  [`probes/region.py`](../probes/region.py), banked when Q-M1e2.7 was filed,
  and the table includes one hole (W3's witness).
- No answer moves. The flag is additive: stdout, stderr, the exit code, the
  summary and the event stream are identical with it and without it, held the
  way `answer_dump::the_flag_moves_no_answer` holds `--dump-answer`.

## Tasks

### Task T1e2.1a.1.1 — The enumeration

All 2ⁿ subsets, in layer order. Each one is a fork of root, and the work is
parallel (rayon, as `--jobs` already is). Memory stays bounded: the record
keeps a state digest, not the state. An optional `--region-states` keeps
the states for S1e2.1a.2's per-node pages, and the stage measures what it
costs.

### Task T1e2.1a.1.2 — States, not only commitments

Two commitments can saturate to one state
([Q-M1e2.7](../open_questions.md#q-m1e27--the-answer-is-a-region-of-the-lattice)'s
(e), and Q-M1e.6's *integrated* hypotheses). The record carries the state
digest, so S1e2.1a.3 can count both ways before the user rules.

### Task T1e2.1a.1.3 — The limit, and its warnings

The refusal, the option that raises the limit, and the two warnings, each
held by a test.

### Task T1e2.1a.1.4 — The door, and the second route

`--dump-region`, and its line in `answer_dump.md`'s neighbour,
`lattice_dump.md`, or a page of its own if the format needs one. Then the
comparison test against `region.py`.

## Notes

- **Why not prune by closure.** Upward-closure of *dead* would let the oracle
  skip every superset of a dead node, and that is exactly the assumption
  holes break. An oracle that prunes cannot find a hole, so this one does
  not prune.
- **What it does not check.** It does not check the saturator (W7), and it
  does not check that the candidate list is complete (W4, W6). It checks the
  walk.
