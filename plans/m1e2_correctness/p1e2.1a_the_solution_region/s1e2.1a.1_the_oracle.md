## Context

[Q-M1e2.7](../open_questions.md#q-m1e27--the-answer-is-a-region-of-the-lattice)
defines the answer as `R = { C : C alive and discharged }`. The only thing
that computes anything like it today is the search under review. An oracle
has to compute R **independently of the walk**: every commitment, not the
ones the join proposes, and classified by what the program's rules say,
not by what the search wrote at root.

The scratch prototype behind Q-M1e2.7's table did this with one `ein
saturate` process per subset. It also found the trap. Read through `solve
-m 0`, the commitment `{(seats Ann C1)}` came back owing nothing, because the
search had promoted `(seats Bob C2)` as `<forced-positive>` and written two
`<lookahead-dies-immediately>` negatives. That is the config-dependent
inference the user ruled may not touch the answer.

### Scope, after the user's answer of 2026-10-15

Reading the engine before writing the oracle turned up a fork in this file's
own definition. *Fork root, assert C, saturate* builds a node on root's
fixpoint. `probes/region.py` (now `utils/region.py`), the second route this stage is checked against,
builds it from the program with C as given facts. The two agree whenever
adding a fact cannot take a conclusion away. They disagree on W8's witness
(`stale-naf-fork.ein`: forked, `{(q one)}` is dead; from scratch, it is in R).
Asked which route defines a node, the user answered:

> I propose to move non-monotonic solution question into phase p1e2.1b; in
> this phase we have to 1) complete handling of monotonic lattice 2)
> understand if any `absent` cause non-monotonicity or only some specific
> cases, clossify them OR move this investigation to p1e2.1b; 3) implement
> detection of non-monotonicity and add a stub for handling this case in
> `solve` and other tools

So this stage does all three. (2) is answered by classification, and the
answer is *only some*: an `absent` is harmless unless it reads, at
non-monotone polarity, a relation a commitment can change. The same check
found a second source that is not an `absent` at all, an obligation whose
trigger a commitment can change. It is measured in
[P1e2.1b § What non-monotone means](../p1e2.1b_the_non_monotone_lattice/README.md#what-non-monotone-means-and-what-is-not),
which also owns everything the classification leaves open.

## Acceptance

- **`ein_infer::region`**, a library module.
  - **Input**: a loaded program, and a candidate list (default: the root
    candidate list, below).
  - **Output**: one record per commitment `C`, holding
    - `C` itself and its **state class**: the smallest mask whose saturated
      state is the same fact set, so two commitments that give one state are
      visible without a digest of interner ids;
    - **two independent status bits**:
      - *dead*, with its core and the rule that derived `(false)`;
      - *owing n*, with the owed instances, **read on a dead state too**.
        Today `owes.root` reports 0 on a dead root whatever it owes:
        `{(seats Ann C1),(seats Ann C2)}` leaves Bob unseated and reports 0.
        Without this bit the minimal discharging sets E cannot be computed.
    - whether `C` is **in R** (alive and owing nothing), on R's **minimal** or
      **maximal** line, or a **hole** (outside R, yet between two members of
      R).

  R's lines are computed by subset comparison over R, never by assuming that
  R has no holes.
- **The node is the fork route.** Root's fixpoint, `C`'s facts written in
  with hypothesis provenance, saturated to quiescence. Saturation never stops
  at the first contradiction, so a dead node's debts are its fixpoint's. The
  from-scratch route is compared on monotone programs only. On a non-monotone
  one a disagreement is evidence for
  [P1e2.1b](../p1e2.1b_the_non_monotone_lattice/README.md)'s S1e2.1b.2, not a
  defect of either route.
- **The cube as the representation.** A node is its n-bit mask, and the
  statuses are one array of 2 bits per node, indexed by mask: 16 KB at
  n = 16 and 256 KB at n = 20. Everything below is computed over that array
  and never re-saturates. The cost of each computation is measured and
  written down; the saturations are the only part that grows with the
  program.
- **R's topology, computed:**
  - **components**: R's connected pieces under one-fact edges;
  - **maximal sub-cubes** `[a … b]` inside R, each with its dimension
    |b| − |a|, the number of free facts in it;
  - **holes**, with each minimal hole's `absent` guard (read off its core);
  - **repair edges**: from a hole node up into R, labelled with the fact
    that revives it;
  - **N**, the minimal dead sets, and **E**, the minimal discharging sets;
  - **local against global**: nodes of R whose one-fact neighbours say
    *maximal* or *minimal* while the whole cube says otherwise;
  - **violations of upward closure**: a dead node with an alive superset, and
    a discharged node with an owing superset, each counted, with the smallest
    witnessing pair.
- **The duality cross-check.** Without holes:
  - the minimal line is the alive members of E;
  - the maximal line is the discharged complements of the minimal sets that
    hit every member of N.

  A test asserts both on every hole-free program the oracle reaches, and
  asserts that the check *fails* on W3's witness, the one with a hole. On
  Q-M1e2.7's table it holds on the six programs without holes and fails on
  W3's. A disagreement on a program with no holes is a defect in the oracle.
- **Monotone only, and said so.** The lines, components, sub-cubes and the
  duality are claimed for programs the detector (below) classifies monotone.
  On any other program the oracle still enumerates and classifies every node,
  and computes the holes and the violations it sees. It labels everything
  above them *assumes monotone* and names P1e2.1b.
- **Classification by saturation alone.** Fork root, assert `C`'s facts,
  saturate, and read `(false)` and the obligations pass. There is **no**
  lookahead, forced positive, kill cache, writeback or learned clause: none
  of the search's machinery. A test pins Q-M1e2.7's witness: `{(seats Ann
  C1)}` on `owed-seats` + `functional` + `injective` owes **2**.
- **The candidate list.** The generator's hypothesis list at root's fixpoint,
  before any search-time write, with the lookahead filter and the kill cache
  off and `EIN_OBLIGATION_CHOICE` not read (the rung at its default). Today's
  [`alive₀`](../../../docs/kernel/inference/solution_semantics.md) is taken
  *after* the forced-positive cascade, which is a config switch, so the two
  differ. The oracle uses the config-free list. Where they differ, the run's
  page says so. That is evidence for Q-M1e2.7's (h), not a decision of it.
  Bits are assigned in the candidates' rendered-text order, so the cube does
  not depend on interner ids.
- **Non-monotonicity, detected: `ein_infer::monotone`.** A static check over
  the compiled plans, with no interning, no event and no counter, so it can
  run inside any solve without moving it.
  - *H* is the relations of the candidate list. *D* is H closed under *a plan
    that reads a relation in D asserts into D*. A stored negative `(not (R …))`
    is its own pseudo-relation `¬R`.
  - Every relation a plan reads is classified **static** (not in D),
    **dynamic, monotone polarity**, or **dynamic, non-monotone polarity**. In
    a saturation rule the non-monotone polarity is an odd `absent` depth: its
    growth can take a conclusion away. In an obligation rule it is an even
    depth, the trigger: its growth can add a debt.
  - A rule whose **activator** relation is in D is reported as a site of its
    own, because a commitment can then compile plans root never had.
  - The answer is `Monotone`, which is a theorem
    ([P1e2.1b](../p1e2.1b_the_non_monotone_lattice/README.md#what-non-monotone-means-and-what-is-not)),
    or the list of **sites**: rule, activator, kind, the relation, the
    polarity.
  - On the cube, the violations above are the empirical half. `region.md`
    gives both, and a monotone verdict with an observed violation fails a
    test, because the theorem would be false.
  - Fixtures: every program of Q-M1e2.7's tables, the probe of a hole without
    `absent` (`examples/lattice/04_obligation_trigger_hole.ein`), W8's
    `stale-naf-fork.ein`, and `zebra2.ein` (its `absent`s are all static).
- **The stub: `non_monotone` handling in `solve` and the tools.** Detection
  is not handling. Handling is P1e2.1b's S1e2.1b.5, and this stage gives it
  one place to land.
  - `solve` computes the classification at root from the plans the run
    compiled, with H read off the root generator's proposals before the
    lookahead filter. The search is unchanged. `Solved` carries it. A
    `monotonicity` event narrates it. `--json-summary` gets a `monotonicity`
    block on every run. A program with a site gets **one line** under the
    verdict saying the answer assumes a monotone lattice and naming P1e2.1b.
  - `ein test --json-report` carries the classification per row, and
    `--dump-region` carries it in `region.json` and `region.md`.
  - The goldens this moves are named here before they move. Every summary
    golden moves, by one block. The stdout goldens move only for programs
    with a site, and their list is the detector's corpus census.
- **The limit**, as the user ruled it on 2026-10-15
  ([Q-M1e2.7 § The oracle's limit](../open_questions.md#the-oracles-limit-ruled-2026-10-15)),
  raised by `--region-limit N` (default 16):
  - n ≤ 16 runs silently.
  - 17 ≤ n ≤ 19 is refused unless the limit is raised. Raised, the run prints
    one warning line on stderr.
  - n ≥ 20 is refused the same way. Raised, the run first prints a prominent
    warning on stderr: 2ⁿ, the per-node cost measured on this program's first
    64 nodes, and the projected wall time.
  - **A refusal is a note, not an error** (the user's choice, 2026-10-15).
    The solve runs as it would have, `DIR` holds the walk and a `region.md`
    saying why there is no region, stderr gets one `note:` line naming
    `--region-limit`, and the exit code is the solve's own.

  Each arm has a test.
- **The door: `ein solve --dump-region DIR`.** It writes `region.json` (every
  node), `region.md` (a summary) and `walk.json`. The walk is what this run did
  with the lattice: its enterings and their outcomes, the recorded models and
  open states, the learned nogoods and the root writes, each matched to the
  oracle's masks by fact text. Classifying the walk against the cube is
  S1e2.1a.2's overlay. The oracle runs inside **the same solve** whose walk it
  is compared with, after the solve and after every other artefact is
  written, on its own load of the program. That is S1e2.1.3's reason for
  making a model a file rather than a second solve: the picture and the
  answer come from one run. Above the limit, the directory holds the walk
  alone and the line saying why there is no region. `help_shape.txt`, the
  option census in `configuration.md` and `config_reference.rs` move
  deliberately, and
  `help_surface::every_artefact_flag_of_solve_is_driven_by_the_review_bundle`
  requires the bundle to pass the flag.
- **Two routes agree.** On the seven programs of Q-M1e2.7's two tables, the
  library oracle's statuses, lines, holes, components, sub-cubes, N and
  duality verdict equal the per-subset route, node for node. That route is
  `probes/region.py`, banked when Q-M1e2.7 was filed and moved to
  `utils/region.py` by this stage, because `plans/` is deleted when the
  milestone closes and a test cannot point there. The table includes one
  hole (W3's witness).
- **No answer moves.** The flag is additive: stdout, the exit code, the
  summary and the event stream are identical with it and without it, and so
  is stderr at n ≤ 16. That is held the way
  `answer_dump::the_flag_moves_no_answer` holds `--dump-answer`. The stub's
  line and block are not behind the flag, and their goldens are named above.

## Tasks

### Task T1e2.1a.1.1 — The enumeration

All 2ⁿ subsets, in layer order. Each one is a fork of the oracle's root, and
the work is parallel under `--jobs` (rayon, through `Terms::worker` views as
the layer fan-out has them). A node a worker cannot number is redone on the
calling thread. Memory stays bounded: the record keeps a state class, not
the state. An optional `--region-states` keeps the states for S1e2.1a.2's
per-node pages, and the stage measures what it costs.

### Task T1e2.1a.1.2 — States, not only commitments

Two commitments can saturate to one state
([Q-M1e2.7](../open_questions.md#q-m1e27--the-answer-is-a-region-of-the-lattice)'s
(e), and Q-M1e.6's *integrated* hypotheses). The record carries the state
class, so S1e2.1a.3 can count both ways before the user rules.

### Task T1e2.1a.1.3 — The limit, and its warnings

The refusal note, `--region-limit`, and the two warnings, each held by a
test.

### Task T1e2.1a.1.4 — The door, the walk, and the second route

`--dump-region`, `walk.json`, and a page of its own,
`docs/kernel/inference/region_dump.md`, because the format is a node record
plus a topology, which neither `answer_dump.md` nor `lattice_dump.md` has.
Then `region.py` moves to `utils/`, gains `--json`, and the comparison test
runs it.

### Task T1e2.1a.1.5 — The detector

`ein_infer::monotone`, its theorem in the module docs, and its fixtures. Then
the corpus census: which entries have a site, by rule and kind. It is
P1e2.1b's S1e2.1b.1 input and the list of stdout goldens T1e2.1a.1.6 moves.

### Task T1e2.1a.1.6 — The stub

The read-out line, the summary block, the event, the `--json-report` field,
and one function, `non_monotone`, that S1e2.1b.5 replaces. The `monotonicity`
event goes in `events.md`, the block in the summary schema, and the line in
`solution_semantics.md` § 5.

## Decisions taken without a ruling

Each is the default the stage proceeded on, stated here so that it can be
overruled in the plan rather than found in the code.

- **A separate load for the oracle.** It does not share the solve's
  interner, KB or memo, and its events are off. Forking root before the solve
  panics: `Kb::program_mut` requires an unshared program, and `solve` writes
  the config through it. Interning the oracle's facts first would renumber
  the solve's, and W11 is a core that depends on interner order.
- **The walk is matched to masks by rendered fact text**, for the same
  reason.
- **Cores** are `explain::smallest_contradiction_frontier`'s, as the search
  reports them, plus the rule whose firing derived `(false)`. They are
  computed for every dead node, and the cost is measured. If it dominates,
  they are kept for N and the minimal holes only, and the page says so.
- **Holes are classified by both sources.** A hole's minimal nodes name their
  `absent` guard where the core has one, and their owed instances where the
  hole is owing.

## Notes

- **Why not prune by closure.** Upward-closure of *dead* would let the oracle
  skip every superset of a dead node, and that is exactly the assumption
  holes break. An oracle that prunes cannot find a hole, so this one does
  not prune. It does not prune on a monotone verdict either: the cube is
  what checks the verdict.
- **What it does not check.** It does not check the saturator (W7), and it
  does not check that the candidate list is complete (W4, W6). It checks the
  walk.
