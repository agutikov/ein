## Acceptance

- **A region becomes a program.** `utils/region_synth.py` takes a target and
  writes a program whose oracle region is that target, node for node.
  - The spec gives R as intervals minus holes, with non-R intervals marked
    owing and the rest dead, plus optional implications so that saturation
    moves nodes.
  - The target is carried in the program's own header.
- **Checked from the outside.** `--check FILE` runs the binary's oracle against
  the header. `--random N` draws targets, writes them and checks them.
- **The static check, tested from the other side.** A program is called
  monotone exactly when its target is: no dead node below an alive one, and no
  owing node above a node of R.
- **The user's shape**, banked: three components (monotone, a one-node hole, a
  bigger hole), with more shapes aimed at Q-M1e2.7's sub-questions.
- **The solution as files.** Each node of R's two lines is written as the
  program plus its facts, so it loads and saturates to that node's state, and
  is drawn as a KB. This is the right answer by construction, set beside the
  engine's.
- **The biggest and most interesting regions, browsable.** A gallery surveys
  every corpus program's region and gives the ones worth reading a page each.

### The encoding

The target has two Boolean functions of the n bits: dead, and owing. Owing is
free on dead nodes, and both are free on nodes saturation moves. Each function
is cut into prime implicants (Quine–McCluskey, essentials first, then a
greedy cover), and each implicant becomes one rule:

| implicant | rule |
|---|---|
| dead: 1-bits `P`, 0-bits `N` | `(rule dead-i () :match (and (h p)… (absent (h q))…) :assert (false))` |
| owing: 1-bits `P` (the trigger), 0-bits `N` (the witnesses) | `(rule owe-j () :match (and (h p)… (absent (and (need Kj ?x) (h ?x)))) :assert (open h))` with `(need Kj q)` for each `q` in `N` |
| implication | `(rule imp-A-B () :match (h A) :assert (h B))` |

The candidates come from one `hrule` over `(slot X)`, so the cube is over
`(h A)`, `(h B)`, … in letter order, and node `{A,C}` is written the way the
user writes it.

- **Owing rules need a witness variable.** The loader refuses a ground
  obligation: *"`(open h)`'s `h` premise binds no variable of its own"*. That
  is why owing is the `need` set. An owing implicant with no 0-bit, a debt
  nothing pays, takes a witness no generator proposes.
- **Monotone targets come out monotone.** A dead set that is upward-closed has
  only positive prime implicants, and an owing set that is downward-closed on
  alive nodes only negative ones. So a monotone target is written with no
  site, and a target with a hole cannot be.

**One target is refused: a dead root under a non-empty R.** The oracle builds
every node from root's fixpoint. If ∅ is dead through an `absent`, that fixpoint
already holds the `(false)`, so every node would be dead. The first draft of
`trigger_hole` was this target, and every alive node came back dead. Which
route builds a node is W8's question and P1e2.1b's, so the script refuses the
target by name (`RootDead`) and the random targets keep ∅ owing.

## Decisions taken without a ruling

1. **The candidates are one unary relation, `(h X)`,** generated by one
   `hrule`. Every target is expressible this way, and a node's name is its
   letters.
2. **Owing on a dead node is left free.** The target says R, owing or dead, and
   the oracle's `dead+owing` reads as dead. A target cannot ask for a dead node
   that also owes.
3. **A dead root under a non-empty R is refused**, not written. See above:
   P1e2.1b decides which route a node is built by.
4. **The gallery keeps every artefact**, so it is gigabytes. Only the per-layer
   pages of a cube past 2¹⁶ nodes are capped, and the raw table keeps every row.
5. **The gallery's walk is the corpus's declared `solve -e` run**, else its
   first `solve`, so *what the engine answers* is the run the corpus already
   holds the program to.
