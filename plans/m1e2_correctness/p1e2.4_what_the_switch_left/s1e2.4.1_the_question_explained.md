# The `absent` question, explained

**For:** the user's ruling in [S1e2.4.1](s1e2.4.1_refutation_under_absent.md), *forbid* or *respect*.
**Ruled:** 2026-11-02, ***forbid*** ([the stage file § 5](s1e2.4.1_refutation_under_absent.md#5-the-ruling)).
This page stays as the explanation the ruling was taken on. § 3's fourth form,
q as a decision, was added after it, at the user's request.
**In Russian:** [`s1e2.4.1_the_question_explained.ru.md`](s1e2.4.1_the_question_explained.ru.md), a translation; this page is the original.
**Written:** 2026-11-02. Every output below was taken that day with the
release binary (`ein.rs/target/release/ein`), and each program is in the repo,
so each command re-takes it. The outputs are trimmed to the lines that matter. The evidence in full (counts, every corpus entry,
every rewrite) is the stage file. This page explains the question from first
principles, using the smallest programs that show each part of it.

The question, as the stage file puts it:

> When a rule concludes `(false)` or `(not …)` and its `:match` reads
> `(absent P)` over a relation that a commitment can still extend, is the
> program refused before any search, with an error naming the replacement
> (*forbid*), or is it legal, with the engine never carrying that refutation
> past the node whose own fixpoint derived it (*respect*)?

---

## 1. The words, one at a time

| phrase | what it means in Ein |
|---|---|
| **a commitment** | a set of candidate facts added to root. A node of the hypothesis lattice is a commitment, and its *state* is `saturate(root ∪ commitment)`. The candidates are the **universe**, which `ein solve -H` lists |
| **R** | the commitments whose state is alive (no `(false)`) and discharged (owes nothing): [`solution_semantics.md`](../../../docs/kernel/inference/solution_semantics.md) |
| **concludes `(false)`** | the rule *refutes* the state, so the node is **dead** |
| **concludes `(not …)`** | the rule stores a negative fact. That is a refutation in waiting: any state that also holds the positive is dead |
| **`(absent P)`** | negation as failure. It holds while `P` is **not in the KB**, read at that point of saturation. It is not a fact, so a later fact can make it stop holding |
| **`(not P)`** in a `:match` | reads a **stored** negative fact. Nothing removes a stored fact, so a read of it can only go from false to true as facts are added, never back |
| **a relation a commitment can still extend** | a relation that some node can hold more of than root does. Either the universe has candidates in it, or a rule derives it from one. S1e2.4.1's F1 asks how exactly to draw that line (§ 6) |

The phrase that matters is the combination: a **refuting** conclusion, a
premise that is an **absence**, and an absence that a **larger commitment can
fill**.

## 2. Why it matters, on seven lines

[`examples/ein-bugs/naf-upward-closure.ein`](../../../examples/ein-bugs/naf-upward-closure.ein)
is W3's witness. Without its comments it is:

```lisp
(relation is-a T T)
(relation p T)
(relation q T)
(is-a A T)

(rule bad ()
  :match  (and (p ?x) (absent (q ?x)))
  :assert (false))
```

The universe is two candidates, `(p A)` and `(q A)`, so the lattice has four
nodes:

```
                 {(p A), (q A)}   alive   ← the one maximal state
                  /           \
      {(p A)}  DEAD            {(q A)}  alive
     "p without q"
                  \           /
                       ∅         alive
```

`{(p A)}` is dead because `q` is absent **there**. Add `(q A)` and the absence
is filled, `bad` no longer matches, and the larger node is alive. So **dead is
not upward-closed**: a dead node has a live superset. R is the three live
nodes, and `{(p A)}` is a **hole** in it:

```
$ ein oracle examples/ein-bugs/naf-upward-closure.ein
  states (k_s)      3
  lattice           not monotone: 1 site (the static check) — 1 hole; …
    minimal hole    {(p A)} — dead: (p A)
  (region (model) (model (q A)) (model (p A) (q A)))
the cube   1 dead node with an alive superset
```

**Why this broke the old engine.** Every fast search rests on one licence:
*if a node is dead, so is every superset, so skip them*. That is what lets
`zebra.ein`'s R be counted without visiting 2ⁿ nodes. With the licence, the
walk saw `{(p A)}` die and never entered `{(p A), (q A)}`. Three mechanisms did
the skipping, and any one of them was enough: the kill cache stored
`(not (p A))`, the singleton writeback did the same, and a width-1 no-good
covered every superset. The walk answered `{(q A)}`, *exhausted*. That is the
register's W3 `wrong`. The right answer is `{(p A), (q A)}`.

**Why it is right today.** Since the switch (2026-10-18) a bare `ein solve`
runs the static check first. It flags this program as non-monotone, and a
flagged program is answered by **route 2, the cube**: every node saturated
from root and its commitment, nothing skipped, nothing written back. That is
correct, but it costs 2ⁿ saturations, and past n = 16 the answer is partial.

So the question is what the language does about this shape.

## 3. The same rule, made harmless

Change any one of the three parts and the hazard is gone.

**Close the relation**, so that no commitment can extend it:
[`closed_q.ein`](s1e2.4.1_probes/closed_q.ein) is the program above plus
`(solve :no-hypothesis (q))`.

```
$ ein oracle …/s1e2.4.1_probes/closed_q.ein
  states (k_s)      1
  lattice           monotone (the static check) — R is convex: no hole
  universe          1 candidate, 1 dead alone
  (region (model))
```

`(absent (q A))` now means the same thing at every node, so `{(p A)}` is dead
for good and the licence holds again. **An `absent` over a closed relation is
ordinary closed-world reasoning, and neither answer touches it.**

**Read a stored negative instead of an absence:**
[`naf_stored_negative.ein`](s1e2.4.1_probes/naf_stored_negative.ein) writes
`(not (q ?x))` where `bad` had `(absent (q ?x))`. This is `std.algebra`'s
`total` discipline, and the rewrite the warning suggests first.

```
$ ein solve …/s1e2.4.1_probes/naf_stored_negative.ein
  states (k_s)      4
  lattice           monotone (the static check) — R is convex: no hole
```

It is monotone, but it **means something else**. Nothing ever stores
`(not (q A))`, so the rule never fires and all four nodes are in R, where the
original had three. That is why the stage file reports that every rewrite in
this form changes R.

**Make it a requirement instead of a refutation.** The program's intent is
*`p` needs `q`*, which is an obligation and not a contradiction. The user read
it that way on 2026-08-28, as the witness's header records:

> not any well-formed ein program is correct. An example with
> `(rule bad () …)` is broken by design … there is no definition of `q` and `p`
> relations, no obligations, only the rule that asserts `(false)`.

The obligation form is
[`naf_open_hrules.ein`](s1e2.4.1_probes/naf_open_hrules.ein):

```lisp
(hrule guess-p () :match (is-a ?x T) :assert (p ?x))
(hrule guess-q () :match (is-a ?x T) :assert (q ?x))
(rule bad-owed ()
  :match  (and (p ?x) (absent (and (q ?y) (eq ?y ?x))))
  :assert (open q))
```

```
$ ein solve …/s1e2.4.1_probes/naf_open_hrules.ein
  states (k_s)      3
  lattice           not monotone: 1 site (the static check) — 1 hole; …
    minimal hole    {(p A)} — owes 1
```

It has the same three states as the original. `{(p A)}` is now a node that
**owes** `q` rather than a dead one, which is the honest description. It is
still a hole, though, because an obligation's trigger reads an absence too.
That kind of hole is P1e2.1b's to define, and *forbid* does not remove it.

Two practical snags show up in this form, which matter for F4 (what the
error message names):

- `(open q)` over a plain `(absent (q ?x))` is refused at load as *"the
  obligation is ground"*. It needs its own witness variable, hence the
  `?y` / `eq`.
- Without the two hrules, the obligations rung proposes only what a state owes.
  Root owes nothing, so the universe is empty and R = {∅}
  ([`naf_open.ein`](s1e2.4.1_probes/naf_open.ein)).

**Make q a decision** (added 2026-11-02). Over the same two candidates no
rewrite can be monotone and keep R, and that is provable: in a monotone
program dead is closed upward, so the alive set is closed under subsets, and
W3's alive set holds `{(p A), (q A)}` without `{(p A)}`. With more candidates
it can. [`dual_rail.ein`](s1e2.4.1_probes/dual_rail.ein) makes q a yes/no
attribute that every state must decide, and refutes only on a decided *no*:

```lisp
(import std.algebra :symbols (functional total-owed))
(relation q-val T Bool)
(is-a yes Bool) (is-a no Bool)
(functional q-val)            ; q is decided at most one way
(total-owed q-val is-a)       ; and it must be decided
(hrule guess-p () :match (is-a ?x T) :assert (p ?x))
(hrule guess-q () :match (and (is-a ?x T) (is-a ?v Bool)) :assert (q-val ?x ?v))
(rule bad () :match (and (p ?x) (q-val ?x no)) :assert (false))
```

```
$ ein solve …/s1e2.4.1_probes/dual_rail.ein
  states (k_s)      3
  lattice           monotone (the static check) — R is convex: no hole
  route             1, the alive down-set — L1 dead is upward-closed
  (region (model (q-val A no)) (model (q-val A yes)) (model (p A) (q-val A yes)))
```

R is W3's, one to one: `{no}` ↔ ∅, `{yes}` ↔ `{(q A)}`, `{(p A), yes}` ↔
`{(p A), (q A)}`. A state that has not decided q **owes** the decision; it is
not dead, and it is not in R. Every obligation is triggered by given facts and
every refutation reads decided values only, so the program is monotone and the
fast route's licence holds. This is how zebra writes every variable: a
functional, total attribute. The rewrite is mechanical for a relation the
search guesses. A derived relation needs its negative derived (completion),
which is not shown here.

## 4. `(not …)` conclusions too

[`not_conclusion.ein`](s1e2.4.1_probes/not_conclusion.ein) concludes no
`(false)`:

```lisp
(rule exclude ()
  :match  (and (is-a ?x T) (absent (q ?x)))
  :assert (not (p ?x)))
```

```
$ ein oracle …/s1e2.4.1_probes/not_conclusion.ein
  universe          1 candidate, 0 dead alone
  lattice           not monotone: 1 site (the static check) — no hole in this cube; …
  (region (model) (model (q A)))
```

At root `q` is absent, so root stores `(not (p A))`, and `(p A)` never even
becomes a candidate. In the node `{(q A)}` the absence is filled, but every
node is built on root's fixpoint and keeps root's `(not (p A))`. A `(not …)`
conclusion is therefore a refutation of `(p A)` decided while `q` was still
open, which is why the question names `(not …)` beside `(false)`.

**Where this meets P1e2.1b.** Whether `{(q A)}` should keep root's negative,
which decides whether `{(p A), (q A)}` belongs in R, is S1e2.1b.2's question:
is a node built on root's fixpoint (fork) or from scratch? *Forbid* would
refuse this rule outright. *Respect* leaves it to S1e2.1b.2. Nothing on this
page asks you to rule on fork or scratch.

## 5. Through a derived relation

The refuting rule need not read the `absent` itself.
[`via_hole.ein`](s1e2.4.1_probes/via_hole.ein):

```lisp
(rule derive-p () :match (and (s ?x) (absent (q ?x))) :assert (p ?x))   ; no refutation here
(rule clash    () :match (and (p ?x) (r ?x))           :assert (false)) ; no absent here
```

with hrules guessing `(s one)`, `(q one)` and `(r one)`.

```
$ ein oracle …/s1e2.4.1_probes/via_hole.ein
  states (k_s)      7
    minimal hole    {(r one), (s one)} — dead: (r one) (s one)
the cube   1 dead node with an alive superset
```

`{(r one), (s one)}` derives `p`, which clashes with `r`, so the node is dead.
Add `(q one)`: `p` is never derived, and `{(q one), (r one), (s one)}` is
alive. It is the same hole as § 2, but `clash` reads no `absent`, so a check
that looks at each refuting rule alone misses it. That is F2.

## 6. "Can still extend": where the line is drawn (F1)

Three readings, from coarse to fine. The counts are from the stage file's
census (`cargo run --release -p ein-infer --example refutation_census`):

| reading | *extendable* means | exposed |
|---|---|---|
| (a) eligible | the hypothesis generator may propose facts of this relation at all (S1e.2.3's warning) | 14 rules over 10 entries |
| (b) in D | the relation has candidates in root's actual universe, or is derived from one (the static check, which routes the modes today) | 13 rules over 9 entries |
| (c) per fact | some candidate, or a fact derived from one, matches the `absent`'s **pattern** (new code) | about 7 entries, four of them W3's |

Two programs show where the readings part:

- **(a) against (b).** `syntax/rule-forall-and-not.ein` has a rule over an
  eligible relation, but the program has no objects, so its universe is empty
  (n = 0). (a) flags it and (b) does not.
- **(b) against (c).** `features/05` activates `std.elim`'s `typecheck-arg-0`:

  ```lisp
  (rule typecheck-arg-0 (?R ?isa ?Dom)
    :match  (and (?R ?a ?b) (absent (?isa ?a ?Dom)))   ; here: (absent (is-a ?a House))
    :assert (false))
  ```

  `is-a` has candidates, so it is in D. But `ein solve -H` shows their shape:
  `(is-a Blue House-1)`, `(is-a Blue House-2)`, …, 30 of them, all membership
  between two objects. None can be `(is-a <x> House)`, so no commitment can
  fill this particular absence. (b) flags the program and (c) would not.

Under (b) and (c) the refusal comes after root is saturated, where the static
check already runs, and not at parse time.

## 7. The two answers on these examples

| example | *forbid* | *respect* |
|---|---|---|
| § 2, W3's `bad` | **refused**: a load error naming the replacements. Two rewrites keep today's answer (§ 3): the obligation plus hrules, which stays flagged with an owing hole, and q as a decision, which is monotone. W3's four register rows reopen until S1e2.2.5 ships the refusal | **legal**, answered by the cube. R = 3 states, which is right. W3's rows stay `fixed` |
| § 3, `closed_q` | legal | legal |
| § 4, `not_conclusion` | refused | legal. Whether a node keeps root's negative is S1e2.1b.2's |
| § 5, `via_hole` | refused only if F2 takes the derived case. Otherwise legal, with a dead hole | legal, answered by the cube |
| `features/05` | refused under (a)/(b) unless it adds `(solve :no-hypothesis (is-a))`. With that line it is monotone and exact: **32 states**, where today it is a partial 7 176 out of 2⁵⁶. Legal under (c) | legal, flagged, answered in part (7 176 states, a lower bound) |
| the corpus | 9 entries refused under (b), 12 if F2 takes the derived case. Five rewrites keep or improve their answer | nothing moves |
| the stdlib | nothing, if `features/05` closes `is-a`. Otherwise three `std.elim` rules need rewriting, and no rewrite keeping their meaning was found | nothing |

**What each one is, in one sentence:**

- **Forbid** is a language guarantee. A program the engine loads cannot refute
  from an absence that a commitment fills (fully so only with F2's derived
  case). So every refutation it does accept is safe to learn from, and the
  fast licence comes back. It costs corpus churn now. It also turns dead holes
  into owing holes, which P1e2.1b still has to define.
- **Respect** is an engine discipline. The shape stays legal, and the engine
  never generalises from a refutation that rests on such an absence: no
  skipped superset, no stored `(not h)`, no no-good. It costs nothing today,
  because the cube already learns nothing. It is a constraint on P1e2.1c's
  region search, which must not bring learning back on these programs, so
  they stay at 2ⁿ, or partial past n = 16.

**Evidence that bears on the choice, without deciding it.** M1f's S1f.10.8
recommended *forbid* unless the census found a legitimate rule that must
refute from an extendable absence. This census found none: every exposed rule
the cube catches has an obligation rewrite that keeps R. The cube sees the
hazard only on the four programs written to show it.
