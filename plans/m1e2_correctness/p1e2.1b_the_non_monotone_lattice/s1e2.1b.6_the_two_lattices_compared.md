So the page starts from the general case. For each property a program can
have, it says what that property lets the engine simplify. It is written for
a reader who needs R **as a whole**, not just its first node:

- a complete answer, with the provenance of its topology;
- the region's properties, studied to improve the theory (the ontology and
  its rules);
- a search over theories, for example for one that has a single solution.

**For a first solution the difference is smaller, but it is not zero.** A
node of R that has been found is checked by one saturation in either lattice.
*Finding* one, or claiming there is none, is different. Learning from a
refutation across a hole can prune every node of R:
`examples/lattice/synth/trigger_hole.ein` has 9 nodes in R, and `ein solve -e`
answers `Contradiction`
([S1e2.1a.8](../p1e2.1a_the_solution_region/s1e2.1a.8_region_to_program.md#the-fixtures-and-what-the-engine-answers-on-them)).

## The starting point: in general, R is its node set

The answer given 2026-10-16, recorded in
[Q-M1e2.7](../open_questions.md#the-rulings-and-the-questions-back-2026-10-16):
**yes.** In general R can be any subset of the 2ⁿ cube.

- S1e2.1a.8's synthesizer writes a program for any target region (2 100 random
  targets, 0 mismatches). The one exception is a dead ∅ under a non-empty R,
  which is S1e2.1b.2's fork-or-scratch question.
- There are 2^(2ⁿ) possible regions, so no description shorter than the set
  exists in general.

The set can still be stored **exactly and compactly** as a union of its
maximal sub-cubes, which the oracle already computes. That form is small when
R is regular and reaches 2ⁿ⁻¹ isolated points in the worst case (parity).

Each step down the ladder is licensed by a property the step above does not
have:

| step | licensed by | R is described by | certificate that a claimed R is R |
|---|---|---|---|
| general | nothing | the node set, or its maximal sub-cubes | every node classified: 2ⁿ saturations |
| convex | **no holes**, observed on the cube | the two lines: R = ⋃ [a … b], a minimal, b maximal, a ⊆ b | as above; the hole count is known only after enumeration |
| monotone | the **static check** says *Monotone*, before any search | the two lines, computed from **N** and **E** without visiting 2ⁿ nodes | N and E, one saturation per member, plus the static verdict |
| shape | which constraints the program states | restrictions only: min = {∅}; obligations only: max = {⊤}; both and well-posed: every component a point | as monotone |

Convex is the common non-monotone case. On 2026-10-16, 13 of the 154 corpus
regions the oracle computed were flagged non-monotone, and only 3 showed a
hole.

**The worked pair.** [`06_friends_tables.ein`](../../../examples/lattice/06_friends_tables.ein)
and its twin `06_friends_tables_everyone_sits.ein` are one seating problem
written two ways, and the page draws both:

| | everyone must sit (`total-owed`) | a group that sits owes its members' seats |
|---|---|---|
| monotone | yes | **no**: an obligation trigger |
| R | 8 seatings, no holes | 21 nodes (∅, the pair alone ×8, the trio alone ×4, both ×8), **166 holes** |
| lines | minimal = maximal = the 8 | minimal {∅}; maximal 14 |
| `ein solve -e` | the 8 | 8 of 21: it misses ∅ and the 6 maximal pair-only nodes |

The second is how a person states *if you come, you all sit*, and the user
wrote it that way on 2026-10-16. **Conditional obligations make trigger holes
as a matter of course**, so the page treats them as the common non-monotone
case and not as an exotic one.

## How to solve, in both cases (draft)

The user's three words, as the page will use them:

- **stable**: the answer is a function of the program alone. It must not depend
  on a lever, on interner ids, on rule order or on `--jobs`. That is the config
  principle.
- **proved**: the answer comes with a certificate that a second, simpler check
  accepts.
- **effective**: the cost grows with the size of the answer's description, not
  with 2ⁿ, wherever the case allows.

| question | monotone | non-monotone |
|---|---|---|
| **is R non-empty** (a first solution) | any sound search. One node found and checked by one saturation is the proof. Learned nogoods are safe | the same check proves a node found. A *no* needs care: learn only from cores that read no third-kind relation (taint the core), or a hole prunes R away |
| **the lines** | enumerate N and E, then dualise. The minimal line is E's alive members; the maximal line is the discharged complements of the minimal sets that hit every member of N. Prior art: MARCO-style MUS/MSS enumeration (Liffiton et al., *Constraints* 2016). Incremental monotone dualisation is quasi-polynomial in input + output (Fredman & Khachiyan, *J. Algorithms* 1996) | no duality. **Split on the guards.** Fix the truth of every ground third-kind read a commitment can flip (g of them). Inside each cell the program is monotone and has lines, and R is the union over the cells whose guess is consistent. This is the Gelfond–Lifschitz reduct's move (guess the negated atoms, solve the monotone remainder, keep it if the guess holds), so it presumes a stable reading, which is S1e2.1b.2's ruling. Cost: 2ᵍ × the monotone cost, with g ≪ n expected |
| **\|R\|, components, sub-cubes** | from the lines: sub-cubes, then inclusion–exclusion | per cell, then union, or enumeration |
| **states, not commitments** | the closed sets in R and their minimal generators (Q-M1e2.7 (e)). Formal concept analysis's closed sets and minimal generators (Ganter & Wille 1999) | classes by state, read node by node |
| **stable, how** | a node's state is unique. Output is ordered by rendered text, the candidate list is config-free, and a lever may only reorder or prune soundly | first rule the node semantics (S1e2.1b.2), then the same |
| **proved, how** | N, E, the static verdict | per cell: its guess, its N and E. Otherwise the full classification |
| **effective, how** | layer-by-layer growth of alive sets: zebra2 with every lever off enters 111 commitments (S1e2.1a.8, not staged). Saturation jumps over transient nodes. One representative per symmetry orbit, with the orbit sizes reported | g, not n, sets the exponent. When g is small the general case costs a constant factor over the monotone one |
