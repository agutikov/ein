## Context

**What a node is today.** [`region.rs`](../../../ein.rs/crates/ein-infer/src/region.rs)'s
§ What a node is: *"the fork route: root's fixpoint, the commitment's facts
written with hypothesis provenance, the saturation resumed and run to
quiescence"*. [`solution_semantics.md` § 1.5](../../../docs/kernel/inference/solution_semantics.md#15-commitment-node-state):
*"For a monotone program, building the state from scratch gives the same fact
set."* [S1e2.1a.1](../p1e2.1a_the_solution_region/s1e2.1a.1_the_oracle.md)
chose the fork route and compared the scratch route on monotone programs only.
On a non-monotone program *"a disagreement is evidence for P1e2.1b's
S1e2.1b.2, not a defect of either route"*. The user moved the question here on
2026-10-15:

> I propose to move non-monotonic solution question into phase p1e2.1b

**Why it is the phase's first ruling.** The node is the one thing every route
shares. [`ein_infer::explore`](../../../ein.rs/crates/ein-infer/src/explore.rs)'s
module docs: *"One node function. Every commitment any mode looks at is
`crate::region`'s own node."* The user ruled on 2026-10-16 that *"results must
be consistent: region is a region of oracle"*
([`walk_and_region.md` § 7](../p1e2.1a_the_solution_region/walk_and_region.md#7-two-rulings-meet-here)).
So whatever is ruled here becomes the oracle's node and every route's, and
holes, learning and the guard split are all stated over it.

## The question

> **On a program the static check flags, what is a node's state? Root's
> fixpoint with the commitment written in and the saturation resumed (fork);
> the program's facts with the commitment as given facts, saturated from
> nothing (scratch); either one checked so that no state counts whose facts
> rest on an `absent` the state falsifies (guards are premises); or is a
> program on which they can differ refused at load?**

| | what a node is | what it is known to change | composes with |
|---|---|---|---|
| **(A) fork, append-only** | `sat(sat(program) ∪ C)`, today's | nothing. W8's rows close `not-wrong` with the reason written, which is S1e2.2.6's third reading. L0 stays a property of the node | — |
| **(B) scratch** | `sat(program ∪ C)` | `stale-naf-fork`'s `{(q one)}` joins R. L0 holds only where scratch agrees with fork. Root is re-derived inside every node, at a cost the stage measures. On an unstratified program the fixpoint can depend on rule order, which (C) or (D) has to settle | (C), (D) |
| **(C) guards are premises** | (A) or (B), and a state holding a fact whose derivation's `absent` premise the state falsifies is not a solution | a node gets a third outcome beside dead and owing, so a sub-question follows: is it its own status, or counted as dead? | (A), (B) |
| **(D) refuse what cannot be stratified** | a load error for a program whose rule dependency graph has a cycle through an odd `absent` over D | `features/07` would be refused. `stale-naf-fork` is stratified and still needs (A), (B) or (C). M1f's [S1f.5.6](../../m1f_hypothesis_and_documentation/p1f.5_documentation_and_other/s1f.5.6_rule_priority.md) plans the diagnostic, so the dependency moves here or waits | (B), (C) |

**On a monotone program the options agree by the theorem**
([P1e2.1b § What non-monotone means](README.md#what-non-monotone-means-and-what-is-not)),
so the ruling binds flagged programs only, and the comparison over monotone
cubes is a check of the theorem's premise rather than evidence for an option.

**A recommendation, mine, conditional on the evidence:** (B) with (D), if the
stratification check refuses no program the corpus needs and scratch is
invariant on every stratified flagged cube. It is the reading under which a
node's state is a function of its commitment alone, and it is what the guard
split presumes. If either condition fails, the evidence says which other
combination is left.

## How it is measured

1. **Both routes, node for node.** Over every flagged cube S1e2.1b.1 lists,
   the register's W8 witnesses and S1e2.4.1's probes: each node's two status
   bits and its state under fork (`ein oracle --dump`) and under scratch
   (`utils/region.py --json`, the second route since S1e2.1a.1). Every
   disagreement is listed with the facts that differ and the site whose rule
   produced them. If `region.py`'s process per node is too slow, a library
   prototype replaces it. No flag reaches the prototype, since a node chosen
   by an option would be a lever that changes R.
2. **The staleness census.** On every node of those cubes, under each route:
   the facts whose primary derivation has an `absent` premise that the node's
   own state falsifies. `region::Node::absent_premises` reads the premises of
   a contradiction today, and the check over every fact is new.
3. **The stratification check.** The rule dependency graph over D, and every
   cycle through an odd `absent`, over every program in S1e2.1b.1's
   selection. It reports which programs (D) would refuse, by name.
4. **Invariance.** Scratch's R at `-j 1` against `-j 16`, under permuted
   interners (as `id_order_invariance` permutes them with `EIN_ID_SEEDS`), and
   under a reordering of equal-priority rules, on every flagged cube. A route
   whose R moves under any of these breaks the config principle there, and the
   option that needs it needs (C) or (D) as well.
5. **Cost.** Per-node wall and facts beyond root, fork against scratch, on
   every flagged cube and on the largest monotone cubes as the control.
6. **The three known cases read under each option**: the `-y` abort on
   `d3-unsat-core`, L0 on `features/12`, and the synthesizer's dead ∅.
7. **W8's two rows**: `right` computed under each option by the route that
   option defines. No hand derivation is left.

Every number goes on a dated page, `node_census.md`, in this phase's
directory, with the commands that re-take it.

### Task T1e2.1b.2.1 — Both routes, node for node

**Done 2026-11-02**, at `7a1353fc` with the example this task adds
([`node_census.md` § 1–3](node_census.md#1-the-headline)):

```sh
cargo run --release --manifest-path ein.rs/Cargo.toml -p ein-infer --example node_census               # 0.1 s
cargo run --release --manifest-path ein.rs/Cargo.toml -p ein-infer --example node_census -- --control   # 59 s
```

[`node_census`](../../../ein.rs/crates/ein-infer/examples/node_census.rs) is
`site_census`'s sibling and shares its loader. It reads each node twice: by
fork through `region::Nodes`, held to `region::compute`'s status bits on a
second load, and by scratch, the program's text with the commitment appended,
loaded and saturated from nothing. It reads both bits, every fact, and the
stale facts (T1e2.1b.2.2) of each. No route reads it and no command reaches it.

- **The flagged cubes**: 18 within the limit, 256 nodes. The routes give a
  different status on **2** nodes and hold different facts on **4**: `{(q one)}`
  on `stale-naf-fork` and its `-warn` twin (dead by fork, in R from scratch),
  and on `features/07` and `f07-fpoff` (in R both ways, the fork's state holding
  `(p one)` beside `(q one)`). Each is the fact `derive-p` derived at root under
  `(absent (q one))`, kept by the fork after the commitment falsifies its guard.
  These are exactly the four programs on which the site census found a site's
  rule firing at root. On the other 14, the nine with a hole among them, every
  node agrees on every fact. No node holds a fact only scratch holds.
- **S1e2.4.1's probes**: 13 within the limit, 206 nodes. One node differs, in
  its state: `not_conclusion`'s `{(q A)}`, by a `(not (p A))` root derived under
  `(absent (q A))`.
- **The control**: the 155 monotone cubes, 268 213 nodes, agree on every
  status and every fact. The fork read here is the oracle's node on every
  program of every run.
- **`region.py` was wrong on pair contradictions.** It tested for a `false`
  fact only, and called 12 of `d3-unsat-core`'s 32 nodes alive, where the
  oracle and both library routes call them dead (`X` beside `(not X)`). Fixed
  here: it now also reads `--json-summary`'s `region.root`.
  `region_dump.rs::the_oracle_and_the_per_subset_route_agree_node_for_node`
  runs it on `d3-unsat-core` too, and fails on the old line. After the fix it
  agrees with the library scratch on every flagged and probe node. So the
  library prototype replaced it not for speed (5–27 ms a node is fast enough)
  but because staleness needs provenance and the control needs 268 213 nodes.
- **Three programs written into the census** (`--written`), for readings no
  corpus program shows: the synthesizer's refused dead ∅, directly and through
  a derived positive, and `stratified_stale`, a stratified program whose
  scratch root holds a stale fact. No corpus file and no golden line is added.
