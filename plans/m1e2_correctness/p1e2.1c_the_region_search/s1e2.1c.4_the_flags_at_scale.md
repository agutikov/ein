## Context

**The flags are the user's four**, 2026-10-16: *"while with some flags can
simplify the task - e.g. look for any solution, or expect there is a single
solution - so k>=2 is a contradiction; or look for only maximal solutions, or
only for minimal solutions"*. They shipped at S1e2.1a.9 as `-n N`, `--single`,
`--maximal` and `--minimal`, on route 1 with a cut per mode, or on the cube for
a flagged program. Every one is held to the oracle by `explore.rs`'s
`every_mode_is_the_oracle`.

**The target** is [`solve_interface.md` § 3.2](../p1e2.1a_the_solution_region/solve_interface.md#32-a-monotone-program-each-modes-route)'s
*at P1e2.1c* column:

| mode | now | at P1e2.1c |
|---|---|---|
| `-n N` | layer order from ∅, stopping at the N-th distinct state | the obligation tree's leaves, in its own order, where L5 holds |
| `--maximal -n N` | the first member of R, then the climb | the same, over states |
| `--minimal -n N` | layer order, expanding owing nodes only | a tree leaf, then shrink it while it stays discharged |
| `--single` | ∅ ∈ R: the alive set. ∅ ∉ R: `--minimal`'s exploration, then a maximality check | the tree: owing-meets-dead closes branches, then the same maximality check |
| `--maximal --single` | climb to s, then route 1 over the alive nodes not under s | the state route |
| `--maximal` | climbing from every discharged node outside the maxima found so far | the state route: at most alive states × n |
| `--minimal` | route 1, expanding owing nodes only | duality, S1e2.1c.2: output-sized |
| describe | route 1, unchanged | S1e2.1c.2 |

**L5 is the new licence.** § 3.1: *"an owed instance's alternatives are
exhaustive"*, when the program is monotone and every fact that can witness the
instance is in H. *"An alive node owing an instance whose every alternative is
dead has no member of R above it. That is the user's owing meets dead, and it
ends a branch."* And: *"It is proved and held to the oracle at P1e2.1c before
any mode relies on it."* `explore::Licence` has no L5 today.

**The tree it licenses already exists**, in the walk's library:
`EIN_TRAVERSAL=tree`, M1d S1d.10.6's, in `solve.rs`, which no command reaches
since the switch. On `zebra2-obligations.ein` it exhausts in 9 enterings, 4
alive and 5 dead
([§ 3.4](../p1e2.1a_the_solution_region/solve_interface.md#34-what-it-costs)).
It declines on the hrule rung, so *"reaching `zebra.ein` itself needs L5's
precondition on the hrule rung, which is P1e2.1c's to prove"*.

**The interim cost, accepted until now**
([§ 7](../p1e2.1a_the_solution_region/solve_interface.md#7-decided-here-unless-the-user-objects)):
*"Between S1e2.1a.5 and P1e2.1c, zebra's `--single`, `--maximal` and
`--minimal` need `--region-budget 2^21` to certify."* And: *"No `--count`.
Until the state route exists, counting costs what describing costs … S1e2.1c.4
adds it if the transversals turn out to dominate describe."*

## Acceptance

- **L5, as a licence.** Its argument is written beside the code, under
  [`standard_of_proof.md`](../../../docs/kernel/standard_of_proof.md)'s rule 2:
  the argument holds while its premise is enforced, and the premise, *every
  fact that can witness the instance is in H*, is checked when the program
  loads. It is `explore::Licence`'s L5, printed in the `route` row when used,
  and held to the oracle on every program within the limit where it applies.
  On the hrule rung it is either proved and tested, or not used, and
  `zebra.ein`'s modes then stay on S1e2.1c.2's routes, written so.
- **Every mode on a monotone program has its route.** For each row of the
  table above: the route, its licences, the certificate it is entitled to and
  its cost, meeting the *at P1e2.1c* cell or saying why not. On a flagged
  program each mode's route, certificate and warning are what they are today,
  and a test says so.
- **§ 3.4 re-taken.** Its zebra and floors tables, with the *at P1e2.1c*
  column measured. Every measured count is under its derived bound where one
  exists. The *interim* note goes wherever the modes certify within the
  default budget.
- **No two modes disagree, and none disagrees with the oracle**:
  `every_mode_is_the_oracle`, `every_mode_at_four_jobs_is_every_mode_at_one`
  and `lever_invariance.rs`, extended to every new route and licence.
- **The walk's library, what the routes reuse.** For each route built here,
  which code of the walk's library it reuses (the tree, the `apriori` join,
  `oblgen`'s owed alternatives, or none), measured, and handed to S1e2.1c.5,
  which deletes the rest.
- **`--count`, measured.** Whether, once k_c is counted rather than
  enumerated, listing still dominates describe on any corpus program. If it
  does, a `--count` is drafted on real corpus programs, with answers computed,
  and put to the user (below). If it does not, § 7's *No `--count`* stands, and
  the page says why.
- **Every answer exits 0**, and every listing stays under the 100-line cap,
  with the rest in `--dump-answer`, as ruled.
- **The goldens it moves are named before they move**: `read_out_examples.md`
  and `region_modes.rs` wherever a mode's route or work changes, and
  `help_shape.txt` if a flag is added.
- **The docs:** `solve_interface.md` § 3.1 (L5 proved), § 3.2 (the column met)
  and § 3.4 (measured), and the `configuration.md` census if a flag is added.

## The question it may put to the user

**`--count`: a flag, or not?** Asked only if the measurement says listing
dominates describe somewhere. The options are (a) add `--count`, which prints
k_s and k_c with no listing, shown first on the corpus programs where it would
matter, or (b) none, which is § 7's ruling, standing. **No recommendation
before the measurement.**

## How it is measured

```sh
ein solve FILE MODE -s                                   # per mode, its route, licences and work rows
cargo test --release -p ein-infer --test explore         # every mode against the oracle
EIN_CORPUS_SLOW=1 cargo test --release -p ein-cli --test lever_invariance
```

§ 3.4's tables are re-taken with § 3.4's own commands on the release build,
with `-j` stated, the commit and the date. The walk's tree is measured on the
same programs, `EIN_TRAVERSAL=tree` through the library, for the reuse
column.
