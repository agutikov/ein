# S1e2.1.2 — Every answer a file

**Phase:** [P1e2.1](README.md) (Seeing the answer)
**Estimate:** 1.5 days
**Depends on:** nothing.
**Blocks:** [S1e2.1.4](s1e2.1.4_a_model_you_can_read.md), whose grid and
KB-diff are drawn from these files, and [S1e2.1.5](s1e2.1.5_every_artefact_rendered.md).

## Context

What a solve answered is, today, three partial copies:

- **stdout.** The verdict block and, with `-p` / `-P` / `-f`, each model's
  facts. Readable, not loadable, and gone with the terminal.
- **`--json-summary`.** `verdict.solutions[]` is `{facts, goal_bindings}` per
  model, `open_states[]` the same per open state, and `unsat_core` a list of
  s-expressions. It is complete about *what* and silent about *how*: it does
  not say which commitment reached a model, at which layer, or what a refuted
  commitment's core and learned clause were.
- **`--dump-states DIR`.** The `MonotonicDumper` tree:
  `00_root_initial.ein`, `00_timeline.jsonl`,
  `layers/layer_NN_{pre,post}.ein`, `summary.json`. It is *root* per layer,
  so it is a dump of the search's frontier, not of its answer.

The engine holds the rest. Under `store_lattice`, which `--trace` and
`ein render lattice` already set, `Solved.proof` is a `LatticeProof`:
`solutions: Vec<SolutionRecord>` (each with `commitment`, `kb`, `firings`,
`layer`, `owes`), `dead_commitments: Vec<DeadCommitment>` (`commitment`,
`unsat_core`, `learned_clause`, `layer`, `kind`), `alive_at_end`,
`learned_nogoods`, `root_firings`
([`solve.rs`](../../../ein.rs/crates/ein-infer/src/solve.rs) § Recorded shapes).
Nothing writes it out.

## The flag

`ein solve --dump-answer DIR`, additive like every artefact flag (stdout,
stderr and the exit code unchanged, with
[`defined_behaviour.md` § 4.4](../../../docs/kernel/defined_behaviour.md)'s
artefact contract and its `error: --<flag> <path>: <os error>` shape):

```
DIR/
  program.ein            the source as loaded, imports resolved (the inlining route
                         stdlib/README.md documents, which a test already round-trips)
  root.ein               the KB after root saturation, before any hypothesis
  answer.json            == --json-summary, so one directory is the whole run
  models/NN.ein          one per recorded solution: the state, loadable
  models/NN.json         {commitment, layer, goal_bindings, owes, added: [facts not in root]}
  open/NN.{ein,json}     the same, per open state
  refuted/NN.json        {commitment, layer, kind, unsat_core, learned_clause}
  alive_at_end.json      the frontier the depth cap left, when it left one
```

`NN` is the verdict's branch order, the order `read_out` already uses, so
`models/02.ein` is "model 2/3" on stdout. `added` is the field the KB-diff
renderer needs and the one a reviewer reads first: **what this commitment
made true that root did not**.

## Acceptance

- Every file loads or parses. Each `models/NN.ein` **re-saturates to
  itself**: `ein saturate` derives no fact and no `(false)`. This is the
  fixpoint check. A recorded state that is not a fixpoint of its own rules is
  exactly the class [CO-M1](../../../docs/history/m1e_review_processing/README.md#the-findings)
  fixed, and the check makes it observable per file. Whether a re-*solve* of
  the file also answers `Solution` with itself as the one model is a stronger
  claim, because the generator may propose again on a loaded state. Measure it
  and write down which holds.
- `answer.json` byte-identical to `--json-summary` on the same run, held by a
  test rather than by a comment.
- **No answer moves.** `--dump-answer` sets `store_lattice`. That is already
  set by `--trace` on every corpus `trace` run, so the search is not new.
  `corpus_exits.txt` and `corpus_shapes.md5` byte-identical, and a test runs
  three corpus programs with and without the flag and diffs the summaries.
- `configuration.md`'s option table and `help_shape.txt` gain one row each,
  moved by `EIN_BLESS=1` deliberately and named in the commit.

## Tasks

### Task T1e2.1.2.1 — Writer

In `ein-render::dump` beside `MonotonicDumper`, as a function over
`(&Solved, &Terms, &Program)` and **not** a `Dumper` impl. It writes after the
search, from the proof, so it cannot perturb the search.
`MonotonicDumper`'s hooks run during the search, and that is the distinction
MA-M2 wrote down at `LatticeProof::root_firings`.

### Task T1e2.1.2.2 — `added`, and the commitment's spelling

`added = facts(model.kb) \ facts(root)`, positive and negative both, sorted the
way `solutions[].facts` is. The commitment is printed as the facts it
asserts, the spelling `00_timeline.jsonl`'s `commitment` field already uses,
not as a `CanonicalSetId`.

### Task T1e2.1.2.3 — Tests

The fixpoint re-saturation over every register case and over `zebra2` and
`zebra2-minus-15 -e -m 3` (32 models). The `answer.json` identity. The
empty-path refusal (exit 2) and an unwritable-dir refusal (exit 1), in
`artefact_contract.rs` beside the other five.

## Notes

- **Why not extend `--dump-states`.** It is a different object, root per
  layer, written during the search, and five tests and a page describe it as
  that. A flag that sometimes means *the frontier* and sometimes *the answer*
  is the shape `SE-M2` removed from the summary.
- **The tree traversal.** Under `EIN_TRAVERSAL=tree` there are no layers and
  no `dead_commitments` learning
  ([`configuration.md` § What `EIN_TRAVERSAL=tree` reports](../../../docs/kernel/configuration.md)).
  The writer writes what the proof has, and `refuted/` may be empty there.
  That is stated in the page, not hidden.

### The finding: `--trace` emptied the summary's `owes.models`

`the_flag_moves_no_answer` failed on its first run: the summary moved. In
`ein_infer::solve`, `run.proof()` **moves** the recorded nodes out of
`lstate`, and the `OwesReport` was built from `lstate.nodes` *after* it. Every
run that keeps a proof therefore reported `owes.models = []`. Before this
stage that was every `--trace` run, and a run without `--trace` reported each
model's tally. Reproduced at `1e0981d` with `--trace` alone on
`tree-dead.ein`: one tally without the flag, `[]` with it. An artefact flag
moved another artefact. Nothing pinned the summary of a `--trace` run, and the
corpus's `solve --trace` cells bank only an exit code. Fixed by tallying
before the proof is taken, and the comment there says why. No answer moves:
`owes.models` is not part of the verdict.

### Decisions the stage text left open

- **Where root comes from.** `Solved` did not hold it. `LatticeProof` gains
  `root_initial: Vec<FactId>`: root's fact ids at the `root_initial` hook, after
  root saturation and before the search's own root writes. They are copied
  under `store_lattice` and nothing is forked. The writes after that point
  (kill cache, writeback, forced positive) get a file of their own,
  `root_writes.json`, because W1, W2 and W12 turn on exactly those.
- **What makes a state file loadable.** The program, inlined, followed by
  every state fact except the program's own `(relation …)` declarations. The
  loader refuses a second declaration, which is why `--dump-states`' snapshots
  do not load (S1e2.1.1's finding). Provenance keywords are kept and load back.
- **`open/` holds every owing record**, with `reported: false` when the answer
  is models. The read-out drops those, and a reviewer wants them.
- **One summary for two sinks.** With `--dump-answer` alone, the summary is
  built with the event stream off, so `--events` does not narrate a summary
  nobody asked for. That is what lets the stream be identical with the flag
  and without.
- **The directory is made before the search** (exit 1 if it cannot be), as
  `--dump-states`' is. `defined_behaviour.md` § 4.4 now names both.
  **`.einb` is refused** (exit 2: no source to head a state file). A **budget
  cut** writes `answer.json`, `program.ein` and an `index.json` saying
  `Aborted`. A **second dump** into a directory whose `index.json` names this
  format clears `models/`, `open/` and `refuted/`, and nothing else is ever
  deleted.
- **`models/NN.json` carries `facts`**, the whole state in the summary's
  spelling, beside `added`. The order test needs it, and S1e2.1.4's grid does
  too.
- **The 32-model check is nightly's.** At ~42 s in the dev profile it is not a
  per-commit cost. `nightly.yml` runs `answer_dump` under `EIN_CORPUS_SLOW=1`
  beside `corpus_cli`.

### Shared rather than copied

The summary's model spelling (`facts`, `bindings`, `binding_value`,
`owes_block`) moved from `ein-cli/src/summary.rs` into
`ein_render::dump::answer` as `facts_json`, `bindings_json` and `owes_json`,
and the summary calls them. One implementation of how a model is written down
is what makes `models/NN.json`'s `facts` comparable with
`verdict.solutions[].facts` by `==`. `summary::text` is now the summary's
bytes for both sinks.

### Cost

On `zebra2-minus-15 -e -m 3`, 25.5 s of solve and ~0.2 s of dump, **56 MB**,
nearly all of it `refuted/`'s 11 577 files.

### Carried forward

S1e2.1.5 still plans to render `--dump-states`' snapshots *"with `ein render kb`
on the snapshot file, which loads as a program"*. They do not load. The model
and root files here do, and S1e2.1.3's `render kb --state` reads this dump.
