## Context

Q-M1e.20 counts **two** artefacts that are produced, tested and unreachable:
the `LatticeDumper` tree and `ein_render::kb_dot`. `utils/README.md` §
Renderers counts a third, `ein_render::ir_dot`, the program as written. Its
reason for declining to reconnect any of them was right for a `utils/`
clean-up: *"a decision about the shipping surface, not one a `utils/` clean-up
should take."* This stage is that decision, taken because the question Q-M1e.20
ended on, *who wants these?*, now has an answer. The reviewer does, and the
reviewer is exactly the second consumer the question named: *a reader chasing
a rule that will not fire, for whom the flag is small*.

| renderer | what it draws | pinned by | door today |
|---|---|---|---|
| `ein_render::ir_dot::to_dot` (`DotOpts { rule_mode, trace_view, levi }`) | the program **as written**, one subgraph per form: ontology UML-ish, facts compact or Levi, the query | `dot_wellformed.rs` | none. `ein ir dot` went in P1.11 (`8378ad7`) |
| `ein_render::kb_dot::to_dot` (`KbDotOpts { colour_by, include_types, include_instances, since, name }`) | one digraph over a **KB**, entities fused across forms, `since` drawing what a step added at `penwidth=3` | `dot_wellformed.rs` | none. `ein kb dot` went in the same commit |
| `ein_render::dump::LatticeDumper` | every commitment tested at every layer, with its firings: `enterings/`, `proof_summary.json` | `golden_dump.rs`, `dump_parity.rs` | none. `--dump-states` builds `MonotonicDumper` |

## The surface

```
ein render program <file> [--levi] [--rule-mode sidebyside|overlay]
ein render kb      <file> [--state root|model:N|open:N] [--since root]
                          [--colour-by relation|origin|none] [--no-types] [--no-instances]
                          [solve flags: -e -m -L … when --state names a model]
ein solve --dump-lattice <DIR> …
```

- **`render program`** draws the parse, before any load or saturation. It is
  what a reviewer reads first, and it is the only view that shows a program
  the loader refuses: `examples/broken/` becomes viewable.
- **`render kb --state root`** (the default) draws the KB after root
  saturation. **`--state model:N`** runs the solve with the given flags and
  draws model `N`, with `--since root` (the default for a model) emboldening
  what the commitment added. That is the transition highlight `kb_dot`
  already implements and nothing has ever asked for.
- **`--dump-lattice`** wires `LatticeDumper::new(Some(dir))` into `make_dumper`
  in [`ein-cli/src/solve.rs`](../../../ein.rs/crates/ein-cli/src/solve.rs)
  beside the three it already chooses between, with `store_lattice = true`.
  It is mutually exclusive with `--dump-states` (one `dumper` per solve). The
  pair is refused at exit 2 with a reason, not silently resolved.

## Tasks

### Task T1e2.1.3.1 — `render program`

`parse` → `ir_dot::to_dot` over every top-level form, with `DotOpts` from the
flags. No load, so no imports are resolved. A `--resolve` that inlines them is
a follow-up only if the review asks for it, because the stdlib's forms would
drown the program's own.

### Task T1e2.1.3.2 — `render kb --state root`

`load` → root saturation → `kb_dot::to_dot`. Measure the node count on
`zebra2` and write it on the page. If it is wallpaper, `--relation R`
(repeatable) is the filter, and it is S1e2.1.4's business to choose the
default view, not this stage's.

### Task T1e2.1.3.3 — `render kb --state model:N|open:N`

After S1e2.1.2: reuse its `store_lattice` solve and pick the `N`th record in
branch order. An `N` past `k` is exit 2 naming `k`. A `Contradiction` has no
model, so `--state model:1` there is exit 2 with the verdict named. The
refutation is `--trace`'s to draw.

### Task T1e2.1.3.4 — `--dump-lattice`

The wiring, the exclusivity refusal, and one test that the CLI tree equals the
library tree `golden_dump.rs` already pins for the same program.

## Notes

- **Why the CLI and not a library call** (Q-M1e.20's option b). The review
  bundle is a script, and a script reaches the engine through the binary.
  That is `utils/`'s rule since S1a.10.4: every script names `$EIN_BIN`.
  A library call would need a second Rust binary in `utils/`, which is the
  shape the repo has avoided.
- **`ein kb` already exists** under the `einb` feature, for the `.einb`
  container. That is why the KB view goes under `render`, which is the verb
  for DOT, and not under `kb`, which is the verb for the cache.
