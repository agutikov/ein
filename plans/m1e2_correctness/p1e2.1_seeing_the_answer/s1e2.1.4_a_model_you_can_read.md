# S1e2.1.4 — A model you can read

**Phase:** [P1e2.1](README.md) (Seeing the answer)

**Depends on:** [S1e2.1.2](s1e2.1.2_every_answer_a_file.md) (a model as a

**Blocks:** [S1e2.1.5](s1e2.1.5_every_artefact_rendered.md).

## Context

`zebra2`'s unique model is **444 facts**
([S1f.5.5](../../m1f_hypothesis_and_documentation/p1f.5_documentation_and_other/s1f.5.5_nl_required.md)'s
register census). A person checks it as a **5 × 5 grid**, the table on
Wikipedia, and nobody checks 444 facts. Every wrong-answer case is small
enough to read as facts, but the review is a comparison of the engine's model
set with the right one, and two fact lists side by side are a diff a person
does badly.

Three renderings, by what the reviewer asks:

| question | rendering | built from |
|---|---|---|
| *is this model right?* | **the grid**, where the program's declarations license one: rows are the objects of an anchor type and columns are the functional / bijective attributes onto it, one cell per value | the model's facts plus the program's `(functional …)` / `(bijective …)` declarations, the licence [`model_set_census.py`](../../../utils/model_set_census.py) already reads off the models to collapse `(R a ·)` into one variable |
| *what did the hypotheses do?* | **root + added**: `kb_dot` with `since = root`, so the commitment's consequences are bold and root is context | `models/NN.json`'s `added`, and `render kb --state model:N` |
| *which model is wrong, and where?* | **the set diff**: models missing from the engine's set, models it has that are not models, and for a pair that nearly match, the per-fact difference | the register's `right.models` against `answer.json` |

The grid is the non-NL half of what
[S1f.5.5](../../m1f_hypothesis_and_documentation/p1f.5_documentation_and_other/s1f.5.5_nl_required.md)
wants: a model a person can read without reading facts. It should not invent
a second register for the same object, so the anchor-type choice is written
once, here, and S1f.5.5 cites it.

## Acceptance

- `ein solve --models grid` beside `list` and `key`, read by every arm that
  prints models, `Solution` included, where `key` is read by `Ambiguity`
  alone. Where no licence exists it says so in one line and falls back to
  `list`. That is `key`'s own *"unaffordable → print the models"* precedent.
- On `zebra.ein` and `zebra2.ein` the grid **is** the published table,
  asserted against `acceptance.rs`'s `GRID` constant (the 25 published cells
  Q8's answer already pins both encodings to), so the renderer is checked
  against the same independent source as the solver.
- The set diff is a library function in `ein-render::models` with unit tests
  on three shapes: a missing model, a spurious model, and a model that
  differs in one fact. The bundle script calls it through
  `ein solve --models diff:<FILE>` or reimplements nothing. The stage decides
  which, and writes the decision down.
- No golden moves. `list` stays the default, for the reason `key`'s stage gave:
  it is what `ein solve` has always printed.

## Tasks

### Task T1e2.1.4.1 — The licence and the anchor

Which type is the row: the codomain shared by the most bijective
declarations (`House` in `zebra2`, carried by every `*-loc`), and in a tie
the first declared. Write the rule, run it over every corpus entry with a
`Solution` or `Ambiguity`, and **list the entries where it picks something a
person would not**. That list is the stage's honest boundary.

### Task T1e2.1.4.2 — The grid renderer

Markdown table out (the bundle is markdown), with the same text a terminal
gets. A cell with two values is a defect in the model or in the licence, and
it is printed **as** two values, never resolved.

### Task T1e2.1.4.3 — The set diff

Models are compared as positive fact sets minus root
([`solution_semantics.md` § 3](../../../docs/kernel/inference/solution_semantics.md),
*a model is the positive part minus the positive initial KB*), and the diff
says which definition it used. Matching is by equality first, then nearest
by symmetric difference, so *spurious + missing* that differ by one fact
reads as one wrong fact rather than as two unrelated models.

## Notes

- **Not the determining key.** `--models key` answers *how do these models
  differ from each other*. The grid answers *what is this one model*. Both
  are wanted, and on an `Ambiguity` the bundle prints the key above the
  grids.
- **Open states** are rendered the same way plus their `owes` line. A grid
  with an empty cell where an obligation is owed is the clearest picture the
  `Open` verdict will ever have.
