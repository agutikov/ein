## Context

The inventory behind P1e2.2 was assembled by reading: question entries,
probe files, fixture headers, hand derivations. Each right answer rests on
a definition the user ruled on 2026-08-28
([Q-M1e.6](../../../docs/history/m1e_review_processing/open_questions.md#q-m1e6--what-is-a-solution-and-what-is-a-model):
a solution is a saturated, consistent state in which every remaining
hypothesis is inconsistent; a model is its positive part minus the positive
initial KB). Several cases are wrong **only** under that definition, and were
right under the P1.5b mode contract their fixture headers still describe.
`lattice/02`'s header says *Expected verdict: Contradiction*, and the ruling
makes it three solutions.

So the review is not a formality before the fixing starts. It is the last
cheap place to disagree with a case, a right answer, or the ruling itself.

## Acceptance

- **Every register row carries the review's verdict**, one of:

  | verdict | what it does to P1e2.2 |
  |---|---|
  | **confirmed** | the stage runs as written |
  | **right answer corrected** | the register's `right` block changes and the stage file is edited before it starts |
  | **not wrong** | `status = "not-wrong"`, the stage is withdrawn with the reason in its file, and the witness's header comment says so |
  | **split** / **merge** | rows and stages renumbered **before** any of them start. Ids are sticky only once a stage has run |

  plus the date and, where the reviewer wrote one, a sentence.
- **Every fixture header that contradicts the ruled answer is corrected**,
  `lattice/02`'s first. It is a comment, so no golden moves, but a header is
  the first thing the next reader trusts.
- P1e2.2's README table and stage files match the register, row for row.
- Anything the review found that is **not** in the register, such as a
  wrong answer noticed on a non-register page, gets a row and a stage, or
  a written reason it does not.

### How to read it

Start at **`build/review/README.md`**. Its table has one row per register row
and a *differs in* column that says what the right answer disagrees with
(verdict, `k`, models, core, a qualifier, or *a reading*). Each case page opens
with the case and the two answers side by side. Then:

- **§ 2 The problem**: the witness's header, which carries the hand
  derivation, and the program as graphs. Check the right answer here first.
- **§ 3 / § 4** put the wrong run, the control and the twins beside the right
  answer, and diff each run's models against it.
- **§ 5 Where it went wrong** links the register's `look_at` pointers into
  each run: the layer, the entering, the root write, the event kind.
- **§ 6** has every artefact of every run, two clicks away. Each run's
  `run.md` reports its five cross-checks; one of them, on `pets.ein`, found the
  inventory's S2 without being told.

The pages are markdown with SVG images. Opening one in VS Code's preview and
one on GitHub is also this stage's check that both viewers draw them.
