## Context

A synthetic instance is **an Ein program first and a text second**. The
generator builds the program — ontology, the stdlib theory it imports and
the activators it asserts, the instance facts, the query — certifies it with
the kernel, and only then realises the English from the facts. That order is
what makes every promise of C2 cheap: *exact ground truth* is the kernel's
verdict, *the exact formal theory* is the program, *controlled difficulty*
is the generator's arguments, *controlled ambiguity and contradictions* are
one clue deleted or one clue added. The repo already has one generator of
this shape, one family wide: [`gen_zebra2_variants.py`](../../../examples/gen_zebra2_variants.py)
derives `zebra2-minus-15.ein` (32 models) and `zebra2-bad.ein` (a
contradiction) from `zebra2.ein` by removing one `:source`d fact and adding
one — *exactly one `:source`d fact, an identical schema + rule set*, the
invariant its docstring pins — and this stage generalises it to eight
families and to arbitrary size.

### The three verdict classes, by construction

| class | how the generator makes it | what `meta.json` records | the ground truth |
|---|---|---|---|
| **unique** | draw a full model (a permutation, a total order, a placement); emit clues true of it, one at a time, in a random order, until `ein solve -e` says `k = 1 ∧ exhausted`; stop — the clue set is minimal-by-construction only if the generator then tries removing each clue and keeps the ones whose removal raises `k`, which is the *minimal* flag and is optional and recorded | `answer.bindings` from the summary | the model |
| **ambiguous** | take a certified `unique` instance and delete one clue (the old acceptance criterion 3 — *a deleted word yields gaps* — as an instance); certify; record `k`, which is now **≥ 2 and known** | `answer.k`, and the sorted `solutions` digest | the model set |
| **unsat** | take a certified `unique` instance and add one clue false of its model — chosen so the contradiction is *local* (two clues) or *deep* (a chain), which is a knob; certify; record the unsat core the kernel reports | `answer.core` — the source facts in the kernel's core, with their `:source` spans | the core |

The gold verdict is **certified, not asserted**: an instance is admitted only
when its `-e` run finished with `exhausted = true`. An instance whose run
hits a cap — `Contradiction` with an empty core and `exhausted = false`, the
[Q-M1d.6](../../m1d_satisfiability/open_questions.md#q-m1d6--may-contradiction-be-said-with-exhausted--false)
signature, or an `Aborted` under `--max-time` — is **not admitted**, is
logged with its knobs, and the log is a measurement of where the kernel's
own scaling curve ([P2.7](../p2.7_failure_scaling_generalization/README.md),
S2.7.2) begins for that family. Nothing about the benchmark depends on M1d
landing; something about its upper size does, and the log says how much.

### The knobs

C4's list, as generator arguments, every one recorded in `meta.json.knobs`:

| knob | what it varies | family it applies to |
|---|---|---|
| `entities` | the size of the domain(s) | all |
| `relations` | how many relations the text uses | all |
| `chain_depth` | the longest derivation the answer needs | deduction, ordering, graph, temporal |
| `branching` | alternatives per choice point before pruning | attribute matching, spatial |
| `density` | clues per entity — from under-determined to over-determined | all |
| `irrelevant` | statements true of the model but unused by any derivation (K5's seed) | all |
| `paraphrase` | which of the ≥ 3 surface templates per statement type is used | all |
| `implicit` | whether a relation is stated or must be inferred (*immediately left* stated, *left* implied) | ordering, spatial |
| `model_count` | the target `k` for the `ambiguous` class | all |
| `distance` | sentences between two clues one deduction needs | all |
| `steps` | the number of transitions | object tracking |

### What "canonical theory" means when the stdlib has none

Six families instantiate a `std.*` module by activators and the program's
theory part is a list of imports and property facts. **Object tracking and
temporal have no module**, and the generator writes its rules into
`gold.ein` — state transitions for the one, an Allen fragment for the other —
under the `;; theory — canonical` comment the anchor uses. Those rules *are*
the canonical theory: constraint precision / recall counts them, G9 lists
them as *not in the library*, and a formalizer that synthesises an equivalent
rule set is scored by what it derives, not by its text
([S2.5.3](../p2.5_harness/s2.5.3_metrics.md) defines the unit). If the
milestone ever grows `std.state` or `std.allen`, it is a recorded kernel
change and a G9 condition ([P2.3 § Risks](README.md#risks)), and the
generator's rules stay as the reference.

### The unit of constraint precision / recall

The gold set for H2 is the instance's **fact forms with `:source`** plus its
**activator forms** (and, for the two families above, its rule forms), each
as canonical text — the `ein-ir` dump, whitespace-normalised, `:source`
stripped. A predicted program's set is computed the same way. Precision and
recall are set arithmetic over those; a generated auxiliary relation or
rule that derives the same closure but is textually different is a *recall
miss on the form* and a *closure hit* — both are reported, and the second is
the one that matters for the two synthesis families.

## Acceptance

- Eight generators under `einaf/benchmark/gen/<family>.py`, one entry point
  `einaf bench generate --family F --class C --seed S --knobs …`, each
  producing the three-file instance of [S2.3.1](s2.3.1_families_and_seed_set.md).
- Determinism: the same arguments and seed produce byte-identical
  `gold.ein` and `text.md`; a test holds it per family.
- Every admitted instance is certified (`exhausted = true`) before it is
  written, and the rejected ones are logged with their knobs under
  `benchmark/rejected.jsonl`.
- ≥ 3 surface templates per statement type per family, chosen by the
  `paraphrase` knob; a test asserts the templates realise to distinct
  strings that all contain the `:source` span the fact cites.
- The attribute-matching generator reproduces `zebra2-minus-15.ein` and
  `zebra2-bad.ein` from `zebra2.ein` — `gen_zebra2_variants.py --check`'s
  invariant, kept.
- A sample of admitted instances (stated size, stated seed) is re-certified
  by the gate: `einaf bench check` over the sample is green in CI.

## Tasks

### Task T2.3.2.1 — The generator frame

`einaf/benchmark/gen/frame.py`: draw a model → emit a program → certify
through `ein solve -e --json-summary` → derive the three classes → realise
the text → write the directory. The frame owns the certification and the
admission rule; a family module owns the model, the clue vocabulary, the
theory part and the templates.

### Task T2.3.2.2 — Attribute matching first

Port `gen_zebra2_variants.py` into the frame: the permutation model, the
Zebra clue vocabulary (`co-located` / the typed `*-loc` relations — both
encodings, since the repo keeps both to tell general reasoning from an
encoding's artefact), `std.bijection` / `std.slots` as the theory part.
Check against the anchor triple; the `--check` invariant becomes a test.

### Task T2.3.2.3 — The six stdlib families

Logical deduction and ordering (a total order; `transitive`, `includes`),
spatial (two orders, `converse`), set / category (`is-a`, disjointness), graph
(an edge list, `transitive` / `symmetric`), and the `ambiguous` / `unsat`
derivations for each.

### Task T2.3.2.4 — The two synthesis families

Object tracking (a state sequence; `steps` knob; the transition rules as
the canonical theory — written once, per family, in the generator, and
copied into every `gold.ein`) and temporal (intervals; an Allen fragment —
`before`, `meets`, `overlaps`, `during` — as the canonical rules).

### Task T2.3.2.5 — The realiser

Per family, ≥ 3 templates per statement type, EN; the `:source` string is
the realised sentence, so the span check is exact. Irrelevant statements
(`irrelevant` knob) are realised from facts of the model that no derivation
uses — the generator knows which, because it knows the model.

### Task T2.3.2.6 — The rejected log and the size ceiling

`benchmark/rejected.jsonl`; and, per family, the first knob setting at which
the kernel fails to certify within the default caps — one table, handed to
[P2.7](../p2.7_failure_scaling_generalization/README.md) S2.7.2 as the first
point on the solver's curve.

## Notes

- The `minimal` flag (a clue set with no redundant clue) costs one `-e` run
  per clue and is worth having for the `density` knob's low end; it is
  recorded, never assumed.
- A generator is also a formalizer's *oracle*: F13's *IR + known theory*
  condition ([S2.6.4](../p2.6_ablations/s2.6.4_representation_ablations.md))
  is this stage's `gold.ein` with the instance part replaced by the model's
  output.
