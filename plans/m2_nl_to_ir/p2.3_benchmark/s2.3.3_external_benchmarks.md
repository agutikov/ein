# S2.3.3 — External benchmarks: adapters

**Phase:** [P2.3](README.md) (The benchmark — Stage C)
**Depends on:** [S2.3.1](s2.3.1_families_and_seed_set.md), the instance format and metadata every adapter
writes; [S2.1.1](../p2.1_kernel_as_instrumentation/s2.1.1_tree_and_outcomes.md), the package. Not on
[S2.3.2](s2.3.2_generators.md): an external instance has no generator and no canonical program, which is the
whole difference between the two halves. It needs the network, for public downloads only.
**Research plan:** [`EinAf.md` § Stage C](../EinAf.md#stage-c--construct-a-heterogeneous-benchmark),
[C2](../EinAf.md#c2-use-both-external-and-controlled-synthetic-tasks): *external benchmarks provide ecological
validity*.

## Context

The synthetic half of the benchmark has an answer known by construction and no claim to being English anyone
wrote for a reason. The external half is the reverse: published tasks, published numbers to stand beside, a gold
**answer** and **no gold theory**. So constraint precision and recall are undefined on it, faithfulness falls
back to [Q-M2.3](../open_questions.md#q-m23--what-is-the-unit-of-faithfulness-without-a-gold-theory)'s judge,
every adapter records which metrics an instance supports, and no table mixes the two halves without saying so.

**None of it is in the tree today**: no file of BBH, CLUTRR, ProofWriter or FOLIO, and no licence or version of
any recorded anywhere ([audit](../analysis/audit_p2.3.md) § B.5). The sources are the ladder of
[F13](../../followups/f13_puzzles_beyond_zebra/ideas.md): BBH's `logical_deduction`, then
`tracking_shuffled_objects`, then CLUTRR, FOLIO and ProofWriter, each chosen there for what it stresses that
Zebra does not. [`docs/lib/12`](../../../docs/lib/12-llm-and-reasoning-benchmarks.md) catalogues BBH in its § 1
and ProofWriter and FOLIO in its § 3 (ProofWriter: *closest in spirit to Ein's three task classes*); CLUTRR is
not in that catalogue (audit § A.3, row 27), and its reference is recorded with its source here. ARC is out by
the user's criterion in F13, text only; its difficulty is rule induction, which is
[F7](../../followups/f7_rule_induction.md)'s subject.

### What an adapter is

A module of the package and two subcommands, one source each.

- **`einaf bench fetch SOURCE`** downloads the source's published files from the address its record names into
  a directory git ignores, by default `build/einaf/external/<source>/`, verifies each file's digest and refuses
  to overwrite a verified file. A run that needs the data is given that path, as it is given the model's file.
  The fetch is a plain download under a generic client name: it sends nothing of this repository, uses no
  account and uploads nothing.
- **`einaf bench adapt SOURCE`** reads the fetched files and writes, for each item it selects, an instance in
  [S2.3.1](s2.3.1_families_and_seed_set.md)'s format with no canonical program: the text, and the metadata with
  `source.kind: "external"`, `gold_by: "source"`, the gold class and short answer, and `supports` without the
  metrics that need a gold theory. It writes them beside the fetched files, not into the tree.
- **In the tree** a source is two files under `einaf/benchmark/external/<source>/`: `SOURCE.json`, its record
  (the address, the version or commit, each file's digest, the licence as the stage read it and where it read
  it, the day fetched, the count of items, the published numbers it is quoted for), and `items.jsonl`, the ids
  of the items a split names, each with the digest of its adapted text and gold. A split is thereby frozen by
  content with no item checked in ([S2.3.4](s2.3.4_splits.md)).
- **No external item is checked in**, whatever its licence allows (the phase's default 11). The one exception
  is an item kept as a fixture of T2.3.3.5, and only where the licence the stage read permits redistribution;
  otherwise the fixture keeps the item's id and the expected extraction.
- **The licence is read by the stage from the source and recorded, not assumed.** A source whose licence the
  stage cannot establish, or that forbids this use, is not adapted, and the user is asked.
- **Nothing goes back to a source.** A defect found in an item (premises that contradict each other, a gold
  that is wrong) is written into the source's record here and the item is left out; no report and no patch is
  sent.

### The sources, and what each maps to

Counts of items are the fetch's to record: none can be checked in the tree (audit § F).

| source | what an item is | family | the gold short answer | in which splits |
|---|---|---|---|---|
| BBH `logical_deduction_{three,five,seven}_objects` | one `input` holding the whole problem with its options, one `target`, an option's letter | ordering | the option's text, with its letter | `dev`, `val` and `test`, a task; the three sizes are a scaling experiment as published |
| BBH `tracking_shuffled_objects_{three,five,seven}_objects` | the same | object tracking | the same | `val` and `test` only: the family is unseen by prompt development ([K3](../EinAf.md#k3-cross-domain-transfer)) |
| BBH `temporal_sequences` | the same | temporal | the same | `val` and `test` only (K3) |
| CLUTRR | a story, two names, the kinship relation between them, by chain length | graph | the relation's name | `test`, and [K2](../EinAf.md#k2-structural-generalization): developed on short chains, tested on long |
| ProofWriter | facts and rules in controlled English, a question, `True`, `False` or `Unknown`, by proof depth, in a closed-world and an open-world variant | set and category | one of the three words | `test` (K3) |
| FOLIO | premises and a conclusion in English, the same three words, with first-order annotations | set and category | one of the three words | `test` (K3); the annotation is never shown to a model, and is kept as a reference theory for the faithfulness sample |

An item's gold class follows its answer: *one answer* for an option, a relation, `True` or `False`; *ambiguous*,
with `finer: "not-stated"`, for `Unknown`, which says that the text does not settle the conclusion. Its gold
short answer is the source's word either way, so an `Unknown` item is scored on the word and counted with the
synthetic instances of its kind.

### The answer contract

An answer is scored as a short text, for every arm alike (the frame's default 7). The contract of a source is
one function of the package, from an arm's answer to the source's vocabulary:

- **A multiple-choice source**: the short answer, printed by the program for the arms that run Ein and
  extracted from the model's last message for the others
  ([S2.5.2](../p2.5_harness/s2.5.2_baselines.md) owns that extraction and its error), is matched to the item's
  options by the comparison every arm is scored with, and the matched option's letter is compared with the
  target. An answer that matches no option, or two, is wrong, and counted apart.
- **An entity-valued source** (CLUTRR): the short answer against the relation's name, by the same comparison
  over the source's list of relation names.
- **`True`, `False`, `Unknown`**: the old plan's two runs, the theory with `(not C)` and the theory with `C`,
  each read by whether it is a `Contradiction`, are not kept as the default. A fact beside its stored negation
  kills a state only where the program imports `std.contradiction`
  ([Q-M1f.557](../../../docs/decisions/stdlib/Q-M1f.557-the-contradiction-is-a-theory-a-program-imports.md));
  and the kernel's answer is a region R, of which one run gives a query's classes, not a count of the models of
  a whole theory. By default the contract reads **one program with two queries**, one whose goal is the
  conclusion `C` and one whose goal is its stored negation, over the part of R the program asks:

  | the source says | the program's queries give |
  |---|---|
  | `True` | `C` in every state |
  | `False`, open-world reading (FOLIO; ProofWriter's open-world variant) | `(not C)` in every state |
  | `False`, closed-world reading (ProofWriter's closed-world variant) | `C` in no state |
  | `Unknown` | neither |
  | *the item is defective* | R is empty: the premises contradict each other |

  The closed-world *False* is read by the contract off a query's empty class, so the program writes no
  `absent` for it and is not flagged on its account (audit § C.3). Which reading an item is under is in its
  metadata, and the formalizer is told ([S2.2.1](../p2.2_formalizer/s2.2.1_contract.md)). **This table is a
  default to be tested, not a result**: T2.3.3.4 checks it on hand-read items before any number rests on it,
  and whether *in every state of the maximal line* is the entailment a source means is what that check is for.

A program can print `True` and an open-world `False` itself, as the `:goal-text` of its two queries (probed: a
query whose goal is a stored negation is answered and prints its sentence). `Unknown` and a closed-world `False`
are the absence of a row, which prints nothing ([§ Risks of the phase](README.md#risks)): there the contract's
function supplies the word from the kernel's values, and the record says which answers were printed by the
program and which were read off its classes.

### Contamination

BBH is in every training set, and a published number on it may be memory. The check is not this stage's to run
and is this stage's to make possible: every BBH item gets a sibling under
[K4](../EinAf.md#k4-novel-relation-vocabulary)'s novel vocabulary (*left of* becomes *zorps*, with its meaning
stated in the text), by a rewrite the adapter applies to the item's text and records in the metadata's `knobs`.
The synthetic families are the half no model has seen, by construction.

## Tasks

### Task T2.3.3.1 — The fetch and the source's record

`einaf bench fetch`, idempotent, verifying digests, never overwriting a verified file; `SOURCE.json` for each
of the six, with the licence read from the source and the place it was read. First act: check this file's
sentences about the tree and the kernel (the frame's default 14), and that `build/` is still ignored by git.
The old task's model for this, a download script of the model's file, is gone: the model's file is not
downloaded by the plan ([S2.2.2](../p2.2_formalizer/s2.2.2_model_runtime.md)).

### Task T2.3.3.2 — BBH, three task groups

The `input` and `target` adapter; the options parsed out of `input`; the option-letter mapping; the K4 rewrite
with its vocabulary table, fixed a family and recorded; `entities` and, where it can be parsed from the item,
`chain_depth` filled into `knobs`, so that the scaling tables can bin on them.

### Task T2.3.3.3 — CLUTRR

The story adapter; the kinship vocabulary as the graph family's relations; the chain length as `chain_depth`;
the gold relation as the short answer.

### Task T2.3.3.4 — ProofWriter and FOLIO

The reading (closed-world or open-world) in the metadata; ProofWriter's depth as `chain_depth`; FOLIO's
first-order annotation kept beside the fetched item, in no text and no prompt, for
[S2.4.4](../p2.4_loop/s2.4.4_faithfulness.md)'s judged sample. **The contract's table is tested here**: for a
hand-read handful of items of each reading the stage writes an Ein program by hand and holds the table's
reading of it to the source's answer; where they differ the table changes, or the item's construct is one the
contract cannot read and is listed.

### Task T2.3.3.5 — The extractor's tests

Twenty hand-read items a source; the contract's function run on answers written by hand for them, right and
wrong; its agreement reported as a number of the record, because a function that favours one side is a
confound; the disagreements kept as fixtures, under the rule of [§ What an adapter is](#what-an-adapter-is).

### Task T2.3.3.6 — What the sources found of Ein

Of each source's twenty hand-read items, write a canonical program for as many as the language says without
strain, unflagged, and list the others with the construct that stopped each, whatever it turns out to be: a
conclusion that is a disjunction, which Ein does not write, an existential, a number, a closed world. A program
written here makes its item one with a gold theory, marked so. The list is the stage's entry in
[the evaluation of Ein](../ein_evaluation.md), under gaps and limits, with the item's id as evidence; F13's
note names FOLIO as the source most likely to show where the relations and rules of Ein stop. A wrong answer is
a row of [the wrong-answer register](../../wrong_answers/README.md) too.

## Acceptance

- Six sources, each with its record: version, digests, the licence as read, the count of items. A fetch
  verifies what it downloads.
- No external item is in the tree but a fixture its licence permits; `items.jsonl` holds ids and digests.
- Each adapter writes [S2.3.1](s2.3.1_families_and_seed_set.md)'s text and metadata with no canonical program,
  and `einaf bench check` skips such an instance saying so, never passing it as checked.
- The answer contract of each source is a function with its test on twenty hand-read items, its agreement a
  number of the record.
- The `True`, `False`, `Unknown` table is held to hand-written programs for items of each reading, or changed.
- The split a source may be in is honoured by [S2.3.4](s2.3.4_splits.md): a `tracking_shuffled_objects` or
  `temporal_sequences` item in `dev` fails the manifest's check.
- The stage's entries in the evaluation of Ein.

## Risks

- **A licence forbids what the plan does**, or cannot be established. The source is then not adapted; nothing
  is fetched on a guess.
- **A source moves.** A re-fetch at another version is a new record and a new split version
  ([S2.3.4](s2.3.4_splits.md)), never an edit of the old one.
- **The three-word contract reads the wrong thing.** The table above is a default of the re-plan, written
  without a formalized item in hand; T2.3.3.4 is where it meets one.
- **The extraction decides the number.** For the arms that answer in free text the mapping to an option is
  itself a model of the answer; its error is measured (T2.3.3.5) and reported beside every table that uses it.
- **Contamination**, as above.
