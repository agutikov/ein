# S2.3.3 — External benchmarks: adapters

**Phase:** [P2.3](README.md) (The benchmark — Stage C)
**Estimate:** 3 days
**Depends on:** [S2.3.1](s2.3.1_families_and_seed_set.md) — the instance
format every adapter writes into. Not on [S2.3.2](s2.3.2_generators.md): an
external instance has no generator and no canonical program, which is the
whole difference and the reason the two stages are separate.
**Research plan:** [`EinAf.md` § Stage C](../EinAf.md#stage-c--construct-a-heterogeneous-benchmark),
[C2](../EinAf.md#c2-use-both-external-and-controlled-synthetic-tasks) —
*external benchmarks provide ecological validity*.

## Context

The synthetic half of the benchmark has exact ground truth and no claim to
being English anyone wrote for a reason. The external half is the reverse:
published tasks, published numbers to stand beside, a gold **answer** and
**no gold theory** — so constraint precision / recall is undefined on them
and faithfulness falls back to [Q-M2.3](../open_questions.md#q-m23--what-is-the-unit-of-faithfulness-without-a-gold-theory)'s
judge. Every adapter records which metrics an instance supports, and no
table mixes the two halves without saying so.

The sources are the user's ladder ([F13](../../followups/f13_puzzles_beyond_zebra/ideas.md)):
BBH `logical_deduction` → `tracking_shuffled_objects` → CLUTRR, FOLIO,
ProofWriter — chosen there for what each stresses that Zebra does not, and
catalogued in [`docs/lib/12`](../../../docs/lib/12-llm-and-reasoning-benchmarks.md)
§ 1 and § 3 (ProofWriter: *closest in spirit to Ein's three task classes*).
ARC is out by the user's own criterion — text only — with the note that its
grids are representable and its difficulty is rule *induction*, which is
[F7](../../followups/f7_rule_induction.md)'s subject and not this
milestone's.

### The sources, and what each maps to

| source | items | format | family | answer contract | in which splits |
|---|---|---|---|---|---|
| BBH `logical_deduction_{three,five,seven}_objects` | 250 per task (a few fewer) | `{"input": "…(A)…(E)…", "target": "(D)"}` — the whole problem is in `input` | ordering | multiple choice: the kernel's goal binding is mapped to the option letter by the adapter, and the letter is compared | `dev` / `val` / `test`, 10 / 30 / 60 % per task, so the 3 / 5 / 7 ladder is a scaling experiment out of the box |
| BBH `tracking_shuffled_objects_{three,five,seven}_objects` | 250 per task | same | object tracking | multiple choice | `val` / `test` only — the family is *unseen* during prompt development (K3) |
| BBH `temporal_sequences` | 250 | same | temporal | multiple choice | `val` / `test` only (K3) |
| CLUTRR | configurable; the published splits by chain length *k* | a story, two names, the relation between them | graph | an entity-valued relation; the kernel's binding compared to the gold relation name | reserved for `test` and K2 (developed on short chains, tested on long) |
| ProofWriter | depth-0…5 subsets, CWA and OWA variants | facts + rules in controlled English, a question, `True / False / Unknown`, a proof | set / category | **two kernel runs** — see below | reserved for `test` (K3) |
| FOLIO | ~1 400 premises-conclusion pairs with FOL annotations | NL premises, an NL conclusion, `True / False / Unknown` | set / category | two kernel runs | reserved for `test` (K3); the FOL annotation is *never* shown to the model and is kept as a second reference theory for the faithfulness sample |

**`True / False / Unknown` is two runs, not one.** Ein's verdict is the
model count of the *whole* theory; entailment of a conclusion `C` is a
question about `T ∧ ¬C`. The adapter's query contract: run `T + (not C)` —
`Contradiction` means **True**; run `T + C` — `Contradiction` means
**False**; neither means **Unknown**; both is the theory itself being
inconsistent, recorded as a benchmark defect. ProofWriter's CWA variant
makes *False* a closed-world statement, which is what `(absent …)` says on
this kernel ([`absent_semantics.md`](../../../docs/kernel/inference/absent_semantics.md));
its OWA variant and FOLIO make *False* the entailment of the negation. The
adapter records which reading an instance is under, and the formalizer is
told.

### Contamination

BBH is in every training set and a published number on it may be memory.
The check is not this stage's to run but is this stage's to make possible:
every BBH instance gets a sibling under K4's novel vocabulary
([`EinAf.md` § K4](../EinAf.md#k4-novel-relation-vocabulary) — `left-of`
becomes `zorps`, with its semantics stated in the text), produced by a
rewrite the adapter applies to `input` and records in `meta.json.knobs`.
The synthetic families are the uncontaminated half, by construction.

## Acceptance

- Six sources, each with a download script that records version, digest
  and licence in `benchmark/external/<source>/SOURCE.json` — the licence
  **read from the source and recorded, not assumed**; a source whose licence
  forbids redistribution is fetched at run time and only its ids and digests
  are checked in.
- Each adapter writes [S2.3.1](s2.3.1_families_and_seed_set.md)'s three
  files with `source.kind = "external"`, `supports.constraint_pr = false`,
  `supports.faithfulness_exact = false`, and — for ProofWriter / FOLIO — the
  reading (`cwa` / `owa`) and the two-run contract in `meta.json`.
- The answer contract per source is a function in the harness with a test
  on a hand-read sample of twenty items per source; its error rate is a
  number in the record, because an extractor that favours one side is a
  confound ([S2.5.2](../p2.5_harness/s2.5.2_baselines.md) says the same
  about B0 / B1).
- The split assignment above is honoured by [S2.3.4](s2.3.4_splits.md) and
  checked: a `tracking_shuffled_objects` item in `dev` fails the manifest
  check.
- `gold.ein` is **absent** for external instances — there is no canonical
  program — and `einaf bench check` skips certification for them and
  says so, rather than certifying nothing and passing.

## Tasks

### Task T2.3.3.1 — The download scripts and `SOURCE.json`

One script per source under `einaf/benchmark/external/`, idempotent,
verifying the digest, refusing to overwrite a verified file (the pattern
[S2.2.2](../p2.2_formalizer/s2.2.2_llama_server_and_client.md)'s model
download uses). `SOURCE.json`: URL, version or commit, digest, licence,
date fetched, item count.

### Task T2.3.3.2 — BBH, three tasks

The `input` / `target` adapter; the option-letter mapping; the per-task
split; the K4 rewrite with its vocabulary table (`left` → `zorps`, `right`
→ `blick`, … — a fixed table per family, recorded); `chain_depth` and
`entities` filled into `knobs` by parsing the item, so the scaling tables
can bin on them.

### Task T2.3.3.3 — CLUTRR

The story adapter; the kinship vocabulary as the graph family's relations;
chain length *k* as `chain_depth`; the gold relation as `answer`.

### Task T2.3.3.4 — ProofWriter and FOLIO

The two-run contract; the CWA / OWA flag; the depth subset as `chain_depth`
(ProofWriter); FOLIO's FOL annotation stored beside the instance as
`reference.fol` — not in `text.md`, not in any prompt — for
[S2.4.4](../p2.4_loop/s2.4.4_faithfulness.md)'s human-judged sample to
compare a generated theory against.

### Task T2.3.3.5 — The extractor tests

Twenty hand-read items per source; the extractor's agreement reported; the
disagreements kept as fixtures.

## Notes

- LogiQA and ReClor (`docs/lib/12` § 3) are **not** adapted: LSAT-style
  argument questions are reading comprehension more than theory
  construction, and the user's ladder does not name them. They are listed
  here so that the omission is a decision.
- A source's published numbers are quoted in [M5](../../m5_presentation/README.md)
  beside the milestone's, with the model and the split named; this stage
  records where each number comes from in `SOURCE.json` so that M5 does not
  have to find it again.
