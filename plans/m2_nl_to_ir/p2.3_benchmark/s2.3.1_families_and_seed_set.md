# S2.3.1 — The families and the seed set

**Phase:** [P2.3](README.md) (The benchmark — Stage C)
**Depends on:** [S2.1.1](../p2.1_kernel_as_instrumentation/s2.1.1_tree_and_outcomes.md), the package `einaf/`
and its gate step: `einaf bench check` is a command of it. An anchor is an Ein program and a paragraph of
English, and the kernel checks it today. One check of an instance, that its program prints the gold short
answer, needs the formatters of [S2.2.5](../p2.2_formalizer/s2.2.5_from_text.md), which exist when this stage
runs: P2.2 comes first in work order.
**Research plan:** [`EinAf.md` § Stage C](../EinAf.md#stage-c--construct-a-heterogeneous-benchmark),
[C1](../EinAf.md#c1-start-with-several-reasoning-families).

## Context

The benchmark is built around a **seed set**: hand-written instances, each with its text, its gold class, its
gold short answer and a canonical program whose claims the kernel holds. It is what a generator
([S2.3.2](s2.3.2_generators.md)) is checked against before it is trusted to write a thousand more, and what a
reader opens first. It is also the first place this milestone writes Ein for problems nobody encoded before:
eight families, of which the corpus has a full-size program for one ([audit](../analysis/audit_p2.3.md) § B.1).
What that finds of the language is a deliverable of the stage (T2.3.1.7).

What exists to start from, by the audit:

- **attribute matching**: both Zebra encodings and their variants, none stating a claim, with `:source` texts
  that are labels (`"condition (N)"`) and not sentences (§ B.2);
- **the word problems**: sixteen programs under [`examples/word_problems/`](../../../examples/word_problems/README.md),
  each with its statement as the header comment, each fact with its sentence as `:source`, queries that read
  the answer as a sentence by `:goal-text`, and one to three claims, all held, none flagged (§ B.4);
- **five families** with single-rule demonstrations that state no claim, and **object tracking** with nothing
  (§ B.1);
- **of the old plan's five puzzles, only Zebra** (§ B.2).

### The instance format

The default; T2.3.1.1 writes it as a page and may change it where an anchor shows it wrong.

```text
einaf/benchmark/
  README.md          the catalogue, generated from the metadata
  FORMAT.md          this format
  <family>/          one directory a family, flat
    <stem>.txt       the text, as a model sees it
    <stem>.ein       the canonical program; none for an external instance
    <stem>.json      the metadata
    <module>.ein     a theory the family keeps for itself, where it has one
```

An instance's id is `<family>/<stem>`. A family is one flat directory because an import is resolved from the
program file's directory and `..` is refused
([Q-M1f.235](../../../docs/decisions/imports/Q-M1f.235-a-module-has-one-path-from-the-program-files.md)): the
word problems import their four theory modules by file name, and a program in a directory of its own could not.
`ein test einaf/benchmark/<family>/` walks the directory, and a module that states no claim is a `(no expect)`
line.

**The canonical program is a plain kernel input.** It carries, in this order: the imports, each listing the
names the file writes; the declarations, each with its `:why`; the theory, as library activators and, where the
library has no rule, rules of its own; the instance's facts, each with the sentence it encodes as its `:source`;
**its lattice**; the answer query, with a `:goal-text` and an `:expect`; and any other claim the class needs
([§ How a class is established](README.md#how-a-class-is-established)). Three rules of the format are there
because the kernel does something else in silence without them:

- **A name of the library is listed in `:symbols`**, or written in full. A `(transitive older)` whose file does
  not list `transitive` is the file's own fact and selects nothing, with no message
  ([E-11](../ein_evaluation.md)).
- **The lattice is stated**: a rule that concludes `(open F)`, an activated obligation, or `(solve :no-search)`
  where nothing is supposed. With none the blind enumerator supposes facts of the program's relations
  ([E-13](../ein_evaluation.md); [§ What admits an instance](README.md#what-admits-an-instance)).
- **A contradiction between a fact and its stored negation needs `std.contradiction`**, imported directly or
  through `std.algebra`, `std.bijection` or `std.slots`
  ([Q-M1f.557](../../../docs/decisions/stdlib/Q-M1f.557-the-contradiction-is-a-theory-a-program-imports.md)).

A worked instance, run at the re-plan on the kernel at M1f's close (`ein test` holds its claim; `ein solve`
describes one state, reached by one commitment, with root owing each person a rank; the static check finds no
site):

```lisp
;; Ann is older than Bob. Bob is older than Carol. Who is the youngest?
(import std.algebra :symbols (functional injective total-owed transitive))

(relation is-a  T T           :why "{?3} is a {?4}")
(relation older Person Person :why "{?3} is older than {?4}")
(relation rank  Person Rank   :why "{?3} has rank {?4}")
(relation lower Rank Rank     :why "{?3} is a lower rank than {?4}")

(is-a Ann Person) (is-a Bob Person) (is-a Carol Person)
(is-a Y1 Rank) (is-a Y2 Rank) (is-a Y3 Rank)
(lower Y1 Y2) (lower Y2 Y3)
(transitive lower)
(functional rank) (injective rank) (total-owed rank is-a)

(older Ann Bob   :source "Ann is older than Bob.")
(older Bob Carol :source "Bob is older than Carol.")

(rule older-is-higher ()
  :match  (and (older ?a ?b) (rank ?a ?ra) (rank ?b ?rb) (lower ?ra ?rb))
  :assert (false)
  :why    "{?a} is older than {?b}, so {?a} cannot have the lower rank {?ra}")

(query :goal      (rank ?who Y1)
       :goal-text "{?who} is the youngest"
       :expect    (model (rank Carol Y1)))
```

It prints *Carol is the youngest*. With the second sentence deleted the same theory has three states and two
answers, claimed as `(or (model (rank Bob Y1)) (model (rank Carol Y1)))`; with *Carol is older than Ann* added it
has none ([§ How a class is established](README.md#how-a-class-is-established) says which kind of none). It is
one encoding of the family, written to show the format: T2.3.1.2 decides the anchor's.

**The metadata**, one JSON file an instance, shared by the check, the generators, the adapters and the metrics:

```json
{ "schema": "einaf-instance/1",
  "id": "logical_deduction/h-0001",  "family": "logical_deduction",
  "source": { "kind": "hand" },
  "class": "one",                    "finer": "complete",
  "answer": { "text": ["Carol"], "query": 1 },
  "gold_by": "author",
  "kernel": { "single": "Solution", "maximal_single": "Solution", "root_in_r": false,
              "k_s": 1, "k_c": 1, "exhausted": true },
  "knobs":  { "entities": 3, "relations": 1, "chain_depth": 2, "irrelevant": 0, "paraphrase": 0 },
  "theory": { "stdlib": ["std.algebra"], "local": [], "own_rules": 1 },
  "supports": ["answer", "class", "constraint_pr", "faithfulness_exact"] }
```

| field | what it is | who reads it |
|---|---|---|
| `source.kind` | `hand`, `corpus` (a copy of a corpus program, with its path and digest), `generator` (with the generator's version, seed and arguments), `external` (with the source's name and the item's id) | the catalogue; [S2.3.4](s2.3.4_splits.md) |
| `class` | `one`, `ambiguous`, `unsatisfiable` | [S2.5.3](../p2.5_harness/s2.5.3_metrics.md) |
| `finer` | [F26](../../followups/f26_consistency_and_completeness.md)'s split: `complete`, `not-stated`, `reading`, `contradictory`; with `assumption: true` where the answer rests on a marked assumption, and `empty: "dead"` or `"owing"` on an unsatisfiable instance | the per-class tables; [the evaluation](../ein_evaluation.md) |
| `answer.text` | the gold short answer, a sentence: one for `one`; the alternatives for `ambiguous`, where they are few and short, else none; none for `unsatisfiable` | every arm's score |
| `answer.query` | which query of the program is the answer query | the check |
| `answer.printed` | `true`, the default and left out: the program prints the short answer through its `:goal-text`. `false`: the answer is one no program prints (a class, a *no* read off the empty class), and EinAf reads it off the kernel's values | the check; the record of a run |
| `answer.values`, `answer.domain`, `answer.aliases` | asked for by the scoring, since the answer is a sentence: the values the gold sentence binds, each with the thing it is bound to (the answer query's rows, formatted); the other values each could have been, where the instance has a closed set of them; other spellings of a value that count as it | [S2.5.2](../p2.5_harness/s2.5.2_baselines.md)'s answer line and normaliser; [S2.5.3](../p2.5_harness/s2.5.3_metrics.md)'s lenient match, which is containment alone where no domain is given |
| `gold_by` | `construction` (a generator counted the answers), `author`, `source`, or `kernel` where nothing but the kernel says it | a reader weighing the gold |
| `kernel` | what the kernel says of the canonical program, **written by the check and never by hand**: `--single`'s word, `--maximal --single`'s word, whether ∅ is in R, and `k_s`, `k_c` and `exhausted` where a description ends within the default budget | [Q-M2.10](../open_questions.md#q-m210--what-does-ein-certifies-a-unique-model-mean-on-r)'s experiment, which needs each reading of *one answer* beside the instance's family and shape |
| `knobs` | the generator's arguments; for a hand-written instance, the same fields read off it | [P2.7](../p2.7_failure_scaling_generalization/README.md) |
| `theory` | the library modules imported, the family's own modules, the count of rules the program writes | [P2.6](../p2.6_ablations/README.md)'s library ablation; [S2.4.4](../p2.4_loop/s2.4.4_faithfulness.md) |
| `supports` | which metrics the instance can be scored on | [S2.5.3](../p2.5_harness/s2.5.3_metrics.md) |

The split is not a field: it lives in the frozen split file ([S2.3.4](s2.3.4_splits.md)), the one statement of
which split an instance is in. The old plan's `{"k": n}` and `{"core": […]}` answers are gone: there are two
counts and neither is the count of answers (audit § A.1, row 4), and a core is an explanation that may vary with
the rules' order ([Q-M1f.6](../../../docs/decisions/answer/Q-M1f.6-a-core-is-an-explanation.md); audit § C.4).

### The anchors

One hand-written instance a family with one answer, and by hand its two siblings, ambiguous and unsatisfiable,
so that the three classes of a family are first met by a person and not by a generator. *Encoding to try first*
is a default; the stage settles each by experiment, and what it settles is the family's canonical theory for
[S2.3.2](s2.3.2_generators.md).

| family | the anchor, in one line | theory | the encoding to try first, and what must be found |
|---|---|---|---|
| logical deduction | three people, two *older than* statements, *who is the youngest?* | `std.algebra` | the order as a bijection onto named ranks, as above; the extremum is a rank, with no `absent`. Whether the order's own properties (`transitive`, `asymmetric`) belong in the theory decides which kind of empty R a contradiction gives |
| ordering | five arrivals, *before* and *immediately before*, *who arrived third?* | `std.algebra`: `(includes immediately-before before)`, `transitive` | the same ranks; *third* is a named rank, not a number ([Q-M1e2.24](../../../docs/decisions/language/Q-M1e2.24-ein-has-no-numbers-and-no-ranges.md)) |
| spatial | a three-by-three arrangement, *left of* and *above*, *what is in the centre?* | `std.algebra`: `converse`, `transitive` | two orders over one set of cells, adjacency as facts ([Q17](../../../docs/decisions/language/Q17-spatial-structure-is-facts-and-rules-with-no.md)); whether `std.slots` carries it |
| object tracking | a key in box A, two swaps, *where is the key?* | none in the library: the anchor's rules are its own, and they are the family's canonical theory | state over named moments, as the word problems write a transfer (`t0`, `t1`); the rule that an object not swapped stays where it was, without an `absent` a commitment can fill |
| attribute matching | Zebra ([§ Zebra](#zebra)) | `std.bijection` or `std.slots` | which of the two encodings is the formalizer's target is [S2.2.1](../p2.2_formalizer/s2.2.1_contract.md)'s; the benchmark's program follows it |
| set and category | *every A is B; no B is C; x is A; can x be C?* | subsumption by `std.algebra`; disjointness as the anchor's own rule | *can* as a hypothesis, `(open (is-a x C))`, which the theory refutes: probed, monotone, and the answer *no* is the class where the goal has no row. What prints *no* has to be found ([§ Risks](#risks)) |
| graph | six nodes, an edge list, *is F reachable from A?* and *who is an ancestor of D?* | `std.algebra`: `transitive`, `symmetric` | *not reachable* without a flagged `absent`: the edges are stated facts and nothing is supposed of them, the case the probe of the minimum found monotone |
| temporal | three intervals, *before*, *overlaps*, *during*; *could X have been at the café when Y was?* | none in the library: an interval fragment of the anchor's own | endpoints as named moments with a stated order, a moment being a name and never a clock time; *could* as in set and category |
| word problems | [§ The word problems](#the-word-problems) | four modules beside the instances | taken as they are |

A family whose anchor cannot be written unflagged in any encoding the stage tries keeps its text and its gold
answer, has no canonical program, and is an entry of the evaluation of Ein and a line of the phase's findings.

### Zebra

Zebra is the smoke test of [S2.2.5](../p2.2_formalizer/s2.2.5_from_text.md) and is in no split. Its three
instances are written for the benchmark:

- **the texts** are [`nl2smt/puzzles/zebra.txt`](../../../nl2smt/puzzles/zebra.txt), `zebra-minus-15.txt` and
  `zebra-contradiction.txt`, copied, a sentence a line; `nl2smt/` is outside Ein and outside the process, and the
  benchmark keeps its own copies;
- **the programs** are the encoding [S2.2.1](../p2.2_formalizer/s2.2.1_contract.md) names as the formalizer's
  target, with each fact's `:source` rewritten to its sentence of the text, and the query's `:expect` added: the
  published answer for the puzzle, the classes of the puzzle's query over the maximal line for the one with
  clue 15 dropped, `(solve :expect (false))` for the contradictory one;
- **the contradictory program encodes the text's contradiction**, *The Norwegian drinks milk.*, and not
  `examples/ein-bugs/zebra2-bad.ein`'s, which puts Green in the first house (audit § B.2).

The corpus's Zebra files are not edited, and
[`gen_zebra2_variants.py`](../../../utils/gen_zebra2_variants.py) stays the one writer of its four
(audit § C.2). The answers have a route outside the engine: `nl2smt`'s pipeline counts one, thirty-two and none
on the three texts ([`nl2smt/README.md`](../../../nl2smt/README.md)).

### The word problems

The sixteen problems are the second domain's seed set. Each becomes an instance: its header's statement is the
text; the program and the four theory modules (`words.ein`, `gaps.ein`, `readings.ein`, `listed_is_all.ein`) are
copied into `einaf/benchmark/word_problems/`, each copy's metadata naming the corpus file and its digest; its
class and finer split are read off [the table of § B.4](../analysis/audit_p2.3.md) and checked against the
claims' shapes. One thing may change in a copy, and the metadata says so:

- **the `:goal-text`**, where it does not print a sentence that answers the question: `bob1.ein`'s `"{?q}: {?n}"`
  prints `(amount Bob apples t1): (n z 3)`, and the gold short answer is a sentence, *Bob has 3 apples*, whose
  value is *3* ([Q-M2.12](../open_questions.md#q-m212--what-prints-the-answer)). Which values the formatters have to read
  (a numeral of the calculator's, a quantity such as `(amount Bob apples t1)`) is a list this stage hands to
  [S2.2.5](../p2.2_formalizer/s2.2.5_from_text.md);
- and nothing else: a problem whose copy would need another change is taken as it is, with `answer.printed`
  false.

They cover what a deleted clue does not: a gap that is named (`gap`, `kinds`, `before`), an answer on a marked
assumption (`gap_assume`, `kinds_assume`, `kinds_listed`), a word with two readings that agree (`boxes12`) and
that do not (`boxes13`), and a contradiction (`contra`).

## Tasks

### Task T2.3.1.1 — The instance format

Write `einaf/benchmark/FORMAT.md`: the files of an instance; the canonical program's parts and the three rules
above; the metadata's schema with each field's meaning and reader; the table of
[§ How a class is established](README.md#how-a-class-is-established), as the definition of a class for a
canonical program; and [§ What admits an instance](README.md#what-admits-an-instance). First act: check each
sentence of this file about the kernel against the kernel (the frame's default 14), the probes among them, which
were run on scratch files and not kept.

### Task T2.3.1.2 — The anchors

Hand-write the eight, each in its three classes. For each: the English first, then the gold class and short
answer, then the program, then `ein test`, then the metadata, in that order, so that the text is not written to
fit the program. Try the encoding of the table first; where it is flagged, does not load as meant, or cannot say
the question, try another and keep both in the stage's record with what each cost. For a family with no library
theory, the anchor's rules go in a module of the family's directory, and that module is the canonical theory.

### Task T2.3.1.3 — Zebra, and the old five

Write Zebra's three instances as [§ Zebra](#zebra) says. The other four of the old plan's five are not written
by hand: the Einstein variant and the two logic grids were never encoded (audit § B.2), and attribute matching
at other sizes and over another ontology is [S2.3.2](s2.3.2_generators.md)'s generator; the *ambiguity stress*,
four sentences with one ambiguous, is the corpus's `boxes13.ein`, a word with two readings and two answers,
taken in with the word problems.

### Task T2.3.1.4 — The catalogue

`einaf bench catalog` writes `einaf/benchmark/README.md` from the metadata: the family table, one line an
instance (id, class, finer, theory, source), the format in two sentences and the pointer to `FORMAT.md`. The
page says it is generated. Its model is [`examples/README.md`](../../../examples/README.md), one line a file.

### Task T2.3.1.5 — `einaf bench check`

The benchmark's own check, for every instance with a canonical program, in the order of
[§ What admits an instance](README.md#what-admits-an-instance): load; the static check; the lattice's writer;
the claims; the class against the claims' shapes; the printed answer against the gold short answer; every
`:source` against the text. It names the first instance that fails and why, writes the metadata's `kernel`
block, and skips an external instance saying so.

- **The kernel's half is `ein test`'s.** The functions that command is written over are the library's
  (`ein_infer::read_out::least`, `describing` and `stands`); whether the check calls them or runs the binary
  with `--json-report` is settled with how [S2.1.1](../p2.1_kernel_as_instrumentation/s2.1.1_tree_and_outcomes.md)
  has EinAf reach the kernel, and either way the two give one verdict on the seed set, which the step holds.
- **Which writer of H a program has** is the library's to say (`ein show hyps` and `ein render h-space` print
  it as *from*; `ein-summary/2` does not carry it).
- **The comparison of a printed answer with the gold** is one function of the package, the one
  [S2.5.3](../p2.5_harness/s2.5.3_metrics.md) scores every arm with. If this stage runs first it writes the
  function's first cut and S2.5.3 takes it over.
- It is a step of EinAf's gate, over the seed set whole.

### Task T2.3.1.6 — The word problems, taken in

As [§ The word problems](#the-word-problems): sixteen instances, their modules, the `:goal-text` changes, the
value kinds the instances print that the formatters of [S2.2.5](../p2.2_formalizer/s2.2.5_from_text.md) have no
case for, each added to them as a case, and the check that names a copy whose corpus file has changed since.

### Task T2.3.1.7 — What writing the anchors found of Ein

Add to [the evaluation of Ein](../ein_evaluation.md), under the user's five kinds, what the anchors showed, one
entry a finding with its program and command. At the least: for each family, whether the question could be said
and at what cost (rules of its own, an encoding away from the natural one, a flag); each construct tried and
refused or silently inert; what the library lacked (disjointness, state, intervals); what the kernel's reply did
not say that the check had to compute; and what served as it is. The candidates the re-plan met are in
[§ Risks](#risks) and are entered by this task once it has run them again. A wrong answer is a row of
[the wrong-answer register](../../wrong_answers/README.md) as well, by its rules, in a commit of its own. The
rows of [F25](../../followups/f25_roughness_found_outside_zebra.md) are read against the anchors, since a corpus
of real programs is its trigger.

## Acceptance

- `einaf/benchmark/FORMAT.md`, and the catalogue generated from the metadata.
- Each of the eight families has a hand-written instance of each class, or its page names the class it lacks
  and why; Zebra's three; the sixteen word problems.
- `einaf bench check` is green over the seed set and is a step of EinAf's gate; `ein test einaf/benchmark/`
  exits 0.
- No canonical program of the seed set is flagged, and none is answered by the blind enumerator.
- Every instance's `kernel` block is written by the check, with each reading of *one answer* it can take.
- The canonical theory of each family is named for [S2.3.2](s2.3.2_generators.md): the library activators, the
  family's module where it has one, and the encoding's reasons.
- The evaluation of Ein has the stage's entries, and every value kind an instance prints has a formatter's case.

## Risks

- **The first encoding that comes to mind is flagged.** Probed at the re-plan: *youngest* as *older than nobody*,
  by `absent`, is monotone under `(solve :no-search)` and flagged with candidates of `older`; without a
  `(solve …)` form the same program is answered by the blind enumerator and flagged, and its claim fails.
- **The answer *no* prints nothing.** Probed: *can x be C?* as a refuted hypothesis is one state, `Solution`,
  and the answer query's class is the empty one, which prints *the goal has no row*. A program can say *no* in a
  sentence only by deriving a fact that says it, a stored negation or a fact like `gaps.ein`'s `unanswered`;
  whether an anchor does, or its short answer is scored as given by EinAf from the empty class, is the stage's,
  by experiment, and the default is the first where one rule does it.
- **A cycle is not refuted by the textbook pair.** Probed: `(transitive older)` and `(irreflexive older)` over a
  cycle of three leave root alive with all six pairs and no self-loop, since `transitive` guards the loop;
  `(asymmetric older)` refutes it. An anchor's unsatisfiable sibling says which property its contradiction
  violates.
- **The text is written to fit the program.** The order of T2.3.1.2 is the guard, and the `:source` check holds
  it afterwards: every fact's sentence is in the text, and a sentence of the text that no fact cites is listed by
  the check, since it is either irrelevant on purpose or a clue the program dropped.
- **An anchor is too clever to check by eye.** The anchors' English is plain on purpose; surface variety is the
  paraphrase knob's ([S2.3.2](s2.3.2_generators.md)).
