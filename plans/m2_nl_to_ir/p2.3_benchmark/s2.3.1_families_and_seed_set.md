# S2.3.1 — The eight families and the seed set

**Phase:** [P2.3](README.md) (The benchmark — Stage C)
**Estimate:** 3 days
**Depends on:** nothing to start — a hand-written anchor is a `.ein` file and
a paragraph of English, and the kernel certifies it today. The `:expect`
form it carries is [M1c S1c.1.2](../../m1c_external_validation/p1c.1_stdlib_conformance/s1c.1.2_test_form.md)'s,
written now so the gate re-checks it the day `ein test` ships.
**Research plan:** [`EinAf.md` § Stage C](../EinAf.md#stage-c--construct-a-heterogeneous-benchmark),
[C1](../EinAf.md#c1-start-with-several-reasoning-families).

## Context

The benchmark is built around a **seed set**: one hand-written instance per
family, with its text, its canonical program and its certified answer — the
thing a generator ([S2.3.2](s2.3.2_generators.md)) is checked against before
it is trusted to produce a thousand more, and the thing a reader opens first.
The old P2.6's five puzzles were a seed set under another name, and they are
kept here with their gold programs; what changes is that they are now five
points in two families rather than the whole benchmark
([P2.3 § Why the old five puzzles are not a benchmark](README.md#why-the-old-five-puzzles-are-not-a-benchmark)).

### The instance format

One directory per instance, readable without the system — Stage Q's second
layer ([`EinAf.md` § Stage Q](../EinAf.md#stage-q--public-research-artifact)),
delivered at the start:

```text
benchmark/<family>/<id>/
  text.md      the statement as a model sees it (EN; RU realisations later, same id + "-ru")
  gold.ein     the canonical program: ontology + theory (std.* imports and activators)
               + instance facts with :source + (query … :expect …)
  meta.json    what the instance is: family, source, verdict class, answer, knobs, theory
```

`benchmark/` and not `bench/`: **`bench/` is [M10](../../m10_external_benchmarks/README.md)'s**
— the six-system corpus and `ein-bench`'s results
([S10.1](../../m10_external_benchmarks/s10.1_problem_corpus.md)) — and the
two are different things that should not share a directory: M10's encodings
are hand-written for six solvers and compared on the answer; this
benchmark's instances are NL texts with one canonical Ein program each and
are what a *model* is run on.

`gold.ein`'s query carries **`:expect` in M1c's recommended form** — the
expected model as facts, `(or S1 S2 …)` for an ambiguous instance, the
empty expectation (or `none`, [Q-M1c.2](../../m1c_external_validation/open_questions.md#q-m1c2--what-may-an-expectation-say))
for an unsatisfiable one — so that the verdict is *implied by the
expectation* and cannot disagree with it
([S1c.1.2 § (c)](../../m1c_external_validation/p1c.1_stdlib_conformance/s1c.1.2_test_form.md)).
`ein test` is not shipped; until it is, the harness runs
`ein solve -e --json-summary` and compares `verdict.type`, `k`, `exhausted`
and the sorted `solutions` to `meta.json`, which says the same thing the
`:expect` says. If M1c decides a different form
([Q-M1c.1](../../m1c_external_validation/open_questions.md#q-m1c1--how-does-a-program-state-what-it-expects)),
the benchmark follows it in one sweep; the *content* of the expectation
does not change.

`meta.json`, the schema the harness and the generators share:

```json
{ "schema": "einaf-bench/1",
  "id": "ordering/0001",            "family": "ordering",
  "source": { "kind": "hand", "author": "…", "licence": "CC-BY-4.0" },
  "verdict": "unique",              "answer": { "bindings": { "?youngest": "Carol" } },
  "knobs":  { "entities": 3, "relations": 1, "chain_depth": 2, "irrelevant": 0, "paraphrase": 0 },
  "theory": { "stdlib": ["std.algebra"], "activators": ["(transitive older-than)"], "synthesised": [] },
  "supports": { "answer_accuracy": true, "constraint_pr": true, "faithfulness_exact": true } }
```

The split is **not** a field here — it lives in the frozen split file
([S2.3.4](s2.3.4_splits.md)), because one source of truth for "which split is
this in" is the whole point of freezing. `answer` is what the H1 metrics
compare against: goal bindings for `unique`, `{"k": n}` for `ambiguous`,
`{"core": [...]}` for `unsat`.

### The eight anchors

One per family, hand-written, verdict `unique`; the `ambiguous` and `unsat`
siblings of each anchor are [S2.3.2](s2.3.2_generators.md)'s first output.
The theory column is the stdlib module the anchor imports and the activators
it asserts — and the two rows where that column is *none* are the benchmark's
point, not its gap ([P2.3 § The shape](README.md#the-shape)).

| family | the anchor, in one line | theory | the old puzzle it absorbs |
|---|---|---|---|
| logical deduction | three people, two `older-than` statements, *who is youngest?* — the plan's own example | `std.algebra`: `(transitive older-than)`; the minimum by closed-world `(absent …)` | — |
| ordering | five arrivals, `before` and `immediately-before`, *who arrived third?* | `std.algebra`: `transitive`, `(includes before immediately-before)` | **the ambiguity stress** — the old 4-sentence puzzle with one deliberately ambiguous sentence is this family's first `ambiguous` instance, hand-written |
| spatial | a 3×3 arrangement with `left-of` / `above`, *what is in the centre?* | `std.algebra`: `(converse left-of right-of)`, `transitive`; adjacency extensional ([Q17](../../open_questions.md#q17--spatial-relation-formalisation)) | — |
| object tracking | a key in box A, two swaps, *where is the key?* | **none** — the anchor's rules are written in the file, and they are the canonical theory the formalizer's *synthesis* is scored against | — |
| attribute matching | Zebra | `std.bijection` (`zebra2.ein`) / `std.slots` (`zebra.ein`) | **Zebra** (the smoke test), **the Einstein variant**, **logic grid A** (4×4, a different ontology), **logic grid B** (5×5 with spatial constraints) |
| set / category | *every A is B; no B is C; x is A; can x be C?* | `std.typing`, `is-a`; the *can* question is a satisfiability question — the anchor's query is the hypothesis and the answer is the verdict | — |
| graph | six nodes, an edge list, *is F reachable from A?* and *who is an ancestor of D?* | `std.algebra`: `transitive`, `symmetric` | — |
| temporal | three intervals with *before* / *overlaps* / *during*, *could X have been at the café at 3 PM?* | **none** — the anchor carries its own Allen-fragment rules, by the same rule as object tracking | — |

**Zebra is the smoke test and is in no split.** Its text is
[S2.2.5](../p2.2_formalizer/s2.2.5_from_text.md)'s `examples/zebra.txt`; the
benchmark entry `benchmark/attribute_matching/zebra/` holds a copy of it,
and a test holds the copy equal to the original. The three programs the
repo already generates from one another — `zebra2.ein`, `zebra2-minus-15.ein`
(32 models), `ein-bugs/zebra2-bad.ein` (a contradiction) — are the
attribute-matching anchor's `unique` / `ambiguous` / `unsat` triple, already
certified: [`gen_zebra2_variants.py`](../../../examples/gen_zebra2_variants.py)
is a generator of exactly S2.3.2's shape, one family wide.

## Acceptance

- Eight directories, one per family, each with `text.md`, `gold.ein`,
  `meta.json`; the attribute-matching family with its five old puzzles and
  the ordering family with the old ambiguity stress.
- Every `gold.ein` loads, and `ein solve -e --json-summary` on it agrees with
  `meta.json` on `verdict`, `k`, `exhausted` and — for `unique` — the goal
  bindings; the harness's `einaf bench check` runs that over the whole
  directory and is green.
- Every `gold.ein` carries `:expect` in S1c.1.2's form, and every `:source`
  string in it is a substring of `text.md`.
- `benchmark/README.md` is a catalog in [`corpus/README.md`](../../../corpus/README.md)'s
  style — one line per entry, the family table above, and the sentence that
  says `bench/` is M10's.
- No anchor's `-e` run hits a cap: `exhausted = true` on every one, or the
  anchor is rewritten smaller. An instance the kernel cannot certify is not
  ground truth ([Q-M1d.6](../../m1d_satisfiability/open_questions.md#q-m1d6--may-contradiction-be-said-with-exhausted--false)).

## Tasks

### Task T2.3.1.1 — The instance format and `meta.json`

Write `benchmark/FORMAT.md`: the three files, the `meta.json` schema above
with every field's meaning and its consumer ([S2.5.3](../p2.5_harness/s2.5.3_metrics.md)
reads `answer` and `supports`; [P2.7](../p2.7_failure_scaling_generalization/README.md)
reads `knobs`; [S2.3.4](s2.3.4_splits.md) owns the split), and the rule that
`gold.ein` is a plain kernel input — no metadata inside it beyond `:source`
and `:expect`, both of which the kernel already accepts or is about to.

### Task T2.3.1.2 — The eight anchors

Hand-write the eight. For each: the English first, then the program, then
`ein solve -e`, then `meta.json` from the summary — in that order, so the
text is not written to fit the program. For the two families with no
stdlib theory, write the rules in the file under a `;; theory — canonical,
no std.* module covers this` comment, and record them under
`theory.synthesised` in `meta.json`; that field is what G9 and the
faithfulness judge read ([S2.4.4](../p2.4_loop/s2.4.4_faithfulness.md)).

### Task T2.3.1.3 — The old five, placed

Zebra (text from `examples/zebra.txt`, program `zebra2.ein`, `split`
excluded), the Einstein variant, the two logic grids and the ambiguity
stress — each in its family's directory with a `gold.ein` written fresh in
the unified is-a model and certified. The old P2.6 planned a gold *trace*
for Zebra; it stays the smoke test's and is [S2.2.5](../p2.2_formalizer/s2.2.5_from_text.md)'s
business, not the benchmark's.

### Task T2.3.1.4 — The catalog

`benchmark/README.md`: the family table, one line per instance (id, family,
verdict, theory, source), the three-file format in two sentences, and the
pointer to `FORMAT.md`. Generated by `einaf bench catalog` from the
`meta.json` files, so it cannot drift.

### Task T2.3.1.5 — `einaf bench check`

The certification run: for every instance directory, load, `solve -e
--json-summary`, compare to `meta.json`, compare every `:source` to
`text.md`, and — once [M1c](../../m1c_external_validation/README.md) ships —
`ein test gold.ein` in place of the comparison. Exit non-zero on the first
disagreement, naming the instance. This is the benchmark's own gate, and
the reason the ground truth is *certified by the kernel, exhaustively,
before a model sees it*.

## Notes

- The anchors' English is deliberately plain. The paraphrase sets
  ([S2.3.2](s2.3.2_generators.md), K1) are where surface variety comes from;
  an anchor that is already clever is an anchor nobody can check by eye.
- RU realisations get the same id with a `-ru` suffix and share `gold.ein`
  and `meta.json` by reference; they are a Level C addition and the format
  allows them from the start.
