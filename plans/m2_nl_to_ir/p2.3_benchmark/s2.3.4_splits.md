## Context

Two things are frozen here and they are different. The **split** is a partition of instance ids into `dev`,
`val` and `test`, versioned and digested, and read by every experiment record; its point is that a claim made
on `test` is made on instances no prompt was tuned against. The **manifest** is the benchmark's inventory, one
entry an instance, generated from the metadata, with the completeness check the corpus's manifest taught this
project: *an instance with no entry fails, an entry with no instance fails*.

Neither is the corpus's. The benchmark is no corpus root ([§ Where it lives](README.md#where-it-lives)), so its
programs have no `corpus/corpus.toml` entry, and the old plan's `runs` column, copied from that manifest, is
moot: `ein test` reads the question off a file's claims and no option chooses it
([Q-M1f.221](../../../docs/decisions/answer/Q-M1f.221-ein-test-asks-a-file-the-least-question-that.md)).

### The split file

`einaf/benchmark/splits/v1.json`:

```json
{ "schema": "einaf-split/1", "version": 1,
  "stratified_by": ["family", "class", "size_bin"],
  "size_bins": { "small": [3, 5], "medium": [6, 8], "large": [9, 15] },
  "dev":  ["ordering/g-0001", "…"],  "val": ["…"],  "test": ["…"],
  "excluded": ["attribute_matching/zebra", "…"],
  "digest": { "dev": "sha256:…", "val": "sha256:…", "test": "sha256:…" } }
```

- **Stratified by family, gold class and size bin**, the bin being the `entities` knob binned. That makes
  [K2](../EinAf.md#k2-structural-generalization)'s structural generalization (*development on 3–5 entities,
  test on 8–15*) a property of the split and not a second benchmark: `dev` draws from `small`, `val` from
  `small` and `medium`, `test` from all three, and a record's `size_bin` says which rows are the extrapolation.
  The finer split is not a stratum; a table reports it.
- **The digest of a split is over its sorted pairs of an id and a content digest**, the content being the
  instance's text, its program and its metadata without the `kernel` block, which the check writes and a later
  kernel may write differently. An instance edited after the freeze changes the digest; an id list alone would
  not see it. For an external instance the content digest is the one in its source's `items.jsonl`. The digest
  is a field of every record ([S2.5.1](../p2.5_harness/s2.5.1_experiment_record.md)).
- **What is never in `val` or `test`**: a hand-written anchor, an instance taken from the corpus (the sixteen
  word problems), and any instance a prompt quotes, which is `excluded`, as Zebra is
  ([S2.2.1](../p2.2_formalizer/s2.2.1_contract.md) checks the prompts against this file). An instance whose
  gold rests on the kernel alone is not in `test`.
- **Sizes** are the stage's to set, met or the shortfall a cell stated. The default is the old plan's aim: a
  family and class, synthetic, twenty in `dev`, fifty in `val`, a hundred in `test`; BBH's tasks by a seeded
  shuffle, a tenth, three tenths and six tenths, with `tracking_shuffled_objects` and `temporal_sequences` in
  `val` and `test` only; CLUTRR, ProofWriter and FOLIO in `test` only, two hundred items each by a seeded draw,
  with the distribution of chain length or depth recorded: the cross-domain set of
  [K3](../EinAf.md#k3-cross-domain-transfer) ([S2.3.3](s2.3.3_external_benchmarks.md#the-sources-and-what-each-maps-to)).

### The lock on `test`

`test` is read by a run only when the run names it and gives a reason, and the reason is written into the
record; a report lists every record that opened `test`. The command that runs a split is
[S2.5.1](../p2.5_harness/s2.5.1_experiment_record.md)'s; this stage states the lock it honours. Prompt
development, the ablations and the failure sample use `dev` and `val`. A number on `test` outside a sanctioned
opening is not a bug of the tooling: it is a mark the tooling cannot remove, and the report shows it.

**Two openings are sanctioned**: the Level B run of this stage, which [the milestone's acceptance](../README.md#acceptance)
puts on `test`, and [P2.10](../p2.10_result_artifact_demo/README.md)'s. The first one tells the phases after it
something about `test`. What it may tell is the table a family; no prompt, example or repair is drawn from its
per-instance records, which stay in the record and are listed as opened. Whether the Level B run should have a
split of its own instead, so that `test` is first read at P2.10, is the user's
([§ Defaults of the phase](README.md#defaults-taken-at-the-re-plan), 12).

### The manifest

`einaf/benchmark/manifest.toml`, schema `einaf-manifest/1`, written by `einaf bench manifest` from the
metadata and never by hand:

```toml
schema = "einaf-manifest/1"

[[entry]]
id       = "ordering/g-0001"
family   = "ordering"
source   = "generator"            # hand | corpus | generator | external:<name>
class    = "one"
finer    = "complete"
supports = ["answer", "class", "constraint_pr", "faithfulness_exact"]
digest   = "sha256:…"             # the content digest the split's digest is taken over
asked    = "--single"             # the question ein test read off the claims; absent for an external instance
check_ms = …                      # measured by the check; absent for an external instance
```

`asked` is the `route` of the claim's row in `ein-test-report/6`. `check_ms` is what the check cost, measured
by the command that checks, under [`utils/bench_env.sh`](../../../utils/bench_env.sh)'s banner and on AC; it
decides which generated instances are in the gate's sample, by a threshold the stage states (the corpus's own
line between slow and not is one second).

### Versioning

A split version is immutable. A new instance, a rejected instance admitted after all, an external source
fetched at another version: each makes `v2.json` beside `v1.json`, and a table names the version it was
computed on. Two tables on different versions are not joined in one figure; the report refuses and says why.

## Tasks

### Task T2.3.4.1 — The stratified draw

`einaf bench split --version 1 --seed S`: the strata, the bins, the rules of
[§ The split file](#the-split-file), each source's rule from [S2.3.3](s2.3.3_external_benchmarks.md), the
`excluded` list, the digests. Written once and frozen by its commit; the command refuses to overwrite a
version. Before the draw, `einaf bench check` runs over the whole benchmark, not the gate's sample, and the
draw refuses on an instance not admitted.

### Task T2.3.4.2 — The manifest and its invariants

`einaf bench manifest`, and its checks as tests of the package, in EinAf's gate step: a file under a family's
directory with no entry, an entry with no files, an id in two splits, an id in no split and not excluded, a
`tracking_shuffled_objects` or `temporal_sequences` item in `dev`, a hand-written or corpus instance in `val`
or `test`, an instance with `gold_by: "kernel"` in `test`, a digest that is not its files'. The step is in the
local gate and in CI alike, as [`utils/check_gate_steps.py`](../../../utils/check_gate_steps.py) holds every
step.

### Task T2.3.4.3 — The lock

The opening and its field of the record; the report's list of the records that opened `test`; the check that
the list holds the sanctioned openings and no other.

### Task T2.3.4.4 — Layer 2

`einaf/benchmark/` reads with no engine and no EinAf installed: `README.md`'s paragraph on how to read an
instance (the text, the class, the answer, the program), `FORMAT.md`, the instances, the splits, the manifest;
and a test that the directory holds no file a reader needs the package to interpret. The old task's sentence
for the root README's layout table is dropped: no `benchmark/` stands at the root (the frame's default 2), and
what the root README says of EinAf's trees is
[S2.1.1](../p2.1_kernel_as_instrumentation/s2.1.1_tree_and_outcomes.md)'s.

### Task T2.3.4.5 — The Level B run

With P2.2's one-shot formalizer, `einaf from-text`, which is the arm B2 ([the arms](../README.md#the-arms)):
one run over `test`, opened with the reason *Level B gate*, every family, the seeds the record names. It
reports, a family: the rates of parse and of load, the rate of each of
[the seven outcomes](../README.md#the-outcomes), and answer accuracy; and, on the synthetic instances whose gold
class is *ambiguous* or *unsatisfiable*, how often the system reported that class and not a guess. How a
formalizer's program is read into a class is [S2.5.3](../p2.5_harness/s2.5.3_metrics.md)'s, under each reading
of *one answer* that [Q-M2.10](../open_questions.md#q-m210--what-does-ein-certifies-a-unique-model-mean-on-r)
keeps open; this run's table has a column a reading. The milestone's acceptance items 1 to 4 are checked off
with the record's id.

### Task T2.3.4.6 — The evaluation of Ein, written up for the gate

The fifth item of the gate. Gather what P2.1 to P2.3 entered in [the evaluation of Ein](../ein_evaluation.md),
add what the Level B run showed of the kernel at work on programs a model wrote (which outcomes, which
refusals, how many flagged, what a description cost), and write it up under the user's five words. Show it, with
the phase's findings page for what was found outside the phase's scope and outside Ein. **The gate is a stop**:
the user says whether EinAf goes on to [P2.4](../p2.4_loop/README.md) or an iteration of Ein comes first
([Q-M2.15](../open_questions.md#q-m215--where-does-m2-stop-for-the-next-iteration-of-ein)).

## Acceptance

- `einaf/benchmark/splits/v1.json` frozen, digested over content, stratified as above, with Zebra and every
  quoted instance in `excluded`; the sizes met or the shortfall a cell stated.
- `einaf/benchmark/manifest.toml` generated and complete in both directions, its invariants tests of the
  package and a part of EinAf's gate step.
- A run reads `test` only with a reason, and the report lists the records that opened it.
- `check_ms` taken for every instance with a program, and the threshold of the gate's sample stated.
- Layer 2 reads without the system.
- The Level B run's table and record; the milestone's Level B acceptance, items 1 to 5, each checked; the
  evaluation of Ein shown, and the user's word on what comes next.

## Risks

- **The first opening of `test` leaks.** The lock records and does not prevent; the default keeps the
  milestone's acceptance as written and names the alternative for the user.
- **A split frozen over a benchmark that is then found wrong.** A defect in an instance after the freeze is a
  new version, never an edit; the old version's tables keep their version's name.
- **The Level B run measures P2.2 on families it never saw.** That is the gate's point and may read as a
  failure: a family where the one-shot formalizer writes no program the kernel passes is a result, reported a
  family, and what of it is the kernel's (a refusal with no reason a model could use, a program that loads and
  is inert) is an entry of the evaluation.
- **Sizes are not met.** A family whose generator stops at a small size ([S2.3.2](s2.3.2_generators.md),
  T2.3.2.6) cannot fill its `large` bin; the shortfall is stated a cell, and K2 is read on the families that
  have one.
