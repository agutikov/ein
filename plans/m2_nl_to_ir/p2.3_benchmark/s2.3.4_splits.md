## Context

Two things are frozen here and they are different. The **split** is a
partition of instance ids into `dev` / `val` / `test`, versioned, digested,
and consulted by every experiment record; its point is that the `test`
split is **opened once**, in [P2.10](../p2.10_result_artifact_demo/README.md)
S2.10.1, and that the claim made there is made on instances no prompt was
tuned against. The **manifest** is the benchmark's own inventory — one entry
per instance with what it supports and how it is certified — in the form
[`corpus/`](../../../corpus/README.md) already uses for the engine's
fixtures, so that the same kind of completeness check that keeps the corpus
honest keeps the benchmark honest: *an instance with no entry fails, an
entry with no instance fails*.

### The split file

```json
{ "schema": "einaf-bench-split/1", "version": 1, "frozen": "2026-…",
  "stratified_by": ["family", "verdict", "size_bin"],
  "size_bins": { "small": [3, 5], "medium": [6, 8], "large": [9, 15] },
  "dev":  ["ordering/0001", …],  "val": […],  "test": […],
  "excluded": ["attribute_matching/zebra"],
  "digest": { "dev": "sha256:…", "val": "sha256:…", "test": "sha256:…" } }
```

`benchmark/splits/v1.json`. Stratified by family × verdict class × size bin,
where the size bin is the `entities` knob binned — which is also what makes
K2's structural generalization ([`EinAf.md` § K2](../EinAf.md#k2-structural-generalization),
*development on 3–5 entities, test on 8–15*) a property of the split rather
than a second benchmark: `dev` draws from `small`, `val` from `small` and
`medium`, `test` from all three, and the record's `size_bin` column says
which rows are the extrapolation. The digest is over the sorted id list per
split and is a field of every experiment record
([S2.5.1](../p2.5_harness/s2.5.1_experiment_record.md)).

**Sizes**, per family and verdict class, synthetic: `dev` 20 / `val` 50 /
`test` 100 — 8 × 3 × 170 = **4 080 instances**, each certified by
`ein solve -e` before admission, which at the anchors' cost is minutes and
at the largest size bin is the log [S2.3.2](s2.3.2_generators.md) T2.3.2.6
keeps. External: BBH tasks 10 / 30 / 60 % per task by a seeded shuffle,
`tracking_shuffled_objects` and `temporal_sequences` in `val` / `test` only;
CLUTRR, ProofWriter and FOLIO in `test` only, 200 items each by a seeded
draw with the chain-length / depth distribution recorded — the K3
cross-domain set ([S2.3.3 § The sources](s2.3.3_external_benchmarks.md#the-sources-and-what-each-maps-to)).

### The rule, and what enforces it

`test` is consulted by `einaf run` only with `--split test --open "<reason>"`,
and the reason is written into the record; `einaf report` lists every record
that touched `test`, and the acceptance of P2.10 is that the list has the
entries S2.10.1 registered and no others. Prompt development, the ablations
and the failure sample use `dev` and `val`. A number on `test` before P2.10
is not a bug in the tooling — it is a flag the tooling cannot remove, and
the record that carries it says so in the report.

### The manifest

`benchmark/manifest.toml`, schema `einaf-bench/1`, one entry per instance:

```toml
schema = "einaf-bench/1"

[[entry]]
id       = "ordering/0001"
path     = "ordering/0001"
family   = "ordering"
source   = "generator"            # hand | generator | external:<name>
verdict  = "unique"
supports = ["answer_accuracy", "constraint_pr", "faithfulness_exact"]
runs     = ["solve -e --json-summary {out}/summary.json"]   # the certification; [] for external
cert_ms  = 41                     # measured, the corpus's cost_ms discipline
```

The `runs` column is the corpus's — the `ein` argv with the file elided,
`{out}` substituted ([`corpus/README.md` § runs](../../../corpus/README.md)) —
so `einaf bench check` and the corpus sweep are the same shape of loop, and
`cert_ms` is what keeps the certification honest about its cost the way
`cost_ms` keeps the corpus's `slow` flag honest: measured, re-taken, and a
claim in both directions.

### Versioning

A split version is immutable. A new instance, a rejected instance re-admitted,
an external source re-fetched at a new version — each produces `v2.json`
beside `v1.json`, and a table names the version it was computed on. Two
tables on different split versions are not compared in one figure; the
report refuses to join them and says why.

## Acceptance

- `benchmark/splits/v1.json` frozen, digested, stratified as above, with
  Zebra in `excluded`; the sizes met or the shortfall per cell stated.
- `benchmark/manifest.toml` complete in both directions — the check is a
  test in the harness, run by CI, and it fails on a directory without an
  entry or an entry without a directory, on an id in two splits, on an id in
  no split and not excluded, and on a `tracking_shuffled_objects` or
  `temporal_sequences` id in `dev`.
- `einaf run --split test` refuses without `--open`, and `einaf report`
  lists the records that opened it.
- `cert_ms` taken for every synthetic entry through the harness under
  [`bench_env.sh`](../../../utils/bench_env.sh)'s machine-state banner, with
  a `slow` threshold stated and measured.
- Stage Q's layer 2 is deliverable: `benchmark/` with `README.md`,
  `FORMAT.md`, the instances, the splits and the manifest is readable with
  no engine installed — the text, the answer, the program, the theory, the
  verdict all there, a test that the directory has no file a reader needs
  the harness to interpret.

## Tasks

### Task T2.3.4.1 — The stratified draw

`einaf bench split --version 1 --seed S`: the stratification, the size bins,
the per-source rules from S2.3.3, the `excluded` list, the digests. Written
once, frozen by commit; the command refuses to overwrite an existing
version.

### Task T2.3.4.2 — The manifest and its invariants

`einaf bench manifest`: generate from the instance directories, then
maintained by hand the way the corpus's is; the completeness and
consistency checks as tests; `cert_ms` taken by the same command that
certifies.

### Task T2.3.4.3 — The `test` lock

`--open` and its record field; the report's list; the CI check that the
list is empty until P2.10 registers its entries.

### Task T2.3.4.4 — Layer 2

The readability test, `benchmark/README.md`'s paragraph on how to read an
instance without Ein, and the one sentence in the root README's layout
table that names `benchmark/` beside `bench/` and says which is which.

### Task T2.3.4.5 — The Level B run

With P2.2's one-shot formalizer: `einaf run --split test --open "Level B
gate"` on every family, once, three seeds; the per-family table of parse /
load / verdict rates and answer accuracy; the milestone README's acceptance
items 1–4 checked off with the record id. This is the one sanctioned
opening of `test` before P2.10, and it is registered as such.

## Notes

- The `small / medium / large` bins are a first cut; [P2.7](../p2.7_failure_scaling_generalization/README.md)
  S2.7.2 may want finer bins for a curve, and gets them from the `knobs`
  field, not from a new split.
- `excluded` is the right home for any instance that becomes a few-shot
  example later: an instance in a prompt is in no split, by the same rule
  as Zebra, and the contract ([S2.2.1](../p2.2_formalizer/s2.2.1_contract.md))
  checks the prompts against the split file.
