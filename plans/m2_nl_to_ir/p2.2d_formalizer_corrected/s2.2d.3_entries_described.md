# S2.2d.3 — An entry described for its use, with what it needs

**Phase:** [P2.2d](README.md) (The formalizer corrected)
**Status:** planned 2026-11-27; not started. It runs under the default of
[Q-M2.37](../open_questions/kernel/Q-M2.37-where-do-a-library-s-descriptions-of-its-rules-live.md): the
descriptions in EinAf's tree.
**Depends on:** [S2.2.4](../p2.2_formalizer/s2.2.4_passes.md): `einaf::catalogue`, its nineteen entries and
their programs, `einaf::check`, `einaf::kernel::root`, `--module-dir`;
[S2.2d.2](s2.2d.2_the_cut.md): the oracle form its measurement runs in.
**Carries:** proposals 4 and 26 of [the analysis of P2.2](../p2.2_formalizer/report/ANALYSIS.md#124-proposal-26-a-rule-described-for-its-use-by-the-library),
as one: a list read by the model as words and by the check as conditions.

## Context

The user's ranking of the library's rules by how hard they are to understand is the model's record, rule for
rule: `symmetric` right where written, `converse` four written and four wrong, `compose` never, `top` and `meet`
a copied shape, `slot-partition`'s form right and its link or its kinds wrong. The catalogue describes each of
its nineteen entries by what the rule derives; nothing says what it is for or what its arguments must be
([E-128](../evaluation/stdlib/E-128-a-library-cannot-say-what-a-selecting-fact-is-for-or-what-it-needs.md)). And
a need that is not met is silent, or a dead root whose core names one house of eleven: three of the Zebra
program's seven defects are a need of `slot-partition` or `top` unmet
([L-M2.24](../findings/model/L-M2.24-the-model-s-zebra-program-has-seven-defects-and-three-repairs-leave-r-empty.md)).

## Acceptance

- **Each entry, and each idiom of several** (the read-back is one thing to a selector and three rules to the
  library), **holds**: what it is for, in a sentence of the problem's kind; each argument's role by name, and what
  must hold of it; what it gives the hypothesis mechanism; what the kernel shows when a need is not met; what it
  is written with; a program that uses it, run by the kernel, with its answer. The catalogue has the third, the
  last and part of the first today.
- **The first text is [the analysis § 12.3](../p2.2_formalizer/report/ANALYSIS.md#123-the-eight-rules-in-the-words-of-their-use)'s
  draft of the eight rules, read by the user first**; a need the draft states and no run has shown is run before
  it is written as one.
- **The check evaluates the needs at root** and reports one finding a selecting fact, in counts read off the
  program: for `(slot-partition R isa sub Super Index)`, every kind under `Super` has a member, each as many as
  `Index` has, and every name standing in a relation read into `R` is of one of those kinds; for `(top R isa Dom
  Ran)`, both kinds have members. The kernel is not asked to read a theory's name: the entries are EinAf's.
- **Held with no model**: no such finding on any entry program or step by hand; on the model's recorded Zebra
  steps 2 and 3, the finding that says in counts what three of its defects are.
- **A module given beside the library is read with its descriptions**, in the same layout, and one with none is
  shown as undescribed.
- **Measured with the model**, a plan committed first, on the two attribute puzzles and the six texts with steps
  by hand, in the oracle form (steps 2 and 3 given the hand's step 1, so that no misread statement hides the
  selection): the catalogue as it stands, with descriptions of use, and with the names alone. Counted: each
  selecting fact against the hand's. And the word texts' module-dir condition again, with the modules described.

## Tasks

### Task T2.2d.3.1 — The description's form, and the eight rules

A file an entry or idiom, beside its program under `einaf/catalogue/`, in a layout a library's tree could take
over. Written first for the eight rules of the two attribute puzzles, then the eleven other entries.

### Task T2.2d.3.2 — The needs as conditions

Each need a condition `einaf::check` evaluates over root as `einaf::kernel::root` returns it; a need a state
above root meets (a read-back whose premises a commitment adds) is not a finding at root, which is the case
[E-123](../evaluation/diagnostics/E-123-no-value-says-whether-a-selecting-fact-was-taken-up.md) cannot tell
apart today. The finding's sentence is the one a loop would show
([S2.4.3](../p2.4_loop/s2.4.3_feedback_ladder.md)).

### Task T2.2d.3.3 — The catalogue from the descriptions, and a directory of modules

`einaf catalogue` prints what a prompt shows from the described entries, so the two cannot part;
`einaf::catalogue::Given` reads a directory in the same layout.

### Task T2.2d.3.4 — The measurement, and what the stage found

The runs and the report. For the user, on Q-M2.37: what a description was worth on these texts, and what moving
the described programs into the library's tree would take. Of Ein, to [the evaluation](evaluation/README.md): a
need of a library rule that no page states.
