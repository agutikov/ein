## Context

The user's question, in Q-M2.44: after the first iteration, is a program better left with too few constraints
(several states) or too many (inconsistent)? Constraints can be taken out by a search with no model, and only a
model reading the text again can put a missing one in. The coordinator's reading is in the question's file: a
wrong statement is a missing right one plus an extra wrong one; an inconsistency comes with a core and an omission
with nothing; so the default target is coverage, with uncertain readings written as alternatives. **This stage
measures that reading on the programs P2.2 recorded**, and most of it needs no model.

## Acceptance

- **What the model's errors are**: every defect of every recorded program on the six texts with steps by hand,
  classified against the hand's program as *omitted* (a sentence with no statement), *wrong* (a statement of a
  sentence that reads it otherwise), *extra* (a statement no sentence makes) or *theory* (a rule, a selection or an
  activator). A table per text, and the Zebra program's seven defects among them.
- **Relaxation by cores, with no model**, on every recorded program that is inconsistent at root: EinAf asks the
  bounded call, takes the core's statements, leaves one out, and asks again, for each choice. Recorded: the
  consistent programs found, how many states each leaves, and whether any is the hand's program or an
  equivalent. The cores' size and how often a core named a statement that is right.
- **Statements as hypotheses**: the uncertain statements of the same programs written `(open F)`; `ein solve
  --maximal` on them and the puzzle's question asked of each maximal set; whether mixing them with the puzzle's own
  hypotheses (`std.slots`) blurs the maximal line, as the question's file warns. Probed, not argued.
- **Confidence measured, and used** (the ruling): every generation of the formalizer asks EinAf's model call for
  its tokens' log-probabilities (the request's `logprobs`, off in every run so far) and its record keeps them;
  EinAf reads a statement's confidence from its tokens (the stage fixes how: the tokens of the statement's form,
  its first token, the least, the mean; each tried); P2.2's recorded outputs are scored by the model with no
  generation, a forward pass over the recorded text. Read: do the statements the classification calls *wrong*
  come first? The order then drives the relaxation by cores, and a statement below a threshold is written as a
  hypothesis from the start. **No stated confidence**: the ruling uses the measured one.
- **No keyword is added to Ein**, and nothing of Ein names a confidence.
- The stage's numbers, against the ruling: what coverage first and the measured confidence give on P2.2's programs.
