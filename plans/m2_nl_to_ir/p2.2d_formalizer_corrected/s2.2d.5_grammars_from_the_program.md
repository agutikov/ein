## Context

A step's grammar is rendered on what is already written, which is what the steps are for: it can quote the
text's sentences and close the vocabulary. Three things it still offers that the program cannot use. Step 3's
grammar offers `(solve :no-search)` whatever step 2 selected, and 4 of 14 programs stated a mechanism that is not
the one the kernel reports. Step 2's grammar lets an import's `:symbols` be composed name by name, and `gap`
wrote `(add product-of)`, the request of one entry and the answer of another, then declared `sum-of` as its own.
And step 1's grammar holds a `:source` to the text's sentences and the relation beside it to nothing.

## Acceptance

Each for the cut that stands when the stage runs, each held with no model by EinAf's acceptor on the recorded
outputs (refused at the token where the slip is) and on the steps by hand and the examples (accepted):

- **Step 3's grammar offers only the mechanism the program can have.** The catalogue knows which writer of H each
  entry leaves; where a selected entry's obligations write H the `:no-search` alternative is not rendered, and
  where nothing writes H a mechanism form is required.
- **An import lists an entry's names together**, a request with its answer; and no `relation` declaration takes
  a name an offered module declares.
- **A statement's relation is an alternative a sentence**: for each sentence of the text, the relation names made
  of its words, which a context-free grammar can state because the `:source` is already held to the sentences.
  Rendered only if S2.2d.4 found the rule holds on the steps by hand with a verb's forms allowed.
- For each rendering: its size, and, on the recorded calls, how many first choices it refuses
  (`chosen_again`), since each refusal is where greedy decoding can leave its own text.

**With the model**, a plan committed first: the calls whose output a new rendering refuses, run again under it
with the stop on a loop; what each then writes.
