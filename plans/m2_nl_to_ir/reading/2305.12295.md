# **Logic-LM: Empowering Large Language Models with Symbolic Solvers for Faithful Logical Reasoning**

**Liangming Pan et al., 2023, EMNLP.**

Logic-LM — одна из работ по нейросимвольным рассуждениям (*neuro-symbolic reasoning*), в которой LLM используется не как непосредственный механизм логического вывода, а как средство преобразования естественного языка в формальное представление, над которым затем работает специализированный символический решатель.

Основная идея работы заключается в разделении двух принципиально разных задач:

- **Autoformalization** — построение формального представления задачи, описанной на естественном языке.
- **Symbolic reasoning** — получение ответа посредством формально определённых алгоритмов вывода.

В контексте Ein и EinAf эта работа особенно интересна как архитектурно близкий подход к интеграции LLM и формального решателя. При этом Logic-LM использует несколько готовых формальных языков и решателей вместо единого механизма представления знаний и дедукции.

## **1. Постановка проблемы**

Авторы выделяют несколько фундаментальных недостатков рассуждений посредством LLM:

- **Unfaithful reasoning** — заключение не обязательно следует из сгенерированной цепочки рассуждений.
- **Hallucinations** — появление необоснованных предпосылок и промежуточных утверждений.
- **Reasoning depth degradation** — падение точности при увеличении количества необходимых шагов вывода.
- **Non-linear reasoning** — трудности с перебором гипотез, рассмотрением альтернатив, исключением вариантов и рекурсивным выводом.

Последний пункт особенно интересен. Обычный Chain-of-Thought преимущественно имитирует последовательную цепочку рассуждений, тогда как пространство логического поиска в общем случае имеет значительно более сложную структуру.

При этом необходимо различать две сложности:

| Сложность                 | Задача                                    |
| ------------------------- | ----------------------------------------- |
| Representation complexity | Формальное описание задачи                |
| Reasoning complexity      | Получение решения из формального описания |

Эти сложности не обязаны коррелировать. Например, описание задачи о 100 ферзях почти не сложнее описания задачи о 8 ферзях, хотя характеристики пространства поиска отличаются существенно.

Именно это разделение лежит в основе Logic-LM.

## **2. Архитектура**

Архитектура Logic-LM по разделу 3 оригинальной работы.

Формально архитектуру можно представить как композицию трёх функций:

$$
A=I(S(F(P,G)))
$$

где:

| Обозначение | Значение           |
| ----------- | ------------------ |
| $P$     | Описание задачи    |
| $G$     | Цель, вопрос       |
| $F$     | Problem Formulator |
| $S$     | Symbolic Solver    |
| $I$     | Result Interpreter |
| $A$     | Ответ              |

Важно, что Logic-LM не является новой архитектурой нейронной сети. Это framework, построенный поверх существующих LLM, не требующий их дополнительного обучения или fine-tuning.

## **3. Problem Formulator — автоформализация**

LLM получает грамматику целевого языка, инструкцию и несколько примеров перевода. В экспериментах используется от одного до пяти in-context examples.

Разработано четыре разных формальных представления.

| Представление     | Решатель          | Тип задач                  |
| ----------------- | ----------------- | -------------------------- |
| Logic Programming | Pyke              | Дедуктивный вывод          |
| First-Order Logic | Prover9           | Доказательство теорем      |
| CSP               | python-constraint | Удовлетворение ограничений |
| SAT/SMT           | Z3                | Аналитические задачи       |

Выбор формального языка в экспериментах определяется типом benchmark, а не универсальным автоматическим механизмом выбора логики.&#x20;

### **3.1. Logic Programming**

Используется Prolog-подобное представление, состоящее из фактов, правил и запросов.

Простой пример автоформализации:

> Все металлы проводят электричество. Все железные предметы являются металлическими. Гвоздь сделан из железа. Проводит ли гвоздь электричество?

Факты:

```
MadeOfIron(Nail, True)
```

Правила:

```
MadeOfIron(x, True) → Metal(x, True)
Metal(x, True) → ConductsElectricity(x, True)
```

Запрос:

```
ConductsElectricity(Nail, True)
```

Решатель Pyke поддерживает forward chaining и backward chaining.

MadeOfIron(Nail, True)

Metal(Nail, True)

ConductsElectricity(Nail, True)

Отдельно стоит обратить внимание на представление отрицания через булевый аргумент предиката:

```
ConductsElectricity(Nail, False)
```

Это не встроенное логическое отрицание произвольной формулы, а соглашение о представлении отрицательных фактов. Семантика такого представления определяется программой и решателем.

### **3.2. First-Order Logic**

Для более выразительных задач используется FOL и автоматический доказатель Prover9.

Пример:

> Все студенты, сдавшие экзамен, получают сертификат. Ни один студент, получивший сертификат, не обязан пересдавать экзамен. Анна — студентка, сдавшая экзамен.

$$
\forall x\;(Student(x)\land Passed(x) \rightarrow Certificate(x))
$$

$$
\forall x\;(Student(x)\land Certificate(x) \rightarrow\neg Retake(x))
$$

$$
Student(anna)\land Passed(anna)
$$

Запрос:

$$
Retake(anna)
$$

Prover9 использует клаузальное представление формул и resolution-based inference.

В общем случае для классификации утверждения $Q$ относительно теории $T$ необходимо различать:

| Результат | Условие                                  |
| --------- | ---------------------------------------- |
| True      | $T\models Q$                         |
| False     | $T\models\neg Q$                     |
| Unknown   | Ни одно из двух следствий не установлено |

Здесь есть существенная теоретическая оговорка: отсутствие найденного доказательства не означает отсутствия логического следствия. Для произвольной FOL невозможен универсальный завершающийся алгоритм разрешения выводимости.

Это накладывает принципиальное ограничение на интерпретацию результата `Unknown`.

### **3.3. Constraint Satisfaction Problem**

Задача представляется тройкой:

$$
CSP=(X,D,C)
$$

где $X$ — переменные, $D$ — их домены, $C$ — ограничения.

Например, имеется пять книг на полке:

- Красная левее синей.
- Зелёная правее синей.
- Чёрная находится на третьем месте.
- Все книги занимают разные позиции.

Формализация:

```
Variables:
    red, blue, green, black, white

Domains:
    {1, 2, 3, 4, 5}

Constraints:
    red < blue
    blue < green
    black == 3
    AllDifferent(red, blue, green, black, white)
```

Одна из допустимых моделей

Решатель определяет допустимые присваивания переменных. Для проверки необходимой истинности некоторого свойства нужно проверить его во всех допустимых моделях либо установить невозможность его отрицания.

### **3.4. SAT/SMT**

Наиболее сложные аналитические задачи передаются Z3.

Например:

> Ксена и ровно три других техника ремонтируют радиоприёмники.

Возможное представление:

$$
Repairs(Xena,Radio)
$$

$$
\sum_{t\in Technicians\setminus\{Xena\}} [Repairs(t,Radio)]=3
$$

Такие представления позволяют работать с конечными доменами, мощностями множеств, арифметическими ограничениями, отношениями и комбинаторными задачами.

Концептуально проверка утверждения $Q$ может осуществляться следующим образом:

$$
UNSAT(T\land\neg Q) \implies T\models Q
$$

Это позволяет использовать поиск контрмодели для установления логического следствия.

## **4. Self-Refinement — итеративное исправление формализации**

Это второй важный компонент работы после самого разделения автоформализации и вывода.

LLM может сгенерировать формальное представление, содержащее:

- синтаксические ошибки;
- свободные переменные;
- неправильные аргументы предикатов;
- неподдерживаемые конструкции языка.

Когда решатель возвращает ошибку, она вместе с ошибочным представлением передаётся обратно в LLM.

Процесс повторяется до успешного исполнения или исчерпания допустимого количества попыток.

Принципиальная проблема этого подхода заключается в следующем:

**Синтаксически корректная формализация не обязательно семантически корректна.**

Например, если исходный текст говорит, что A находится левее B, а LLM записала:

```
A > B
```

вместо:

```
A < B
```

решатель не сообщит об ошибке. Он корректно решит другую задачу.

Self-Refinement в Logic-LM исправляет преимущественно ошибки исполнимости, а не ошибки соответствия формализации исходному тексту.

## **5. Result Interpreter**

Последний компонент переводит результат решателя обратно в естественный язык.

В зависимости от задачи используются два подхода:

| Подход     | Пример                                                |
| ---------- | ----------------------------------------------------- |
| Rule-based | `Entailment` → `True`                                 |
| LLM-based  | Присваивания переменных → ответ на естественном языке |

Например, решатель возвращает:

```
red   = 1
blue  = 2
black = 3
green = 4
white = 5
```

Интерпретатор преобразует это в ответ: «Красная книга находится первой, синяя — второй» и т. д.

Использование LLM на этом этапе потенциально возвращает проблему галлюцинаций. Если ответ может быть получен непосредственно из формального результата, детерминированный интерпретатор предпочтительнее.

## **10. Основные ограничения с точки зрения логики**

Здесь начинается уже мой анализ работы, а не пересказ утверждений авторов.

### **10.1. Soundness не решает проблему autoformalization**

Пусть существует предполагаемая формальная теория $T^*$, соответствующая смыслу исходного текста.

LLM генерирует теорию $T$.

Решатель устанавливает:

$$
T\vdash Q
$$

Если система вывода sound, то:

$$
T\vdash Q\implies T\models Q
$$

Однако из этого не следует:

$$
T^*\models Q
$$

Для такой гарантии необходима дополнительная связь между исходной и сгенерированной теориями.

Например, если они сформулированы на одном языке, достаточным условием будет:

$$
T^*\models T
$$

При этом для сохранения всех исходных следствий в обе стороны потребуется более сильное условие — логическая эквивалентность либо соответствующее сохранение семантики при переводе между языками.

Logic-LM не предоставляет механизма формальной проверки этого соответствия.

### **10.2. Неоднозначность формализации**

Рассмотрим утверждение:

> У каждого человека есть друг.

Одна формализация:

$$
\forall x\;(Person(x)\rightarrow \exists y\;Friend(x,y))
$$

Другая:

$$
\exists y\;\forall x\;(Person(x)\rightarrow Friend(x,y))
$$

В первом случае у каждого человека может быть свой друг. Во втором существует один общий друг для всех людей.

Обе формулы синтаксически корректны. Обе могут успешно обрабатываться решателем. Но их семантика принципиально различна.

Поэтому проблема autoformalization не сводится к генерации корректного синтаксиса.

### **10.3. Отсутствие единого формального языка**

Logic-LM фактически использует четыре отдельных стека логического вывода.

**Logic Programming**

Pyke

**First-Order Logic**

Prover9

**CSP**

python-constraint

**SMT**

Z3

Что произойдёт, если задача требует одновременно:

- дедуктивного вывода;
- транзитивного замыкания;
- арифметических ограничений;
- экзистенциальных утверждений;
- комбинаторного поиска;
- рассуждений о свойствах самих отношений?

Отдельные решатели способны покрывать несколько таких категорий, но в Logic-LM не разработана общая семантика взаимодействия между ними, объединения теорий и передачи промежуточных результатов.

### **10.4. Отсутствие интеграции с процессом рассуждения LLM**

В Logic-LM LLM в основном выполняет первоначальную трансляцию. Затем решение делегируется целиком внешнему механизму.

Обратная связь ограничена исправлением формализации.

Не исследуется полноценное взаимодействие, в котором LLM могла бы:

- создавать вспомогательные определения;
- выдвигать леммы;
- запрашивать частичный вывод;
- исследовать контрмодели;
- выбирать направления поиска;
- расширять формальную теорию;
- пересматривать смысловое представление задачи.

Иначе говоря, Logic-LM является прежде всего **solver-augmented LLM**, а не глубоко интегрированной нейросимвольной системой рассуждений.

### **10.5. Отсутствие оценки proof faithfulness**

Эксперименты в основном измеряют точность выбора ответа.

Не оцениваются систематически:

- эквивалентность формализаций;
- корректность всей цепочки преобразований;
- минимальность доказательства;
- полнота формального представления;
- независимая проверяемость доказательства.

Правильный ответ и правильное доказательство — разные вещи. Особенно на benchmark с несколькими вариантами ответа.

Но это преимущество необходимо доказать — выразительность единого представления может сопровождаться снижением эффективности специализированных алгоритмов.

## **12. Какие эксперименты стоило бы воспроизвести в EinAf**

Я бы использовал Logic-LM непосредственно как baseline, выделив следующие исследовательские вопросы.

| Research question           | Эксперимент                                                                |
| --------------------------- | -------------------------------------------------------------------------- |
| RQ1: Autoformalization      | Точность перевода NL → Ein относительно LP/FOL/CSP/SMT                     |
| RQ2: Reasoning depth        | Зависимость accuracy от глубины доказательства                             |
| RQ3: Model size             | Зависимость accuracy от размера LLM                                        |
| RQ4: Unified representation | Все пять benchmarks на одном решателе                                      |
| RQ5: Semantic refinement    | Исправление не только синтаксических, но и смысловых ошибок                |
| RQ6: Interactive reasoning  | Однократная автоформализация против итеративного LLM–solver взаимодействия |
| RQ7: Theory synthesis       | Генерация новых определений, правил и вспомогательных теорий               |
| RQ8: Efficiency             | Время, токены, память, объём пространства поиска                           |
| RQ9: Proof correctness      | Независимая проверка доказательств                                         |

Особенно интересен эксперимент с небольшими моделями — например, 1.5B, 3B, 7B и 14B параметров.

Logic-LM исследует преимущественно проприетарные GPT-модели. Вопрос о том, насколько малой может быть LLM, если практически весь дедуктивный вывод вынесен за её пределы, в этой работе остаётся открытым.

## **13. Научный вклад работы**

Logic-LM не предлагает новую логику, новый calculus, новый алгоритм доказательства или новую архитектуру нейросети.

Её вклад заключается в другом:

1. Экспериментальная демонстрация эффективности разделения автоформализации и логического вывода.
2. Применение единой архитектурной парадигмы к нескольким классам логических задач.
3. Использование ошибок решателя в качестве обратной связи для LLM.
4. Демонстрация большей устойчивости к увеличению глубины рассуждений.
5. Выявление автоформализации как одного из основных узких мест нейросимвольных систем.

Главный вывод, который я бы вынес из этой статьи для EinAf: **нет необходимости доказывать с нуля, что использование LLM для автоформализации в сочетании с символическим решателем повышает точность логических рассуждений.** Logic-LM уже предоставляет экспериментальные свидетельства в пользу этой гипотезы.

Научная новизна EinAf относительно Logic-LM могла бы заключаться в едином формальном представлении, синтезе теорий, более глубокой интеграции символического вывода в процесс рассуждения LLM и исследовании того, насколько такой подход позволяет компенсировать ограниченные reasoning capabilities малых языковых моделей.
