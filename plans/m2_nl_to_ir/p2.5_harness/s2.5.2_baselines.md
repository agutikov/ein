**Depends on:** [S2.5.1](s2.5.1_experiment_record.md) — every condition is

**Research plan:** [`EinAf.md` § Stage D](../EinAf.md#stage-d--establish-baselines).

## Context

*A research result is meaningless without credible alternatives*, and the
plan names the alternatives that would explain a positive result away: the
model already knew the answer (B0); thinking longer would have found it
(B1); formalizing once was enough (B2); the kernel is a retry trigger and
nothing more (B3); one word of verdict is all the information that matters
(B4). B5 is the claim. The comparison that isolates symbolic verification is
therefore **not** *LLM vs Ein* — B5 spends more calls than B0 and would win
a naive comparison by spending — but *same model, similar inference budget,
different feedback information*.

| | receives | produces | the answer is |
|---|---|---|---|
| **B0** | the text, an answer-format instruction | text | extracted ([T2.5.2.4](#task-t2524--answer-extraction-and-its-own-error-rate)) |
| **B1** | the text, *think step by step*, then up to *k* *reconsider your answer* turns until the budget is spent | text | extracted from the final turn |
| **B2** | the S2.2.1 contract: spec, catalogue, few-shot, text | one program | the kernel's goal bindings, or the verdict |
| **B3** | B2, then the loop at **F0** — the kernel says only *not yet* | a program per iteration | the kernel's |
| **B4** | B2, then the loop at **F2** — one word: inconsistent / multiple models / unknown | a program per iteration | the kernel's |
| **B5** | B2, then the loop at **F8** — the full feedback object | a program per iteration | the kernel's |

Two things are fixed across B3–B5 so that the level is the only variable:
the strategy is **repair** (the model sees its own theory and the feedback;
regenerate is G-row material in [P2.6](../p2.6_ablations/README.md), not a
baseline), and the termination policy is [S2.4.1](../p2.4_loop/s2.4.1_state_machine.md)'s
with the same budgets. At F0 the kernel still decides *whether* to
continue — success stops the loop — it just says nothing about *why*; that
is the point of B3, and it is why B3 is a loop and not a fixed number of
retries.

Where the plan says *where possible add another symbolic backend*, the
answer is [P2.8](../p2.8_representations/README.md), later and on its own:
a sixth column here would be a sixth system, and this stage has one.

## Acceptance

- Six conditions as six `config.json` files under `einaf/conditions/`,
  each with a pre-registration paragraph; a config whose `condition` name
  does not match its `level` / `strategy` / prompt fields is rejected.
- The budget rule is a number with a tolerance, measured on `dev`, written
  into each condition's config as `budgets.output_tokens`, and the actual
  spend is a column of every table that shows the condition.
- The B0 / B1 extractors agree with a hand-read sample of 100 answers at a
  measured rate, and that rate is a footnote of the main table.
- B2–B5 involve **no extraction**: the answer is read from the feedback
  object — goal bindings for `unique`, the verdict itself for the
  `ambiguous` and `unsat` classes.

## Tasks

### Task T2.5.2.1 — Six conditions, six configs

`einaf/conditions/B0.json … B5.json`, differing only in the fields that
define them; everything else — model SHA, seeds, split, Ein commit — comes
from the experiment's base config at run time, so the six can never drift
apart on a field that is not the variable. The condition name is *derived*
(`B4` ⇔ `level = F2 ∧ strategy = repair ∧ prompts = the contract's`) and
checked, not declared.

### Task T2.5.2.2 — B0 and B1

B0 is the plain model: the problem text and one line naming the answer
format the source uses — `(A)…(E)` for BBH, `True / False / Unknown` for
ProofWriter and FOLIO, an entity name for the synthetic families, and for
the `ambiguous` / `unsat` classes the explicit options *the question cannot
be answered* / *the statements contradict each other* so that B0 can say
what the kernel says. No specification, no stdlib, no examples.

B1 is the plan's *explicit reasoning / self-reflection*: *think step by
step, then answer*, followed by *reconsider your reasoning and answer
again* turns until the output-token budget of [T2.5.2.3](#task-t2523--the-budget-and-the-matching-rule)
is spent; the last turn's answer counts. Both prompts are stored by hash
like every other.

### Task T2.5.2.3 — The budget and the matching rule

The primary unit is **output tokens per task** — what the model generates
is what costs, and it is the unit the envelope records exactly; calls and
wall are secondary and reported beside it. The rule: run B5 on `dev`, take
its median output-token spend per family; give B1 and B3 that budget
±10 % (B1 as reflection turns, B3 as iterations), and let B4 and B5 stop
when they stop. Every condition's *actual* spend is a column next to the
budget it was given, so a reader sees the match rather than trusting it.
The tolerance and the unit are written once, here and in each config, and
the plan's phrase *similar inference budget* means this number.

### Task T2.5.2.4 — Answer extraction, and its own error rate

For B0 / B1 a deterministic extractor per source format: a regex for the
`(X)` option, a normaliser for entity names (case, articles, the
benchmark's own alias list), the three-word vocabulary for T/F/U, and the
two refusal phrasings for the verdict classes. An extractor is a source of
error that favours whichever side is stricter, so its agreement with a
**hand-read sample of 100** B0/B1 answers is measured before the main table
and reported in its footnote. B2–B5 never go through it: the kernel's goal
bindings are the answer, rendered through the program's own `:goal-text`
template, and a `multiple_models` or `inconsistent` verdict *is* the
answer on the instances whose gold says so.

### Task T2.5.2.5 — Pre-registration and tests

Each condition's config carries the paragraph that says what a high or low
number under it means for the claim — B0 high on a family: *the family is
in the model*; B3 ≈ B5: *the kernel is a retry trigger*; B4 ≈ B5: *F3–F8
add nothing* — so the table is read by a rule written before it exists.
Tests: the extractors on a fixture of 30 hand-written answers per format,
including the adversarial ones (two options mentioned, an answer in
Russian, a refusal).
