# S2.5.1 — The experiment record and the canonical workflow

**Phase:** [P2.5](README.md) (Baselines, metrics, records — Stages D, H, N)
**Estimate:** 3 days
**Depends on:** [S2.1.2](../p2.1_kernel_as_instrumentation/s2.1.2_feedback_object.md) —
`ein-feedback/1` is what `solver.jsonl` holds; [S2.2.2](../p2.2_formalizer/s2.2.2_llama_server_and_client.md) —
the invocation envelope is the record's first field. **Runs before the

**Research plan:** [`EinAf.md` § Stage N](../EinAf.md#stage-n--reproducibility);

## Context

Stage N is the plan's last-but-three stage and this milestone's first
deliverable after the formalizer, for a reason M1a already paid for: every
number in [`baseline.md`](../../../docs/history/m1a_rust/measurements/baseline.md)
names its instrument and its machine state, the PyPy columns are frozen
because the instrument that took them is gone, and `cost_ms` in the corpus
is *a measured claim, checked in both directions*
([`corpus_cost.md`](../../../docs/history/m1a_rust/measurements/corpus_cost.md)).
The same discipline applied to an LLM experiment says: a number without the
model file's SHA, the prompt's hash, the seed, the Ein commit and the split's
digest is not a number — it is a demo that happened once.

So the record is the **unit of evidence**. A table is a view over records;
a plot is a view over records; a sentence in [M5](../../m5_presentation/README.md)
cites a record id. Nothing in this milestone is allowed to exist only in a
terminal scrollback.

**Where.** `experiments/` at the repository root. The plan suggests
`docs/experiments/`; declined in one sentence: `docs/` is prose and a record
is data — JSONL, programs, gzipped event streams — that prose is *generated
from*, and when the milestone closes the measurement *documents* go to
[`docs/history/`](../../../docs/history/m1a_rust/README.md) the way M1a's
did while the records stay where they are and are cited by id.

**What one record is.**

```text
experiments/
  README.md                 the index — one line per experiment: id · date · what it is
                            evidence for · split + digest · Ein commit · status
  _prompts/<sha256>.tmpl    every prompt ever used, by content hash; never edited
  _reports/<name>/          tables and plots, each with a footer naming its record ids
  exp-0042/
    README.md               written BEFORE the run — the pre-registration: what this
                            experiment is evidence for, and what reading each outcome has
    config.json             einaf-record/1 — see below
    machine.txt             utils/bench_env.sh output, verbatim
    tasks.jsonl             the instance ids, one per line, with split + digest
    generations.jsonl       every LLM call: the S2.2.2 envelope (model SHA, server id,
                            grammar SHA, request, response, usage, timing)
    theories/<task>/<iter>.ein   every program, every iteration — plain kernel input
    solver.jsonl            every ein-feedback/1 object, with the path of the
                            ein-summary/1 it was produced from
    transitions.jsonl       the loop's transcript (S2.4.1)
    events/<task>/<iter>.jsonl.gz   ein-events/1, only when the level needs it (F7, F8)
    metrics.json            einaf-metrics/1 — derived, by `einaf evaluate`
```

`config.json` names, and a missing field is a rejected record:

```json
{ "schema": "einaf-record/1", "id": "exp-0042",
  "condition": "B5", "level": "F8", "strategy": "repair",
  "budgets": {"iterations": 6, "output_tokens": 4000, "ein": {"max_time": 30, "max_enterings": null}},
  "model": {"name": "…", "file_sha256": "…", "server_image_digest": "…"},
  "generation": {"temperature": 0.0, "seed": [1, 2, 3], "max_tokens": 2048},
  "prompts": {"system": "sha256:…", "ontology": "sha256:…", "theory": "…", "instance": "…", "query": "…", "repair": "…"},
  "spec_commit": "…", "stdlib_manifest_sha256": "…",
  "ein": {"commit": "…", "version_output": "ein 0.1.0\nprotocol ein-events/1\n…", "solver_config": { "…": "the 17 fields, from the summary's config block" }},
  "benchmark": {"manifest_version": "…", "split": "val", "split_digest": "…"},
  "unknown_derived": true }
```

The last field is [Q-M2.1](../open_questions.md#q-m21--when-is-the-kernel-frozen)'s
bridge made visible: `true` while the loop derives `unknown` from
`(type, k, exhausted, core)` itself, `false` the day M1d gives the engine a
word for it — so a reader can tell which records were taken under which
instrument.

## Acceptance

- `experiments/` exists with its index, the prompt store and the record
  layout above; `einaf run` creates a record and refuses to write into an
  existing one.
- `einaf evaluate <record>` writes `metrics.json` from the record's files
  and nothing else, and is deterministic: two evaluations of one record are
  byte-identical; a record with a missing `config.json` field is rejected
  with the field named.
- `einaf report` over two identical records yields identical tables, and
  every table it emits carries a footer with the record ids and their
  `config.json` digests.
- [Q-M2.1](../open_questions.md#q-m21--when-is-the-kernel-frozen) is
  decided and written beside its entry: frozen **per experiment, by
  commit**.
- The first seed-set run of [S2.2.5](../p2.2_formalizer/s2.2.5_from_text.md)
  is `exp-0001`.

## Tasks

### Task T2.5.1.1 — The layout and `einaf-record/1`

The directory shape and the `config.json` schema above, with a versioning
rule copied from [`events.md`](../../../docs/kernel/inference/events.md):
an added optional field keeps the number, a removed or renamed field bumps
it, and `einaf evaluate` refuses a schema it does not know. `machine.txt` is
[`bench_env.sh`](../../../utils/bench_env.sh)'s output verbatim — the
same instrument M1a's measurements were taken under, not a new one.

### Task T2.5.1.2 — `einaf run`: allocation, pre-registration, immutability

Ids are `exp-NNNN`, sequential, allocated by adding the index line — which
means the **index line and the pre-registration `README.md` exist before
the first LLM call**, and a run that was never pre-registered cannot have
an id. A record is write-once: `run` refuses an existing directory, a
re-run is a new id, and the index line of an abandoned run says `abandoned`
rather than disappearing. The only file ever rewritten is `metrics.json`,
and only by an evaluator whose own commit is written into it.

### Task T2.5.1.3 — `einaf evaluate` and `einaf report`: records only

`evaluate` reads a record and writes `metrics.json`
([S2.5.3](s2.5.3_metrics.md) owns the definitions); it does not touch the
network, the model or the engine. `report` reads one or more records and
emits markdown tables and SVG plots under `experiments/_reports/<name>/`,
each with a provenance footer; its only inputs are record directories, so
**a number that cannot be traced to a record is not in a table** — there is
no way to hand it one. The main table, the ablation tables and the curves
of [P2.7](../p2.7_failure_scaling_generalization/README.md) are all
`report` invocations named in their stage files.

### Task T2.5.1.4 — Q-M2.1 decided: frozen per experiment, by commit

Written beside the question: the kernel is frozen **per experiment**, by
the `ein.commit`, `stdlib_manifest_sha256` and `solver_config` fields; a
kernel change between experiments is a replication question — the
baselines ([S2.5.2](s2.5.2_baselines.md)) re-run on the new commit before
any ablation does, and the report refuses to put two Ein commits in one
table without a `--mixed-commits` flag that prints the fact in the
table's caption. A kernel change *inside* a phase's table is thereby
impossible rather than forbidden.

### Task T2.5.1.5 — Size and git

Generations, theories and feedback objects are text and small; the corpus
is 128 entries and `zebra2`'s solve is 29 ms, so `solver.jsonl` stays in
kilobytes per task. Event streams are the exception — the verbose stream of
one solve can be millions of lines — so they are written only for levels
that read them (F7, F8) and gzipped. Policy: a file over **1 MiB** is
gzipped; a file over **10 MiB** is not committed — it goes under
`experiments/_blobs/` (gitignored) and its record carries an `_index.json`
entry with SHA-256 and size, the same digest family as
`stdlib/MANIFEST.sha256`. Everything else is committed: the records are the
evidence and Stage Q's layer 4 (*raw results, not just charts*) is the
repository itself, with the blob archive as a release asset.

### Task T2.5.1.6 — Tests

Round-trip (a fixture record evaluates to a known `metrics.json`, twice,
byte-identical); rejection (each required field removed in turn, the
evaluator names it); report determinism (two copies of one record, one
table); allocation (a second `run` into `exp-0001` refuses).

## Notes

- The prompts live under `_prompts/` by hash and nowhere else; the
  templates in `einaf/prompts/` ([S2.2.4](../p2.2_formalizer/s2.2.4_passes.md))
  are the *working copies*, and a record names the hash, so editing a
  working copy cannot change what a past experiment used.
- The `generations.jsonl` line for a call is the whole envelope including
  the response text — the raw model output the plan insists on releasing.
