## Context

*Do not reduce evaluation to answer accuracy.* An answer can be right for
the wrong theory, a theory can be valid and unfaithful, a repair can fix
one error and add two, and a system can be accurate and unaffordable. Four
layers, defined **once**, in one module, computed from records only by
`einaf evaluate`, each with a fixture whose value was worked out by hand
before the code existed — the discipline of
[`summary_properties.rs`](../../../ein.rs/crates/ein-cli/tests/summary_properties.rs),
which holds the engine's counters to thirteen arithmetic identities, applied
to the numbers the paper will print.

Everything is reported **per family and aggregate**, and the aggregate is a
**macro-average over families**: the claim is about reasoning families, the
families differ in size by orders of magnitude (a BBH task has hundreds of
items, a hand-written anchor set has five), and a micro-average would let
`logical_deduction`'s item count decide the number. Per-class (unique /
ambiguous / unsat) breakdowns are always beside the family figure.

| layer | metric | definition | denominator |
|---|---|---|---|
| **H1** final task | answer accuracy | the rendered answer equals the gold answer, or the reported verdict equals the gold verdict on the `ambiguous` / `unsat` classes | all instances |
| | exact match | string-exact on the normalised answer — the strict form, reported beside the lenient one | all |
| | unique-answer accuracy | accuracy restricted to gold-`unique` | gold-`unique` |
| | ambiguity detection | precision and recall of *reported `multiple_models`* against *gold `ambiguous`* | the class, both ways |
| | contradiction detection | precision and recall of *reported `inconsistent`* against *gold `unsat`* | the class, both ways |
| **H2** formalization | parse success · load success · solver acceptance | the feedback object's outcome is not `invalid` at the respective stage; *acceptance* = an outcome other than `invalid` and `unknown` | all |
| | semantic faithfulness | the fraction of instances whose final theory has **zero** faithfulness events ([S2.4.4](../p2.4_loop/s2.4.4_faithfulness.md)) | instances with a program |
| | constraint recall · precision | over [S2.3.2](../p2.3_benchmark/s2.3.2_generators.md)'s unit — a fact form or an activator form, canonical text — against the canonical theory; an invented constraint is a false positive, a dropped one a false negative | **synthetic only**; external instances report `n/a`, never 0 |
| **H3** repair | fraction repaired | initially failing instances (B2's outcome ≠ `unique`-and-correct) that end correct | initially failing |
| | iterations to repair | median and the distribution, from the transcript | repaired |
| | new errors introduced | a repair whose diff adds a diagnostic kind or a faithfulness event that the previous iteration did not have | repairs |
| | semantic hallucination rate | repairs that add a form in a *generated* B2 category without a licensing span | repairs |
| | repair-cycle rate | transcripts terminated by the cycle condition | loop runs |
| **H4** system | LLM calls · tokens in / out | from the envelopes | per task, per condition |
| | wall | the harness's clock around each process and each call | per task |
| | Ein runtime · enterings · saturation rounds · layers · no-goods | the summary's `stats`: `enterings_total`, `saturate_count`, `layers_explored`, `nogoods_emitted`; wall is the harness's, `--timing` the phase breakdown when asked | per solve |
| | memory | peak RSS of the `ein` process, taken the way [`e2e_baseline.py`](../../../utils/e2e_baseline.py) takes it | per solve |
| | cost per correctly solved task | total output tokens (and, beside it, total calls) over correctly solved count | per condition |

And the two numbers the milestone turns on, each with its denominator
printed:

```text
certified(i)  :=  outcome = unique  ∧  search_complete            (from ein-feedback/1)

P(correct  | certified)  =  #{certified ∧ answer correct}   / #{certified}
P(faithful | certified)  =  #{certified ∧ zero faithfulness events} / #{certified}
```

On synthetic instances *faithful* is arithmetic; on external ones it is
[Q-M2.3](../open_questions.md#q-m23--what-is-the-unit-of-faithfulness-without-a-gold-theory)'s
judge, and the number carries the flag that says so. The **gap** between the
two is the plan's faithfulness-vs-satisfiability distinction as a number;
every table that shows either shows both.

## Acceptance

- `einaf/metrics/` defines every metric above exactly once, as a function
  `(record) → (value, numerator, denominator)`; `metrics.json` is
  `einaf-metrics/1` and carries all three for every metric.
- A fixture record — twelve tasks across three families and three classes,
  with hand-computed values for every metric — evaluates to those values.
- `einaf evaluate` over the same record twice is byte-identical; it reads
  no file outside the record.
- The two conditional probabilities are reported with their denominators
  and, on external instances, with the faithfulness-judge flag.
- The one-shot numbers of [S2.2.5](../p2.2_formalizer/s2.2.5_from_text.md)'s
  seed-set record re-evaluate under this module without change of meaning.

## Tasks

### Task T2.5.3.1 — The module and `einaf-metrics/1`

`einaf/metrics/h1.py … h4.py`, one function per metric with the three-part
return, a registry that names them, and `metrics.json`'s schema with the
same versioning rule as the record's. A metric that cannot be computed on
an instance (constraint recall on BBH) yields `n/a` with the reason, never
a zero — a zero in a table is a claim.

### Task T2.5.3.2 — H1 and H2

The answer comparison per source format (the normaliser of
[S2.5.2](s2.5.2_baselines.md) T2.5.2.4, shared, so B0 and B5 are compared
by one rule); the verdict comparison on the two classes; precision and
recall both ways for detection, because a loop that says *ambiguous* on
everything has perfect recall. H2's three success rates from the feedback
object's outcome; faithfulness from the events; constraint P / R from the
canonical theory, over forms in canonical text, with the unit's definition
imported from S2.3.2 rather than restated.

### Task T2.5.3.3 — H3 and H4

H3 entirely from `transitions.jsonl` — the per-repair diff, the
diagnostics and faithfulness events per iteration, the termination
condition — so a repair metric is a fold over a transcript. H4 from the
envelopes (tokens, calls), the harness's own clock, the summary's `stats`
block, and peak RSS measured as M1a's end-to-end baseline measured it, the
process cold. Cost per correctly solved task is the one H4 number that
divides by an H1 number, and its denominator is printed.

### Task T2.5.3.4 — The two conditional probabilities

`certified` from the feedback object; both probabilities with numerator
and denominator; the external-instance flag; and a third line, the gap,
because it is what [M5](../../m5_presentation/README.md) § 9.3 is about.

### Task T2.5.3.5 — Fixtures and tests

The twelve-task fixture record under `einaf/tests/fixtures/exp-fixture/`,
hand-worked in a `VALUES.md` beside it that shows the arithmetic; one test
per metric; the determinism test; and a test that removes each file of the
record in turn and checks the evaluator names what it could not compute.

## Notes

- *Exact match* and *answer accuracy* are two columns on purpose: the
  lenient one is what the plan calls accuracy, the strict one is what a
  sceptical reader will recompute.
- `enterings_alive` / `enterings_dead_*`, `facts_merged`, `forced_positives`
  and `nogoods_subsumed` stay in the record and out of the tables unless a
  scaling curve in [P2.7](../p2.7_failure_scaling_generalization/README.md)
  asks for one.
