## Context

The old P2.3 had the right shape — lift the IR into GBNF so the model can
only emit valid IR, then restrict the grammar per task — and one wrong
premise: that the grammar would be generated *from the Python parser's
keyword inventory*. There is no Python parser, and there is something
better: [`00_ebnf.md`](../../../docs/kernel/ir/03-ein-lang/00_ebnf.md) is
**the source of truth for what parses**, transcribed from the Lark grammar
before it left, checked against the recursive-descent parser by a 78-case
decision table, and already normative. The generator reads the EBNF blocks
of that page and emits GBNF; the page cannot drift from the parser without
the kernel's gate noticing, and the grammar cannot drift from the page
without this stage's test noticing.

What GBNF buys and what it does not, stated once: a grammar guarantees a
**parseable** program — balanced forms, legal atoms, the reserved shapes —
and guarantees nothing the loader checks: an undeclared relation, a wrong
arity, a type mismatch. The one exception is the facts grammar
**parameterised on the ontology**: when the instance atoms are substituted
into the grammar, an atom the ontology does not declare is *unemittable*,
which is the old plan's best idea and is kept. Everything else semantic is
the loader's, reported through [`ein-feedback/1`](../p2.1_kernel_as_instrumentation/s2.1.2_feedback_object.md)
as feedback level F1.

[S2.1.3](../p2.1_kernel_as_instrumentation/s2.1.3_boundary.md) fixes the
language; the generator below is a script under `einaf/`, and the grammars
it writes are text files under `grammars/`, language-neutral.

## Acceptance

- `grammars/ein.gbnf` is regenerated by one command from
  `00_ebnf.md`, and a test asserts the generated grammar **accepts every
  `.ein` in the corpus** (128 entries, `positive` / `stdlib` / `regression`
  groups and the `load-` / `compile-negative` ones, which all parse) and
  **rejects every `parse-negative` fixture**.
- Four per-pass grammars exist with their inventory in `grammars/README.md`.
- The echo round-trip holds over the corpus through `llama-server`: each
  top-level form, echoed under the full grammar, parses back to the same
  canonical dump.
- Tokens/s under the full grammar measured and recorded; Q24 decided by
  that number and the per-pass grammars' own.

## Tasks

### Task T2.2.3.1 — The generator

`einaf/grammar/from_ebnf.py`: reads the `ebnf` fenced blocks of
`00_ebnf.md` — the lexical layer in § 1, the syntactic layer after it —
and emits GBNF. The translation is mechanical for the productions
(`::=`, alternation, grouping, `?*+`, character classes) and **not**
mechanical for two things the page's § 3 explains: the lexical / syntactic
boundary is not a scanner pass, and `A - B` (difference) has no GBNF
equivalent and is rewritten by hand per production, with the rewrite
listed in `grammars/README.md` so a reader can check it. The old
hand-written skeleton — `root`, `top-form`, `head`, `args`, `atom`,
`keyword`, `string`, `number`, `ws` — survives as the *expected output* the
generator's first test compares against, then is deleted.

### Task T2.2.3.2 — The acceptance test

`einaf/tests/grammar/test_ein_gbnf.py`: a GBNF acceptor (llama.cpp's
`gbnf-validator`, run as a subprocess, or a small Python one if the binary
is not in the image) over every file the corpus manifest lists
([`corpus/corpus.toml`](../../../corpus/README.md), `ein-corpus/2`):
accepted for every group but `parse-negative`, rejected for those. This is
the test that keeps the grammar honest the way the kernel's gate keeps the
EBNF honest, and it runs offline.

### Task T2.2.3.3 — The per-pass grammars

One grammar per pass of [S2.2.4](s2.2.4_passes.md); each restricts the
kernel grammar to one set of top-level heads, so a pass cannot emit a form
it is not responsible for:

| grammar | restricts to | parameterised on |
|---|---|---|
| `grammars/ontology.gbnf` | `relation` forms, and the `is-a` / instance facts that declare types and members | — |
| `grammars/theory.gbnf` | `import` of `std.*`, activator facts whose head is a property the catalogue lists (`bijective`, `transitive`, `converse`, …), and — behind a flag the theory pass sets only when it has stated a missing property — `rule` / `hrule` forms | the catalogue: the property names are substituted |
| `grammars/facts.gbnf.in` | facts whose head is a declared relation and whose arguments are declared instances, `:source "…"` **mandatory** | the ontology: relation names and instance atoms are substituted by `render_grammar` at request time |
| `grammars/query.gbnf` | one `query` form with `:goal` and `:goal-text` | the ontology: relation names |

`einaf/grammar/render.py::render_grammar(template, **subs)` substitutes
`{RELATIONS}`, `{INSTANCES}`, `{PROPERTIES}` — the old `render_grammar` of
S2.2.2 T2.2.2.3, unchanged in purpose. The old `ambiguity.gbnf` — the
alternatives wrapper — is **not** written here: it is
[S2.4.5](../p2.4_loop/s2.4.5_alternatives_as_hypotheses.md)'s, and exists
only if that stage keeps the form.

### Task T2.2.3.4 — The echo round-trip

`einaf/tests/grammar/test_roundtrip.py`, integration, skipped without
`LLAMA_HOST`: for each top-level form of each `positive` corpus entry,
send it to the server under `grammars/ein.gbnf` with the system prompt
*echo exactly the form you receive; you may normalise whitespace*, and
assert the reply's canonical dump (`ein` has one; the harness calls the
binary to produce it) equals the input's. A form the model cannot echo
under its own grammar is a grammar bug, and the test names the form.

### Task T2.2.3.5 — Tokens/s, and Q24

Measure decoding speed for a 100-token emission under the full grammar
and under each per-pass grammar, on the pinned model of
[S2.2.2 T2.2.2.6](s2.2.2_llama_server_and_client.md), through
[`bench_env.sh`](../../../utils/bench_env.sh) so the machine state is on the
record. Target, inherited from the old T2.3.1.4: **≥ 30 tok/s** under the
full grammar on the dev workstation. Q24's working answer is *many*; the
number is what could reverse it — if the full grammar decodes as fast as
the restricted ones, the restriction buys focus and nothing else, and the
verdict says so. Recorded beside [Q24](../open_questions.md#q24--one-gbnf-or-many).

### Task T2.2.3.6 — The inventory

`grammars/README.md`: one table, the grammars, what each restricts the
model to, which pass uses it, what it is parameterised on, and the
hand-rewritten productions of T2.2.3.1. Regeneration command at the top.
The stdlib's `MANIFEST.sha256` convention is borrowed: a `grammars/MANIFEST.sha256`
lists the generated files' digests, and the record names the grammar by
digest, not by path.

## Notes

- GBNF has no semantic predicates, so the facts grammar cannot check
  arity or types; the loader does, at F1. The grammar's job is to make the
  *vocabulary* closed, which is what turns "the model hallucinated a house"
  from a repair into an impossibility.
- A hosted replication arm ([Q-M2.2](../open_questions.md#q-m22--must-the-model-be-local))
  has no grammar; the acceptance test above is then run on its *output*
  instead, and the parse rate becomes a reported column — the first thing
  GBNF is shown to have been worth.
