# S2.2.1 — The formalization contract: B1 to B4

**Phase:** [P2.2](README.md) (The formalizer — Stage B)
**Depends on:** [S2.1.1](../p2.1_kernel_as_instrumentation/s2.1.1_tree_and_outcomes.md): the tree the page's
tests live in, and the operational test of the seven outcomes the page names;
[S2.1.3](../p2.1_kernel_as_instrumentation/s2.1.3_feedback_object.md): the feedback object, the form in which a
prior diagnostic reaches the model. Independent of [S2.2.2](s2.2.2_model_runtime.md): the page needs no model.
**Research plan:** [`EinAf.md` § Stage B](../EinAf.md#stage-b--define-autoformalization-as-an-explicit-task),
[B1](../EinAf.md#b1-define-the-formalization-contract) to [B4](../EinAf.md#b4-establish-prompt-versioning).

## Context

Stage B has one instruction above its four items: *avoid mixing solving and formalization*. The model turns a
text into a program, and everything else (whether the program is consistent, how many states its region has, what
its answer is) is the kernel's. This stage writes that division down as one page before a prompt exists, so that
the prompts, the grammars, the passes and the record are derived from the page and the page is not reconstructed
from them afterwards.

What the page says that the plan of August could not, each from
[the audit](../analysis/audit_p2.2.md#a-stale-claims) or a ruling:

- **The output has five parts.** The hypothesis mechanism is one
  ([the phase README](README.md#what-the-formalizer-emits)), and one query prints the answer
  ([Q-M2.12](../open_questions.md#q-m212--what-prints-the-answer)), in the form every arm is asked for
  ([the frame's default 7](../README.md#the-defaults-the-re-plan-took)).
- **The language has decided how provenance is marked.** A fact takes `:source`, `:rule` and `:using`, and any
  other keyword is a parse error
  ([Q-M1e2.28](../../../docs/decisions/language/Q-M1e2.28-each-form-takes-a-closed-list-of-keywords.md); the
  audit's run s06). The `:origin` alternative and the census question it waited on are gone: a category is kept
  beside the program.
- **A formalization can be flagged.** A program the static check finds not monotone loads and prints an answer of
  which nothing is claimed
  ([Q-M1f.564](../../../docs/decisions/answer/Q-M1f.564-a-non-monotone-program-loads-with-a-warning.md)); to the
  loop it is an outcome of its own, never certified
  ([Q-M2.11](../open_questions.md#q-m211--what-is-a-flagged-program-to-the-loop)).
- **Texts are English and names ASCII.** A character that is not ASCII is written only in a string or a comment
  ([§ 1.6](../../../docs/ein/user/04-reference/07-diagnostics.md#16-a-character-that-is-not-ascii-is-written-only-in-a-string-or-a-comment)),
  so a text in another language is out until Ein's names are not ASCII only (the frame's default 9).
- **The harness is Rust and links the kernel**
  ([Q-M2.7](../open_questions.md#q-m27--what-language-is-the-frontend-written-in)): the canonical text of a form is
  `ein_ir::dump_canonical`'s, which no command prints and a library caller has.

The page is a document. What enforces it is named clause by clause: a grammar ([S2.2.3](s2.2.3_gbnf.md)), the
contract's check on the assembled program ([S2.2.4](s2.2.4_passes.md)), the record
([S2.5.1](../p2.5_harness/s2.5.1_experiment_record.md)), the faithfulness judge
([S2.4.4](../p2.4_loop/s2.4.4_faithfulness.md)), or the kernel.

## Acceptance

- `docs/einaf/contract.md` exists and states B1 to B4 in the form below. Every clause names what enforces it, or
  says that nothing does.
- **Its examples follow it**: each prints its answer in the answer line's form, from the one query that carries a
  `:goal-text`, and the mechanical judge finds no event in any.
- **Its examples are run.** Each program on the page is a file a test of `einaf/` loads and asks through
  `einaf::kernel`, which is the one module that calls the engine's crates
  ([S2.1.3](../p2.1_kernel_as_instrumentation/s2.1.3_feedback_object.md)), and the test compares the outcome and
  the answer's line with what the page says. No model is needed, so the test is in EinAf's gate step.
- **The categories partition the forms.** A test assigns every top-level form of the reference programs (the
  target shape of [the phase README](README.md#the-target-shape-and-the-program-that-is-the-model-of-it), the
  sixteen word problems, the page's own examples) to exactly one row of T2.2.1.2's table and reports none
  unassigned.
- Every prompt written in [S2.2.4](s2.2.4_passes.md) cites the section of the page it implements, and holds no
  text the page does not list under B3.
- The reading list exists, one line an entry, each saying which question it informs.

## Tasks

### Task T2.2.1.1 — The contract page: the task (B1)

`docs/einaf/contract.md`, one page. **Input:** a problem statement in English. **Output:** one Ein program the
kernel loads as it stands, in five parts:

| part | the forms | the page's rule |
|---|---|---|
| ontology | `relation` forms; membership facts | every relation carries a `:why` that reads its declaration (`{?3}` is its first label, [natural language, § 1](../../../docs/ein/user/03-syntax-and-semantics/14-natural-language.md#1-the-four-texts)); a name is a run of the characters [`02-syntax.md` § 1](../../../docs/ein/user/04-reference/02-syntax.md#1-lexical-rules) allows, taken from the text's own words |
| theory | `import` forms with `:symbols`; the facts that activate what is imported; a `rule` only on the named condition of [S2.2.4](s2.2.4_passes.md) | a theory is written as the catalogue writes it; a rule carries a `:why` that says what it concludes and from what |
| hypothesis mechanism | nothing, where a selected theory's obligations propose; a rule that concludes `(open F)`, or a written `(open F)`; `(solve :no-search)`; `(solve :hypothesis-relations (R …))` | **the program states its mechanism**: one of the four, or the first two together, whose hypotheses the kernel takes as one set. The record holds the writer the kernel reports (`obligations`, `hypothesis-rules`, `union`, `no-search`, `blind` among `ein_infer::oblgen::Mode`'s words, which `ein show hyps` prints); `blind` with no `(solve …)` list is a mechanism not stated |
| instance | facts and stored negations with `:source` | the `:source` is **a sentence of the input, verbatim**; a quantity the theory computes with is a numeral, `(n z 5)`, and any other number is a name |
| query | **the answer query: the one `query` that carries a `:goal-text`**. Any other query carries none and is a check (what the answer rests on, what the text does not state) | the answer query's goal asks for what the text's question asks, and its `:goal-text` **prints the short answer in the form the answer line asks for** (a name, a number, an option's label: [S2.5.2](../p2.5_harness/s2.5.2_baselines.md)), which is the form the gold short answer has: `"{?who}"`, not `"{?who} is the youngest"`. Its variables bind names and numerals. A program with no such query has no answer; with two, the check reports it and the first is read |

The page then states, each with what enforces it:

- **The order.** The passes write the parts in the order above. Whether the answer moves with the order of a
  program's forms is checked on the page's examples and the reference programs, by reversing each (the audit's
  run s26 and one run of this re-plan found no move; two instances are no proof).
- **What the program may not hold**: a `(config …)` (no flag changes R), a `(trace …)`, a saved file's wrapper,
  a string outside the three keywords that take one.
- **The answer is the program's.** The model writes no answer beside its program. What is reported is each row of
  the answer query rendered through its `:goal-text`
  ([`14-natural-language.md`](../../../docs/ein/user/03-syntax-and-semantics/14-natural-language.md)), with
  EinAf's formatters over the values that do not read as text. Every arm is scored by exact match, after
  normalisation, against a gold short answer that is the bare value, *3* and not *Bob has 3 apples*
  ([S2.5.3](../p2.5_harness/s2.5.3_metrics.md)), so a `:goal-text` that wraps the value in a sentence fails a
  right program. A line is printed per row and for nothing else, so where the answer query has no single class
  with a row, or the kernel's outcome gives no state to read, the answer is one of a few fixed texts of EinAf's,
  chosen by the kernel's values and never written by the model ([S2.2.5](s2.2.5_from_text.md) words them; the
  frame's default 15).
- **Which encoding is the target.** For an attribute puzzle it is the `std.slots` formulation, the shape of
  [the phase README](README.md#the-target-shape-and-the-program-that-is-the-model-of-it); the benchmark's Zebra
  programs follow it ([S2.3.1](../p2.3_benchmark/s2.3.1_families_and_seed_set.md)). For a word problem it is the
  word theory's, as the sixteen programs write it.
- **What a formalization comes to.** One of the seven outcomes
  ([the frame](../README.md#the-outcomes);
  [S2.1.1](../p2.1_kernel_as_instrumentation/s2.1.1_tree_and_outcomes.md) has the test of each), and beside it
  the findings of the contract's own check, which are not the kernel's: a `:source` that is no sentence of the
  input, a selected theory that activated nothing, a mechanism not stated, a fact of a relation the program does
  not declare, a form of a declared relation at another count, a number written as a name where the theory
  computes, a `:goal-text` reference nothing binds, a `:goal-text` on no query or on two
  ([S2.2.4](s2.2.4_passes.md) builds the check). The kernel refuses none of them
  ([the audit, runs s04, s11, s15, s18](../analysis/audit_p2.2.md#snippet-runs-the-table-sections-a-to-c-cite)).
- **What flagged is.** The page's own example, below, in three forms.

**The page's worked example**, run at this re-plan with the binary of the tree (the files were scratch: the stage
keeps them under `einaf/` and its test runs them). The text is the host probe's question
([`host.md`](../analysis/host.md#what-the-model-does-through-llama-server-a-probe)).

```lisp
;; Ann is older than Bob. Bob is older than Cy. Who is the youngest?

;; ontology: the relations, each with its :why, and who the text names
(relation person   Person        :why "{?3} is a person")
(relation older    Person Person :why "a {?3} is older than a {?4}")
(relation youngest Person        :why "a {?3} is the youngest")
(person Ann :source "Ann is older than Bob.")
(person Bob :source "Ann is older than Bob.")
(person Cy  :source "Bob is older than Cy.")

;; theory, selected: the import lists the name the file writes
(import std.algebra :symbols (transitive))
(transitive older)

;; theory, synthesised: a rule of the program's own, for the least element
(rule youngest-is-older-than-nobody ()
  :match  (and (person ?p) (absent (older ?p ?q)))
  :assert (youngest ?p)
  :why    "{?p} is older than nobody, so {?p} is the youngest")

;; hypothesis mechanism: none, the text states every fact there is
(solve :no-search)

;; instance: what the sentences state, each with its sentence
(older Ann Bob :source "Ann is older than Bob.")
(older Bob Cy  :source "Bob is older than Cy.")

;; query: the goal, and the answer in the form the answer line asks for, a name
(query :goal (youngest ?who) :goal-text "{?who}")
```

| the mechanism line | `ein show hyps` | the static check | `ein solve --single` | the answer printed |
|---|---|---|---|---|
| `(solve :no-search)`, as above | *H, from `no-search`: no candidate* | monotone | `Solution` | *“Cy”* |
| the line deleted | *H, from `blind`: 5 candidates* | **flagged**: the rule's `absent` reads `older`, which a commitment can fill | `Ambiguity`, under the capitals of the warning | nothing is claimed of it |
| `(__closed__ older)` in its place | *H, from `blind`: 2 candidates*, `(youngest Ann)` and `(youngest Bob)` | monotone | `Ambiguity` | *“Cy”* in one state, *“Ann”* and *“Cy”* in another |

The three rows are the argument for the third part: one theory and one set of facts, and the answer is right,
unclaimed or wrong by the mechanism line alone. The third row is the one a reader does not expect: with the
relation the rule reads closed, the blind enumerator still supposes facts of the relation the rule concludes.

The blind enumerator alone, with no rule in the way, on the five forms a formalizer with no theory would write
(also run at this re-plan): *H, from `blind`: 7 candidates*, a region of 128 states, the static check monotone,
and `--single` answers `Ambiguity`. Nothing the kernel prints says that the program stated no mechanism.

```lisp
(relation older Person Person :why "a {?3} is older than a {?4}")
(relation youngest Person :why "a {?3} is the youngest")
(older Ann Bob :source "Ann is older than Bob.")
(older Bob Cy  :source "Bob is older than Cy.")
(query :goal (youngest ?who) :goal-text "{?who}")
```

### Task T2.2.1.2 — The categories, and how each is told (B2)

*The formalizer may restructure information from the source but must not invent problem-specific facts.* B2 names
five categories. A category is **computed** by EinAf from the program, the input text and the catalogue, and kept
in the record beside the program, in **the sidecar**: one row a top-level form, keyed by the form's canonical
text (`ein_ir::dump_canonical`, through `einaf::kernel`), with the pass that wrote the form and, for a
synthesised rule, its reason. The findings of the contract's check stand in the same file. Nothing is added to
the program, which stays a plain input of the kernel.

| category (B2) | the forms, in today's Ein | told by | to the faithfulness judge ([S2.4.4](../p2.4_loop/s2.4.4_faithfulness.md)) |
|---|---|---|---|
| **source-derived fact** | a fact, a stored negation or a written `(open F)` whose `:source` is a sentence of the input, verbatim; a membership fact is one where it quotes the sentence that names the thing | the keyword and the text | nothing; the event `unfound_source` where the text is no sentence of the input |
| **generic theory (stdlib)** | an `import`; a fact that activates a rule of an imported module; a fact of a relation a module reads and does not declare (`(bijective R)`, `(slot-partition …)`) | the catalogue lists it | nothing from the mechanical judge; the canonical judge compares it with the canonical program, where there is one |
| **generated auxiliary relation** | a `relation` form of which no source-derived fact is a fact | the declaration and the facts | the note `generated_relation` |
| **generated inference rule** | a `rule` form, one that concludes `(open F)` among them, with each fact that activates it; a `macro` | the form; its reason is the theory pass's named condition | the note `generated_rule` |
| **generated assumption** | a fact or a stored negation the program states **as holding**, with no `:source`, that the catalogue does not list: a membership fact no sentence names, a condition no sentence states | the absence of the keyword | **the event `generated_assumption`**, the moment it appears |
| *the program's frame* | what a program needs to be well formed and to state its lattice: a `relation` form some source-derived fact is a fact of, with its `:why`; the queries; a `(solve …)` form; a `(__closed__ R)`; a written `(open F)` with no `:source`, which supposes and states nothing | the forms | **never an event**; a note at most |

**The line between an event and a note is this table**, which is what S2.4.4 reads it for: an event counts
against a program, and a final program is *faithful* in the metrics where it has none
([S2.5.3](../p2.5_harness/s2.5.3_metrics.md)). Only a form that says something holds, with no sentence behind
it, is an event. The worked example above has none: its `(solve :no-search)` states its lattice, and each of its
facts quotes a sentence.

The last row is not one of B2's five: today's forms need it, since a declaration, a question and the statement
of a lattice are not knowledge of the problem. The texts the frame carries (`:why`, `:goal-text`) are the
model's own words and in no category; whether a judge reads them is S2.4.4's. The corpus's own Zebra programs
write `:source "condition (2)"`, a citation; the contract requires the sentence, as the word problems write it,
because the mechanical judge checks that it is in the text.

### Task T2.2.1.3 — What the model receives (B3)

The list, in the order a prompt is assembled, each item versioned and hashed. Which item goes into which prompt is
[S2.2.4](s2.2.4_passes.md)'s. The tool's function description carries what the filter's prompt holds of Ein
([S2.4.6](../p2.4_loop/s2.4.6_ein_as_a_tool.md)), so the two arrangements differ by no knowledge of the
language.

1. **An excerpt of Ein's reference**, cut from pages at a named commit. The text of the forms is
   [`02-syntax.md`](../../../docs/ein/user/04-reference/02-syntax.md);
   [`03-reserved-names.md`](../../../docs/ein/user/04-reference/03-reserved-names.md#quick-reference--from-intent-to-word)
   has a table from intent to word; the concept pages are
   [`03-syntax-and-semantics/`](../../../docs/ein/user/03-syntax-and-semantics/README.md), with
   [`14-natural-language.md`](../../../docs/ein/user/03-syntax-and-semantics/14-natural-language.md) for the three
   texts. [`01-grammar.md`](../../../docs/ein/user/04-reference/01-grammar.md) holds railroad diagrams and one
   table, no grammar text. Whole pages do not fit a prompt
   ([the audit, A.4 row 30](../analysis/audit_p2.2.md#a4-paths-pages-other-plans) has the sizes), so the item is
   an **excerpt**, a file under `einaf/prompts/`, which the tool's stage calls the primer: every Ein block in it
   is loaded by a test, its hash is the record's, and its length in the model's own tokens is recorded.
2. **The catalogue of the library**: for each theory of `std.*` a program may select, the module, the import
   line to write with the names it lists, the facts that activate it with their arguments, the facts it needs
   beside them, what it gives the hypothesis mechanism, and one line of meaning taken from the rule's own
   `:why`. The library's manifest SHA stands at its top. This task **specifies an entry**;
   [S2.2.4](s2.2.4_passes.md) builds the catalogue, each entry a program the kernel runs. **It holds the
   library's modules and no family's own**: a family's module is its canonical program's and is not shown to the
   model, so that where the library has no theory the formalizer's synthesis is what is measured
   ([P2.3](../p2.3_benchmark/README.md)). Which modules a program may import is G9's condition
   ([S2.6.4](../p2.6_ablations/s2.6.4_representation_ablations.md)): the main arms run under the library's, and
   offering a family's module is that ablation's widest condition.
3. **Examples: a text beside its program.** What the corpus has: the sixteen word problems, each under its text
   as a comment and each stated fact carrying its sentence
   ([`examples/word_problems/`](../../../examples/word_problems/README.md)); the walkthrough's table of the
   fifteen conditions beside their Ein forms
   ([`06-zebra-walkthrough.md`](../../../docs/ein/user/02-guide/06-zebra-walkthrough.md#condition-cross-reference));
   the target shape. What the stage writes: the page's own examples. **An example follows the contract**: one
   query with a `:goal-text`, printing the bare answer, and no import of a module the catalogue does not hold. A
   corpus program that differs (the word problems import their family's modules and carry a `:goal-text` on
   several queries) is an example of the widest library condition only, or is edited, and the prompt's copy is
   what is listed. **Never a benchmark instance of `val` or
   `test`**: every program a prompt quotes is listed in the record, the list goes to
   [S2.3.4](../p2.3_benchmark/s2.3.4_splits.md), which marks each `excluded`, and a check in EinAf's gate step
   holds every prompt's examples to the split file once there is one.
4. **The problem statement**, with what its instance says of the task: its family's answer line
   ([S2.5.2](../p2.5_harness/s2.5.2_baselines.md)), which is given to every arm in the same words, and, for an
   external item, what its adapter tells the formalizer
   ([S2.3.3](../p2.3_benchmark/s2.3.3_external_benchmarks.md)). Both come after this phase in work order: its
   own runs, on Zebra and the word problems, have the text alone.
5. **Prior diagnostics, if iterative**: the feedback object
   ([S2.1.3](../p2.1_kernel_as_instrumentation/s2.1.3_feedback_object.md)) rendered at the run's level of the
   ladder ([S2.4.3](../p2.4_loop/s2.4.3_feedback_ladder.md)), and under *repair* the current program. Absent in
   one shot.

What the model does **not** receive is listed too: no benchmark answer, no canonical program beyond the listed
examples, no output of the kernel but the rendered feedback object, no human edit between iterations.

### Task T2.2.1.6 — What the stage found of Ein

The stage drives the kernel on the page's examples and on the reference programs. What it finds of Ein goes to
[the evaluation of Ein](../ein_evaluation.md) under the user's five kinds, each entry with its program and its
command. Two findings of this re-plan are already of that kind and are the stage's to confirm and file: the three

enumerator supposing facts of a relation a rule concludes; no word from the kernel that a program stated no

### Dropped as moot

- **The marking decision between a sidecar and an `:origin` keyword**: the language refuses an unknown keyword on
  a fact (the audit, A.1 row 4), and no ruling changes the kernel for it
  ([Q-M2.9](../open_questions.md#q-m29--does-the-kernel-grow-a-machine-surface-for-diagnostics) is the only
  kernel change).
- **Russian input**, and the model's handling of it as a measured column: names are ASCII (the frame's default 9).
- **`server_image` and the manifest of model files** among the record's fields: there is no container
  ([Q-M2.14](../open_questions.md#q-m214--what-runs-the-model)).

## Risks

- **The page is written before the model has been seen writing Ein.** [S2.2.2](s2.2.2_model_runtime.md)'s probe
  runs beside this stage, and what it finds of the model's habits (a number written as a name, a `:why` left
  out, an import with no `:symbols`) is a reason to change the examples and the excerpt, never the contract: the
  contract is what today's Ein asks.
- **The frame hides invention.** A `:why` and a `:goal-text` are the model's words and are in no category. A
  `:goal-text` that holds a name of its own beside its references (*“Norwegian”* written in the template, with
  no variable) answers without the kernel. The contract asks for the references alone, the check reports a
  template that holds more, and [S2.4.4](../p2.4_loop/s2.4.4_faithfulness.md)'s mechanical judge notes it.
- **A contract stricter than the kernel has two judges.** The check's findings are EinAf's. The record keeps
  them apart from the kernel's diagnostics, so that what the kernel said is never mixed with what EinAf holds a
  program to.
