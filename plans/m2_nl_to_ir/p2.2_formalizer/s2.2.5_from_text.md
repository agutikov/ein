## Context

The old S2.4.4 tied the passes together behind one command and put a
`(meta …)` block at the top of every emitted file so a saved program could
be reproduced months later. Both ideas survive; both move. **The command is
`einaf from-text`, in the harness, not a subcommand of `ein`**: the kernel
stays LLM-free — a binary that links `snmalloc` and embeds the stdlib does
not also need a GGUF path and an HTTP client, and Stage A's *instrument*
has no neural component by definition. The milestone README and the phase
README say `einaf from-text` too, and name the old `ein from-text` only as
what the 2026-05 plan called it; the command is `einaf from-text`, and
[S2.1.3](../p2.1_kernel_as_instrumentation/s2.1.3_boundary.md) fixes the
language it is written in. **The metadata moves out of the program and into
the record**: the `.ein` file is a plain kernel input with a one-line `;;`
header naming its record id, and everything the old `(meta …)` block held —
input SHA, ontology source, the invocation envelope, the Ein version — is
the record directory [S2.5.1](../p2.5_harness/s2.5.1_experiment_record.md)
defines, which every later phase reads the same way.

Two modes, as before: **direct** — the program to stdout or a path — and
**chained** — the program handed to `ein solve -e --feedback`, the feedback
object and the kernel's outputs kept. One shot only: no repair here, no
second generation. That is deliberate — this command's output on the seed
set is baseline **B2** of [S2.5.2](../p2.5_harness/s2.5.2_baselines.md),
and the loop of [P2.4](../p2.4_loop/README.md) calls this command as its
GENERATE state and nothing else.

## Acceptance

- `einaf from-text examples/zebra.txt --solve` runs the four passes, hands
  the program to `ein solve -e --feedback`, and the feedback object says
  `unique`, `search_complete = true`, with the canonical bindings — the
  Norwegian drinks water in House-1, the Japanese keeps the zebra in
  House-5 — one shot, on the pinned model, with the theory selected from
  `std.*`.
- Every run writes a record directory with the fields of
  [S2.2.1 T2.2.1.4](s2.2.1_contract.md), the four invocation envelopes, the
  program, the sidecar and — chained — the feedback object and the summary.
- `--gold PATH` reports a structural diff against a gold program: empty on
  the Zebra smoke test's own gold, non-empty and correctly located on a
  mutated copy.
- The seed set's one-shot numbers — parse, load, verdict distribution,
  answer accuracy, per puzzle — exist as the **first record** under
  `experiments/`, produced by this command and read back by `einaf report`.

## Tasks

### Task T2.2.5.1 — The command

```text
einaf from-text PATH
  [--ontology PATH]     load a hand-written ontology; skip the ontology pass (Q9's escape hatch)
  [--llm-host URL]      llama-server (default http://127.0.0.1:9080)
  [--model NAME]        a manifest entry; default the pinned model
  [--lang en|ru]        override detection
  [--out PATH]          the program (default: stdout in direct mode)
  [--solve]             chain: ein solve -e --feedback, keep everything
  [--gold PATH]         structural diff against a gold program
  [--record DIR]        the experiment directory (default: a new id under experiments/)
  [--seed N]            default 0; recorded
```

`--solve` runs the binary named by `$EIN_BIN`, the convention
[`utils/`](../../../utils/README.md) already has, so the record's
`ein_commit` is whatever `ein --version` of that binary says and never an
assumption. The `--max-set-size` / `--max-time` budgets are passed through
and recorded, because the sixth outcome depends on them
([P2.1 § The sixth outcome](../p2.1_kernel_as_instrumentation/README.md#the-sixth-outcome-today)).

### Task T2.2.5.2 — The record, per run

Written by the command into `--record DIR`, in the layout
[S2.5.1](../p2.5_harness/s2.5.1_experiment_record.md) fixes: `config.json`
(every B4 field), `invocations.jsonl` (the four envelopes), `program.ein`
with its `;; einaf record <id>` header, `program.sidecar.json` (the
category per form), and under `--solve` `feedback.json` and `summary.json`
plus whatever `--events` / `--trace` the config asked for. The old
acceptance — *a saved IR file can be reproduced from the same inputs months
later* — becomes: the record is sufficient to re-run the command and get
the same program, and a test does so on a captured record.

### Task T2.2.5.3 — `--gold`

A structural diff of two programs as multisets of canonical forms, the
`:source` strings ignored (a citation and a span are the same fact), the
sidecar categories reported beside each difference. This is the old
S2.5.2's *structural F1* reduced to a diff; the metric built on it —
constraint precision / recall against a canonical theory — is
[S2.5.3](../p2.5_harness/s2.5.3_metrics.md)'s, and the diff is what it is
computed from.

### Task T2.2.5.4 — The Zebra smoke test, end to end

`examples/zebra.txt` is checked in — the Wikipedia statement, the
fifteen conditions and the two questions, beside the two hand encodings —
and `einaf/tests/test_from_text.py` runs the acceptance's first bullet
against it (integration, skipped without `LLAMA_HOST`), plus the offline
replay of a captured record through the assembler and the chained `ein
solve` (no model needed; the binary is). The trace coverage check the old
S2.6.1 wanted — the gold trace's named rule firings present in the run's
`--trace` — stays here as the Zebra-only smoke assertion it always was.

### Task T2.2.5.5 — The seed set, one shot

Run the command over every seed-set puzzle
([S2.3.1](../p2.3_benchmark/s2.3.1_families_and_seed_set.md)), three
seeds, chained; produce the first `experiments/` record; `einaf report`
prints the per-puzzle table — parse rate, load rate, the verdict
distribution over the six outcomes, answer accuracy, tokens, wall, Ein
wall. This is the phase's acceptance number and the row the whole of
Level C is measured against. It is committed with the record, labelled
*seed set, one shot, B2*, and not called a result.

## Notes

- Direct mode's stdout is a `.ein` program and nothing else, so
  `einaf from-text x.txt | ein solve -` is a pipeline if `ein` ever reads
  stdin; today it does not, and `--out` plus a path is the way.
- The old `--trace=PATH` flag is gone as a flag of this command: the trace
  is one of the kernel outputs the record keeps when the config asks,
  exactly like `--events`; nothing about the trace is the formalizer's.
- A hosted replication arm ([Q-M2.2](../open_questions.md#q-m22--must-the-model-be-local))
  uses the same command with `--model hosted:<name>`; the record's
  `model_sha256` is then absent and the table says so.
