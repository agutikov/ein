## Context

The plan of August split extraction into passes because one pass over a whole puzzle was too much load and
because an ontology written first keeps the facts from naming things that do not exist. Both reasons hold. Its
third pass, the theory, is the one the plan before it lacked and
[F7 B](../../followups/f7_rule_induction.md#connection-to-m2) put on the critical path.

```text
text ─► ontology ─► theory ─────────────► instance ─► query ───────────► assembly ─► the contract's check
        relations   imports, activating   facts with  the answer query,  one program   EinAf's own findings,
        with :why,  facts, the            :source     with :goal-text                   and the categories
        membership  hypothesis mechanism
```

The theory pass is where the user's three neural actions
([F13](../../followups/f13_puzzles_beyond_zebra/ideas.md)) become three priced moves: **reinterpretation** is a
new ontology or instance pass; **theory selection** is a fact from the catalogue, cheap and checked, the default;
**theory synthesis** is a `rule` form, permitted only after the pass has stated which property it needed and did
not find, so that every synthesised rule carries the reason it exists.
[F12](../../followups/f12_rules_and_relations/ideas.md)'s *select, do not invent* is held by that order.

What the stage is built on that the plan of August did not have
([the audit, B.0 and B.4](../analysis/audit_p2.2.md#b0-the-four-passes-in-todays-language)):

- **A program with no theory does not sit idle**: the blind enumerator answers it. So the theory pass also states
  the hypothesis mechanism, and the check reads which writer the kernel reported.
- **Selecting is spelling.** An activating fact works only under a name the file can write: one it lists in
  `:symbols` from the module that declares it, the full name, or an alias. A relation a module reads and does not
  declare (`bijective`, `slot-partition`, `slot-spatial`) is written as it is
  ([`04-stdlib/` § What to list](../../../docs/ein/user/04-reference/04-stdlib/README.md#what-to-list)). Several
  selections take more than a relation: `(slot-partition co-located instance type Attribute House)` names the
  membership relations and two kinds.
- **The target exists in one formulation.** For an attribute puzzle it is `std.slots`, whose obligations write H
  ([the phase README](README.md#the-target-shape-and-the-program-that-is-the-model-of-it)). In the `std.bijection`
  formulation `(bijective R)` needs its hierarchy facts beside it and the conditions need rules the library does
  not have.
- **The passes are Rust and read the kernel through `einaf::kernel`**, the one module that calls the engine's
  crates ([S2.1.3](../p2.1_kernel_as_instrumentation/s2.1.3_feedback_object.md)): a reply is parsed by
  `ein_ir::parse`, a form's canonical text is `ein_ir::dump_canonical`'s, and a program is run by the bounded
  kernel call. Where this file names a function of the crates, it names what `einaf::kernel` wraps; this stage
  adds to that module what it does not yet give. No binary is called.

## Acceptance

With the model, one shot, each run a record. On the Zebra text
([`nl2smt/puzzles/zebra.txt`](../../../nl2smt/puzzles/zebra.txt)) and on the sixteen word problems:

- **the ontology pass**: its output parses, holds only its own forms, and every relation carries a `:why`;
- **the theory pass**: every import and activating fact is an entry of the catalogue; the check finds every
  selection active; the writer of H the kernel reports is the one the entry promises, and is not `blind` unless
  the program says so; there is no `rule` form without the marker of a missing property;
- **the instance pass**: every `:source` is a sentence of the input, and the report says which sentences have no
  fact;
- **the query pass**: one query with a `:goal-text`, the answer query, every reference of which the goal binds
  and which prints the answer in the answer line's form;
- **the assembled program** loads, and its outcome among the seven and the findings of the contract's check are
  reported. The answer is the acceptance of [S2.2.5](s2.2.5_from_text.md) and of
  [the phase](README.md#acceptance), not of this stage.

Without the model, in EinAf's gate step:

- **Every entry of the catalogue is run by the kernel**, and the test fails on an entry whose selection is not
  active or whose stated effect the kernel does not show.
- Recorded generations, one a pass, replay through parsing, assembly, the check and the table of categories.
- [Q9](../open_questions.md#q9--ontology-provenance) is decided in the ledger.

## Tasks

### Task T2.2.4.1 — The prompts

`einaf/prompts/`, one template a pass and one for the whole program (T2.2.4.9). Each cites the section of
[the contract](s2.2.1_contract.md) it implements and holds only what B3 lists: the excerpt for its pass, the
catalogue (the theory pass only), the examples for its pass, the text, and the output of the passes before it. A
template is rendered by filling named slots; the template's hash and the rendered prompt's are the record's.

**The examples are never the item's own, and each follows the contract.** For the Zebra run no example quotes
a Zebra clue: the examples of an attribute puzzle are a smaller puzzle over the same theory, written by the stage
with its text, kept under `einaf/prompts/` and answered by the kernel in a test. For a word problem the examples
are word problems written over the library alone, the calculator's requests and rules of the program's own, since
the corpus's sixteen import their family's modules, which the main arms do not show
(T2.2.4.8); no item is shown an example of its own text family. Every program a prompt quotes is listed
([S2.2.1](s2.2.1_contract.md), T2.2.1.3).

### Task T2.2.4.2 — The ontology pass, and Q9

One call, thinking off, under the ontology grammar where grammars are per pass. Output: `relation` forms, each
with a `:why` that reads its declaration, and membership facts, each with the sentence that names the thing as
its `:source` where there is one.

- **Membership is a relation the program chooses.** The kernel reads no name of it
  ([Q-M1f.436](../../../docs/decisions/engine/Q-M1f.436-the-kernel-reads-no-theorys-name.md)), and the library
  takes it as an argument. The examples fix one convention so that the theory pass knows what to pass on.
- **A reply that does not parse** is a bug of the grammar where one is on ([S2.2.3](s2.2.3_gbnf.md), T2.2.3.2's
  second test), recorded as that; with no grammar it is the *invalid* outcome.
- **Q9**, the ontology's provenance, reframed by the ledger as theory selection. The three options in today's
  language: **B**, the pass infers the vocabulary from the text; **C**, the catalogue of the library; **A**, a
  module given with the problem, `--module-dir DIR` on `einaf from-text`, which the program imports and this
  pass is skipped for: a file beside a program is a module, and an import brings it whole
  ([`02-syntax.md` § Import](../../../docs/ein/user/04-reference/02-syntax.md#import)). The working answer
  stands: B with C in the main arms, and A as the escape hatch, which is the widest condition of the library
  ablation ([S2.6.4](../p2.6_ablations/s2.6.4_representation_ablations.md)) and no part of the main arms. What
  the stage's runs can show: how far B gets on a family whose canonical vocabulary is a theory's own (the word
  problems), with A beside it. The verdict, with the runs it rests on, goes to the ledger.

### Task T2.2.4.3 — The theory pass, and the hypothesis mechanism

One call under the theory grammar with `rule` forms off. The reply is `import` forms with their `:symbols`, the
facts that activate what was imported, and the hypothesis mechanism:

- by the selection itself, where the catalogue's entry says the theory's obligations propose the candidates;
- `(solve :no-search)`, where the text states every fact there is and the answer is root's;
- a rule that concludes `(open F)`, or a written `(open F)`, where neither holds. That is synthesis, below.

**Synthesis is a second call with a cause.** If the reply carries the marker of a missing property (a line of a
fixed shape the prompt asks for and the grammar allows, naming the property and the relation), a second call
runs with `rule` forms on and the marker in its prompt. The rules it writes carry a `:why`, are categorised
*generated inference rule* with the marker as their reason, and their count per family is reported. On the
families the library has no theory for (it has none for time and none for tracking objects:
[the audit, B.4](../analysis/audit_p2.2.md#b4-s224-the-passes)) the second call is expected.

**A synthesised rule may flag the program.** A rule that reads an `absent` over a relation a commitment can fill
makes the program not monotone, and the same rule under `(solve :no-search)` does not
([S2.2.1](s2.2.1_contract.md) has both runs). The pass forbids neither. The record holds the sites the static
check names, and the outcome is *flagged*, never certified
([Q-M2.11](../open_questions.md#q-m211--what-is-a-flagged-program-to-the-loop)).

### Task T2.2.4.4 — The instance pass

Sentence by sentence by default: one call a sentence, the whole text in the prompt with the sentence marked, so
that a pronoun has its antecedent (*“He gave 2 to Alice.”*) and the `:source` is the marked sentence by
construction. The split of the text into sentences is recorded. A sentence may state no fact, and the grammar
allows an empty reply. The whole text in one call stays as a mode, for the question of whether context helps.

- The grammar is the instance grammar rendered with the ontology's relations and names
  ([S2.2.3](s2.2.3_gbnf.md)), so a name the ontology lacks cannot be written. With no grammar the contract's
  check finds it.
- **A number.** A quantity the theory computes with is a numeral of the calculator, `(n z 5)`, 12 being
  `(n (n z 1) 2)`, and the model writes it as the examples do. EinAf rewrites nothing the model wrote: a number
  written as a name is counted by the check. If the probe and this stage's runs show the model cannot write
  numerals, turning a decimal name into a numeral at assembly is the other direction of
  [S2.2.5](s2.2.5_from_text.md)'s formatter; taking it changes what *the model's program* means and is raised
  before it is done.
- **The cost.** A call a sentence repeats the prompt; with a kept context ([S2.2.2](s2.2.2_model_runtime.md))
  the shared prefix is evaluated once. The budget counts generated tokens (the frame's default 6), and the
  prompt's are recorded beside.

### Task T2.2.4.5 — The query pass, and the answer's form

One call. It writes **the answer query**, the one query that carries a `:goal-text`
([the contract](s2.2.1_contract.md)): `(query :goal … :goal-text "…")`, the goal over relations the program
writes, a relation only a rule concludes among them; one variable a thing asked for, named from the question;
and a `:goal-text` that **is a sentence saying the answer in the problem's words**, with a reference where each
value stands, `"Bob has {?n} apples"` ([Q-M2.12](../open_questions.md#q-m212--what-prints-the-answer)). The examples show a goal whose
variables bind names and numerals, so that the answer needs no formatter the family does not have
([S2.2.5](s2.2.5_from_text.md)). Any other query the pass writes carries no `:goal-text` and is a check.

**The answer line** is given to the pass with the text. It is [S2.5.2](../p2.5_harness/s2.5.2_baselines.md)'s
to write, one a family, the same words for every arm, and that stage comes after this one. So this stage writes
the two its own runs need (each asks for a sentence: how many, for the word problems; who drinks water and who
owns the zebra, for Zebra), each a prompt by
hash, and S2.5.2 takes them over or rewords them, which is a new experiment id.

- A reference in a `:goal-text` that the goal does not bind prints as written, `{?zz}`
  ([natural language, § 1](../../../docs/ein/user/03-syntax-and-semantics/14-natural-language.md#1-the-four-texts)):
  the kernel loads it, and the check counts it.
- The pass writes no `:over`. Which part of R an answer is read over is
  [Q-M2.10](../open_questions.md#q-m210--what-does-ein-certifies-a-unique-model-mean-on-r)'s, open, and the
  record carries each reading.
- For an external instance whose answer is a letter or *true*, *false*, *unknown*, the goal is the one the
  adapter of [S2.3.3](../p2.3_benchmark/s2.3.3_external_benchmarks.md) expects.

### Task T2.2.4.6 — Assembly, and the contract's check

**Assembly.** The parts in the contract's order, each form as the model wrote it, under one comment that names
the record: the record keeps a program as written
([S2.5.1](../p2.5_harness/s2.5.1_experiment_record.md)). A form's canonical text (`ein_ir::dump_canonical`) is
what the sidecar and the program's digest are keyed by, so that a form has one key however it was spaced.
Nothing the kernel does not read is added.

**The check** is EinAf's, over the assembled program, the input and the catalogue. It reports, and refuses
nothing:

1. a `:source` that is no sentence of the input;
2. **a selection that is not active**: an activating fact whose name the file does not list from the module that
   declares its rule, or, read off root's saturation, a selected rule the events name no firing of and a
   selected obligation they name no `owe` of ([`05-events.md`](../../../docs/ein/ein.rs/05-events.md)). Which of
   the two readings the check uses is the stage's; the second is the kernel's own evidence;
3. **the mechanism**: the writer of H the kernel reports, and whether the program stated one;
4. a fact of a relation the program does not declare and no imported module has, and a fact or a goal's
   pattern of a relation, the program's or a module's, at a count it is not declared at. This re-plan's own
   first word problem over the calculator asked `(diff-of X Y ?n)`, three arguments where the answer has four:
   it loaded, the outcome was *one*, and the answer query had no row ([S2.2.5](s2.2.5_from_text.md));
5. a number written as a name where the relation's theory computes;
6. of the answer query: no query with a `:goal-text`, or more than one; a reference nothing binds; a template
   that holds more than its references, which is an answer written without the kernel.

Then the table of categories ([S2.2.1](s2.2.1_contract.md), T2.2.1.2). Findings and categories are the sidecar,
kept in the record apart from the kernel's diagnostics. **The check is built once, here**, because the one shot
has to know what it produced. The lints of the feedback ladder
([S2.4.3](../p2.4_loop/s2.4.3_feedback_ladder.md)) are these findings given a sentence each; which of them a
level shows to the model is that stage's.

### Task T2.2.4.7 — Tests

**In EinAf's gate step, no model:** a recorded generation for each pass replayed through the parser, the
assembler, the check and the categories; the catalogue's entries (T2.2.4.8); each template's hash against the
record that used it. **With the model, by hand, each a record:** the acceptance's measurements on the Zebra text
and on the word problems.

### Task T2.2.4.8 — The catalogue

Built first: the theory pass has nothing to select from without it.

- **Its generated part.** From the library the kernel resolved (`ein_ir::stdlib`: the modules and their text),
  each module parsed with `ein_ir::parse`: every rule's name, its parameters and its own `:why`. The library's
  manifest SHA stands at the top, which is `ein --version`'s `stdlib` line.
- **Its written part.** For each theory a program may select, an **entry program**: a few lines of Ein with the
  import line, the activating facts with their arguments, a fact or two and a query. The lines the prompt shows
  are cut from the entry program, so the model is shown text the kernel ran. An entry says what the selection
  gives the hypothesis mechanism.
- **Its test.** Each entry program is loaded and asked, through the bounded kernel call, and the test holds it to
  its stated effect: the rule fired or the obligation owes, the writer of H is the one stated, the query's answer
  is the one stated.
  [`tests/stdlib/`](../../../tests/README.md) already holds a program for each rule of the library, written to
  break and not to teach; an entry is written fresh and may be checked against it.
- **It holds the library's modules and no family's own.** The word problems' theory is four modules of
  `examples/word_problems/`, examples and no part of the library
  ([Q-M1f.334](../../../docs/decisions/corpus/Q-M1f.334-the-word-theory-is-examples-not-a-module.md)): it is the
  canonical program's, and the main arms do not show it to the model. Two families have no theory in the library
  at all, and that is where a formalizer's synthesis is exercised
  ([P2.3](../p2.3_benchmark/README.md)); a catalogue that offered a family's module would take the measurement
  away. Offering one is the widest condition of the library ablation
  ([S2.6.4](../p2.6_ablations/s2.6.4_representation_ablations.md)), reached by `--module-dir`; an entry for
  such a module, where that condition is run, is built as the library's are and names the directory the program
  is loaded from.
- **Its sizes.** The whole catalogue, and the *minimal* one of G9 ([P2.6](../p2.6_ablations/README.md)); each has
  its hash and its length in the model's tokens.

Where the stage reads how a theory is written:
[`04-stdlib/`](../../../docs/ein/user/04-reference/04-stdlib/README.md), a page a family, with
[the relation algebra](../../../docs/ein/user/04-reference/04-stdlib/02-relation-algebra.md),
[the bijections](../../../docs/ein/user/04-reference/04-stdlib/04-bijections.md),
[the slots](../../../docs/ein/user/04-reference/04-stdlib/05-slots.md) and
[the calculator](../../../docs/ein/user/04-reference/04-stdlib/07-calculator.md); and
[`stdlib/README.md`](../../../stdlib/README.md).

### Task T2.2.4.9 — The whole program in one call

The prompt of [S2.2.2](s2.2.2_model_runtime.md)'s probe, kept as a mode of the formalizer: one call, the whole
grammar or none, the same assembly and the same check. It is what the tool arm writes and what research plan B1
says not to assume worse than a decomposition. Both modes run on the phase's material and the record says which
a program came from. The comparison on the benchmark is G8's ([P2.6](../p2.6_ablations/README.md)). Which mode
baseline B2 runs with is decided here: the passes, unless this stage's runs show the one call no worse on both
materials, in which case the simpler is taken and the ledger says so.

### Task T2.2.4.10 — What the stage found of Ein

The stage is where a model first selects from the library. To [the evaluation of Ein](../ein_evaluation.md), each
entry with its program and command: which selections the model misspelt and whether anything the kernel said
could have told it; what the catalogue had to say that no page of the library says in one place; which theory a
family needed and the library lacks; what the check finds that the kernel loads in silence, by count.

### Dropped as moot

- **The Python modules and `string.Template`**: the harness is Rust
  ([Q-M2.7](../open_questions.md#q-m27--what-language-is-the-frontend-written-in)).
- **Calling the binary to dump a reply canonically**: no command prints a canonical dump; the library has it
  (the audit, A.2 row 20).
- **The *unified model* with `is-a` up to `T`**: the page it cited says there are no types and that `is-a` and
  `T` are names a program writes (the audit, A.1 row 11).
- **The Russian examples**: texts are English (the frame's default 9).
- **Accepting *either formulation* in the theory pass's own test**: the test is of the catalogue's entries, and
  the answer is S2.2.5's.

## Risks

- **A selection misspelt is silent.** It is the commonest mistake a model can make in this pass, and the kernel
  loads it and answers something else. The check's second finding is the only thing that sees it, which is why
  the catalogue's entries are run and not written from memory.
- **Four calls compound.** A name the ontology pass got wrong is wrong in every later pass. The per-pass reports
  say where a failed program first went wrong, and T2.2.4.9's one call is the comparison.
- **A sentence alone is not a context.** The marked-sentence prompt is the answer to pronouns; whether it is
  enough is one of the instance pass's reports.
- **The prompt has to fit.** The excerpt, the catalogue and the examples together are cut to the context the
  device holds ([S2.2.2](s2.2.2_model_runtime.md)); the minimal catalogue may be what the default has to be.
