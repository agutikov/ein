## Context

S2.2e.2's change of `std.slots` failed three of EinAf's tests that replay a recorded model run, because the
catalogue the model is shown begins *The library is sha256:…* (`einaf::catalogue`, `Catalogue::text`): any change
to `stdlib/` changes that line, the prompts no longer match their records, and a replay finds no call. The user
chose the second of the three ways offered: **take the digest out of what the model sees**. It is a hash, no help to
a model, and it belongs to the record, which says what the model was shown and against which library. Recorded
once again, a replay then breaks only where the library changes what the catalogue shows, which is what a
recording should follow.

## Acceptance

- The catalogue's text, as every prompt shows it, carries no digest; the sentence that held it keeps the rest of
  what it says. The library's digest is a field of every record that is not in the prompt (the run's and each
  call's, beside the prompt's version), so a record still says what library it was made against.
- The prompts' version follows the change, by the rule `einaf::prompts` versions a template by.
- **The two recorded runs are recorded again with the model**, once, as their plans say they were made
  (`einaf/tests/fixtures/from_text/zebra-contradiction/`, `einaf/tests/fixtures/steps/bob1/`): the runtime with the
  feature `cuda`, `qwen3.5:4b`, the settings each record names. Where the model now writes something else, the
  test's expectation is re-stated with why, and a page of `docs/einaf/` that shows the run is read again.
- The probe line (`einaf/tests/fixtures/model/probe_lines.jsonl`) judged again from its own record with no model
  (`einaf probe run --replay`), which writes the new library's digest and nothing else.
- **A replay survives a library change that leaves the catalogue's text alone**: a test that replays a fixture with
  `EIN_STDLIB` set to a copy of the library whose manifest differs and whose catalogue text does not.
- EinAf's tests are green; the gate is green on the phase's last commit.
- L-M2.31 closed by the stage's commit.

### Defaults taken

1. **The prompts' version moves by digest, and no template is renamed**: the catalogue's text is code that fills a
   slot, not a template file, and `einaf::prompts`' rule versions a prompt by its digests, which move. A template
   renamed `.v2` with its text unchanged would be a version with nothing in it.
2. **The library's digest is a field of the run's record and of each step's (`StepRun`), and of the one shot's
