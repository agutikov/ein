## Context

The node function takes a dead node's core where `axes.cores || facts.is_empty()`
(`ein-infer/src/region.rs`, `node_in_region`): root's on every run, whatever the question. Only a description
(`ein solve`) and `--no-search` print root's core; `--single`, `-n`, `--minimal`, `--maximal` and `--count` print
none, and their summaries write `region.core` `null` though root is dead. The core is searched and thrown away,
against two decisions Ein already has:
[Q-M1f.29](../../../docs/decisions/read-out/Q-M1f.29-a-question-that-prints-no-core-writes-a-dead.md) (*a count's
question is how many, and a mode's is a part of R; neither takes a core it would not print*) and
[Q-M1e2.31](../../../docs/decisions/answer/Q-M1e2.31-each-question-about-r-does-the-least-work-it.md) (*a core is taken
only where a surface prints one*). The code and a design page say otherwise and mean it: `region::Cores`' note,
*root's is taken on every run*, and
[`03-design/07-search.md` § 6](../../../docs/ein/ein.rs/03-design/07-search.md#6-cores-and-explanations), *root's and,
on the cube, the minimal holes' always*.

On the model's Zebra program (`p2.2_formalizer/from_text/runs/library/zebra/program.ein`), whose root dies on a link
several rules derive with every derivation recorded, the core is the whole cost: `--single` 72 s, of which root's
saturation and everything else some 60 ms; under `:record-alternative-justifications false`, 0.05 s. Since S2.2e.3
the core's search reads the clock, so under a clock every question on such a program ends at it with no answer.

## Acceptance

- **Root's core is taken only where the question prints it**: a description and `--no-search`, and the surfaces
  that print a visited node's core (`--events`, `--dump-lattice`, and any other the stage finds and names); not
  under `--single`, `-n`, `--minimal`, `--maximal` or `--count`. `--count` takes describe's route with describe's
  mode (`explore::run_with`), so the count's question reaches the node function's axes.
- **No answer and no printed byte moves**, on any command, under any question: held by the sweeps that already read
  them (the corpus through the CLI, the shape golden, the read-out's reference, the lever and route invariances, the
  oracle). A golden that moves is a finding, not a re-bless.
- **The test that a run printing no core takes none** (`explore.rs`,
  `a_run_that_prints_no_core_takes_none_and_answers_alike`) compares root's core too, and fails on the code as it
  stands; a test that a dead root's description still prints its core.
- **The model's Zebra program**: `ein solve --single`, `--count`, `--maximal` answer in what root's saturation costs,
  with no clock, and `-T 5` gives the same answers within its bound; the description still prints its two `unsat core`
  rows, and under `-T 5` is *not decided* as S2.2e.3 left it. Measured through `utils/bench_env.sh`, the probe's
  commands and outputs in the record.
- **What says otherwise is rewritten**: `region::Cores`' note, `03-design/07-search.md` § 6, and any page of
  `docs/ein/` that says root's core is taken on every run. No decision is written: Q-M1f.29 and Q-M1e2.31 already
  say it, and the page that cites them stays true.
- **EinAf follows**: its tests and [`docs/einaf/03-feedback.md`](../../../docs/einaf/03-feedback.md) where they state
  that a question on such a program costs the core's search or ends at the clock; the bounded call's description
  under `Listing::False` keeps its core.
- E-130 closed by the stage, its entry saying by which commit; E-126's entry noted where it says what is left.

### T2.2e.6.2 — The question reaches the node function

**The axis.** `region::Cores` gains a third field, `root`, a dead root's core, beside `visited` (every dead node
visited) and `nogoods` (each member of `N`); `Cores::ALL` and `Cores::READ_OUT` ask it. The axes take the three,
`Axes::taking_cores(Cores)`, on every route that builds them (the modes' space, the state route, route 1, the cube,
the claim check's fixpoints), and the node function takes a dead node's core `if dead && (axes.cores ||
(facts.is_empty() && axes.root_core))`, where it took it `if dead && (axes.cores || facts.is_empty())`.
`root_core` is `Cores::of_root`, `root || visited || nogoods`: a visited node's core is printed with root's among
them, and where root is dead `N` is `{∅}`, whose member's core is root's.

**The question.** `explore::Options::cores_taken` reads it: `root` is kept where the question is a description or
`--no-search`, and cleared under a mode and `--count`; `nogoods` is kept under a description alone. `explore::run_with`
reads it first, into the options every route is handed, before `--count` is asked as describe with describe's mode,
so the count's question, which no route sees after that, has already reached the axes. `Options::new` still asks
`Cores::READ_OUT`, which the question keeps or clears, so the library's `--single` takes no core, as the binary's does.
`ein solve` asks `root` always and lets the question decide; `ein test` asks it only where its `--json-summary`
writes it (Defaults 4); `ein render lattice` asks it beside every visited node's.

**The tests, failing first.** Each was run with the node function's old condition put back for the run (the field
read and ignored), and failed; then with the fix, and passed:

- `ein-infer/tests/explore.rs`' `a_run_that_prints_no_core_takes_none_and_answers_alike`, over every corpus program
  and regression witness but the slow ones: `--count` joins the questions; root's core is compared with the eager
  run's under a description and held absent from `--count`'s description; and on every program whose root is dead,
  under every question, the lazy run's walk, read by `--dump-lattice`'s watch, takes root's core under describe and
  under no other. With the fix: 4 440 runs, 966 questions of a dead root (161 programs), 68 542 dead nodes walked with
  no core, 1 500 members of `N` taken after the walk. Before it: *root's visits took a core [true], and the question
  prints none* on every dead root under `--minimal`, `--maximal`, `-n 2`, `--single` and `--count`, and *root's core is
  taken, and the question prints none* under `--count`.
- `ein-cli/tests/bounded_saturation.rs`' new `a_question_that_prints_no_core_answers_a_dead_root_within_the_clock`, on
  `dead_link.ein` (root's saturation 30 ms, its core's search 17 s): `--single`, `--count`, `-n 2`, `--minimal` and
  `--maximal` under `-T 0.3` each exit 0, `region.core` `null`, their `region` and `verdict` blocks those of the
  program with the lever; `ein test` with no summary `ok`; the library's `--single` and `--count` answered under a

  clock: a description, `--no-search`, `--single --events`, `--count --dump-lattice`, `ein oracle`, `ein test
  --json-summary`, and the library's describe.
- `every_mode_unit` (`every_mode_is_the_oracle` and its twin above a saved node) held `--count`'s answer to describe's
  field for field, root's core among them, and failed with the fix on 258 lines at the default budget and 225 at a
