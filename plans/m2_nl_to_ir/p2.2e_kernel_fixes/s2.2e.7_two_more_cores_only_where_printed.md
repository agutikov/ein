## Context

S2.2e.6 took a dead root's core only where a question prints it. Its list of every surface that prints a core, and
every question's route to the node function, found two more cores searched and thrown away. Both go against
[Q-M1e2.31](../../../docs/decisions/answer/Q-M1e2.31-each-question-about-r-does-the-least-work-it.md) (*a core is
taken only where a surface prints one*) and
[Q-M1f.29](../../../docs/decisions/read-out/Q-M1f.29-a-question-that-prints-no-core-writes-a-dead.md):

- **The cube's minimal holes', under a line mode.** On a program the static check flags, within `--region-limit`, a
  line mode the cube does not decide early computes the whole cube: `--maximal` under any ask, or `--minimal` where
  root owes. `region::compute_prepared` then takes each dead minimal hole's core whatever the question, and
  `explore::of_cube` prints them for a description alone. A description prints them (the read-out's `minimal hole`
  rows, the summary's `region.holes.minimal[].core`), and `--count` writes them in its summary.
- **The whole node's, under a progress watch.** The modes' obligation tree reads the whole node (`tree.rs`,
  `read_structure`). Where that node is dead, `structure::coupling::node` takes its core wherever the run is narrated
  (`Space::narrated()`). `--events` and `--dump-lattice` print that core, and they ask `Cores::visited`. `-v` and
  `--layer-progress` narrate too but print no core, so under them alone the core is searched and dropped.

## Acceptance

- **The minimal holes' cores are taken only where the question prints them**: a description, and `--count`, whose
  summary writes them. They are not taken under a line mode. `explore::Options::cores_taken` already decides this for
  root's core and for `nogoods`.
- **The whole node's core is taken only where `Cores::visited` asks for it** (`--events`, `--dump-lattice`, and any
  other surface the stage finds that prints it), not merely wherever the run is narrated.
- **No answer and no printed byte moves**, on any command, under any question. That is held by the sweeps that
  already read them (the corpus through the CLI, the shape golden, the read-out's reference, the lever and route
  invariances, the oracle, the events' goldens). A golden that moves is a finding, not a re-bless.
- **The test that a run printing no core takes none** (`explore.rs`,
  `a_run_that_prints_no_core_takes_none_and_answers_alike`) reads both, and fails on the code as it stands: a flagged
  program within the limit under `--maximal` and `--minimal`, and a monotone program whose whole node dies, under
  `-v` and `--layer-progress`.
- **Each case measured where a program in the corpus or the probes shows a cost**, through `utils/bench_env.sh`,
  before and after; where none does, the record says so.
- **What says otherwise is rewritten**: notes in `region.rs`, `explore.rs`, `tree.rs` and `structure::coupling`, and
  any page of `docs/ein/` that says these cores are taken. No decision is written: Q-M1e2.31 and Q-M1f.29 already say
  it.
- E-131 closed by the stage, its entry saying by which commit.

### T2.2e.7.2 — The fix

**The holes.** `region::Cores` gains a fourth field, `holes`, each dead minimal hole's on the cube; `Cores::ALL` and
`Cores::READ_OUT` ask it. `compute_prepared` takes the holes' after the walk where `holes` asks (and `visited` is off,
as before), where it took them whenever `visited` was off. `explore::Options::cores_taken` keeps `holes` under a
description and `--count`, and clears it under every mode; `run_with` reads it before `--count` is asked as describe,
as it does root's. `ein solve` asks it always and lets the question decide; `ein test` asks it where its
`--json-summary` writes it (Defaults 3); `ein oracle` (`Cores::ALL` or `READ_OUT`) and `ein render lattice` ask it.

**The whole node.** `explore::Space::takes_whole_core`: the run narrated and `Cores::visited` asked (the axes'
`takes_cores`). `structure::coupling::node` reads it where it read `Space::narrated()`. `--events` and
`--dump-lattice` ask `visited` and narrate, so they take and print the core as before; a watch alone, `-v` and
`--layer-progress`, is handed the node with no core, as it is every node the node function computes under it
(Defaults 1).

**The tests, failing first.** Each was run with the old behaviour put back for the run (`compute_prepared`'s
condition `opts.cores.holes || true`, and `node.rs` reading `sp.narrated()`), and failed; then with the fix, and
passed:

- `ein-infer/tests/explore.rs`' `a_run_that_prints_no_core_takes_none_and_answers_alike`: its lazy run is now read by
  a watch (`DeadCores`, which marks the whole node, a dead visit with a commitment and no closure), and its walk takes
  no dead node's core but a dead root's where the question prints it; on `dead_link_whole.ein`, `--single` and `-n 2`
  visit the dead whole node and take no core, and answer as the run nothing watches; on `dead_link_hole.ein`,
  `--maximal` and `--minimal` answer within a 5 s clock as the program with
  `:record-alternative-justifications false` answers them, and a description and `--count` end at a 0.5 s clock. With
  the fix: 4 440 runs over the corpus, 38 minimal holes, 22 dead, 1 500 members of `N` taken after the walk, 68 542 dead
  nodes walked with no core, 966 questions of a dead root, and 2 dead whole nodes watched with no core taken, the
  fixture's (29.5 s). Before it: *dead_link_hole.ein Mode { which: Maximal, ask: Describe }: Err("--max-time reached
  inside the cube") after 5.006s*, the same for `Minimal`, and *dead_link_whole.ein Mode { which: All, ask: Single }:
  the watched walk took a core at the whole node, 25 candidates, and the question prints none*, the same for `Find(2)`
  (84 s, the two watched runs some 17 s each).
- `ein-cli/tests/bounded_saturation.rs`' new `a_line_mode_takes_no_holes_core_and_a_watch_no_whole_nodes`: on the
  hole fixture `--maximal`, `--minimal`, `--maximal -n 2` and `--maximal --single` under `-T 2` exit 0 with the lever
  twin's `region` and `verdict` (`region.holes` `null`), and a description, `--count` and `--maximal --dump-lattice`
  end at a 0.3 s clock; on the whole fixture `--single -v`, `--single --layer-progress` and `-n 2 -v` under `-T 5` exit
  0 with the read-out, `region` and `verdict` of the run with no watch. Before the fix the four line modes were the
  clock's abort after 2.00 s, and the three watched runs exit 2 after 18.5 s, the core's search running past the 5 s
  clock (E-132).

No corpus program outside the slow set has a whole node the tree reads dead, so the corpus sweep of the explore test
alone did not fail on the old code for the whole node: the fixture is what reads it, and the test asserts that a dead
