## Context

**The order.** Ein reads a file whole before it loads any form, and on S2.2.0a's programs an answer does not
depend on the order of the forms: the six Zebra encodings in synthesis order and in theory-first order answer
alike under every question. The formalizer assembles a program in the order its steps make it. No page of Ein
says an answer may not depend on that order, and no test of Ein writes a program's forms in another one.

**The table.** The parser's banked table of refused shapes has a row for a string glued to a name and none for a
string glued to a block comment, and none for a form whose closing paren a line comment takes. A second reader of
the syntax held to the table and the corpus alone would accept both.

## Acceptance

On Q-M2.24's ruling (the user, 2026-11-27: *"So for now let's state it and record as a known fact, a guarantee, so
if will ever see different behaviour it would be considered a bug"*):

- a decision under `docs/decisions/`, under the id Q-M2.24, in the subject it belongs to: an answer (R, every
  question's outcome, the queries' classes and rows, H) does not depend on the order a program's forms are written
  in; why, in the user's two reasons (a form is its own object and a name one object wherever it is written; the
  load that connects names and builds the program's compiled rules, indexes and registries reads the whole
  program, and no module is loaded at run time); what may move under another order (what § 1.3 of the
  determinism page allows); and that a run that shows otherwise is a wrong answer, a bug;
- a row of [`01-determinism-and-order.md`](../../../docs/ein/ein.rs/03-design/01-determinism-and-order.md) § 1.2's
  list of what a run may not depend on, citing the decision;
- **no test**: the ruling states it for now. Neither the decision nor the page claims a test holds it.

With the phase, whatever is ruled:
