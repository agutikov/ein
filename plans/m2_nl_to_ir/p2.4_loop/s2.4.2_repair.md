## Context

E2 is a comparison and not a choice: *regenerate the entire theory* against *edit the existing theory*. The case
for the second is that **Ein localises**: a core names facts and, through their `:source`, sentences; what a
state owes names a relation and an object; two states name the facts they differ in. A model told *where* can
change *that* and leave the rest. Whether it does is [P2.6](../p2.6_ablations/README.md)'s to measure. This
stage makes the two strategies two values of one parameter with everything else equal, in the filter
([S2.4.1](s2.4.1_state_machine.md)); the tool has no REPAIR state, and what the model does after a call is its
own ([S2.4.6](s2.4.6_ein_as_a_tool.md)).

**What is gone.** The old stage's premise was that its validator's three checks (*unknown atom*, *type mismatch*,
*structural contradiction*) were *the loader's and the kernel's already*, so that *the residue is nothing*. None
of the three holds as written ([`audit_p2.4.md`](../analysis/audit_p2.4.md) § A.4, items 25 to 28): a fact over
an undeclared relation or name loads in silence; Ein has no types, and a declared relation at another count is
another relation; two facts of a relation contradict only where the program imports the theory that says so and
activates it (`std.algebra`'s `functional`, then a dead root with a core of the two facts). What the kernel does
not check and the contract wants checked is F1's residue, and it is [S2.4.3](s2.4.3_feedback_ladder.md)'s. The
`:source` pre-check and its *29 ms per solve* are gone too (T2.4.2.4).

### The two strategies, in a kept context

The model runs in EinAf's process, and the runtime keeps a context between the turns of one episode
([Q-M2.14](../open_questions/model/Q-M2.14-what-runs-the-model.md)). An episode's context has a **prefix** (the
instructions, the catalogue, the text) evaluated once, and then turns.

| | what the model is given | in the kept context |
|---|---|---|
| **regenerate** | the text and the rendered feedback | the context is rolled back to the prefix; the feedback is the one new turn |
| **repair** | the text, its own program and the rendered feedback | the program is already there, as the model's last turn; the feedback is appended, and the reply pays for the feedback's tokens only |

`history` says how much of the episode a repair sees: `all` (the default: every earlier program and its
feedback stay in the context) or `last` (the context holds the prefix, the last program and its feedback). It is
a parameter and a field of the record because it is information: a model that sees `T₀ … Tᵢ` can see its own
cycle. Regenerate has no history by definition. The context has a length; what is dropped first when an episode
reaches it is this stage's to fix, and a run that dropped something says so in its record.

Both strategies receive the feedback as an opaque block from the renderer of the run's level: the prompt does not
know what F5 is, the renderer does.

### One reply the repair must admit

*The statement does not determine this, and the program is unchanged.* On an instance whose gold class is
ambiguous the feedback says *several* and, at F4, shows a difference, and the faithful reply is to add nothing.
A repair that can only return an edited program forces the E3 failure (*several → invent → one*) by
construction. In the filter the model writes an Ein program and nothing else
([Q-M2.13](../open_questions/einaf/Q-M2.13-who-calls-the-kernel.md)), so **the reply *unchanged* is the same program
again**: the machine sees the syntactic identity it has just seen, the fixed point ends the run, and the outcome
standing is the episode's, with the fixed text that names it for an answer
([S2.4.1](s2.4.1_state_machine.md)). The same holds for *inconsistent* where the text itself is inconsistent: the faithful
repair reports the core and deletes no source fact.

The cost is the program's tokens, generated a second time, which the budget rule prices like any generation. A
shorter spelling (one form the harness reads as *unchanged*) would be the one thing the filter accepts that is
not a program; T2.4.2.2 weighs it.

## Tasks

- **T2.4.2.1 — The two prompts.** `einaf/prompts/`: *regenerate* is the text, the rendered feedback and the
  one-shot skeleton of [S2.2.4](../p2.2_formalizer/s2.2.4_passes.md), whose three steps it runs again with the
  feedback in each step's prompt; *repair* is the feedback turn after the model's own program, and carries the
  research plan's instruction with the sentence that admits the reply above:

  > Repair the theory using only information justified by the original statement. If the statement does not
  > justify a change, return the theory unchanged.

  and, beside it, the user's order of change
  ([P2.4 § The theory before the facts](README.md#the-theory-before-the-facts)): the ontology and the theory
  first, a fact of the text only where the feedback names it and nothing else answers it.

  Each is versioned by its hash, and the hash is in every record that used it. A whole program is returned, never
  a patch: a patch invites the model to edit a line it has not read.
- **T2.4.2.2 — The reply *unchanged*.** The default is the same program again. The stage measures on the seed
  set, under replay and then with the model, what that costs in generated tokens and how often a model asked to
  change nothing returns its program byte for byte, canonically equal, or altered. If a short form is wanted
  instead, it is a harness-level form the grammar of [S2.2.3](../p2.2_formalizer/s2.2.3_gbnf.md) admits beside a
  program, it never reaches the kernel, and the decision is written here with the measurement; the ruling's words
  (*forced to write ein code*) are the bar it is held to.
- **T2.4.2.3 — The diff.** Top-level forms by canonical text (`ein_ir::dump_canonical`, a form at a time),
  classified *added*, *removed* or *changed* (the same head and first argument, another body), each with its
  category from the table of categories of [S2.2.1](../p2.2_formalizer/s2.2.1_contract.md). It is written into the
  transition record, and it is what [S2.4.4](s2.4.4_faithfulness.md) judges. H3's *new errors introduced by
  repair* is [S2.5.3](../p2.5_harness/s2.5.3_metrics.md)'s to define, over what the record holds a repair: the
  diff, the outcome before and after, and each diagnostic kind and faithfulness event the iteration before did
  not have. **A fact newly in a core is no new error**: a core is an explanation and may move with the order the
  rules are written in ([Q-M1f.6](../../../docs/decisions/answer/Q-M1f.6-a-core-is-an-explanation.md)); the old
  task counted it as a regression.
- **T2.4.2.4 — The kept context.** The episode's context as the two strategies use it: the prefix evaluated
  once; a repair appended; a regenerate rolled back; `history`; the limit and what is dropped at it. The record's
  three token counts a turn (generated, evaluated anew, reused) are taken from the runtime, and a test under the
  replayer holds that a repair's *evaluated anew* is the feedback turn's tokens and no more. *This id was the
  `:source` pre-check, kept or dropped by what a kernel round trip costs. It is moot: the figure had no command
  ([`audit_p2.4.md`](../analysis/audit_p2.4.md) § A.1, item 6), the kernel is a library EinAf links, and a
  finding of the judge fed back to the model would be a second feedback channel beside the kernel's, which
  S2.4.4 keeps out of the loop.*
- **T2.4.2.5 — Fixtures and tests.** Canned replies for the replayer, over three texts of the seed set
  ([S2.3.1](../p2.3_benchmark/s2.3.1_families_and_seed_set.md)): a program with one wrong source fact (two houses
  swapped in one clue), which one repair at F5 mends with a diff of exactly one form changed; an ambiguous text
  (the puzzle with a clue dropped), which ends at the fixed point with *several* and a diff of no form; a text
  that contradicts itself, which ends at the fixed point with *inconsistent*. The Zebra puzzle's text and its two
  edits of these shapes exist under `nl2smt/puzzles/` (`zebra.txt`, `zebra-minus-15.txt`,
  `zebra-contradiction.txt`), outside the project and the process; whether the seed set takes them is S2.3.1's.
  The tests run in EinAf's step of the gate, with no model.
- **T2.4.2.6 — The evaluation.** Into [the evaluation of Ein](../evaluation/README.md): where the kernel's reply
  localised a repair and where it could not (a diagnostic with no place: a loader message about a top-level form
  ends `at None`, [F23](../../followups/f23_diagnostics_in_eins_words.md)'s D-2; a core whose facts carry labels
  and no sentence); what a canonical form a time took from the library.

## Acceptance

- `strategy` (`regenerate`, `repair`) and `history` (`all`, `last`) are parameters of a run and fields of every
  transition record. `readings` is [S2.4.5](s2.4.5_alternatives_as_hypotheses.md)'s parameter and none of
  `strategy`'s values.
- The two prompts exist, each hashed into every record that used it.
- Every REPAIR transition records a form-level diff of `Tᵢ → Tᵢ₊₁`; the reply *unchanged* is a diff of no form.
- The three fixtures of T2.4.2.5 end as stated, under the replayer.
- Under the replayer, a repair's newly evaluated prompt tokens are the feedback turn's alone, and a regenerate's
  context is the prefix and one turn.
- By hand, with the model and a record: regenerate and repair run on the seed set at F8, and the transcripts'
  counts are reported. They are not compared here, which is G1's.

## Risks

- **Regenerate is not *no information*.** Both strategies receive the rendered feedback; what differs is whether
  the model also has its own program. The arms B3 to B5 fix the strategy at *repair*, so that only the level
  varies down the table ([S2.5.2](../p2.5_harness/s2.5.2_baselines.md)); the strategy's axis is P2.6's, and G1
  holds one axis while it varies the other.
- **`history` is a second variable hiding in the first.** A repair with the whole episode in its context is given
  more than E2's *original statement, current theory, diagnostic*. The default is `all` because that is what the
  kept context gives for the fewest evaluated tokens, the tool's episode is one conversation too, and the two
  arrangements then see their own history alike; `last` is E2 to the letter, and P2.6 may ask for it.
- **The same program again is the costliest way to say nothing.** On a long program the reply spends the
  episode's token budget on a copy. T2.4.2.2 has the number before the default is kept.
- **A model does not copy exactly.** A reply meant as *unchanged* that moves a comment or reorders two facts is a
  new syntactic identity and the same semantic one: it is a cosmetic repair, the run stops on the semantic
  identity all the same, and how often it happens is a count of the record.
