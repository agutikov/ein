## Context

The plan's E2 is a comparison, not a choice: *regenerate the entire theory*
vs *edit the existing theory*, and the case for the second is that **Ein
localises** — an unsat core names the facts, a missing dependency names the
relation, a model difference names the sentence — so a model told *where*
can change *that* and leave the rest. Whether it does is
[P2.6](../p2.6_ablations/README.md)'s to measure; this stage makes the two
strategies two values of one config parameter with everything else equal.

The old S2.4.2 was *repair under F1, three attempts*: a validator with three
checks and a "try again, but…" prompt. What survives of it is the prompt's
shape and the iteration budget; the checks do not, because the kernel
already makes them:

| old check | who reports it now | as |
|---|---|---|
| unknown atom — a fact names an instance the ontology does not declare | the loader, at load time | a `diagnostics[]` entry of kind `undefined_symbol`, with the pinned message ([`defined_behaviour.md` § 1](../../../docs/kernel/defined_behaviour.md)) and the location [S2.1.2](../p2.1_kernel_as_instrumentation/s2.1.2_feedback_object.md) gives it; and the ontology-parameterised facts grammar of [S2.2.3](../p2.2_formalizer/s2.2.3_gbnf.md) makes most of them unemittable in the first place |
| type mismatch — a relation's argument violates its signature | the loader / compiler | `type_error` |
| structural contradiction — two facts of a functional relation with different destinations | the kernel, by `std.algebra`'s `functional` rule: two conflicting stored facts ⇒ `(false)` | `inconsistent`, with a **two-fact unsat core** whose `:source` quotes name the two sentences — which is better than the validator's verdict, because it is the same mechanism that catches the puzzle's own contradictions |

The residue is nothing, and the stage keeps only a *cheap pre-check* —
`:source` spans present and found in the text, which is
[S2.4.4](s2.4.4_faithfulness.md)'s mechanical judge run early — if a
measurement on the seed set shows it saves a kernel round-trip often enough
to matter. At 29 ms per solve it will not, and the pre-check is then dropped
with its number.

### One reply the repair prompt must admit

*The statement does not determine this; the theory is unchanged.* On an
instance whose gold verdict is `ambiguous`, the feedback at F3 / F4 says
*four models remain* and shows a difference — and the faithful response is
to add nothing. A repair prompt that only accepts an edited theory forces
the E3 failure (*ambiguous → invent → unique*) by construction. So the
repair grammar admits an unchanged program with a stated reason, the
machine sees `program_sha` unchanged, the fixed point terminates the run
([S2.4.1](s2.4.1_state_machine.md)), and the verdict standing — `multiple_models` —
is the answer. The same holds for `inconsistent` when the text itself is
inconsistent: the faithful repair is to report the core, not to delete a
source fact.

## Acceptance

- `strategy ∈ {regenerate, repair, alternatives}` is one config parameter;
  the third is [S2.4.5](s2.4.5_alternatives_as_hypotheses.md)'s and this
  stage only reserves the value.
- The two prompts exist, are hashed into every record that used them, and
  the repair prompt carries the plan's instruction verbatim.
- Every REPAIR transition records a form-level diff of `Tᵢ → Tᵢ₊₁`; the
  *unchanged* reply is a diff of zero forms with a reason string.
- A fixture program with one wrong source fact is repaired in one
  iteration at F5 under a mocked LLM, and the recorded diff is exactly one
  form changed; a fixture with a genuinely ambiguous text ends at the fixed
  point with `multiple_models` and a zero-form diff.
- On the seed set, regenerate and repair run at F8 with three seeds each,
  and the transcript counts are reported — not compared, which is G1's job.

## Tasks

### Task T2.4.2.1 — The two prompts

`einaf/prompts/regenerate.tmpl` — the text, the rendered feedback, the
one-shot skeleton of [S2.2.4](../p2.2_formalizer/s2.2.4_passes.md).
`einaf/prompts/repair.tmpl` — the text, the current theory, the rendered
feedback, and:

> Original statement … Current theory … Diagnostic … Task: Repair the theory
> using only information justified by the original statement. If the
> statement does not justify a change, return the theory unchanged and say
> why.

Both prompts take the feedback as an opaque block from the renderer of the
run's level — the prompt does not know what F5 is, the renderer does.

### Task T2.4.2.2 — The repair grammar

`grammars/repair.gbnf`: a full program (the four-part output) **or** the
literal `(unchanged :reason "…")` form, which is harness-level and never
reaches the kernel. A repaired program is the whole program, not a patch:
patches invite a model to edit a line it has not read, and a whole program
costs tokens the budget rule prices anyway.

### Task T2.4.2.3 — The diff

`einaf/loop/diff.py`: top-level forms by canonical text (the producer's
`dump_canonical` per form, or the harness's own normalisation until the
feedback object carries per-form hashes), classified *added* / *removed* /
*changed* (same head and first argument, different body), each with its
B2 category from [S2.2.1](../p2.2_formalizer/s2.2.1_contract.md)'s sidecar.
Written into the transition record; it is the input [S2.4.4](s2.4.4_faithfulness.md)
judges and the thing H3's *new errors introduced by repair* counts
([S2.5.3](../p2.5_harness/s2.5.3_metrics.md)): a diff whose added form
produces a new `diagnostics[]` entry or a new core member on the next
iteration is a regression.

### Task T2.4.2.4 — The pre-check, measured

On the seed set at F5, count the REPAIR outputs that would have failed the
`:source` pre-check, the kernel round-trips saved, and the wall saved; keep
the pre-check only if the saving is a number worth a line in a table.
Record either outcome in this file's Notes.

### Task T2.4.2.5 — Fixtures and tests

`einaf/tests/fixtures/repair/`: the one-wrong-fact program (a Zebra clue
with two houses swapped), the genuinely ambiguous program
(`examples/zebra2-minus-15.ein`'s text with the fifteenth clue absent), the
self-inconsistent text. `einaf/tests/test_repair.py` runs each under the
mocked LLM with canned replies and checks the diff, the reason, and the
termination condition.

## Notes

- **Regenerate is not "no information".** Both strategies receive the
  rendered feedback; what differs is whether the model also receives its
  own previous theory. The baselines B3–B5 fix the strategy at *repair* so
  that only the level varies down the table
  ([P2.5](../p2.5_harness/README.md)); the strategy axis is
  [P2.6](../p2.6_ablations/README.md)'s, and G1 holds one axis while
  varying the other.
- The per-repair diff is also what the demo shows
  ([P2.10](../p2.10_result_artifact_demo/README.md)): the repaired program
  *with the diff* is the frame where the idea is visible.
