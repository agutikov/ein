## Context

This stage was *the census*: Stage A re-taken against the engine with `file:line`, two measurements, and the six
outcomes written into `defined_behaviour.md`. [The analysis](../analysis/README.md) is that census (its
[audit of P2.1](../analysis/audit_p2.1.md) § 0 is the fact base), both measurements are answered (an unknown
keyword on a fact is a parse error, [Q-M1e2.28](../../../docs/decisions/language/Q-M1e2.28-each-form-takes-a-closed-list-of-keywords.md);
the rules no program activated are a gate test over the library, by `fire` and `owe`), and the page is gone. What
is left of it is one list. What is new is that **nothing of EinAf exists**, and the user has ruled where it lives
and in what language.

So the stage creates the tree, wires it into the process, and writes into it the first thing EinAf has to know of
the kernel: which outcome a run is.

**The seven outcomes** are [the frame's](../README.md#the-outcomes). What each is read from, in the library's
values and, for a reader of the binary, in `ein-summary/2`'s keys (the audit's § 0 has each run):

| outcome | read from | not to be confused with |
|---|---|---|
| **invalid** | the load returns an error: a parse error, or a refusal of [`07-diagnostics.md`](../../../docs/ein/user/04-reference/07-diagnostics.md) § 2. No answer exists and no summary is written today | exit 1, which is also a claim the run refuted, with a summary ([Q-M1e2.33](../../../docs/decisions/cli/Q-M1e2.33-every-answer-exits-0.md)) |
| **flagged** | the static check's finding, read before any answer: `monotonicity.warning` and its sites | any of the five below: an answer is printed and nothing is claimed of it ([Q-M1f.564](../../../docs/decisions/answer/Q-M1f.564-a-non-monotone-program-loads-with-a-warning.md)) |
| **not decided** | the run stopped first: `region.exhausted false` with `region.stopped.why` `budget` or `limit`, `verdict.word null` under `--single`; or the deadline error of a `-T` run, which writes no summary today | `region.stopped.why "asked"`, which is a run that did what it was asked (`-n N`, `Ambiguity` after two states) |
| **inconsistent** | R is empty and its kind is `dead`: `Contradiction` under `--single`; under a description `region.empty "dead"` with `core`, `core_status`, `refuted_by` | an empty R whose kind is `owing` |
| **incomplete** | a state owes: `Open` under `--single`; `region.empty "owing"` or `region.root "owing"`, `root.owed`, `region.frontier` | a query whose class has no row, which is the query's axis |
| **several** | `Ambiguity`, with two states that differ | — |
| **one** | `Solution` | — |

Two things the table cannot settle and the function must carry instead of hiding:

- ***one* and *several* have two readings.** R holds partial commitments where a program states no obligation, so
  a program can be `Ambiguity` over all of R and `Solution` over its maximal line
  ([`06-solution-semantics.md`](../../../docs/ein/reasoning/02-kb-evolution/06-solution-semantics.md)). Which
  reading *certifies* is [Q-M2.10](../open_questions/answer/Q-M2.10-what-does-ein-certifies-a-unique-model-mean-on-r.md),
  the user's after experiments. The function returns the outcome **with the reading it was taken under**, and a
  caller that wants both asks both.
- **The outcome is of a question.** A bare solve has no verdict word; `--no-search` states no R at all. The
  function is defined for each question it accepts, and says which it was asked.

Beside the outcome, and not part of it: each query's own axis (its classes, their rows, whether they agree), and
whether a claim the program states held.

## Risks

- **A package outside the workspace builds the crates a second time**, into a `target/` of its own, and the gate
  pays for it on every run. If that is too much, EinAf's step shares the engine's target directory; it does not
  join the workspace.
- **The function invites a single verdict where the kernel has none.** A bare solve of an under-determined program
  can stop at the default budget after finding every state (the audit's § 0, the ambiguous Zebra variant): the
  function says *not decided* of that question and does not guess from the states listed.
- **Writing the process's rules for a tree before the tree has content** fixes them early. They are few, each is
  one line of a script, and T2.1.1.3 puts the proposal before the user.

### What was built

- **[`einaf/`](../../../einaf/Cargo.toml)**, one package, `einaf`, a library and a binary, the root of a workspace of
  its own. Path dependencies `ein-core`, `ein-ir`, `ein-infer`, `ein-render`; `ein-corpus` a dev-dependency. Its
  manifest copies three things of the engine's that a manifest outside the workspace does not inherit: the
  `[patch.crates-io]` for `lrpar` (without it `ein-ir` does not compile, E-62), the `gate` profile, and the lock file,
  `einaf/Cargo.lock` started from `ein.rs/Cargo.lock` so every shared crate is at the engine's version (the diff
  is crates removed and `einaf` added). Inherited `workspace = true` fields, `include_dir!` of the stdlib and the
  generated parser's build script needed nothing.
- **`einaf::kernel`** ([`src/kernel/mod.rs`](../../../einaf/src/kernel/mod.rs)), the one module that calls the
  library: `Program::load_file` / `load_text` (the read, `ein_ir::saved::load_text` as `ein solve` loads, then the
  hypothesis mechanisms judged on a copy of root as `ein-cli`'s `common::judge_mechanisms` does, E-64);
  `Program::ask(Question, Bounds) -> Run`, on a copy of the load (`read_out::run`); `Program::statically_flagged`
  (`explore::check_monotone`), `Program::claims` (each claim's shape) and `Run::claims_checked` (the kernel's
  `Held`/`Failed`/`NotChecked` of each), for the tests; `Run::read_out_text` (`ein_render::read_out::render`).
  `Question`: `Describe`, `Single(Part)`, `Line(Part)`, `Count`, `NoSearch`, each `ein solve`'s flags;
  `Part`: `All`, `Minimal`, `Maximal`, the reading; `Bounds`: the facts budget, the cube's limit, the clock.
  `Refusal { stage: Read | Parse | Load | Run, message, parse: Option<ParseError> }`, built in one function,
  `refusal_of_load`, which S2.1.2's values replace.
- **The seven outcomes** ([`src/kernel/outcome.rs`](../../../einaf/src/kernel/outcome.rs)): `Outcome`, and
  `outcome(&Run, Part) -> Option<Reading>`, `None` where the question gives no such reading. Read in this order: a
