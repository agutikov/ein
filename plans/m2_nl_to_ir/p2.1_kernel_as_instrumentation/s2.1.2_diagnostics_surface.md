## Context

**What the kernel says to a program today, and what it says only to a terminal**
([`analysis/audit_p2.1.md`](../analysis/audit_p2.1.md) § 0 has each case run):

| the situation | in the library | on a machine surface of the binary |
|---|---|---|
| a parse error | a value: `ParseError`, every error with its line, column, notes and ranked repairs | **nothing**: lines on stderr, exit 1, no summary; `ein test --json-report` says `outcome: "error"` and no message |

| a `-T` abort | a value, `SolveError::Deadline` | **nothing**: one line on stderr, exit 2 (a usage error's code), no summary |
| a load's and a run's `note:` lines (a redundant hypothesis declaration, an unchecked claim, a partial run) | strings (`ein_infer::mechanisms`' `notes`, and the read-out's) | stderr only; no key of `ein-summary/2` |

### A saturation is bounded

**Nothing in a solve stops a saturation that has no fixpoint.** A rule that nests its conclusion one deeper than
its premise ([`grow.ein`](../analysis/probes/p2.7/grow.ein)) ran until a timeout killed it after 20 s, under
`-T 1`, under `-T 2` and under `--region-budget 1000` alike, at gigabytes of memory within seconds. The clock is
read between a route's steps and never inside a saturation; the budget counts facts beyond root, so root's own
saturation is under no bound at all; and Ein's page says so: *termination is assumed, not given*
([`02-saturation.md`](../../../docs/ein/reasoning/02-kb-evolution/02-saturation.md)). `ein saturate --max-steps`
stops such a run, and the library's saturator takes that cap, which no route passes on.

By [Q-M2.16](../open_questions.md#q-m216--what-of-the-kernel-may-change-inside-m2) the kernel is given the bound, as a feature that changes nothing of what a program means:

- **the clock reaches inside a saturation**, root's included: a run under `-T` ends at the clock wherever it is,
  and says what an abort says today;
- **a saturation has a limit that depends on no machine**: the cap on steps the saturator already takes reaches
  every saturation of a solve, and a run it stops says so as a run a budget stops does. Whether that is the
  budget `--region-budget` extended to root's saturation or the option `ein saturate` has, given to `ein solve`,
  is the design's (T2.1.2.1); an option moves `help_shape.txt` and the census of
  [`06-config.md`](../../../docs/ein/user/04-reference/06-config.md), which is then part of the change;
- **no new word and no new outcome**: a stopped run is *not decided*, as every stopped run is. The engine's own
  word for *did not stop*, a bound that is the saturation's by default, and a static check that a program's
  rules cannot grow a term are [M1g](../../m1g_logic/README.md)'s, in its stage on a saturation that does not
  stop, with the user's question there; this stage takes none of them.

### The design, to be confirmed by the stage before it writes code

A default, the coordinator's; T2.1.2.1 holds it against Ein's rules and the code and changes what does not fit.

1. **A refusal is a value with a kind.** The three load-side errors that a program can reach (`KbLoadError`,
   `LoadError`, `MacroError`; no program reaches a `CompileError`, by its own comment) carry a list of findings,
   each with: its **kind**, one a refusal of `07-diagnostics.md` § 2, named after its section; its **place**,
   where the loader has one today; and its **message**, the normative text, byte for byte what is printed now.
   `Display` prints what it prints today, so no `.expected` fixture and no golden moves.
2. **The vocabulary is the page's.** A kind is a section of `07-diagnostics.md` § 1 and § 2; the page gains each
   kind's name beside its section, and a test holds the two lists to each other, the way the page's messages are
   held to the fixtures.
3. **The summary is written wherever the run got far enough to know where to write it**, with one more top-level
   key, `diagnostics`: a list of `{kind, severity, message, place}`, `severity` one of `error`, `warning`,
   `note`. On a refusal and on a `-T` abort the answer's keys are `null`, as every key that does not apply is
   today, and the list says why. A run that answers lists its notes there. Streams and exit codes do not change:
   an artefact option still *changes neither stream nor the exit code*
   ([`05-cli.md`](../../../docs/ein/user/04-reference/05-cli.md)). Whether one more key is `ein-summary/2` still
   or `/3` is decided by how the page defines the schema's number.
4. **`ein test --json-report` carries the diagnostics of a row whose outcome is `error`.**
5. **A core's sources stand beside the core**: a key next to `region.core`, in the core's order, each entry the
   `:source` text of that fact or `null`. `region.core` keeps its shape, which six scripts under `utils/` and the
   corpus sweeps read.
6. **No new option for the diagnostics**, so `help_shape.txt` and the option census of
   [`06-config.md`](../../../docs/ein/user/04-reference/06-config.md) do not move for them; the bound of the
   section above may bring one.

**What the stage leaves as it is, each for a reason on file:**

- **A message that names no place gets none.** A loader message about a top-level form ends `at None`
  ([Q-M1a.6](../../../docs/decisions/diagnostics/Q-M1a.6-a-loader-message-about-a-top-level-form-names-no.md));
  giving it one moves a third of the load fixtures and is F23's D-2 and D-22. Here its `place` is `null`.
- **`--single` takes no core** (Q-M1f.29): a caller that wants one asks for a description.
- **No exit code changes** ([Q-M1e2.33](../../../docs/decisions/cli/Q-M1e2.33-every-answer-exits-0.md)): a `-T`
  abort still exits 2, inside a saturation as between two. What tells it from a usage error is now the summary's diagnostic, not the first word of a
  line.
- **No analysis is added**: an unused fact, a relation no rule reads, a query nothing reaches are not diagnostics
  Ein has, and are recorded in [the evaluation](../ein_evaluation.md) (E-28), not built.

## Risks

- **Kinds invite renaming the refusals.** The stage names what is there. A refusal whose section covers two
  different mistakes gets one kind and an entry in the evaluation, not a new section.
- **A summary on a refusal is the first artefact a refused program writes**, and something may count on its
  absence (a sweep that reads *no file* as *refused*). T2.1.2.1 looks for such a reader before the behaviour
  changes.
- **The notes are built in two crates and printed in a third.** If making them values means moving where they are
  made, the stage stops at the ones a load makes (D-18) and records the run's (L-125) as left, with what it would
  take.
- **Scope.** F23 holds other rows on the same paths (D-1, D-3, D-20). They are not this stage's; a row it happens
  to close is said so in F23, and none is taken up for its own sake.

#### The design, and the ones not taken

**The bound is the run's, carried by the saturator.** `ein_infer::saturator::Bound { deadline, max_steps }`; a
saturation built by `Saturator::new` takes the bound of the `saturator::bounded(bound, f)` switch of its thread
(none by default), and one resumed takes its snapshot's, which is how a worker's node (`-j N`) is bounded as root
is. `step` counts every firing it returns, a redundant one too (`ein saturate --max-steps`' unit), and past the cap
fails with `SaturateError::Steps(cap)`; every `CLOCK_EVERY` = 2^10 firings and at each quiescence (where the
boundary already took an `Instant`) it reads the clock and fails with `SaturateError::Deadline`.
`From<SaturateError> for SolveError` turns the latter into `SolveError::Deadline`, so every `?` already on the
path carries the clock to the CLI's abort. `explore::run_with` and `read_out::run_with` run everything under
`Options::bound()`; the oracle's `region::compute_with` runs under its clock alone; the CLI's `ein solve` and `ein
test` set the switch before the load, so the mechanisms' judgement (`ein_infer::mechanisms::check`, which saturates
a second load of the program) and `--trace`'s copy of root are bounded too.

**The limit is a cap on firings per saturation, `--max-steps N` on `ein solve` and `ein test`, default 2^20.** A
run it stops is *not decided* and **establishes nothing of R**: `explore::Stopped::Steps { cap, root }`, no
candidate, no state, no count, no verdict, root's standing and H unknown, the static check not read. Its read-out
is the question's own rows (`exhausted`; `--single`'s `verdict` *not decided — the run stopped first* and `decided`
*no — …*, as a budget's stop prints them; `--no-search`'s `R`), each query with no state to answer from, each claim
NOT CHECKED, a `note: … partial — …` on stderr, exit 0. The summary: `region.exhausted` false, `region.stopped`
`{why: steps, steps, saturation: root|node}`, `region.root`, `universe`, `route` `null`, `verdict.word` `null`, and
the `monotonicity` and `root` blocks `null`.

Rejected:

- **`--region-budget` extended to root's saturation** (and inside a node's). The budget counts facts beyond root
  summed over the run and is checked by projection before each step; counting root's facts against it, or cutting
  a node mid-saturation at what is left of it, stops runs the corpus and the tests make today under small budgets
  (`zebra2.ein`'s cell `solve --region-budget 1`, `summary_properties`' five questions under a small budget, the
  routes' own budget tests): answers would move. A second number in the budget's unit, apart from it, is the cap
  with another unit.
- **A facts cap rather than firings.** Facts are the semantic unit (the `work` row, the budget), but
  `ein saturate --max-steps` already counts firings, and one option name with one meaning across commands won.
  Recorded as a finding: the count is an engine count.
- **A partial answer at a node's stop** (root's standing, H and the static check, as `--no-search` reports them).
  Worth having for a caller, but it needs the prepared root carried out of a failing route; every part of R rests
  on states, and a stopped state is neither known alive nor dead (M1g's word), so this task claims nothing at
  either stop and says which saturation was stopped.
- **A new outcome or a word for *did not stop*, and a bound on the saturation by default** (every saturation of
  every command): M1g's (S1g.6.1), not taken. `ein saturate`, `ein show hyps`, `ein render h-space`,
  `ein render kb` and `ein solve --monotone` read root's fixpoint, answer no question about R and stay unbounded;
  `ein oracle` takes the clock inside its saturations and no cap (it saturates every node to its fixpoint, its one
  bound past the limit is the clock); `ein render lattice` runs its describing question under the default cap.
- **The fixture in the corpus.** `ein_corpus::corpus_files()` is every `.ein` under `examples/`, `stdlib/` and
  `tests/`, and some forty sweeps saturate every one of them through readers no question's bound reaches (the
  shape golden's `saturate`, `plan`, `match`, `explain` ops; `ein saturate`; the KB views; the oracle; the
  container round trip; the detector, interning and alive-set sweeps): a program with no fixpoint there hangs
  them. The two fixtures are `ein.rs/crates/ein-cli/tests/bounded/grow.ein` (the probe, copied) and
  `grow_node.ein` (the same rule started by a hypothesis: root reaches its fixpoint, the node of `(seed zero)` does
  not), beside the test that reads them, with no corpus entry and no catalog line.

**Library API.** Additive fields and items: `explore::Options::max_steps: Option<u64>` (`Options::new` takes
`Some(DEFAULT_MAX_STEPS)`), `Options::bound()`, `explore::DEFAULT_MAX_STEPS`, `saturator::{Bound, bounded,
current_bound, CLOCK_EVERY}`, `Saturator::steps()`. **Two enums gain variants**: `explore::Stopped::Steps { cap:
u64, root: bool }` and `SaturateError::{Deadline, Steps(u64)}`. A downstream exhaustive `match` on `Stopped` needs
one arm, and EinAf's `einaf/src/kernel/outcome.rs` has one (`match &a.stopped`), so the merge needs, beside its
`Deadline` arm:

```rust
Some(Stopped::Steps { cap, root }) => {
    return (
        Outcome::NotDecided,
        format!(
            "stopped at --max-steps {cap}: {} saturation had no fixpoint within it",
            if *root { "root's" } else { "a node's" }
        ),
    );
}
```

#### Defaults taken

1. **The option**: `--max-steps N` on `ein solve` and `ein test`, the name and unit of `ein saturate --max-steps`;
   one or more (`--region-budget`'s rule), a usage error otherwise.
2. **Its default**: 2^20 firings per saturation, the region budget's power. The corpus's largest saturation is
   17 587 firings (`beyond_arith/laws.ein`; the median 4, the 99th percentile 4 096), measured once over every
   corpus file under six questions with a counter that is not kept; the default stops `grow.ein` in 1.1 s at a
   peak of 942 MB here.
3. **Nothing of R is established at either stop**, root's or a node's; the stop says which (`root`, `node`).
4. **`why: steps`** in `region.stopped`, with `steps` and `saturation`: the stop is named by its option, as
   `budget` and `limit` are; no new outcome, verdict word or exit code. `explore::Stopped::Steps` a new variant.
5. **`monotonicity` and `root` `null`** in the summary of a cut run, the convention of a block that does not apply.
6. **The other commands**: `ein oracle` the clock only; `ein saturate`, `ein show hyps`, `ein render h-space`,
   `ein render kb`, `ein solve --monotone` unbounded; `ein render lattice` the default cap, no option.
7. **The clock's interval**: every 2^10 firings, and at each quiescence.
8. **A coupling's whole node** (the obligation tree's reading of the couplings) stopped by the cap is not read, as
   when its own bound stops it, and the run goes on; every other saturation past the cap stops the run.
9. **The fixtures beside the test, not in the corpus** (above).
10. **The examples page's X22** on `zebra2.ein --max-steps 100`, a corpus program, since a page example is a corpus
    file.

#### Findings for the evaluation

- **`ein saturate --max-steps N` on `grow.ein` crashes for N past some 30 000**: the step-limit line renders the
  last firing's binding, a term nested N deep, through the recursive `Terms::fact_text`, and the main thread's stack
  overflows (SIGSEGV under gdb, *thread 'main' has overflowed its stack* otherwise). Any surface that renders a
  deeply nested fact whole shares it. A bug by Ein's rules: a crash is no exit code.
- **`--events` is quadratic on a term that deepens at every firing**: every `enqueue` and `fire` line renders the
  bindings whole, so `ein solve grow.ein --max-steps 20000 --events f` wrote 300 MB in 60 s without ending, and under
  the default cap the stream would be some 10^12 bytes. The cap bounds firings, not a firing's narration; only the
  clock bounds that.
- **The default cap costs about a gigabyte on a runaway program** (942 MB peak, 1.1 s for `grow.ein`): a caller
  that runs many programs in one process wants its own, lower cap.
- **A run the cap stops hands back nothing of what was established**, as the clock's abort does: at a node's stop
  root's standing, H and the static check are known and discarded, and only `region.stopped.saturation` says the
  program's own rules have a fixpoint and a hypothesis takes it away.
- **A program with no fixpoint cannot be a corpus program** while most corpus sweeps saturate every file through
  readers no question bounds; the witness lives beside its test.
- **`ein solve --monotone`, `ein show hyps`, `ein render h-space` and `ein render kb` still run without end on a root
  with no fixpoint, and take no `-T`**: their one bound is the caller's.
- **The cap counts firings, an engine count**: a redundant firing counts, a resumed node does not re-fire root's
  applications, so the count for one state is the engine's and not a property of the program; the facts a
  saturation derives would be.
- **`ein test` asks a cut file twice**: the least question stops at the cap, the describing question is asked of a
  second load and stops there again.
- **`region.stopped.why` had values no page listed**: the summary writer also writes `deadline` and `no-search`,
  which reach no summary today (`-T` writes none, `--no-search`'s `region` is `null`); the page listed `asked`,
  `budget`, `limit`, and now `steps`.
