## The design, to be confirmed by the stage before it writes code

A default each, the coordinator's; T2.1.4.1 holds them against the pages and the code.

1. **E-79: no surface recurses on a term's depth.** The printer of a fact (`Terms::fact_text` and what the
   step-limit line, the read-out, `--dump-answer`, the summary, `ein show`, the DOT views and `--events` render a
   fact through) walks a term with an explicit stack, not the call stack. A term is printed whole, as today: no
   cut, no `…`, so no line changes. Every other walk of a term the code makes (interning, hashing, comparison,
   matching, serialisation) is listed with whether it recurses on depth, and each that does is made iterative or
   recorded with the depth it reaches. The test drives `grow.ein` past the old crash (a cap of 100 000, depth
   past 30 000) through every surface that prints its facts, and the deep-term probe of S2.1.3
   (`analysis/probes/p2.1/deep_term.py`) is run at its old depths to show nothing moved but the crash.
2. **E-74: one line for a missing file, made in one place.** `ein_ir::load_file` and `ein test`'s walk read a path
   through `ein_ir::read`, as every other command does, so the library and every command print one line, and
   `ein-cli/tests/` holds every command and the library to it. **The line is the page's**,
   `FileNotFoundError: [Errno 2] No such file or directory: '<path>'`, so no `.expected` fixture moves; replacing
   it with a line in Ein's own words is D-1's other half, and shown to the user as the alternative (it moves the
   page's row and every fixture and golden that holds the line).
   The choice is the user's, [Q-M2.21](open_questions/kernel/Q-M2.21-a-missing-files-line-the-pages-python-spelling-or-eins-own.md).
3. **E-101: a module is named by the path the program names it.** A message, a finding's `place.file` and the
   summary name a module as the program's directory, as given, joined with the module's name as written: from the
   repository's root, `examples/broken/load/import_cycle_b.ein`. The resolver may keep its canonical path to tell
   one module from another (a cycle, one copy per program); it is not printed. A test runs every refused corpus
   program whose message names a module from two working directories and holds its lines to differ only in the
   program's path as given. EinAf's corpus comparison then compares paths as they are, and its strip of the
   repository's root goes, in a commit of EinAf's own.
4. **E-90: the abort is stderr's line under `ein test` too.** `ein test` prints the clock's abort on stderr in the
   words `ein solve` prints it; its `ERROR` row stays on stdout, the file's row of the listing, and says only that
   the file was aborted. The summary's `diagnostics` keep stderr's order, so S2.1.2's default 11 (*listed after
   what stderr printed, though `ein test` prints it on stdout*) goes. Exit codes do not move.
