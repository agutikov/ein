# S2.2g.2 — The user's reading, worked out

**Phase:** [P2.2g](README.md) (Names across an import)
**Status:** planned 2026-11-27; not started.
**Needs:** [S2.2g.1](s2.2g.1_every_name_a_module_writes.md)'s table and census.

## Context

The user's reading: every name a module writes is the module's, so the module declares `(m.relation m.likes m.Person
m.Drink)` and a program `(relation m.likes Person Drink)`. The user left one point open: *"I don't yet wknow how to
import `m.relation`"*. This stage writes the reading out and the ways a program could meet a module's declarator,
each worked on programs that run, so that the user can rule.

## Acceptance

- **The reading as a page**: what each kind of name of S2.2g.1's table is under it, in the program and in the
  module, with the user's words.
- **The options for the declarator**, today's among them. Each is worked on Q-M2.43's five probes and on one
  library program (`zebra3.1.ein` over `std.slots`), and gives:
  - what loads and what each query answers;
  - what the kernel reads as a declaration, and how without reading a theory's name (Q-M1f.436);
  - what a module written in place answers (Q-M1f.137);
  - what the import form changes (Q-M1f.249);
  - which decisions it supersedes, by id;
  - what it costs the loader, the library and EinAf.

  Where an option needs an Ein that does not exist, it is shown as programs written by hand in today's Ein that
  stand for it, said so.
- **The same for the constants**, if S2.2g.1 finds that the reading's scoped constants change answers.
- **Q-M2.45's three questions**, each with its options, today's among them:
  - what a module owns;
  - the order imports make, and whether Ein states a structure of it (a partial order, a lattice, one bottom);
  - what of a module is public and what private, and how a module would say so.

  Each is worked on programs that run, with what it costs the library, the invariances and EinAf's catalogue.
- **Q-M2.37's places for a module's descriptions**, read with the public face the options above give: the module's
  comments, a declaration of the selecting fact, a described program beside the module in the library's tree (its
  proposal), a keyword beside `:why` (a syntax change, for the iteration of Ein). S2.2d.3's descriptions, if written
  by then, are the text each place would hold.
- **The coordinator's recommendation**, with its reasons.
- **The stage stops for the user's ruling**: on Q-M2.43, Q-M2.45 and Q-M2.37, and on each question the page adds, filed under the
  milestone's next free ids.
