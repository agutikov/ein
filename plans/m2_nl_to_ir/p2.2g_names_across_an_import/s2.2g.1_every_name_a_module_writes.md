# S2.2g.1 — Every name a module writes, today

**Phase:** [P2.2g](README.md) (Names across an import)
**Status:** planned 2026-11-27; not started.
**Reads:** the import decisions under [`docs/decisions/imports/`](../../../docs/decisions/imports/README.md);
[`ein-ir/src/imports.rs`](../../../ein.rs/crates/ein-ir/src/imports.rs); S2.2e.1's probes,
[`a-modules-relation/`](../p2.2e_kernel_fixes/probes/a-modules-relation/).

## Context

Before any option is weighed, the phase finds what Ein does now with every name a module writes, and what rests on
it. The user's reading scopes every name to its module. Today only a declared name is scoped. The survey says where
the two differ and what each difference would reach.

## Acceptance

- **The table.** The rows are each kind of name a module writes:
  - a declared relation, rule or macro;
  - a constant in a fact (`Cy`);
  - a label in a declaration (`Person`);
  - the declarator `relation`, and every other word of the kernel (`open`, `absent`, `eq`, `neq`);
  - the library's `false` and `not`;
  - a name of `std.core`;
  - a name the module takes from a module it imports.

  The columns are the import shapes: bare, `:symbols`, `:as`, and the module written in place. Each cell gives what
  the loaded program holds (`ein saturate --dump`), what a query of the program's own over it answers, the decision
  that says so, and the test that holds it. Every cell is a probe, with its command and output.
- **What rests on it, counted by a committed script**:
  - the library modules and corpus programs in which a module's rule matches a constant the program writes, or a
    program's rule matches one the module writes;
  - those in which a module's constant meets a program's under one name;
  - those that read a module's declaration.

  Each count names its programs. These are what a module-scoped constant or declarator would read otherwise.
- **The order imports make**, as the loader builds it: the import graph, the cycle refused, a module reached by two
  paths read once, where `std.core` comes in, and what of it a program can see. Probed, for
  [Q-M2.45](open_questions/kernel/Q-M2.45-what-is-a-module-its-names-the-order-imports-make-and-what-is-public.md)'s
  second question.
- **What of a module is public today**: which of its names a program may write, short or full; which of its
  relations the program may state facts of; which of its rules read the program's facts. Each is probed, for
  Q-M2.45's third question, and the census counts the library's relations a program states facts of and the
  library itself only derives (its circuits).
- **Whether P2.3's attribute programs** (over `std.slots`, the formalizer's target shape) are among them.
- No change to Ein. Anything of Ein the survey finds goes to the phase's evaluation.
