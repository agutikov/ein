# S1.9.E25 — Multi-justification (OR/AND) provenance + true minimal explanation

**Phase:** P1.9, §engineering / UX (added 2026-08-16).
**Estimate:** L (research-grade search component).
**Value:** M (explanation quality; lifts the E19 caveat).
**Status:** 📅 parked — recorded here so the design survives
[R3](../p1.21_review_response/reports/r3_min_core.md) instead of dying in it.
**Origin:** [REVIEW_M1-01 §3](../REVIEW_M1-01.md) option (b), investigated in
[R3 §3(b)](../p1.21_review_response/reports/r3_min_core.md); the staged path
(c) shipped the rename ([E19](s1.9.e19_unsat_core_min.md) →
`frontier.smallest_contradiction_frontier`) and parked this.

## The gap this closes

The KB keeps **one** `Provenance` per `(relation, args)` fact — first
derivation wins (`store.add_and_index_fact` returns the existing object; the
incoming fact's provenance is never read). Every re-derivation's justification
is silently dropped, so
[`frontier.smallest_contradiction_frontier`](../../../ein.py/src/ein/inference/frontier.py)
is minimal only over *recorded* derivations: R3 §E3 shows the reported
frontier flipping between `{C, Y}` (2 facts) and `{A, B, Y}` (3 facts) on rule
`:priority` alone — the strictly smaller explanation exists but is invisible.
`tests/inference/test_frontier.py::test_result_depends_on_recorded_derivation_order`
pins this caveat; a fix here should flip that test deliberately.

## Shape (from R3 §3(b) — feasibility mapped, costs named)

- **Record at the dedup seam — cheap.** The alternative justification is
  already materialised as a `Provenance` at firing time
  (`firing.py`) and reaches `store.add_and_index_fact`; appending it to a
  KB-level side table `dict[FactId, tuple[Provenance, ...]]` is a local edit.
  Runtime is a non-issue: a 2026-08-16 cProfile puts the whole saturate
  subsystem at ~1 % of a solve (the stage-file fear that
  `add_and_index_fact` is hot was *not* reproduced).
- **Storage — the first real cost.** `Fact` is `frozen=True` with a single
  `provenance` field excluded from identity; alternatives need a side table
  that joins the fork/snapshot copy contract and the S1.21.1 state-identity
  story (a justification recorded inside a hypothesis fork is not valid at
  root; NAF-stage-dependence).
- **Consumers — the second cost.** Every provenance walker assumes one
  justification: `walk_premises` / `reaches` / `build_derivation_dag` /
  `detect_provenance_cycles` in `kb/provenance.py`, plus their callers across
  `trace/answer.py`, `trace/linearize.py`, `render/slice.py`,
  `render/lattice_dag.py`, `inference/commitment.py`,
  `inference/monotonic/_helpers.py` / `_state.py`, and no-good lifting —
  ≈ a dozen modules re-reasoned for OR-nodes.
- **Search — the third cost.** Minimum-cardinality source frontier over an
  AND/OR proof DAG is the minimum-axiom-set / ATMS-label problem —
  worst-case exponential (why ATMS labels blow up). "Define/search real
  minimality" is a deliverable in itself, not a patch.
- **Completeness caveat even then:** alternatives are only the firings the
  saturator actually attempts, so "minimal" stays relative to the rule set
  and saturation strategy.

## Companion follow-up (cheap, independent)

Wire `smallest_contradiction_frontier` into the **contradiction answer** — the
E19 use-site ("the contradictions answer calls it for the legible why",
[E19 § Implemented](s1.9.e19_unsat_core_min.md#implemented-2026-06-15)) was
never wired: the shipped `k = 0` verdict carries the *union* frontier
(`_union_dead_cores`), and the function has zero production callers (R3 §E4).
Changes acceptance-visible output → deliberately kept out of T1.21.3.2; do it
as its own reviewed step.

## Acceptance (when activated)

- Alternative justifications recorded at the dedup seam; fork/snapshot
  contract extended; consumers handle OR-nodes.
- A minimal-explanation search over the proof DAG, with an explicit
  complexity/anytime budget.
- `test_frontier.py::test_result_depends_on_recorded_derivation_order`
  flipped: the frontier no longer depends on rule priority for the R3 §E3
  fixture.
