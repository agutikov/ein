## Framing — half of this is already true

**"Relation declarations are just facts"** — they already are, *in
addition to* being a kernel word: the loader mirrors every declaration as
an ordinary `(relation Name A B)` fact
(`ein.py/src/ein/kb/from_ir.py:187-194`), and `:match (relation ?R …)` is
exactly how std.bijection / std.algebra / std.typing consume it today.

**The sketched `typed-binary-relation` rule exists** — not with an empty
`:match` (invalid: a rule needs a premise), but in the established
*activator fact + generic rule* idiom: `(relation ?R ?A ?B)` +
`(bijective ?R)` + `(typecheck-hierarchy ?isa)` drives the
`typecheck-arg-*` stack (`stdlib/bijection.ein:71`). The functionality is
not the question.

**The question is only the residue**: what does the kernel *word* do that
the fact alone does not, and should that residue stay kernel-side? Per
S1.22.3's census, the residue is:

| what | site | if demoted, becomes… |
|---|---|---|
| reserved-name shadow check at load | `kb/from_ir.py:172` | ? — load-time errors have no rule-space analogue |
| duplicate-declaration check | `kb/from_ir.py:176` | expressible as a ⊥-rule for *conflicting* sigs: `(relation ?R ?A ?B) ∧ (relation ?R ?C ?D) ∧ (neq ?A ?C) → false`; identical re-declaration dedupes as any fact |
| `:why` render-template capture | `kb/from_ir.py:182` | needs a home — a kw on the fact, or a separate `(why R "…")` fact |
| `declared=True` + `signature` on the entity | `kb/entities.py:92-93` | kernel keys on the *fact* instead (it already reads `(__closed__ R)` facts, so the pattern exists) |
| `NameRef.category` assignment (name is a relation, not an object) | loader | derived from fact-head occurrence — already how undeclared heads work (`kb/entities.py:80-89`) |
| grammar production `relation_decl` | `ir/grammar.lark:97` | folds into `generic_fact` |

## The two options

**(i) Keep `relation` kernel-side; record why.** The mirrored fact already
gives userspace *full* reflection — demotion buys purity, and its price is
error ergonomics: shadow/duplicate mistakes become saturation-time
contradictions (or silence) instead of load errors with a `loc`. Under
this option the decision memo states the rationale, S1.22.3's docs are the
lasting artefact, and the scratchpad question is closed with "by design,
because X" rather than code.

**(ii) Demote to a stdlib/loader-convention word.** The kernel keys its
three structural signals off the `(relation …)` *fact*; validation
becomes rules where expressible and is otherwise dropped or moved;
`:why` gets a new carrier. This is a kernel refactor of the same species
as S1.7.23/S1.7.24 — grammar, loader, entities, hypgen, closed, CLI —
and therefore **cannot execute in this phase**: P1.22's own
[README §Out of scope](README.md) rules out engine behaviour change. If
(ii) wins, this stage *designs and parks* it.

Sub-items that ride along **whichever** option wins (each is independent
engine work):

- **Unary hypothesis targets** — hypgen's arity-2 limit
  (`inference/hypgen.py:293`) is an M1 cut, not a design position; a
  declared unary relation is never guessed today.
- **Bare untyped declaration `(relation R)`** — rejected at *load* today
  (the form parses; the loader's relation branch refuses an empty
  signature); legalising it interacts with the kernel's signature-presence
  keying (S1.22.3 census Q2).
- **Unary rendering in the compact DOT view** — the "arrow with no
  head-object" question; the Levi view needs nothing.

**Scope ruling (user, 2026-08-17).** These were originally to be *parked*
per [P1.22 §Out of scope](README.md). The user overrode that: decide **and
implement** in this stage. The out-of-scope rule is amended accordingly
(see the README) — engine change is in scope for S1.22.4 only, and only

strictly more important than the other three: **generic relation
reflection**, the user's own item-5 ask, which turned out to be blocked by
arity-coupling rather than by the kernel word.

### T1.22.4.2 — Generic relation reflection: the membership fact

**The gap** (measured in C4 §5): reflection over declarations is
**arity-coupled**. The loader mirrors `(relation likes Person Drink)` as a
3-arg fact, so `(relation ?R ?A ?B)` sees only *binary* declarations,
`(relation ?R ?A)` only unary ones, and `(relation ?R)` — the user's own
spelling — matches **nothing**. Consequence: `std.bijection` /
`std.algebra` / `std.typing` all spell the binary pattern and therefore
silently ignore any non-binary declaration.

**Change.** Every declaration also stores the arity-1 fact `(relation R)`
(`kb/from_ir.py`, `_ingest_relation`). Decisions taken:

- **Declared only.** Auto-vivified property-tag carriers have no
  declaration, so they get neither mirror nor membership fact — the
  pattern means precisely *declared relation*, and nothing has to be
  emitted mid-saturation when a rule vivifies a new head.
- **No stdlib migration.** `std.bijection` et al. genuinely need the two
  sorts; the new fact answers the *membership* question, not the
  *signature* question. The old channel is untouched.
- **Unifies with T1.22.4.4.** For an empty signature the mirror *is* the
  membership fact, so exactly one fact is stored.

### T1.22.4.3 — Unary hypothesis targets

`hypgen._fill_slot` returns immediately unless the signature has length 2.
Lift it to fill arity 1 as well: one candidate `(R obj)` per focal object
(no filler loop, no self-edge check). Arity ≥ 3 stays unenumerated — the
one surviving M1 arity cut. Note the blast radius is small by
construction: `emit_closed` auto-closes any relation no rule produces, so
the new guess only arises where a rule can produce the unary relation.

### T1.22.4.4 — Bare untyped declaration `(relation R)`

Grammar `SYMBOL+` → `SYMBOL*`; the loader accepts an empty signature.
Semantics: a relation node with **no declared arg types**, and therefore
**not a hypothesis target** — signature *presence* is the kernel's
"declared domain relation" signal (S1.22.3 census Q2) and an empty
signature deliberately fails it. `(relation R T)` stays the spelling for
"guessable, no meaningful type".

**Regression guard.** With an empty signature legal, the R10 rejection of
the wrapped-arg form `(relation R (T1 T2))` no longer falls out of
`not sig` — it would silently load as a bare declaration. The loader must
check explicitly that every arg after the name is a type Atom or a
kw-pair.

### T1.22.4.5 — Unary rendering in the compact DOT view

Draw a unary fact as a labelled **self-loop** `a → a [label="rel"]` — the
degenerate case of the binary collapse, source == target. It keeps the
per-fact edge styling (derived → dashed, transition highlight →
`penwidth`) that dropping to an octagon scatters over two DOT elements.
`not`-headed facts keep their own encoding. The Levi view is unchanged.

**Two emitters.** `ir/to_dot.py` (IR forms) and `kb/render.py` (the KB
view) are separate; both need the convention, or T1.22.4.2's membership
facts turn every KB drawing into a field of one-armed octagons.

## Outcome (2026-08-17)

**Decision: (i) — `relation` stays kernel-side.** Memo:
[`reports/c4_relation_kernel_word.md`](reports/c4_relation_kernel_word.md).

**The argument that settled it** is not the cost/benefit ledger the brief
sketched, but a category error in option (ii): **demotion removes no kernel
interpretation.** S1.7.23/S1.7.24 each made the kernel *stop deciding
something about user semantics*; the declarator decides nothing — it is a
schema channel. The three structural signals must survive any demotion (they
are what makes hypothesis generation terminate), so the kernel would go on
hardcoding the name `relation`, merely as a reserved **fact head** (the
`__closed__` / `not` / `false` category) rather than a declarator. The
reserved set is renamed, not shrunk. Related: **"stdlib word" is not an
available shape at all** — stdlib words are rules/macros the matcher runs,
and no rule can create an entity, assign `NameRef.category`, capture `:why`,
or reject a duplicate at load. The only real (ii) was "kernel-read fact
head".

**Price of the road not taken, measured** (four load probes, C4 §2): the
malformed / shadowed-name / duplicate checks lose their `loc`-bearing load
error, and `:why` is silently dropped (facts discard unrecognised kw-pairs).
The duplicate case is the serious one — a conflicting re-declaration becomes
**two** stored mirror facts (`Fact` identity is `(rel, args)`, so they do
not dedup) and an ambiguous signature lookup feeding
`hypgen._raw_candidates` / `_candidate_objects`: a silent search
perturbation in place of a load error, which is the wrong trade for an
auditable reasoner.

**The `.signature` grep the task asked for** (C4 §4): 7 hits, 6 production
(hypgen ×4, closed, CLI). **None needs the entity** — all are mechanically
re-keyable onto the mirror fact. Feasibility was never the argument against
(ii); value was.

**The stage's real finding — the user's item-5 ask is a *different*,
additive change** (C4 §5, measured with a three-rule probe). Reflection over
declarations is **arity-coupled**: `(relation ?R ?A ?B)` matches only binary
declarations, `(relation ?R ?A)` only unary ones, and `(relation ?R)` —
the user's proposed spelling — matches **nothing**, because no arity-1
mirror is ever stored. So `std.bijection` / `std.algebra` / `std.typing` are
silently **binary-only**, and there is no generic "is `?R` a relation?"
pattern. The blocker was never the declarator's existence; the fix is to
*publish more* (a companion `(relation R)` fact), not to demote —
implemented below as T1.22.4.2.

**Docs:** the S1.22.3 home
([`01_grammar.md` §what the signature means](../../../docs/kernel/ir/03-ein-lang/01_grammar.md))
gained a **Why `relation` is a kernel declarator and not a stdlib word**

**Design calls taken while implementing:**

- **The membership fact is declared-only.** Auto-vivified property-tag
  carriers get none, so `(relation ?R)` means precisely *declared
  relation*. This also dodges the alternative's real cost: relations are
  vivified lazily *during* saturation, so an "every relation node" rule
  would have to emit facts inside the saturation loop.
- **.2 and .4 unify rather than collide.** C4 flagged them as competing
  for the same syntax. They do not: for an empty signature the signature
  mirror *is* the membership fact, so a bare `(relation R)` stores exactly
  one fact and a hand-written membership assertion is idempotent with the
  auto-emitted one.
- **A bare declaration is not a hypothesis target.** Signature presence
  stays the "declared domain relation" signal; `(relation R T)` remains
  the spelling for "guessable, no meaningful type".
- **`not` is excluded from the self-loop path.** A bare `(not X)` is a
  negation marker, not a property of `X`.

**Two bugs the test suite caught, both fixed:**

1. **R10 regression (my own).** With an empty signature legal, the
   wrapped-arg form `(relation R (T1 T2))` stopped erroring and silently
   loaded as a *bare* declaration — the old rejection had been an
   accidental consequence of `not sig`. Replaced with an explicit check
   that every arg after the name is a type Atom or a kw-pair.
   `tests/test_ir_ast.py::test_relation_wrapped_form_rejected_at_load` is
   the witness that caught it.
2. **Half-implemented .5.** `ir/to_dot.py` and `kb/render.py` are separate
   emitters; patching only the first turned every new membership fact into
   an octagon in KB drawings (octagon counts 8 → 13 in
   `test_zebra_octagons_are_the_n_ary_facts`). Both now carry the
   convention, and the counts returned to their original values.
