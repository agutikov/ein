## The ruling (user, 2026-08-16)

`(type T)` / `(instance a T)` are **not valid Ein**. No `type`/`instance`
keywords exist; the unified model is the language: membership is
`(is-a a SomeType)`; relations are declared `(relation name T T)`; `T` is
an ordinary top atom needing **no declaration**. The classic encoding
(`examples/zebra.ein`) and every echo of it — plus the P1.7c-removed block
heads `(rules …)/(ontology …)/(facts …)` — are obsolete and must leave
code, comments, and documentation.

## T1.22.1.1 — Census + report → `reports/c1_obsolete_syntax.md`

Read-only. Deliver:

1. **Exhaustive site list** (`file:line`), classified: (a) real obsolete
   Ein syntax in fixtures/examples; (b) code that *emits or special-cases*
   the obsolete forms (`cli/saturate.py` printers); (c) comments/docstrings

   row, tests importing it, bench scripts, docs, the classic-vs-unified

   depends on a *second* encoding existing; the acceptance suite runs on
   zebra2).
3. **Kwargs ruling** — are `:layer` / `:source` fact kwargs parser-live,
   and used anywhere outside zebra.ein? If classic-only: purge with it; if
   load-bearing elsewhere: keep, and say where.
4. **Rewrite plan per test file** — modern-syntax replacement for each
   fixture (semantics-preserving: same fact/arity shapes via `is-a` +
   declared relations), flagging any test whose *subject is the obsolete
   syntax itself* (e.g. parser cases asserting `(type Person)` parses) —
   those convert to negative tests or get deleted, per the ruling.
5. **Purge inventory** — exact file list for T1.22.1.2, with the
   suggested edit per site and the tests whose golden outputs shift
