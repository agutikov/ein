## The ruling (user, 2026-08-16)

There are **no `type` / `instance` keywords**. The kernel builds no
type-system entity-view (S1.7.23); the unified model *is* the language:
membership is `(is-a a SomeType)`, relations are declared
`(relation name T T)`, and `T` is an ordinary top atom needing **no
declaration**. The P1.7c-removed block heads `(rules …)` / `(ontology …)` /
`(facts …)` are likewise gone. Every echo of any of that must leave code,
comments, and documentation.

**Clarified by the user, 2026-08-17 — two corrections to the reading above.**

1. **`type` and `instance` are not forbidden *atoms*, only absent
   *keywords*.** Nothing stops a puzzle from using `type` as an ordinary
   relation name — `(type Subtype Type)` is well-formed the moment the
   puzzle declares `(relation type T T)`, exactly like any other relation.
   What is obsolete is the *special-cased* reading: a `(type …)` form the
   kernel interprets as a type declaration, a `(instance …)` form it reads
   as membership, and the registries/printers that served them. The census
   must therefore classify by **whether the kernel special-cases the head**,
   not by the head's spelling — an undeclared `(type …)` is an error
   because it is an undeclared relation, which is the ordinary rule.

2. **`examples/zebra.ein` is valid Ein.** The scoping sweep's premise —
   that the classic encoding is obsolete *syntax* — is withdrawn. It parses
   and loads; the ruling does not condemn it. What it does not do is solve,
   and the reasons are **ontological, not linguistic**:
   - some of the relation properties it needs are not effectively
     implemented *in that formulation* — the encoding names properties the
     rule library does not act on;
   - and it generates far too many hypotheses for the search to close.

   > "Not because its language is broken, but because problem ontology is
   > not sufficient."

   So the verdict is **rewrite, not delete**, and it is no longer a
   question the census has to answer — it is its own stage,
   [S1.22.1a](s1.22.1a_zebra_ein_modernisation.md). This stage keeps only
   the parts of `zebra.ein` that are genuinely obsolete *syntax* (block
   heads, kernel-special-cased forms) and hands the ontology work over.
