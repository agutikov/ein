# S1.22.1b — The cross-layer contradiction bug; remove knowledge layers from the engine

**Phase:** P1.22, inserted after [S1.22.1](s1.22.1_obsolete_syntax.md) and
**before** [S1.22.1a](s1.22.1a_zebra_ein_modernisation.md) — see §Ordering.
**Priority: P0** — the first half is a soundness bug: the engine holds a
contradiction in its KB and does not report it.
**Estimate:** M for the fix, L for the removal (the reader set is wide).
**Depends on:** S1.22.1 shipped.
**Blocks:** S1.22.1a (it changes what the search kills), S1.22.2 (terminal).

## The ruling (user, 2026-08-17)

> cross-layer restriction is a BUG! it ignores contradictions between facts
> in kb; remove `:layer` and completely remove layers in the reasoning engine

Two things, in that order: **fix the bug**, then **delete the concept** that
made it expressible.

## Why this exists

[`contradiction.py`](../../../ein.py/src/ein/inference/contradiction.py)
refuses to report a `(X, (not X))` pair whose two facts sit in different
knowledge layers:

```python
if positive.layer is not negative.layer:
    # Cross-layer pair — by design, NOT a contradiction.
    continue
```

The module docstring defends it as epistemic hygiene — "a FACT-layer
positive shouldn't cause a derived negative to flag it as broken" — and
defers the real answer:

> P1.5 will introduce branch-scoped layers; the cross-source case becomes
> meaningful there.

**P1.5 shipped, and branch scoping ended up done by `fork`, not by layer.**
The deferral's premise expired; the restriction outlived its justification.

### It is reachable, and it hides real contradictions

Minimal reproducer — the KB simultaneously holds a stated fact and its
derived negation:

```lisp
(rule one-per-seat ()
  :match  (and (sits ?p1 ?s) (is-a ?p2 Person) (neq ?p1 ?p2))
  :assert (not (sits ?p2 ?s)) :why "{?s} is taken by {?p1}" :priority 100)
(sits A S1 :source "clue (1)")
(sits B S1 :source "clue (2)")
```

```
stated : [(('A','S1'), 'fact'),      (('B','S1'), 'fact')]
derived: [(('B','S1'), 'reasoning'), (('A','S1'), 'reasoning')]
contradictions detected: 0
```

Change nothing but the clues' layer (`:layer reasoning`) and the same KB
reports **2**. A flatly inconsistent puzzle is silently accepted.

It is not only synthetic. A real `zebra2` solve produces **two** such pairs,
both of which are the engine deriving the negation of a *given* clue:

| pair | positive | negative |
|---|---|---|
| `(nation-loc Norwegian House-1)` | `:source "condition (10)"` | rule `adjacent-via-fwd-negative` |
| `(drink-loc Milk House-3)` | `:source "condition (9)"` | rule `injective-negative` |

Those branches are dead and *are* killed today — but by the **direct `(false)`
shape**, via the stdlib's `injective` / `functional` checks. Correctness
currently rests on a second mechanism happening to cover the same branches.
A puzzle that uses the `(not X)` idiom without the cardinality library gets
no such backstop.

### Removing it is safe, measured

- **Restriction deleted, full gate run:** acceptance **17/17 green**; the
  unit suite loses exactly **one** test —
  `test_contradiction.py::test_cross_layer_non_conflict`, which pins the
  restriction itself. Nothing else depends on it.
- **`:layer` stripped from all 8 `.ein` files that use it (23 occurrences):**
  no fact-set change and no contradiction-count change anywhere. Only the
  layer histogram moves.

## Why the concept goes too

`Layer` is a **denormalised copy of `Provenance`**. `from_ir._layer_of`
literally derives it from the provenance annotation: `:rule`/`:using` →
REASONING, `:source` → FACT, neither → ONTOLOGY.

Measured over every `examples/**/*.ein` (load + `emit_closed` + saturate),
against the candidate rule *"`kind` in {rule, hypothesis} → REASONING;
`provenance.source` is not None → FACT; else ONTOLOGY"*:

```
facts checked: 3039     mismatches: 23
```

**All 23 mismatches are facts carrying an explicit `:layer`** — and there are
exactly 23 `:layer` occurrences in `examples/`. A 1:1 correspondence: the
override is the *only* thing that makes a fact's layer un-derivable.

So the two halves of the ruling fit together. Remove `:layer`, and `Layer`
becomes a pure function of `Provenance` — carrying no information of its own,
and therefore removable without loss. Presentation stops reading the copy and
reads the original.

Note the refinement the census must confirm: the discriminator is
`provenance.source is not None`, **not** `kind` alone — `kind == "source"`
covers both the 18 sourced clues (FACT) and 48 ontology facts whose
`source` is `None` (zebra2 figures).

## Two meanings of "layer" — only one is in scope

The codebase uses the word for two unrelated things. **Do not touch the
second.**

| | meaning | in scope |
|---|---|---|
| **Knowledge layer** | `Layer.{ONTOLOGY,FACT,REASONING}` — a fact's epistemic origin | **yes — this stage removes it** |
| **Lattice layer** | search depth in the monotonic solver — `_explore_layers`, `layer_start`, `layers/layer_01_pre.ein`, `max_enterings` per layer | **no — untouched** |

`monotonic/state_dump.py` is almost entirely the *second* kind despite
matching a `layer` grep. The census must separate them before anything is
edited.

## Attack surface

### A — the bug and its mirror (soundness; do first)

1. **`contradiction.py:183`** — the restriction. Delete.
2. **`contradiction.py:132,163,190`** — `Contradiction.layer` field and the
   `by_layer()` filter. Consumers?
3. **`lookahead.py:197,203`** — `existing.layer is Layer.REASONING`
   **mirrors the same rule** to predict whether positing a candidate would
   create a contradiction. It must move in lockstep. Get this wrong in one
   direction and the lookahead under-kills (safe, slower); in the other it
   **reports a live hypothesis as dead**, which its own docstring forbids and
   which is verdict-affecting with the default-on kill cache. Treat as the
   riskiest edit in the stage — it is the same class as P1.21's D3.

### B — the data model

4. **`kb/entities.py`** — the `Layer` enum and `Fact.layer` field.
   `Fact` identity is `(relation_name, args)` and already excludes layer, and
   `canon.state_key` excluded it at S1.21.1 — so lattice identity is
   unaffected by construction. Confirm, don't assume.
5. **`kb/store.py`** — `facts_in_layer`, and the `ontology()` / `fact_layer()`
   / `reasoning()` / `all_layers()` `FactView`s. Decide per view: drop, or
   re-express over provenance.
6. **`kb/from_ir.py`** — `_layer_of` and the `:layer` kwarg. Removing the
   kwarg needs a **decision**: silently ignore it (the Q32 `:where`
   precedent), or reject it at load. S1.22.0's finding argues for rejecting —
   a silently-dropped annotation is how the `(or …)` bugs survived — but
   `:where` sets the opposite precedent. Pick one and say why.

### C — presentation (the wide part)

Every reader migrates to `Provenance`. Counted by module:

`kb/render.py` (14), `cli/saturate.py` (11),
`inference/monotonic/_lattice_dump.py` (9), `_helpers.py` (8),
`render/lattice_dag.py` (7), `_serialise.py` (6), `state_dump.py` (4 — check
which meaning), `render/slice.py` (1), `cli/_factdump.py` (1).

Two need care:

7. **`kb/render.py`** — layer drives *styling*: ONTOLOGY plain solid, FACT
   solid + `(N)` source id, REASONING dashed + rule name, plus `layers_set`
   filtering (and whatever CLI flag feeds it). All three distinctions are
   available from `Provenance`; the goldens shift only if the mapping is
   imperfect, so a golden diff is the check that it isn't.
8. **`monotonic/_serialise.py:79-82`** — the flat `.ein` dumper **emits
   `:layer`** for exactly the facts whose provenance would not re-derive it.
   It already encodes the derivation rule, and it is the round-trip guarantee
   for `state_dump`'s `.ein` snapshots. With `:layer` gone this emission goes,
   and the round-trip becomes exact by construction rather than by patching.

## Outcome (2026-08-17)

**Both halves shipped.** Census

### The bug

Reproduced exactly as §Why predicted — a KB holding `(sits A S1)`,
`(sits B S1)` and both their derived negations reported **0**
contradictions. The restriction is gone, and `lookahead._is_contradiction`
lost its two `existing.layer is Layer.REASONING` guards in the same commit.
Three pins, each **verified to fail** with the restriction patched back in:

- `test_derived_negative_contradicts_stated_positive` — the unit shape;
- `test_mutually_negating_clues_are_detected` — the §Why reproducer, saturated;
- `test_is_contradiction_ignores_how_g_got_there` — the lookahead mirror.

`test_cross_layer_non_conflict` deleted (it pinned the restriction), and
`test_detect_layer_scopes_correctly` with it — `Contradiction.layer` and
`detect_layer()` went too, because once a pair may *span* two layers "the
layer the contradiction lives in" is not a well-defined field.

**No verdict moved, and no branch changed classification.** Same
`stop_after` / `max_set_size` as the acceptance gate, with the pre-fix
restriction monkeypatched back for the "before" column:

| fixture | verdict | k | enterings | dead_post | alive | contradictions before → after |
|---|---|---:|---:|---:|---:|---|
| `zebra2` | Solution (both) | 1 | 101 | 67 | 34 | 8308 → **8442** |
| `zebra2-minus-15` | Ambiguity (both) | 2 | 215 | 30 | 185 | 3720 → **3780** |
| `zebra2-bad` | Contradiction (both) | 0 | 0 | 0 | 0 | 246 → **252** |

Every entering counter is identical, so the extra records are additional
*witnesses on branches already dead* — not new kills. That matches the root
measurement (§6.1 of the census): the two SAT fixtures and the ambiguous one
hold **zero** cross-layer pairs at the root, so `_phase1_root` could not flip.

### The removal

`Layer`, `Fact.layer`, `facts_in_layer()`, `ontology()`, `fact_layer()`,
`reasoning()` and `to_dot(layers=…)` / `render_state(layer_filter=…)` are
gone. `all_layers()` → `all_facts()`. Presentation reads
**`Fact.is_given` / `Fact.is_derived`**, two properties computed from
`Provenance` — `kb/render.py` styling, `cli/saturate.py`'s
BACKGROUND/GIVEN/DERIVED dump, `cli/_factdump.py`'s `--print-final-*`
filter, `_serialise.py`'s ordering. `monotonic/_serialise.py` no longer
emits `:layer` at all, so the dump → reload round-trip is exact by
construction. The duplicated IR-form grouper `_flat_layer` (in
`ir/to_dot.py` and `render/constraints.py`) became `_render_group` and
lost its `:layer` branch — it buckets *forms* for DOT and never touched
the enum.

**§B.6 decision: reject.** `:layer` is a **load error**
(`` (:layer …) at <loc>: `:layer` was removed in S1.22.1b … ``), not a
silent drop. `:where`'s precedent does not apply: `:where` was inert, so
ignoring it preserved behaviour, whereas `:layer` was *authoritative* and
fed this very bug — dropping it in silence is how the `(or …)` bugs S1.22.0
found survived. 23 occurrences across 8 `.ein` files, all in-repo, all
removed here. Pinned by `TestLayerKwargRejected`.
