## Why this exists

S1.21.7 and S1.21.8 landed, and were then attacked. The attack ran five
angles; **two completed, three did not** — their agents were killed
mid-flight by a rate limit (checkpoint `3dd6d28`, recovered in `95b3d36`).

What the completed angles found is the reason this stage is P0 and not a
nice-to-have:

- the *soundness* angle found **D-S8-1** — `NafGuard.scope` dropped the
  rule's activator parameters, so a predicate guard under an `(absent …)`
  compared against `None` and **passed on a false absence**. A real
  unsoundness, in code that had a green 1342-test suite;
- the *explain-search* angle fuzzed `inference/explain.py` over randomised
  AND/OR graphs and came back clean.

So the base rate on this change is "one confirmed soundness bug per two
completed attack angles". The three angles that never ran are the subject
here. The regression suite covers them only incidentally: every mechanism
below was *introduced* by S1.21.8 and is exercised by the existing tests
only in the shapes those tests happen to use.

**Nothing here is a known defect.** This stage may well close with "no
findings, N pins added" — that is a successful outcome and should be
recorded as one. What is not acceptable is leaving the question open while
the milestone's plans are deleted.

## Attack surface

### A — `_watch_stamp` invalidation

[`saturator._watch_stamp`](../../../ein.py/src/ein/inference/saturator.py)
skips re-judging a parked candidate when no relation its guards read has
grown. It is a pure optimisation, so **any** case where the stamp is equal
while the verdict differs is a completeness bug (a firing that should
happen never does). Its stated soundness argument is:

> Sizes suffice because the KB grows monotonically within a saturation
> run: a relation cannot lose a fact, so equal size means equal extent.

Attack each clause:

1. **"The KB grows monotonically within a run."** `is_stalled`'s own
   docstring says callers write facts directly outside `step()`'s flow.
   Does any caller *replace* or *reorder* a relation's extent rather than
   append? `_index_fact` rebinds each key to a fresh tuple — confirm the
   rebinding is always an append, including on the `__symmetric__` mirror
   path and the monotonic root writebacks.
2. **"Every relation the guard reads is in `watched`."**
   [`_watched_relations`](../../../ein.py/src/ein/inference/compile.py)
   walks `Scan`/`Join` and recurses into nested `AbsentGuard`s. It does
   **not** account for a `Guard` predicate. Audit
   [`predicates.py`](../../../ein.py/src/ein/inference/predicates.py): is
   every registered predicate genuinely stateless over the KB? One
   KB-reading predicate makes the stamp incomplete.
3. **Eq-classes.** `match._candidates` documents that the participation
   index "does not apply eq-class resolution — neither does the unifier",
   which is what keeps extent-size equivalent to match-set equality. Pin
   that coupling: if `kb.classes` ever becomes live (F4), the stamp breaks
   silently.
4. **Nested-pattern args.** A `Scan` on `not` carrying a `NestedPattern`
   arg is keyed on `not` alone. Confirm growth of the *inner* relation
   cannot change that scan's match set without `not` also growing.

### B — Monotone-retirement

`_admit_from_boundary` **discards** a candidate whose failing guard is
`monotone`, on the argument that an anti-monotone query that has found a
match will keep finding one. A wrong retirement is permanent: the
candidate is never re-judged.

1. **Is the `monotone` test right?**
   [`compile._has_nested_absent`](../../../ein.py/src/ein/inference/compile.py)
   checks only the **top level** of `sub_steps`. Establish that a nested
   `AbsentGuard` cannot appear deeper — `(and …)` flattens through
   `_compile_premise`, so it should land at top level, but prove it rather
   than assume it.
2. **`(absent (or …))`.** `_compile_premise` returns `[]` for a nested
   `(or …)`, so the guard's sub-plan is *empty* — and an empty step tuple
   yields one match, making the guard fail always, and (being "monotone")
   retire its candidate permanently. Determine whether this shape is
   reachable from the surface language, and if so whether the silent
   always-fail is acceptable or must become a compile error.
3. **Interaction with `_seen` — the sharpest hypothesis.**
   `_binding_key` is `(rule_name, activator_args, bindings)` and carries
   **no disjunct index**, while `naf_guards` is per disjunct. If two
   `(or …)` disjuncts of one rule can produce the *same* bindings with
   *different* guards, `_enqueue_binding`'s `_seen` check admits only the
   first — so a disjunct whose guards would pass can be masked by one
   whose guards fail (and, with retirement, fail permanently). Construct
   such a rule. Note this dedup predates S1.21.8; what is new is that the
   two disjuncts now carry different guards, which turns a harmless
   duplicate into a possible lost firing.

### C — Fork parity + determinism under the new `Saturator` state

S1.21.8 added `_parked`, `_park_stamp`, `naf_rounds`, `naf_admitted`,
`naf_retired`; S1.21.7 added `kb._alt_justifications`.

1. **Fork parity.**
   [`test_saturator_fork_parity.py`](../../../ein.py/tests/inference/test_saturator_fork_parity.py)
   pins that saturating `kb` and `kb.fork()` yield the same fact set.
   Extend it to the boundary: same admissions, same retirements, same
   final parked set — on a fixture with `forall`-style guards, not just
   zebra2's shape.
2. **Determinism.** Boundary-admission order now decides the answer on
   non-stratified rule sets (`absent_semantics.md` §Divergence introduced
   by the fix). Confirm nothing hash-derived reaches it: `_parked` is a
   heap on `(priority, tiebreaker)`, and `tiebreaker` follows enqueue
   order, which follows `cache.values()` / `pos_index` iteration. Pin
   under several `PYTHONHASHSEED`s.
3. **Snapshot/state leakage.** Confirm none of the new state reaches
   `canon.state_key`, `LatticeSnapshotV1`, or the lattice-dump goldens —
   `state_key` is `(relation_name, args)`-only by S1.21.1, so this should
   hold by construction; pin it so a future field cannot leak in.
4. **`World.commitment` is never populated.** `Saturator` always builds
   `World(self.kb)`, so the commitment argument — documented as what makes
   a world branch-relative — is dead in the live engine. Decide: wire it
   (the fork's commitment is available at `commitment.try_commitment_set`)
   or document it as a contract-carrying parameter the saturator does not
   need because the fork *is* the world. Do not leave it undecided.

## Outcome (2026-08-17)

**Executed — both tasks. Three confirmed defects, two of them soundness
bugs; 14 regression pins.** Full evidence:
[`reports/c0_boundary_verification.md`](reports/c0_boundary_verification.md).

The stage's own base rate held exactly: three angles, three defects.

- **Angle A — clean.** All four items sound, three with new pins. `_watch_stamp`'s
  monotonic-growth clause verified over a real `zebra2` saturation (321
  firings, 38 relations, zero shrink events) and by auditing every write
  path incl. the monotonic root writebacks; the predicate-`Guard` hole in
  `watched` is sound only because the registry is `eq`/`neq` and both are
  KB-free — demonstrated by registering a KB-reading predicate and watching
  the stamp stay equal while the verdict flipped, then pinned; eq-classes and
  nested-pattern `not` args both sound and pinned.
- **Angle B — three defects (D-S8-3, D-S8-4, D-S8-5).** The stage's
  "sharpest hypothesis" (B3) was right: `_seen` collapsed `(or …)` disjuncts
  carrying different guards, making the connective order-dependent. B2's
  question is answered — `(absent (or …))` is reachable and the silent
  always-fail is **not** acceptable; it and its positive-path twin (a nested
  `(or …)` dropped from a conjunction, which fires the rule on a false
  premise) are now `CompileError`s. B2c was found en route: an
  arity-mismatched activator left `steps=()`, which matches **vacuously** —
  live in `zebra2.ein`, harmless only by luck. B1 proved rather than
  assumed: `(and …)` flattening puts any nested absent at the top level of
  `sub_steps`, so `_has_nested_absent`'s top-level check is sufficient.
- **Angle C — clean, and C4 decided.** Fork parity extended to the boundary
  observables on a `forall` fixture; determinism verified across five
  `PYTHONHASHSEED`s and pinned on the unstratifiable `p ← absent q; q ←
  absent p` program, where admission order genuinely decides the model; no
  boundary state reaches `state_key`. **`World.commitment` is documented as
  deliberately inert and pinned** — the saturator building `World(kb)` is
  correct because in a branch the fork *is* the world; the consumer that
  would want the tuple is branch-relative negative provenance, which needs a
  `Provenance` field, not a `World` one (recorded as a followup).

**Gate:** `./run_tests.sh` 1359 passed (1345 + 14) + acceptance 17/17,
verdicts and bindings unchanged; `ruff check ein.py/` clean; exhaustive
`zebra2` **11.3–13.8 s → 9.4–10.1 s** (no regression — the gain is the junk
plans D-S8-5's fix removes; acceptance phase 95 s → 68 s).
