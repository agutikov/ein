## The gap this closes

*(Closed 2026-08-17 — kept as written so the defect this stage removes stays
legible.)*

The KB kept **one** `Provenance` per `(relation, args)` fact — first
derivation wins (`store.add_and_index_fact` returns the existing object; the
incoming fact's provenance is never read). Every re-derivation's justification
was silently dropped, so
[`frontier.smallest_contradiction_frontier`](../../../ein.py/src/ein/inference/frontier.py)
is minimal only over *recorded* derivations: R3 §E3 shows the reported
frontier flipping between `{C, Y}` (2 facts) and `{A, B, Y}` (3 facts) on rule
`:priority` alone — the strictly smaller explanation exists but is invisible.
`tests/inference/test_frontier.py::test_result_depends_on_recorded_derivation_order`
pins this caveat; a fix here should flip that test deliberately.

## Shape (from R3 §3(b) — feasibility mapped, costs named)

- **Record at the dedup seam — cheap.** ~~The alternative justification is
  already materialised as a `Provenance` at firing time (`firing.py`) and
  reaches `store.add_and_index_fact`~~ — **corrected 2026-08-17, see
  [§Two corrections](#two-corrections-to-this-stage-file-2026-08-17)**: the
  seam named here is the wrong one and the runtime argument misread its own
  profile. Recording *is* cheap (+2.5 % measured), but at
  `Saturator._apply`, not at the store.
- **Storage — the first real cost.** `Fact` is `frozen=True` with a single
  `provenance` field excluded from identity; alternatives need a side table
  that joins the fork/snapshot copy contract and the S1.21.1 state-identity
  story (a justification recorded inside a hypothesis fork is not valid at
  root; NAF-stage-dependence).
- **Consumers — the second cost.** Every provenance walker assumes one
  justification: `walk_premises` / `reaches` / `build_derivation_dag` /
  `detect_provenance_cycles` in `kb/provenance.py`, plus their callers across
  `trace/answer.py`, `trace/linearize.py`, `render/slice.py`,
  `render/lattice_dag.py`, `inference/commitment.py`,
  `inference/monotonic/_helpers.py` / `_state.py`, and no-good lifting —
  ≈ a dozen modules re-reasoned for OR-nodes.
- **Search — the third cost.** Minimum-cardinality source frontier over an
  AND/OR proof DAG is the minimum-axiom-set / ATMS-label problem —
  worst-case exponential (why ATMS labels blow up). "Define/search real
  minimality" is a deliverable in itself, not a patch.
- **Completeness caveat even then:** alternatives are only the firings the
  saturator actually attempts, so "minimal" stays relative to the rule set
  and saturation strategy.

## Two corrections to this stage file (2026-08-17)

Found while executing, by adversarial verification of the § Shape claims
against the code. Both are recorded rather than silently rewritten, because
the same two errors are repeated in
[`frontier.py`](../../../ein.py/src/ein/inference/frontier.py)'s pre-execution
docstring and in [R3 §3(b)](reports/r3_min_core.md).

- **C1 — the named seam sees almost nothing.**
  [`saturator._apply`](../../../ein.py/src/ein/inference/saturator.py) returns a
  `redundant=True` Firing **before** calling `fire()` when every conclusion is
  already known, so a wholly-redundant re-derivation never builds a
  `Provenance` and never reaches `store.add_and_index_fact`. Instrumented on
  `examples/zebra2.ein` (exhaustive): **8** store-level dedup hits against
  **193 599** redundant firings — the seam saw ~0.004 % of the alternatives it
  was supposed to capture. The alternative justification *is* materialised at
  firing time, but as the redundant `Firing`'s `premises`, one frame earlier.
  **Shipped at `_apply`**; the store seam is kept for the partially-novel
  multi-assert case (those 8) and any other `add_and_index_fact` caller.
- **C2 — "saturate is ~1 % of a solve" misread a self-time table.**
  [`utils/profile_solve.py`](../../../utils/profile_solve.py) buckets
  *tottime* (self), and `saturator.saturate`'s **cumtime** is >99 % of the
  solve — saturation drives the whole run; its self-time is small only
  because most of it is inside `match.py`, which it calls. Worse, the
  `saturate` bucket excluded the seam's own module (`store.py` fell into
  `other`), and two needles (`"/compile.py"`, `"/resolve.py"`) could never
  match at all because the key is built from `Path(fn).name`. Both fixed
  2026-08-17; the corrected table puts `saturate` self-time at 12 %, not 1 %.
  The *conclusion* survives on new evidence — an interleaved best-of-5
  benchmark measures **+2.5 % median** wall clock for recording on an
  exhaustive `zebra2` solve — but not on the evidence originally cited.

## Implemented (2026-08-17)

**Recording.** `Fact.provenance` keeps the primary justification; every other
derivation lands in a KB side table
`_alt_justifications: dict[FactId, tuple[Provenance, ...]]`, read through
`kb.justifications(fact)` (primary first). Written at three sites:
`Saturator._apply`'s redundant branch (the volume — C1),
`store.add_and_index_fact`'s dedup return (partially-novel multi-assert), and
the `__symmetric__` native mirror's already-exists skip. Gated by
`SolverConfig.record_alternative_justifications` (default **on**).

Three contracts keep the model honest:

- **Terminals take no alternatives.** A `source`/`hypothesis` primary is the
  frontier — a given stays given, or an explanation would stop naming the
  premise the user supplied. A rule-kind primary with empty `premises_raw` is
  a synthetic engine writeback (`<forced-positive>`,
  `<monotonic-unconditional>`, `<lookahead-dies-immediately>`) whose contract
  is that walks ground out on it; an alternative would give it a real
  derivation and silently change every core passing through it.
- **Capped, shortest-first.** `store.MAX_ALT_JUSTIFICATIONS = 32`, kept
  sorted by premise count, so the cap biases towards the small explanations
  the search wants rather than towards whichever fired first — and a full
  list rejects a no-shorter arrival in O(1), which is what keeps the hot path
  cheap (115 189 `record_justification` calls on an exhaustive solve).
- **Copied, not shared.** The table joins the *facts* copy contract in
  `_copy_fact_indexes_into` — a justification recorded inside a hypothesis
  fork can name `hypothesis` premises root never assumed, so sharing it the
  way `_nogoods` is shared would surface a phantom assumption in a root-level
  core. `rebuild_indexes()` deliberately leaves it alone: it is *history*,
  not a projection of `facts`.

**Search.** New `inference/explain.py` — ATMS-style label propagation over the
AND/OR graph. Each fact gets the subset-minimal environments (sets of frontier
facts) it follows from: terminals seed themselves, interior nodes fold each
justification's premises with set union and keep the minimal elements, and the
whole thing is a least fixpoint from the frontier up. That last property is
what makes **cyclic** justification graphs safe — and they are now the norm,
since recording re-derivations makes `(R a b)` and `(R b a)` justify each other
through the symmetric mirror in any ordinary puzzle. `detect_provenance_cycles`
therefore stays load-time and primary-only, documented as such.

The search is worst-case exponential (minimum-axiom-set / ATMS-label), so
every axis is capped by `ExplanationBudget` (`max_environments`, `max_rounds`,
`max_env_size`, `max_facts`); truncation only ever *discards* environments, so
a budgeted answer stays sound, and `Explanation.exhausted` says whether it is
also minimum. Blowing `max_facts` degrades to the pre-S1.21.7 recorded-primary
frontier rather than to nothing.

**Consumers.** `walk_premises` / `build_derivation_dag` grew an opt-in
`justifications=` selector (`justifications_of` is the shared chooser), surfaced
as `kb.unsat_core(..., all_justifications=False)` and
`kb.derivation_dag(..., all_justifications=False)`. **Defaults are unchanged,
deliberately**: unioning over alternatives makes a core monotonically *larger*,
which is the opposite of a legible explanation — the OR-aware union's use is as
a soundness envelope (no explanation names a fact outside it). `DerivationDAG`
gained `and_nodes` (the per-justification premise groups a flat edge set cannot
express) and `is_or_graph`, and `to_dot()` draws a diamond per justification
when it is one — so the golden DOT is untouched on the primary path.

Nogood lifting was left alone on purpose: the clause is still
`frozenset(commitment)`, pinned by `contract.py`'s equality assert. Deriving a
clause from the core is the step multi-justification *invites* and where a
justification-selection error stops being cosmetic — a too-small clause wins
subsumption, prunes satisfying commitments pre-fork, and changes `k`. That is
its own soundness-argued step, not this one.

**Measured.** +2.5 % median wall clock, exhaustive `zebra2`, interleaved
best-of-5 (10.40 s → 10.66 s). 1323 unit tests pass (+21), acceptance 17/17,
verdicts unchanged.
