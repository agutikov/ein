## The claim

[`inference/canon.py:29`](../../../ein.py/src/ein/inference/canon.py) returns
`hash(tuple(sorted(...)))` — a Python `int` — and the lattice/solution
machinery uses that int as **model identity**: solution-node dedup
([`solution.py:43`](../../../ein.py/src/ein/inference/solution.py),
[`monotonic/_state.py:71-90`](../../../ein.py/src/ein/inference/monotonic/_state.py)),
snapshot canonicalisation
([`monotonic/snapshot.py`](../../../ein.py/src/ein/inference/monotonic/snapshot.py)
groups nodes and keys `solutions` by `state_hash`), and the solver's dedup
comments ([`solver.py:356,407`](../../../ein.py/src/ein/inference/monotonic/solver.py)).

Chain today: `logical state → hash:int → identity`. Required:
`logical state → canonical representation → identity`, with any hash demoted
to accelerator/index. Since the verdict is *defined* by the number of
distinct models `k`, `hash(M1) == hash(M2)` with `M1 ≠ M2` flips
`Ambiguity` (k=2) → `Solution` (k=1): a **soundness** bug, not perf.

Secondary claim: the canonical form includes `f.layer.value`, while fact
identity everywhere else in the KB is `(relation_name, args)` — layer +
provenance ignored (`add_and_index_fact` dedup;
[`commitment.py:171-178`](../../../ein.py/src/ein/inference/commitment.py)
`_is_new_relative_to` states the contract). The extensional identity of a
model must be defined explicitly — the review argues `M = {(R, args)}`, not
`M = {(layer, R, args)}`.

   *identity* (dict/set key, equality proxy, persisted id) vs *display/log*:
   `solution.py`, `monotonic/_state.py` (`kb_index`, `state_hash_merges`),

   `monotonic/state_dump.py` / `_lattice_dump.py` (persisted dumps?), tests.
2. **Decides model identity**: is there any live behaviour that
   distinguishes two branches *only* by a fact's layer? (Check `Layer`
   values crossing branches, `(not …)` facts, REASONING-layer hypothesis
   writes.) Recommend `M = {(R, args)}` or justify keeping layer.
3. **Designs `StateKey`** — `tuple[CanonicalFact, ...]` (sorted tuple of
   `(relation_name, hashable_args)`), used directly as the dict/set key so
   Python's dict falls back to tuple equality on hash collision. Estimate
   memory/latency on the zebra2 lattice (node counts from the acceptance
   run); if too big, spec the two-step `digest → bucket → canonical
   equality verification` form. Explicitly: digest alone is never identity.
4. **Migration list** — every signature/field that changes type
   (`int` → `StateKey`), persisted-dump compatibility, and the tests to add.
