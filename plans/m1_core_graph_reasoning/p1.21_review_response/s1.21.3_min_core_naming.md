## The claim

[`min_core.py`](../../../ein.py/src/ein/inference/min_core.py) documents
itself honestly ("smallest single-contradiction source frontier",
sound-by-construction via one witness's provenance leaves, deliberately
*not* the deletion-based MUS minimiser because that is NAF-unsound). But:

- It is **not** a subset-minimal MUS
  (`C unsat ∧ ∀c∈C: C∖{c} sat`) — and the top-level
  [`README.md:19`](../../../README.md) promises "minimal unsat core";
  [`reserved_engine_strings.md:46`](../../../docs/kernel/inference/reserved_engine_strings.md)
  repeats it.
- Stronger: even "smallest frontier **over all derivations**" is not
  guaranteed, because the KB stores **one `Fact` per `(relation, args)`**
  and a re-derivation returns the existing object without recording an
  alternative justification. If `A,B → X` fired first, the shorter
  `C → X` proof never enters `X`'s provenance, so the reported explanation
  depends on firing order (`{A,B}` reported while `{C}` exists).

Review options: (a) rename — `smallest_contradiction_frontier()` — and say
exactly what it is; (b) extend provenance to an OR/AND proof DAG
(`Fact X ├─ justification 1: A∧B └─ justification 2: C`) and then define/
search real minimality.
