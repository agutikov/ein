## The claim

Docs equate the lattice search's learned no-goods with CDCL
(`no-good ≈ CDCL conflict clause` as analogy is fine), but the *mechanism*
description drifts into CDCL vocabulary the algorithm doesn't earn:

```text
CDCL:  decision trail → implication graph → conflict analysis
       → learned asserting clause → non-chronological backjump
Ein:   set C → fork → saturate whole C → dead → learn C as no-good
       → suppress supersets
```

The learned clause is basically a dead *environment*, not a minimised
implication-graph conflict clause. The accurate positioning — and, per the
review, one of Ein's most original parts — is:

> **ATMS-style environment search with Apriori candidate generation and
> nogood learning.**

CDCL stays as an analog / optimization direction (that's
[P1.9](../p1.9_hypothesis_loop_followups/README.md)'s E-catalog turf).
