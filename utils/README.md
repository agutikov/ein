# `utils/` — the scripts that are not the engine

**Forty-five scripts** (`ls utils/*.py utils/*.sh | wc -l`), **all but nineteen driving `ein.rs`** — bar
[`doc_audit.py`](doc_audit.py), whose subject is the documentation and the references of every tracked file, and
which reads the crates as text, [`check_release_voice.py`](check_release_voice.py),
[`check_doc_blocks.py`](check_doc_blocks.py),
[`history_census.py`](history_census.py),
[`check_hashmap_iteration.py`](check_hashmap_iteration.py), [`check_test_scratch.py`](check_test_scratch.py),
[`check_gate_steps.py`](check_gate_steps.py) and [`check_tool_mirrors.py`](check_tool_mirrors.py),
which read the tree or a test run's scratch directory as text, [`render_diagrams.py`](render_diagrams.py), which
draws the documentation's diagrams, [`stdlib_manifest.py`](stdlib_manifest.py), which
writes the stdlib's manifest, [`gen_arith_tables.py`](gen_arith_tables.py), [`gen_num9.py`](gen_num9.py),
[`gen_gates.py`](gen_gates.py), [`gen_arith_examples.py`](gen_arith_examples.py),
[`gen_zebra2_variants.py`](gen_zebra2_variants.py), [`gen_send_written.py`](gen_send_written.py),
[`gen_random_programs.py`](gen_random_programs.py) and [`gen_stdlib_rule_pages.py`](gen_stdlib_rule_pages.py), which
write three stdlib modules or their tables, the stdlib's
Boolean property tests, seven example programs, two test fixtures, the rules' regions of the standard library's
reference with the sources of their drawings and, on demand, an arithmetic program of a stated size, and [`rule_census.py`](rule_census.py), which reads the corpus's rules as text and runs the engine for one
comparison alone. Nothing here is built, shipped or imported by the engine;
everything here *runs* it, *reads* it, or *renders* what it produced. **The dependency runs one way**: a script here
may read and run the project, and nothing in the project reads, names or runs a script here. So a check that ties a
script to the project — a generator's `--check`, a tool's copy of a list of the engine's, a second route the oracle is
held to — is a script and a step of the gate, never a crate test: a check of the project alone belongs in
`cargo test`.

**Naming the binary.** Every script that runs the engine says which build:
`$EIN_BIN` or `--bin`, defaulting to `ein.rs/target/release/ein`. One wants a
build of its own: `profile_ein_rs.py` → `--profile profiling`, which it builds.

**Every script reads the engine whose answer is the region R.**
`region_census.py`, `region.py` and `region_synth.py` read `ein oracle --dump`,
`fuzz_engine.py`'s two `solve` runs read R's description and maximal line, and
the review bundle (`review_bundle.py`, `review/`) runs each open wrong answer's
`[case.now]`, shows the register's recorded answers as its record, and draws
the row's run on the oracle's cube from its own dumps; its gallery surveys
`ein oracle --dump`. The search R replaced, the walk, had seven instruments of
its own here, and they went with it: they live in git.

## Checks

Five things the gate cannot do from inside `cargo test` — **write** a file
it also checks, **grep** the source tree, **search unboundedly**, **sweep
the whole corpus under `--events`**, and **read the documentation tree** — and
one generator, and one way to run the gate on the CI's own image. Where a row's last column names a cadence, `./run_tests.sh`
runs the per-commit ones, as `.github/workflows/per-commit.yml` does,
`./run_tests.sh --nightly` the nightly's, as `nightly.yml` does (M1e2
S1e2.3.6), and `./run_tests.sh --dev-host` the dev host's, the nightly's at
full budget and the long ones CI does not run (M1f S1f.5.27);
[`check_gate_steps.py`](check_gate_steps.py) holds each list to its workflow's, the dev host's to the nightly's.
