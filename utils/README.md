# `utils/` — the scripts that are not the engine

**Forty-three scripts** (`ls utils/*.py utils/*.sh | wc -l`), **all but twelve driving `ein.rs`** — bar
[`doc_audit.py`](doc_audit.py), whose subject is the documentation and the references of every tracked file, and
which reads the crates as text, [`check_release_voice.py`](check_release_voice.py),
[`history_census.py`](history_census.py), [`decision_census.py`](decision_census.py),
[`check_hashmap_iteration.py`](check_hashmap_iteration.py) and [`check_test_scratch.py`](check_test_scratch.py),
which read the tree or a test run's scratch directory as text, [`stdlib_manifest.py`](stdlib_manifest.py), which
writes the stdlib's manifest, [`gen_arith_tables.py`](gen_arith_tables.py), [`gen_num9.py`](gen_num9.py),
[`gen_gates.py`](gen_gates.py) and [`gen_arith_examples.py`](gen_arith_examples.py), which write three stdlib modules
or their tables, the stdlib's Boolean property tests, three example programs and, on demand, an arithmetic program of
a stated size, and [`rule_census.py`](rule_census.py), which reads the corpus's rules as text and runs the engine for
one comparison alone. Nothing here is built, shipped or imported by the engine;
everything here *runs* it, *reads* it, or *renders* what it produced. If a check belongs in the gate it belongs in
`cargo test`.

**Naming the binary.** Every script that runs the engine says which build:
`$EIN_BIN` or `--bin`, defaulting to `ein.rs/target/release/ein`. One wants a
build of its own: `profile_ein_rs.py` → `--profile profiling`, which it builds.
Two more did, `fork_delta_verify.py` (`--features fork-delta`) and
`spec_audit.py` (`--features spec-audit`): they audited the walk's fork and its
speculated layers, and went with the walk and their two features at M1e2
[S1e2.1c.5](../plans/m1e2_correctness/p1e2.1c_the_region_search/s1e2.1c.5_wrong_answers_re_scoped.md)
(2026-11-03).

**Seven are the walk's instruments.** Since M1e2 S1e2.1a.5's switch no command
runs the walk, and since S1e2.1c.5 no code: `fork_split.py`, `e2e_baseline.py`,
`feature_matrix.py`, `layer_census.py`, `openness_census.py`,
`model_set_census.py` and `closure_census.py` measure it: each says so in its
docstring, re-takes against a binary built at or before commit 7ec8a480, and
its record is the walk's. The switch ported the ones R needs —
`region_census.py`, `region.py` and `region_synth.py` to `ein oracle --dump`,
`fuzz_engine.py`'s two `solve` runs to R's description and maximal line, and
`read_out_examples.py` off its pre-switch budget. The review bundle
(`review_bundle.py`, `review/`) was re-pointed on 2026-11-01, when the
nightly's bundle step had failed on every run since the switch: it runs each
register row's `[case.now]` and shows the walk's blocks as the register's
record, and the gallery surveys `ein oracle --dump`. Since
[S1e2.1a.7](../plans/m1e2_correctness/p1e2.1a_the_solution_region/s1e2.1a.7_the_bundle_shows_r.md)
every case and program page has a § The region: the row's run drawn on the
oracle's cube, from its own dumps.

## Checks

Five things the gate cannot do from inside `cargo test` — **write** a file
it also checks, **grep** the source tree, **search unboundedly**, **sweep
the whole corpus under `--events`**, and **read the documentation tree** — and
one generator, and one way to run the gate on the CI's own image. Where a row's last column names a cadence, `./run_tests.sh`
runs the per-commit ones, as `.github/workflows/per-commit.yml` does,
`./run_tests.sh --nightly` the nightly's, as `nightly.yml` does (M1e2
S1e2.3.6), and `./run_tests.sh --dev-host` the dev host's, the nightly's at
full budget and the long ones CI does not run (M1f S1f.5.27); a test holds
each list to its workflow's, the dev host's to the nightly's.

and the commit it was taken at: the project states no measured number, so a census lives here, on the side of the
